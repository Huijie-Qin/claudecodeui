## 真实接口与修复

14 项接口检查全部通过：真实登录与文件列表、三份二进制文件内容及 MIME、只读账号下载、未登录访问、缺少工作区、跨租户用户、跨租户工作区、同租户私有工作区、目录穿越、越界符号链接、文件不存在、只读账号写入拒绝。覆盖上传后再次运行，下载响应仍与当前源文件逐字节一致。

首次运行发现：工作区内的符号链接能指向授权边界外的文件并返回 200。修复后，文本读取和二进制预览/下载入口在读取前解析真实路径，校验仍位于已授权工作区内；越界返回 403，正常内部符号链接继续可读。

界面上传复现：同名图片覆盖成功后，已打开预览仍显示旧图片。修复后，图片与工作簿订阅当前工作区的本地及 WebSocket 文件变化，合并重复事件后重新加载；XLSX 重载回到首表第一页。随后使用真实上传接口再次覆盖已加载的图片与工作簿，两个标签均显示新内容。

## 代码验证与范围限制

- `npm run test:file-preview`：25 项前端测试、8 项后端路径测试通过。
- 前后端 TypeScript 检查、涉及文件的 ESLint、差异空白检查通过。

- 覆盖后重复下载：已点击传统 XLSX 下载和只读账号图片下载，但未确认新的本机文件。随后浏览器自动化的日志读取和状态查询连续超时，因此本项保留为未确认，不能据此认定产品下载成功或失败。首次界面下载和覆盖后的真实接口下载校验均已通过。
- 本轮未覆盖所有图片编码、真实加密工作簿、网络断开/限速和所有浏览器。启动阶段已有缺少租户上下文的项目请求、专家检查返回 400；未将它们计为预览测试通过项。

## 重现

```sh
npm run build:client
npm run preview:files:e2e
```

保持服务运行，在另一个终端执行：

```sh
npm run test:file-preview:api
npm run test:file-preview
```

测试服务生成的 `artifacts/file-preview-e2e/manifest.json` 包含当前临时地址、测试账号和样例路径。验收 v1 时，浏览器登录后访问 `/`，选择工作区，再点击“文件”，依次打开图片和 XLSX。验收 v2 时访问 `/data-agent/files` 验证标签预览。覆盖测试应先打开图片和工作簿，再上传同名新文件，分别检查当前和后台标签。

结束时向启动器发送终止信号或在其终端按 Ctrl+C，清理临时服务与数据。

## v1 补充接入

用户明确要求 v1 可用后，再次核对了根路径与会话页的文件管理器、工具卡片、正文文件链接。文件管理器和工具卡片已有工作区上下文，并复用图片与工作簿预览；文件管理器的浏览器验收结果见上文。
