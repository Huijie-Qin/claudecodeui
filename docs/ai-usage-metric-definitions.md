## 代码产出：2026-09-24 会话 SQL 口径

| 项目 | 当前来源与计算 | 实现边界 |
| --- | --- | --- |
| 生成代码行数（SQL） | 夜间扫描会话中各轮 AI 回复，提取 SQL 并累计物理行数，先写 `ai_usage_report_rows` 的 `sql_generations`，再投影为 `generated_sql_lines` | 不再读取任何 Hook 记录；不是所有语言代码、语句数或采纳量。仅覆盖保留且可读取、可识别的会话内容 |
| 提交代码行数 | 夜间读取 `ai_mr_submissions`，仅 `status='merged'`，取 `additions`，先形成旧表 `code_submissions`，再投影为新表 `submitted_code_lines` | 按 `merged_at` 的上海业务日统计，以租户和主表 ID 标识记录；不是全部 commit/push，不减去 deletions，不按 SHA 跨 MR 去重。将其视为 AI 生成是约定的归因假设 |
| 表格、图表、导出 | 卡片、按日趋势、用户／工作区／日／周／月分组和 XLSX 使用同一新表、同一筛选与发布批次 | 服务端对全部匹配事实聚合后再分页；XLSX 导出全部匹配分组，不仅当前页。所有 Sheet 合计最多 50,000 条匹配记录且受文件大小限制，超限明确报错 |

原始来源为 Claude 原生会话 JSONL（可读取时优先），否则读取项目 `agent_session_messages.normalized_json` 中的规范化 AI 回复；其他已支持提供方使用该规范化消息表。夜间任务沿用 Skill 的受信任会话范围、文件游标、数据库变更队列及闲时窗口，不在白天查报表时重新扫描。代码页、筛选和统一 XLSX 均使用同批 SQL 明细。预览使用独立模拟会话：600 条含 SQL 回复合计 **3,300** 行；模拟 Hook 仍有自身的 13,800 行，两者不再相加或互相取数。

### SQL 提取与去重

- 扫描所有可读取的轮次，而不只取会话最后一条回复。只取 assistant 文本；用户输入、工具调用参数、工具返回、思考内容和流式片段不作为 SQL 产出。可识别的 fork 继承历史不重复统计，原生子会话按独立分支标识去重。
- 识别 SQL／常见方言代码块（包括 mysql、postgresql、sqlite 等）、无语言但以 SQL 关键字开头的代码块、JSON 的 sql／query／statement 字符串、`<sql>` 块、行内 SQL 和以 SQL 关键字开头的纯文本片段。非 SQL 语言代码块、未闭合的代码块不计；这是文本识别，不执行 SQL，也不保证识别所有非标准格式。
- SQL 片段统一换行后去除首尾空白，按物理行数计算，内部空行和注释行保留。相同回复中完全相同的 SQL 片段去重；不同轮次重新输出的 SQL 各计一次，不做全会话内容去重，也不推断代码是否实际采用。
- 以租户、工作区、用户、提供方、会话、子分支和消息稳定标识生成 `sql_record_id`。重复读取同条消息不累计；内容修正或删除后，下一次夜间批次更新／移除原贡献。SQL 正文不复制进统计表，仅保存行数及追溯标识。
- 日期按回复自身的业务时间转上海日期，不采用扫描时间。历史首次回扫只覆盖仍保留的记录，已删除或不可读历史不以 Hook 结果补数。
- 本次计算版本新增 `session_sql_v11`：部署后第一次闲时任务自动回扫保留的会话，旧正式结果在新候选全部准备好前保持不变；新旧明细、宽表、五表同事务发布。之后按变更增量处理，不需要新增环境变量，也不改变任务执行时刻。

SQL 没有仓库字段，不臆测仓库归属；占比不展示。已有离线 HTML 是导出时快照，不会自动更新本次口径。Hook 业务统计依然展示 Hook 自己记录的数据，本次不删除 Hook 原记录或改变其字段统计。

整体概览、AI 使用、Skill、代码产出固定查询五张主题表：`ai_dashboard_ai_detail`、`ai_dashboard_skill_publication_detail`、`ai_dashboard_skill_invocation_detail`、`ai_dashboard_sql_generation_detail`、`ai_dashboard_code_submission_detail`。Hook 执行、Hook 业务统计、Agent 模板仍查询 `ai_usage_report_rows`，不提供数据源切换。宽表 `ai_dashboard_integration_detail` 保留对接及中间投影职责；五表只由同批旧结果经宽表投影，所有正式结果同事务发布。本次只调整 SQL 生成来源，其他指标定义不变。详见 [取数方案](ai-dashboard-split-detail.md)。

### CodeHub 现有表在哪里

- `ai_mr_submissions`：提交／MR 主表，保存 `tenant_id`、`user_id`、`workspace_id`、`repository_url`、`commit_sha`、`additions`、`deletions`、`files_changed`、MR 状态和时间等。
- `ai_mr_submission_files`：逐文件明细，使用 `submission_id` 关联主表；保存 `file_path`、`additions`、`deletions`、`is_binary` 等。两个表是同一批行数的不同粒度，不能把两表求和后相加。
- 建表定义：`server/database/schema.js`；数据库由 `server/database/db.js` 的 `DATABASE_PATH` 配置决定。2026-09-17 已检查本机实际数据库 `/Users/da-group/.cloudcli/ccui/data/auth.db`，`ai_mr_submissions` 当前为 0 条。统计预览使用独立内存库，不是该业务数据库。
- 写入：`server/routes/codehub.js` 的创建 MR / 提交 MR 流程，通过 `aiMrSubmissionsDb.create` 事务写入主表及明细。普通独立 commit、push 路由和任意 CodeHub MCP 调用不保证写入；创建 MR 失败也可留下 `mr_failed` 记录，因此“表中有记录”不代表 MR 已合并。
- 本次按用户确认采用**已合并 MR 新增行数**：`status='merged'`、`additions`、`merged_at`。未合并／失败记录不计；合并时间缺失或无效不改用创建时间；新增行数缺失或非法为 NULL。修改、撤销合并和删除由后续夜间增量修正，不在白天查询业务表补数。CodeHub 原始写入流程和 `getAdminStats` 未改动。
- 迁移旧已发布批次不会伪造其中没有的 CodeHub 事实。该旧批次尚未采集 CodeHub 时显示不可用；重新加载后端后，下次夜间批次才能建立来源覆盖。有覆盖且实际无记录才显示 0。

## 1. 先看这几条

- 报表不是实时看板，展示最近一次成功发布的统计批次。
- 顶部四张整体概览卡片使用固定口径，不受页面筛选、Tab、分组、排序或分页影响。
- Tab 内先按日期、用户和工作区筛选事实，再分组计算。不是先取一页数据再统计。
- 人数、会话数等去重指标的合计重新去重，不能直接相加各组人数或各天会话数。
- Skill 发布数量和调用次数归属发布者；会话、AI 时长、活跃人数归属实际使用者。
- 记录性 Hook 统计的是落地的业务记录及字段值；Hook 执行统计的是执行事件。两者不是同一指标。
- `0` 表示当前可用数据中结果为零；`—` 表示值未知或该指标明确不可用。部分覆盖仍可能显示已知部分的数字，不代表全量。

### 查看方式：对象与时间分开

- **按对象**：根据报表选择用户、工作区、Hook、模板、Skill 或发布者，比较所选日期范围内各对象的汇总数据。没有时间汇总能力的报表只显示统计对象，不放无效的时间入口。
- **按时间**：单独选择按天、按周、按月；这是另一种表格查看方式，不与用户／工作区组合成二维分组。进入或切换时间粒度默认按日期升序，仍可点表头排序。
- 周一至周日为一周，表中显示实际纳入计算的日期区间；首末周按日期筛选截取。例如筛选 8 月 14 日至 9 月 12 日，首周显示 `2026/08/14 — 2026/08/16`。月汇总遇到不完整月份时也标出所含日期，既不扩大范围，也不补算筛选外的日期。
- 按用户查看时，不显示每行只能为 0／1 的活跃使用人数；记录性 Hook 的记录用户数同理。汇总区仍保留全量去重人数，工作区和时间汇总仍展示人数列。零使用用户仍保留，不通过删行把 0 改成 1。
- XLSX 与当前可见统计列、日期区间标注一致；上方每日趋势和固定概览不因表格查看方式改变。底层聚合与统计口径不变。

## 2. 时间、刷新与数据范围

| 项目 | 当前口径 |
| --- | --- |
| 数据截至日 D | 当前发布批次覆盖的最后一个业务自然日；以批次统计时区计算，不采用浏览器时区 |
| 统计时区 | 本次新旧双表链路统一 Asia/Shanghai；新表时间保存为 `YYYY-MM-DD HH:mm:ss`。旧的非上海批次须重新生成，不能只改时间文字 |
| 起止日期 | 两端均包含，按业务日期筛选；结束日期不能超过 D；单次最多 366 天 |
| 默认查询范围 | D−29 至 D，包含 30 个自然日 |
| 自然日 | 统计时区的 00:00 至下一日 00:00，不是过去 24 小时 |
| 自然周 | 周一开始，标签为该周周一日期；先筛选，再把已选日期归入各周，首末周可能不是完整周 |
| 自然月 | 自然月标签 YYYY-MM；首末月同样可能只覆盖所选的部分日期 |
| 默认运行设置 | 统计默认关闭；启用后默认 02:00 开始、06:00 窗口结束、并发 1，可配置 |
| 上次成功 | 当前批次成功完成时间，不是最近一次浏览页面的时间 |
| 下次开始 | 调度计划，不保证这一时刻数据必然已更新 |
| 刷新结果 | 重新读取发布结果，不触发历史消息扫描或立即重算；页面有确认步骤 |
| 失败或暂停 | 保留上一成功批次；未完成的批次不替换当前报表 |

数据截至日只说明业务日期边界，不保证所有外部文件和迟到记录已到齐。后续批次可能补齐历史日期。新结果先在暂存表算完整，再事务替换正式明细；正式表无 `partition_id`，不保留历史结果版本。查询携带的批次已被替换时，须刷新重试；同次请求在只读事务中保持一致。权限撤销或原记录删除等安全修正可能使已发布结果中的可见数据减少。详见 [暂存刷新说明](ai-usage-staged-refresh.md)。

## 3. 顶部整体概览：四张卡片

概览标题旁统一显示数据截止日（含年份）。每张卡下方采用“统计周期标签 + 日期范围”：会话与 MAU 显示近 30 天起止日期，Skill 显示历史累计截止日，DAU 显示截止日当天。跨年区间两端均显示年份。日期来自已发布批次，不使用打开页面当天，也不继承下方筛选；离线 HTML 的日期固定于内嵌快照。

| 卡片 | 定义与计算 | 范围 | 是否受页面筛选影响 |
| --- | --- | --- | --- |
| 会话次数（近 30 天） | 期间发生过有效用户交互的逻辑会话数，按逻辑会话标识去重；不是消息条数，也不是请求轮数 | D−29 至 D，当前租户 | 否 |
| 累计发布 Skill 数量 | 截至 D 有确认首次发布事实的 Skill ID 去重数；重复发布同一 Skill 不累加 | 已采集的首次发布历史至 D，当前租户 | 否 |
| 日活用户 DAU | D 当天发生过有效用户交互的用户 ID 去重数 | D 当天，当前租户 | 否 |
| 近 30 日活跃用户 MAU | D−29 至 D 至少交互过一次的用户 ID 去重数；不是自然月人数，也不是每日 DAU 相加 | D−29 至 D，当前租户 | 否 |

累计发布数量不等于当前市场可见数量，也不等于下载数、导入数、发布操作次数。当前仅统计能确认首次发布时间和 Skill ID 的发布事实；历史留痕缺失时不能凭导入时间推断首次发布。

## 4. AI 使用

### 4.1 指标

| 指标 | 计算方式 | 归属与注意事项 |
| --- | --- | --- |
| 会话次数 | 当前筛选范围内有效交互的逻辑会话标识去重数 | 实际使用用户；一个会话多次发消息仍只算一次 |
| AI 活跃时长 | 已完成请求的“用户请求开始 → AI 响应完成”区间按日期切片后求和 | 实际使用用户；不是登录在线时长、会话首尾跨度或 Token 生成时长 |
| 活跃使用人数 | 当前范围内有有效交互的实际使用用户 ID 去重数 | 按用户时隐藏重复的 0／1 列，合计保留；按工作区、日、周、月分组体现该组人数 |

逻辑会话标识由租户、工作区、用户、模型提供方及提供方会话 ID（或可信替代标识）组成，避免同名会话和不同来源互相混合。页面不再提供模型来源分组，但底层仍保留其身份隔离。

AI 使用表只计算交互与请求时长事实，不再混入发布者贡献。期间新增发布数与 Skill 调用次数统一在“Skill 发布与调用”查看；顶部累计发布卡片保持原有固定口径。

有效交互来自可信请求事实和可识别的真实用户消息。内部元消息、工具结果、Skill 展开正文、Hook 恢复及 MCP 循环内部结果、子代理内部用户消息不作为新的真实用户交互。可读取的 Claude 原生历史优先于重复数据库副本。

### 4.2 时长的边界

- 每轮分别累计，不把上一轮结束到下一轮开始之间的等待算进去。
- 跨日按统计时区拆分。例如 23:58 开始、次日 00:03 完成，前一天 2 分钟、后一天 3 分钟，合计 5 分钟。
- 未结束的请求不以当前时间补终点；终点确认后，由后续批次补齐受影响日期。
- 当前仅完成态贡献时长。失败、取消、终止、incomplete、unsupported 不贡献时长；不能从缺失时间推算。
- 并发请求按每轮区间相加，不取时间区间并集；因此并发较多时总时长可以超过自然经过时长。
- 主响应终点使用可信主流程完成边界，不把子代理消息作为新增用户轮次，也不简单延长到 Hook 后置处理全部结束。
- 历史或其他提供方缺少可信起止边界时，可有会话数而没有完整时长。当前时长覆盖不能视为全部模型、全部历史均完整。

### 4.3 柱状图与表格

柱状图按天展示，可切换会话次数、DAU、MAU；受顶部公共日期、用户名、工作区名称筛选影响。图上某日 MAU 是以该日为终点的滚动 30 日人数，即使图的开始日期较晚，也不是仅从图的开始日期累计。

表格支持用户、工作区、日、周、月分组。表内分组、排序和翻页不改变柱状图。默认按用户展示，保留当前租户中没有匹配使用事实的成员作为零值行；零值占位不增加活跃人数。工作区筛选后也可能看到该工作区内使用为零的租户成员，这不代表其属于该工作区。

## 5. Skill 发布与调用

| 列 | 定义 |
| --- | --- |
| Skill 名称 | 业务 Skill 名称，身份以 Skill ID 为准；同名不同 ID 不合并 |
| 发布者 | 能由可信发布事实或业务时点绑定解析出的平台用户，不把市场账号 ID 当作平台用户 ID |
| 首次发布时间 | 已确认的首次发布事实时间；未知显示 `—`，不以导入时间替代 |
| 期间新增发布数 | 筛选日期内确认首次发布的 Skill ID 去重数；与顶部截至 D 的累计数量不同 |
| Skill 调用次数 | 所选期间该 Skill 的有效调用发起次数，不等于成功次数 |
| 调用人数 | 所选期间调用过该 Skill 的实际调用用户 ID 去重数，与发布者是不同角色 |
| 最近调用时间 | 所选期间匹配调用的最晚发起时间；没有调用则为空 |

有效调用规则：

1. 纳入明确的原生 `Skill` 工具调用，以及真实用户提交且可验证对应 Skill 的 `/名称` 命令。
2. 斜杠命令须由当时有效的 Skill 绑定，或同请求下对应的原生工具／Skill 展开记录证明。不能把所有 `/help` 类命令都算作 Skill。
3. 同一请求、同一分支、同一 Skill 的斜杠命令与对应工具调用合并；不同工具调用 ID 保留独立次数。
4. 不纳入普通文本提及、Read/Bash 读文件，以及可信来源为 Hook、Agent Graph、Top Skill 的内部调用。
5. 重复数据源与同一事实的重复导入不重复计数；不能可靠归属发布者的调用不记给调用者冒充个人贡献。

本页默认按 Skill ID 与发布者关联展示，也可切换为按发布者分组。按发布者时，期间新增发布数及调用次数汇总到该发布者，调用人数按其全部匹配 Skill 的实际调用用户重新去重，不直接相加各 Skill 的人数。表内合计同样覆盖全量匹配事实，不受分组和分页影响。Skill 名称筛选在两种分组下都先限定 Skill，再计算结果；导出遵循同一范围。

保留所选结束日前已发布但期间零调用的 Skill，历史发布不能被计作期间新增。公共栏“发布者用户名”筛选发布者；工作区筛选在调用事实中指调用工作区，在新发布打点中指发布工作区。新表 `ai_skill_publish_events` 记录确认发布请求及其成功、失败、不确定结果，首次上传与发布更新都留痕；只有确认首次上传发布的成功事件进入新增发布指标，更新不冒充首次发布。旧发布事实缺失的工作区不猜测补齐，使用工作区筛选仍可能排除旧发布事实，影响期间新增发布数、零调用 Skill 的保留及首次发布时间。详见 [发布打点与代码产出来源](skill-publish-tracking.md)。

发布者未知、历史绑定缺失或冲突的 Skill 调用，不能保证计入当前可归因列表；因此此表不是所有本地 Skill 执行的完整审计日志。

## 6. Hook 执行统计（历史口径，看板已移除）

| 指标 | 计算方式 |
| --- | --- |
| 执行次数 | 匹配的 Hook 执行事件 ID 数；一次执行一条事实，不按输出字段数计数 |
| 成功次数 | 状态为 succeeded 的执行事件数 |
| 失败次数 | 状态为 failed 的执行事件数 |
| 未结束次数 | 状态为 running 的执行事件数；不直接判成失败 |
| 平均执行耗时 | 所有匹配执行中有效 durationMs 的算术平均；仅已结束且时长有限、非负的记录参与，运行中或时长缺失不补零 |

执行日期取开始时间，不取完成时间。耗时展示可以使用毫秒；不能把 500ms 当作 500 分钟。成功与失败的有效完成耗时都参与平均，不是只平均成功事件。若后续出现其他状态，执行总数仍包含事件，三类状态小计不一定覆盖全部事件。

支持 Hook、用户、工作区、自然日、自然周、自然月分组，Hook 名称关键字筛选。用户指执行记录所属用户，不是 Hook 配置作者。执行记录入口展示该 Hook 的执行时间、所属用户、工作区、事件、状态和耗时等安全元数据。

## 7. 记录性 Hook：新的两层设计

### 7.1 第一层：Hook 列表

每个 Hook ID 一行，显示 Hook 名称、业务记录数、记录用户数、涉及工作区数，以及“进入统计”。不再先把所有 Hook 的字段与统计结果混在一张表里。

| 指标 | 定义 |
| --- | --- |
| 业务记录数 | 已落地、已发布、匹配筛选条件的业务记录 ID 数；不是 Hook 执行次数，不是字段值之和 |
| 记录用户数 | 这些记录中用户 ID 非空的去重人数；用户未知的记录仍可计入记录数，但不凭空增加人数 |
| 涉及工作区数 | 这些记录中工作区 ID 非空的去重数量 |

目录按当前公共日期、用户名、工作区及 Hook 名称筛选。仅包含该范围有业务记录的 Hook，暂不展示从未产生记录的配置目录或零记录占位。相同名称、不同 Hook ID 仍是不同入口。

### 7.2 第二层：单个 Hook 统计弹窗

统计结果只显示数值，不追加“分、条、行、分钟”等单位；不推断或要求 Hook 提供 `unit` 字段。记录明细同样显示字段原值，不额外拼接单位。字段名称保留原定义，例如“SQL 行数”。

点击“进入统计”后，在当前列表上方打开居中悬浮弹窗，不在列表下方展开。背景列表、筛选条件和滚动位置保留；弹窗内独立滚动，标题和关闭按钮保持可见。

弹窗固定 Hook ID，不固定某个字段或某个版本，默认按用户分组、求和、全部数值字段。上方提供本 Hook 的日期、用户名、工作区名称筛选；下面选择分组、数值字段和统计方式。

| 控件 | 影响范围 |
| --- | --- |
| 起止日期、用户名、工作区名称 | 同时限定数值统计与记录明细；点击应用后生效 |
| 数值字段 | 全部或某个字段键；选具体字段时，明细仅保留该字段存在有效数值的记录 |
| 查看方式 | 按对象选择用户、工作区、整体统计；按时间另选按天、按周、按月。只改变统计分组，不把原始记录变成分组行 |
| 统计方式 | 求和、平均值、最小值、最大值，一次显示一种；只改变显示的计算结果 |
| 表头排序、分页 | 各自控制统计表或明细表，全量排序后分页；不改变计算数据范围 |
| 重置筛选 | 恢复进入该 Hook 时的日期／用户名／工作区条件，并恢复全部数值字段；不修改外层列表筛选和顶部四张卡片 |
| 关闭弹窗 | 点击右上角关闭、按 Esc 或点击遮罩，回到原列表位置，保留外层筛选；重新进入时恢复默认统计选项 |

用户名、工作区名称采用关键字匹配；同名用户、同名工作区仍按各自 ID 分组。未知身份可单独形成未知组，不与真实用户或工作区合并。

### 7.3 四种数值统计公式

对当前筛选范围内、当前分组中的同一字段，设有效值为 x₁…xₙ：

| 统计方式 | 公式 | 例：10、20、30 |
| --- | --- | --- |
| 求和 | Σx | 60 |
| 平均值 | Σx ÷ n | 20 |
| 最小值 | min(x) | 10 |
| 最大值 | max(x) | 30 |

- 字段必须已开放给报表、声明为 number，且记录值确实是有限数字。
- 缺失、null、数字字符串、布尔值、NaN／无穷值不参与；不会当作 0，也不会自动把字符串转数字。有效的 0 参与计算。
- 普通自定义 number 可以包含有效负数；历史内置 SQL 数量适配只接受非负数。
- 每个字段都有自己的有效样本数，平均值分母不是整张表记录数，也不是所有字段的样本数。样本数虽然不展示为列，后台仍使用它计算。
- 跨日汇总使用“所有日总和 ÷ 所有日有效样本数”，不是各日平均值再简单平均。
- 同一条记录有多个 number 字段，会分别参与各字段统计；不能把不同字段、不同单位的结果当成一个总数相加。
- 结果覆盖所有匹配记录，不限当前 20 条；没有有效数字时显示无可统计结果，不制造零值。

### 7.4 版本、字段与原始记录

新单 Hook 统计页将相同定义的字段跨版本合并。相同定义要求 Hook、后置行为、记录类型、记录来源、字段键、字段标签、单位一致，且为 number。不同后置行为、单位或其他定义仍分组隔离。

这不意味着拿最新草稿重解释历史：每条历史记录先依据其发布版本提取安全字段，再对兼容字段统计。若业务含义改变，即使还是数字，也应更换字段键或相应定义，不应继续复用同一字段身份。

旧兼容字段接口仍保留版本隔离；新页面使用单 Hook 专用接口，不能把旧截图或旧接口返回行数当成当前页面的口径。

记录明细展示记录时间、用户名、工作区名称、后置行为和已开放的业务字段。文本、布尔值只展示，不做上述四种数值聚合；不会展示整份 Hook JSON 或聊天正文。每个后置行为最多开放 20 个平级字段，不支持任意嵌套路径。旧 SQL 指标存在固定字段适配，其他未配置记录类型可能只有记录数而没有可统计字段。

### 7.5 使用示例

查看“每个用户的 SQL 行数总和”：

1. 在记录性 Hook 列表找到 SQL 产出记录，点击“进入统计”。
2. 选择日期范围；需要时输入工作区或用户名关键字，应用筛选。
3. 分组选择“用户”，数值字段选择“SQL 行数”，统计方式选择“求和”。
4. 统计表中每个用户对应一个 SQL 行数结果；下方明细是本次计算范围内的有效 SQL 行数记录。

同样可以查看某工作区每天的 SQL 行数、每个用户的平均评分、指定日期范围的最大耗时等，字段由 Hook 实际开放的 number 定义决定，不限于 SQL。

## 8. Agent 模板使用

| 指标 | 定义 |
| --- | --- |
| 活跃使用人数 | 被关联到该模板、且发生有效用户交互的实际使用用户去重数 |
| 会话次数 | 关联到该模板的有效交互逻辑会话去重数 |

当前页面仅保留以上两项指标；主表、分析弹窗、合计及 XLSX 同步移除应用次数、应用人数和 AI 活跃时长。按用户查看时仅列会话次数，活跃人数保留在去重合计中；按工作区和时间查看时展示两项。

有效交互只有在事件时间不早于该工作区模板应用快照创建时间、且能关联模板时，才贡献模板使用指标。模板可能在筛选开始日前已应用，所选期间仍在使用；两项指标归属于实际使用者，而非应用模板的人。

主表固定按模板比较，保留模板名称筛选、两项指标及合计。点击某个模板的“查看使用分析”打开弹窗，以模板 ID 精确限定数据，再按用户、工作区、日、周或月分组；同名不同 ID 的模板不混合。弹窗继承公共日期、用户名和工作区筛选，导出覆盖该模板当前分组的全部匹配结果。不会恢复已移除的应用记录或关联会话按钮。

兼容与限制：底层仍保留应用快照和时长事实，不删除历史数据或改变采集流程。应用快照数不是每次切换、重应用的完整事件账本；快照覆盖或历史归属缺失会影响能恢复的历史范围。当前模板使用关联仍依赖工作区模板快照，不代表逐次模板调用日志。

## 10. 去重、权限、缺失与导出

- 业务事实以稳定来源身份去重；同一记录重扫或翻页不会增加计数。不同记录 ID 即使字段内容相同，仍是不同记录。
- 合计从当前筛选的全量事实重新计算。跨日同一用户、会话可在多个日期组出现，但期间合计只去重算一次。
- 当前页面固定为租户全员视图，仅向有租户报表权限的身份展示，不把“去掉仅本人开关”解释为给普通用户扩大权限。
- 后台每次请求核验当前登录用户、租户有效状态、成员关系及角色；不信任页面传入的角色，也不能通过改批次或 Hook ID 读取其他租户数据。
- 名称优先展示当前用户名称／工作区名称，安全历史快照兜底；分组身份仍用 ID，改名不是新增用户。
- 未知身份、不可用时长或发布来源缺失不伪造；部分覆盖下的 0 仅表示已覆盖范围内为 0。
- 顶部统一下载 XLSX，按报表分 Sheet，规则见本文开头；不再提供各表 CSV 按钮。
- 单 Hook 统计作为独立 Sheet，使用保存的筛选、数值字段与统计方式，不追加单位、不混入原始记录。数值保留查询结果精度。
- 点击总下载时冻结所有已应用筛选，逐页读取同一已发布批次。下载中切换 Tab 或修改筛选不改变本次快照；切换租户、离开看板会取消下载。开始、逐表及下载前重新校验权限，批次、总行数或分组不一致时整个下载失败，不生成残缺文件。空结果保留筛选信息与表头，不伪造零值。
- 所有 Sheet 合计最多 50,000 条匹配记录，导出数据序列化后最多 10 MB；超限须缩小筛选范围，不静默截断。名称中的公式样式文本按字面导出。文件直接由浏览器下载，不上传第三方、不在服务器保存，也不触发夜间重算。
- 后台异步任务基础设施保留但未配置生产序列化器；统一 XLSX 下载不依赖该异步服务。旧版离线压缩包不会自动获得新功能，需要重新打包。
- 查询只读取已发布的安全报表数据。数值聚合优先使用夜间每日汇总；删除修正或旧汇总不兼容时回退到安全记录投影，不扫描原始聊天正文。

## 11. 当前仍需业务确认或补齐

1. 失败、取消、人工确认等待、并发请求的时长计入规则，是否继续采用当前保守实现。
2. 全部模型提供方的可信请求完成边界，以及缺失历史的恢复策略。
3. Skill 历史首次发布、发布工作区和发布者绑定证据不完整的补齐方式。
4. Agent 模板是否需要完整的“应用／切换事件”历史，而不只是工作区快照。
5. 零记录 Hook 目录是否展示，以及已删除 Hook 的历史目录策略。
6. 如需服务器端大批量异步导出，仍需确认相应文件格式、文件保留期及刷新冲突的重试策略；正式明细不再保留历史统计分区。
7. 已复用字段键但实际业务含义改变的历史数据如何区分，避免跨版本误合并。
