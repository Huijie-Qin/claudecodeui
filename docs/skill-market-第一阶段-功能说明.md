# 技能市场第一阶段 · 功能说明

更新：2026-09-15。状态：待实现方案与离线交互原型，不表示生产功能已上线。

本文件是第一阶段的产品范围及完整交互基线。[详细设计](skill-market-第一阶段-详细设计.md)说明实现落点和技术约束；[第一阶段原型](prototypes/skill-market/phase1.html)用于评审。此前完整版文档及 index.html 保留作为后续参考，不作为本期验收范围。

## 1. 本阶段目标与范围

让运营通过会话描述需求创建 Skill，直接调用验证，将真实任务沉淀为用例，由后台测评和自动优化减少重复人工调整。平台管理员维护全平台通用片段，运营无需理解模板配置。

| 功能 | 本阶段交付 | 主要入口 |
| --- | --- | --- |
| 会话创建 | 技能创建模式、描述输入、调用 skill-creator、自动保存、会话继续调整 | 会话底部能力按钮 |
| 验证沉淀 | 普通会话直接调用 Skill；完整调用后保存为用例 | 调用输出下方 |
| 测评用例 | evals/evals.json；手工添加、AI 添加、编辑、删除及已发布保护 | 我的技能 → 测评 |
| Skill 测评 | 静态检查、后台串行运行全部、逐例完整输出与判定 | 我的技能 → 测评 |
| 自动优化 | 全量前测、修改自动落盘、全量后测、输出和文件对比 | 我的技能 → 测评 |
| 公共片段 | 平台管理员新增/编辑/删除；全员查看搜索；编辑时插入；创建时自动匹配 | 技能 → 片段管理；文件编辑 → 快捷插入 |

本期不新增：模板中心、模板选择弹框、模板配置、自定义模板字段、贡献请求、评审/合并、负责人转移、Skill 管理员配置、新发布流程、公开测评报告分发、Skill 历史版本、独立调试页面、其他 Skill/MCP 快捷插入、无上限或定时无人值守优化。本期支持用户发起、受最大迭代次数约束的自动优化。

既有技能市场、导入/更新、手工创建和文件操作可保持生产原状，不在本文件展开，也不要求删除现有代码。本期原型仅展示必要的“我的技能、片段管理、聊天”，不复制所有现有页面。已有发布链路保持原状，本期测评结果不新增发布门禁；发布门禁和公开报告如何接入另排后续阶段。自动优化绝不触发发布。

## 2. 用户与权限

| 操作 | 运营：可编辑工作区 | 运营：只读工作区 | 平台管理员 |
| --- | --- | --- | --- |
| 浏览/搜索公共片段 | 可以 | 可以 | 可以 |
| 维护公共片段 | 不可以 | 不可以 | 可以 |
| 在工作区创建/调整 Skill | 可以 | 不可以 | 同样需要该工作区编辑权限 |
| 插入片段、维护用例 | 可以 | 不可以 | 同样需要该工作区编辑权限 |
| 运行测评、自动优化 | 可以 | 不可以 | 同样需要该工作区编辑权限 |
| 查看已有本地报告 | 需要该工作区读取权限 | 可以 | 不跨工作区自动授权 |

“平台管理员”仅用于公共片段治理，不等于每个 Skill 的管理员。本期不引入新的 Skill 管理角色。市场导入的本地可编辑副本也能添加用例和测评，不要求当前用户是远端负责人；修改只影响当前工作区副本。

## 3. 会话直接创建 Skill

### 3.1 进入与填写

1. 会话底部在其他能力按钮同一排显示“技能创建”。这是模式按钮，不是普通提交按钮。
2. 点击后保持在当前会话，不打开模板弹框、不跳转、不发送消息。
3. 当前输入框改为创建描述区，placeholder 为“请描述你想创建的技能：用于什么场景、提供哪些输入、希望得到什么结果…”。输入区最小高度 112px。
4. 按钮立即高亮，并通过 aria-pressed 标记选中。无内容、正在输入、输入法组合输入、失焦再聚焦，均不取消高亮。
5. 第一阶段不展示“技能标识”字段或其他创建表单，只填写技能描述。SKILL.md 的 name 仍存在，由 skill-creator 根据描述生成，服务端负责合法性与唯一性校验，无需用户填写或确认。
6. 原有输入文字保留，不把 placeholder 作为正文写入。用户描述应包括对象、输入、任务与期望结果；不要求填写固定格式或 JSON。
7. 再次点击按钮退出创建模式，恢复普通会话 placeholder，保留已输入的描述。再次进入可接着填写。切换会话时按会话隔离草稿，不把模式带到其他会话。

示例描述：“根据门店提供的活动记录和销售汇总生成周报，包含进展、风险和下周计划。没有具体数据时不要推算增长比例，用运营能理解的语言表达。”

### 3.2 发送与创建

1. 发送前检查描述非空、工作区可写。用户不提供标识；后台生成 name 并检查格式，重名时自动分配唯一后缀，同时保持目录、SKILL.md 与 evals/evals.json 中的名称一致，绝不覆盖已有技能。失败保留内容与高亮。
2. 创建模式下的发送携带明确的 create-skill 意图，不能依赖模型猜测是否在创建技能。普通聊天发送不携带此意图。
3. 服务端接受后显示当前会话中的创建进度，禁用重复发送；按钮在创建期间仍高亮但不可点击。
4. 后台读取公共片段库作为参考，由 AI 判断与需求相关的片段，不默认把所有正文拼入 Skill。无匹配则不插入。整个过程不需要用户勾选片段。
5. 独立生成任务调用 skill-creator。产物经过路径、name、文件格式和安全校验后，自动保存到当前工作区 `.claude/skills/<name>/`。
6. 初始化 `evals/evals.json`；没有生成合法用例时初始化空数组，不伪造已测评结果。生成成功不等于业务测评通过。
7. 当前会话显示完成信息、目录和所用片段的简短说明；我的技能及斜杠命令列表刷新。无需“确认保存”。成功后退出创建模式并清空已提交描述，恢复普通输入状态。
8. 失败或取消时不留下半成品，不覆盖同名技能；恢复创建模式及提交时的内容，按钮重新可用且继续高亮。重试不得重复创建成功产物。

### 3.3 创建后继续调整、调用

1. 留在同一普通会话继续输入“补充风险处理”“输出再简短一点”等指令；Agent 对刚创建的目标 Skill 做修改。
2. 目标不明确时询问用户，不凭名称相近修改其他 Skill。调整须使用文件摘要检查，不能覆盖期间手工改动。
3. 调整完成直接保存，不再“确认采用”；反馈修改了哪些文件。旧测评报告如不匹配当前内容，显示已失效。
4. 验证时直接 `/skill-name 任务描述` 调用，不新增“试用技能”模式或独立调试入口。普通调用按既有会话权限运行，不自动获得写入生产资源的权限。
5. 第一阶段原型用预设结果展示这个流程，不能用于判断真实 Skill 的效果。

## 4. 从会话保存测评用例

1. 只有能绑定到某个本地 Skill 的完整调用结果才显示“保存为测评用例”。创建成功提示、普通聊天、执行失败、正在运行的消息不提供该按钮。
2. 点击后直接把本次 query、参考输出、必要输入资料保存至该 Skill 的用例文件，不弹出验收标准确认。
3. 用户的点击代表希望复用此次结果，不代表系统已经证明输出正确。expected_output 保存为参考结果；后续测评仍需独立判断。
4. 文本、工具调用、subagent、文件产物均可成为运行证据；工具耗时、调用 ID 等不稳定字段不作为必须完全一致的预期。
5. 输入附件复制到技能目录内的 `evals/files/`，再以相对路径引用。不可复现、无权限或包含未脱敏敏感资料时，明确拒绝保存并提示原因，不静默丢失关键输入。
6. 同一调用重复点击只保存一次。成功后显示“已保存为测评用例”，我的技能中可立即看到，并允许后续编辑。

## 5. 测评用例管理

唯一来源：每个 Skill 的 `evals/evals.json`，而不是数据库中的另一套场景配置。

入口：我的技能 → 选择 Skill → 测评。页面使用一张表：验证场景、预期结果、运行结果、操作。顶部三个按钮集中在“技能测评”标题行右侧，窄屏时整体换到标题下方。

### 手工添加 / 编辑

1. 添加验证场景 → 添加场景，显示场景输入、预期结果、可选检查要点；示例只作 placeholder，不预填为真实数据。
2. 附件引用遵守用例 schema；可在文件编辑中管理目录和路径。表单编辑时保留既有附件，不因未展示字段而丢失。
3. 保存时校验并原子写入用例文件；成功即生效，不存在“草稿待确认”。失败保留表单。
4. 文件编辑器修改同一个 JSON，也使用相同的格式与删除保护校验。用例改变后旧测评报告失效。

### AI 添加

1. 添加验证场景 → AI准备场景，读取 Skill、现有用例和授权材料。
2. 默认补充正常、缺失输入、异常边界等场景；AI 生成符合相同格式的新用例。
3. 校验通过直接追加，不覆盖已有用例、不要求确认。显示新增数量；失败不写入非法 JSON。

### 删除与保护

- 从未发布的本地用例可删除。
- 曾随 Skill 发布的用例始终不可删除，表格、JSON 编辑、文件删除均受保护；可编辑但会使旧报告失效。
- 本期不新增发布功能；导入包可确认的已发布用例建立保护登记，已有可信保护记录继续保留。来源不明不伪造保护历史，单独标记并由迁移策略处理。
- 测评期间冻结本次用例，不允许页面同时编辑同一技能；外部改动触发并发冲突处理。

## 6. 运行全部

1. 不跳转会话页面；后台创建测评任务，页面显示串行进度及停止入口。
2. 冻结当前 Skill、用例、输入材料与测评策略；先做静态检查。
3. 阻断项失败时不运行动态用例，展示具体文件/字段原因；建议项不冒充阻断错误。
4. 严格按 evals 数组顺序，执行一条 → 等待全部工具/subagent 结束 → 收集消息与文件 → 判定 → 再执行下一条。没有并行执行全部用例。
5. 业务不符合预期可继续下一条；环境、权限、限额异常独立标记，不假装是 Skill 能力失败。
6. 每行“查看详情”显示当次固定预期及完整可见输出，沿用会话的用户、助手、工具、子任务和文件格式；判定和证据单列，不用一句摘要替代输出。
7. 文本只要求语义与约束符合，不要求固定 JSON 或逐字相同。运行全部不修改 Skill。
8. 空用例不显示“通过”。取消保留已完成结果，其余标记未执行。断线后可恢复查询任务。

## 7. 自动优化

1. 点击“自动优化”先打开设置弹框，填写“最大迭代次数”，默认 3 次，允许 1–10 的整数；点击“开始优化”才启动任务，取消不启动。随后后台重新完整运行全部用例，得到本次前测，不直接使用旧测评结果；若已全部通过则直接结束，无需改动。
2. 优化 Agent 读取 Skill、固定预期及前测证据，生成修改。不得修改用例、输入材料和评分规则来获得高分。
3. 路径、安全和并发检查通过后直接写入当前 Skill；立即反馈“修改已保存”，不提供“确认改动 / 采用”。
4. 再串行完整运行同一批用例，形成后测；无实质修改时也做后测并说明。
5. 用例详情左右两列默认展示本任务初始前测与最新一次优化后完整可见输出，标明最新迭代序号，顶部固定预期；窄屏局部横向滚动。中间各轮结果单独保存在任务报告中，不混入当前列。缺少后测时显示未执行，不混入旧报告。
6. “查看 Skill 修改对比”显示本次前后的实际文件内容与差异。这是任务快照，不是产品版本历史。
7. 后测退化、执行失败或写入后取消，都保留已经保存的改动并明确提示；不虚假显示成功，不自动回滚，不自动发布。
8. 一次迭代计为“一次优化尝试（修改直接落盘）+ 全量复测”，初始前测不计数。没有实质改动的优化尝试也计一次，防止无限空转。复测全部通过则提前结束；未通过且未到上限，使用本轮完整复测作为下一轮依据继续优化，不重复空跑同份内容的前测。达到上限仍未通过，明确显示“已达到最大迭代次数，仍有用例未通过”，不是优化成功。页面显示已执行次数 / 上限；运行中不可修改上限。停止、冲突和环境/评分异常同样终止循环。可由用户另行发起新任务。

## 8. 公共片段

### 查看、搜索与维护

- 入口在技能区域，与我的技能同级；没有模板中心占位入口。
- 所有租户共享同一个公共库，普通用户能看到、搜索、查看正文并使用；只有平台管理员能新增、编辑和删除。
- 字段为片段名称、用途说明、固定 Markdown 正文；本期不设版本、参数或双重分类。
- 搜索覆盖名称、用途和正文；有输入才显示框内右侧 × 图标，点击清空并保留焦点。图标与文字不重叠。
- 删除确认说明“不影响已插入的技能”；无结果显示空态。没有权限的用户看不到维护按钮，后端也必须拒绝写入。

### 编辑中插入

1. 我的技能 → 文件编辑 → SKILL.md → 快捷插入，弹框仅展示片段。
2. 搜索后左侧选择，右侧预览完整正文；插入到正文光标或替换选区。光标在 frontmatter 头部时改为追加正文末尾，避免破坏技能元信息。
3. 插入后成为普通 Markdown，可继续编辑；保存文件才落盘。搜索无结果清空旧选择，避免误插入。
4. 不写入片段 ID、引用语法或运行时链接，不创建更新追踪。片段库以后变化不影响已插入内容。

### 创建时参考

发送创建请求时冻结公共片段库参考清单，由模型按需求选择，再由服务端核验所选正文。全库作为参考不等于所有全文都塞进上下文：库较大时使用索引和按需读取。没有匹配、内容冲突或超出授权时跳过，并在生成说明中解释。无论如何，最终 SKILL.md 仅保留普通正文，不依赖片段服务运行。

## 9. 本期验收清单

1. 所有新入口均无模板、贡献、版本、管理角色或独立调试页面。
2. 创建模式从点击、空输入、填写、失焦直到发送始终高亮；取消和失败恢复规则正确；普通发送不会误创建。
3. 只填写描述即可发送；name 自动生成并校验，重名自动处理且不覆盖；只读无权限；创建成功刷新我的技能，失败无半成品。
4. 创建后可继续调整、直接调用、一次点击保存用例且防重复。
5. 手工、AI、会话保存、JSON 编辑均落到同一个 evals/evals.json；已发布保护不可绕过。
6. 运行全部严格串行并留在测评页；完整输出可查看；工具/子任务/文件证据不丢失。
7. 自动优化前测全量、各次改动落盘及全量复测；上限校验、提前通过、达到上限、取消和异常均能停止；左右输出可对比，无采用按钮，终态不掩盖未通过结果。
8. 普通用户片段只读，管理员可维护；插入后与库解耦，创建自动匹配不强制全插。
9. 原型只用于交互评审；真实模型、隔离环境、持久任务、权限与安全验收须在生产实现阶段补齐。


### 运行期间修改提示（2026-09-16 更新）

测评及自动优化使用启动时固定的 Skill、用例和输入资料副本。页面提示期间修改 Skill 不会影响执行。工作区编辑允许保存；优化回写遇到新编辑时不覆盖，继续在任务副本完成并保留候选与差异，报告不代表当前新编辑内容通过。普通内容修改不是停止条件；权限撤销、取消或运行异常仍按规则停止。
