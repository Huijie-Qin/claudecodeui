## 当前可用能力

- 页面 `/ai-usage`：AI 使用、各 Skill 调用统计、Hook 执行统计、记录性 Hook、Agent 模板使用五个并列页签；侧栏和平台管理面板均有入口。
- `tenant_users.role=tenant_admin` 仅允许查看所属租户的全员报表；普通用户只能查看本人。平台管理员保持既有 `is_system_admin` 权限。角色由平台管理员配置，不放开通用管理、工作区或聊天权限。
- AI 会话按租户、工作区、使用者、provider 和会话标识去重；时长按可信的每轮请求到最终响应累计，包含轮内工具耗时，不计轮间等待。10:00–10:02 加 10:30–10:33 为 **5 分钟**。
- 新增 DAU、近 30 日 MAU 卡片及逐日趋势，沿用同一闲时批次，不提供实时估计。
- Skill 共创统计首次成功发布数量、可核验归属到发布者的被调用次数；调用者身份单独保存，未归因调用不算给调用者或工作区所有者。
- Hook 按 Hook ID、后置行为 ID、记录类型、发布版本和来源分别统计，支持分页明细和明确配置的字段汇总。同名 Hook 不合并；记录条数不等于 Hook 执行次数。
- Agent 模板分别展示工作区模板应用记录，以及模板来源工作区中的实际用户会话，避免把应用次数当作会话次数。
- 刷新、筛选和分页只读取已发布统计投影，不扫描消息；日期默认不含当天。页面显示数据截至日期、上次完成时间、时区及覆盖不足提示。
- 各页签统一为统计表，支持分组、表头升降序和全量结果分页。页面固定查询租户全员，访问前检查租户报表权限；移除个人范围切换、模型提供方分组和指标上下界筛选。

## 刷新确认、逐 Skill 明细与 Hook 记录（9 月 12 日追加）

- “刷新结果”先弹出二次确认；取消不触发刷新，确认后重新查询已发布批次。此操作有数据库查询开销，但不扫描原始消息、不启动夜间任务、不提前产生当日数据。子表与分组结果也会随确认刷新。
- “AI 使用与共创”改名为“AI 使用”。新增“各 Skill 被调用明细”：Skill ID、名称、发布者、首次发布时间、所选期间的被调用次数、去重调用人数和最近调用时间。独立支持 Skill 名称搜索、排序和分页。
- Skill 列表保留截至结束日期的历史发布投影，范围外发布但范围内被调用的 Skill 不会丢失；已发布但零调用也展示。同名 Skill 按 ID 与发布者分别统计。只有可确认发布者的调用才纳入；未知发布时间显示 —，不推测。用户明细／分组中的发布数仍指所选日期期间的新增发布；顶部概览已改为累计口径，详见下节。
- “Hook 执行统计”与“记录性 Hook”独立：前者来自已有 `hook_executions`，夜间提取执行元数据，按 Hook／版本／触发事件统计次数、成功／失败、未结束和平均耗时，并可查看执行记录。平均值只包含已有有效耗时的结束记录；未结束不填 0。分组合计重新计算平均值，不平均各组平均值。
- 执行来源新增轻量变更标记及历史补扫，计算版本升级到 `hook_executions_v4`；下一次启用的夜间批次完成后才发布新增投影。执行结束或状态更正会在后续夜间修正历史，刷新页面本身不会更新状态。执行输入、脚本输出和日志不进入报表投影。
- “记录性 Hook”优先展示“具体业务记录 · 字段统计”，包括归档条数、质量评分、复核耗时、SQL 行数等已配置字段的求和／平均／极值和有效样本数。按 Hook、行为、版本、类型及单位隔离，支持字段键精确筛选、排序及分页。点击“记录明细”后，每个已开放字段单独成列，文本结果也可见，不再挤在一个通用 JSON 栏里。
- 新增 API：`skills`、`hook-field-statistics`、`hook-executions`、`hook-executions/:id/records`，均沿用实时权限校验和固定已发布批次。不在白天查询原始业务表。

## 记录性 Hook 数值字段四项统计（9 月 14 日调整）

- 报表中所有已开放的 `number` 字段均计算求和、平均值、最小值、最大值，不再按字段的 `aggregation` 预选一个结果。展示改为“统计方式”单选下拉框，默认求和，仅保留有效样本数和所选统计结果一列，不将四项并列。
- 按 Hook、按用户和记录明细弹窗使用同样的选择框；从字段统计打开明细时沿用已选方式，明细也可单独切换。名称／样本数排序不受切换影响；如正在按统计结果排序，则切换服务端排序字段并回到第一页，保留筛选条件，仍是全量排序。只切换展示不会查询原始记录或启动夜间重算。
- Hook 编辑器保留字段开放范围、名称、类型、单位，移除“统计方式”选择器。旧配置的 `sum/avg/min/max/none` 元数据兼容读取，但不再控制数值字段是否计算或展示哪一项；未开放字段不会因此进入报表。文本／布尔值只展示记录原值，不做数值计算。
- 只计有限数值，保留零、负数和小数；空值、数值字符串、布尔值及无效数值不计入有效样本。平均值由总和除以有效样本数计算，不平均每日平均值；不同 Hook、用户（按用户模式）、后置行为、记录类型、版本和单位继续隔离。
- 夜间定义升级为 `hook_numbers_v5`，沿用已有定义升级时的夜间重建流程；新批次保存 `hookNumericStatisticsVersion=1`，每日汇总覆盖全部已开放数值字段。未升级的旧批次或删除 revision 变化时，暂从已发布的脱敏字段记录计算四项，不读取原始消息／Hook 表。查询不触发重建，原始数据重建仍只在夜间窗口执行。
- 示例：用户 #139 的归档质量分（10 个样本）为总和 990、均值 99、最小 99、最大 99；归档条数为总和 50、均值 5、最小 5、最大 5。选择求和显示 990／50，选择平均值显示 99／5，两个字段都支持四种方式。

## 固定整体概览（9 月 14 日调整）

- 四张卡片移到页签和筛选区上方，所有页签共用。独立组件与独立 `GET /api/ai-usage/summary` 请求，不随日期、用户、工作区、名称、本人／全员切换、分组、指标条件、排序或分页重新加载或改变结果。
- 权限范围不是业务筛选：管理员固定查看当前租户全员概览；普通用户固定查看本人概览。换租户、身份／权限变化、发布批次变化或确认刷新时重新加载，失败不显示旧范围数据。
- 会话次数固定为数据截止日 D 往前 29 天至 D 的去重会话数；DAU 为 D 当天的去重交互用户；MAU 为 D−29 至 D 的去重交互用户。卡片直接展示固定起止日期，不随下方筛选结束日变化。
- “累计发布 Skill 数量”为当前已发布统计批次中，首次成功发布时间不晚于 D 的全部可核验 Skill，按 Skill ID 去重；重复发布不累加，同名不同 ID 分别计数。不要求落在近 30 天或明细日期内，不按工作区分摊；只存在调用归因、没有 confirmed 发布记录的 Skill 不算发布。既有删除遮蔽与权限隔离仍生效，不将其解释为实时市场在架数量。
- 新接口只接受批次和授权范围作为概览依据，主动忽略明细筛选参数。只查夜间发布的投影与滚动活跃集合，不扫描原始消息、发布或 Hook 业务表，不开启新夜间任务。下方趋势／明细／分组仍使用原有筛选口径；概览失败不会使明细一并失败。
- 模拟概览：会话 601、累计发布 30、DAU 4、MAU 41。下方默认期间内没有新增发布，所以用户明细的期间发布数仍可为 0；普通用户样本累计发布为 15。

## DAU／MAU 与交互分析（9 月 12 日新增）

- DAU：所选结束日期 D 内，有实际用户消息交互的去重用户数。不是登录人数，也不直接使用旧 admin 看板的 `session_index.updated_at` 判定活跃；跨日时长本身不会凭空增加次日活跃用户。
- MAU：D−29 至 D（含首尾）的实际交互用户去重数；不是自然月人数，也不是 30 天 DAU 之和。页面即使只查看一天或七天，MAU 仍回看完整 30 日。
- 下方趋势／原有查询接口中的两项指标遵守租户、本人／全员、用户、工作区和 provider 筛选。相同用户跨会话、工作区或 provider 的重复交互只计一人；本人范围只会得到 0／1。顶部四卡现为独立固定概览，不受这些业务筛选影响。
- 夜间重建交互日分区时，顺带生成 `daily_active_users`（用户、工作区、provider 的每日去重存在记录）；随后从这些小型投影分页生成 `active_users` 的每日滚动活跃集合。保留成员身份是为了筛选后仍能正确去重，不在白天读取原始消息计算 MAU。
- 某个历史日期变更时，标记该日及后续 29 日重算；尚未到可发布日期的标记留给后续夜间窗口。无新增交互时，窗口到期仍能正确归零。处理有独立检查点，暂停／失败保留旧发布批次，全部完成才切换。
- 计算版本已升级。旧批次未生成活跃集合时显示“—／等待夜间生成”，不伪装成 0；已生成但确实无活动时才显示 0。历史交互覆盖仍可能为 `partial`。

| 页签 | 支持的分组维度 | 分组后的指标 |
| --- | --- | --- |
| AI 使用 | 用户、工作区、自然日、自然周、自然月 | 会话次数、活跃时长、Skill 发布与被调用次数、区间去重活跃人数 |
| Hook 执行统计 | Hook、用户、工作区、自然日、自然周、自然月 | 执行次数、成功、失败、未结束次数、平均执行耗时 |
| 记录性 Hook | Hook、用户、工作区、自然日、自然周、自然月 | 业务记录数、记录用户数、涉及工作区数 |
| Agent 模板使用 | 模板、用户、工作区、自然日、自然周、自然月 | 应用次数、应用人数、实际活跃人数、会话次数、活跃时长 |

自然周从周一开始；月／周仅汇总所选日期范围内的数据，不自动扩展日期。分组按 ID 而不是名称，同名 Hook／模板不会合并。Skill 发布没有 provider 归属，按 provider 分组时列入未知／不适用组，不猜测模型来源。

日期、用户 ID、工作区 ID、名称，以及相关页签的 provider／Hook 来源／记录类型先筛选；指标上下界在聚合后应用。活跃时长筛选的页面单位为分钟，API 单位为毫秒。合计覆盖全部匹配分组，重新去重用户与会话，不受分页影响；不提供 DAU／MAU 的简单求和。分组指标条件只作用于分组表及其合计，顶部卡片使用独立固定概览口径。

排序与聚合均在服务器对已发布投影执行，排序后才分页（每页 20／50／100 条），不是只排序当前页。API 只接受代码内白名单维度、指标与排序字段，不开放任意 SQL、表达式或自定义公式。查询日期最多 366 天。滚动成员集合需要额外存储，互动分析仍有 SQL 聚合开销；生产启用前需测试容量与时延，不能称为零开销。

## 数据生成与性能策略

| 数据 | 白天留存的依据 | 夜间处理 |
| --- | --- | --- |
| AI 时长 | Claude SDK 记录请求开始、可信响应边界、会话归属及终态至 `ai_usage_turn_facts` | 已完成轮次按业务日期拆分；未完成/失败等只保存状态，不估算耗时 |
| 会话、Skill 调用 | 已有 provider 消息表；Claude 原始 JSONL 与 display-command 侧文件；本地 Skill 绑定历史；`ai_usage_skill_context` 的请求/工具/来源元数据 | 已知归属范围内增量读取，关联去重并排除内部来源，只重算受影响的请求/工具组 |
| DAU／MAU | 复用已有用户交互依据，无额外逐消息写入 | 每日存在投影 → 30 日滚动成员集合，历史补数修正受影响日期 |
| Skill 发布 | 发布链路保存操作结果与首次成功发布证据 | 仅统计 confirmed；不把绑定导入时间当首次发布 |
| Hook | 既有 `hook_data_records`，补齐行为/版本/来源 | 发布版本中的字段白名单投影；按类型和定义版本聚合 |
| Agent 模板 | 既有 `workspace_agent_template_snapshots` | 应用投影与实际会话关联 |

不用 MQ/Redis，不另开微服务。业务表触发器只在原事务内维护“变更来源 ID + generation”，不复制消息正文、不进行聚合。必要的请求边界和 Skill 发布留痕有少量写入开销，不能宣称零开销。

调度器只在窗口内启动 `worker_threads`；Worker 单独连接 SQLite，在后台解析文件与汇总。业务和统计仍共享 SQLite 的写锁，需要上线前测量锁等待、IO、数据库体积和窗口内处理能力。

增量及恢复机制：

- 首次历史索引按来源 ID 分页；后续消费变更标记。每页默认 200 个统计键，先按索引取下一页，再仅对该页候选去重，避免每页重排整个日分区。
- JSONL 持久化完整行字节偏移、文件身份和前缀指纹；尾部半行留到后续批次。文件遍历也保存游标及本批次已见文件，窗口结束后可继续。
- 新原始文件出现时撤销旧数据库副本；原始文件确认缺失后撤销该来源并回退到仍保留的数据库消息。遍历未完成不视为文件删除。
- 本地事实的旧、新业务日期都标记为待重算。当前结果先复制到暂存表，只重算受影响日期，其他日期保留复制的结果。
- 全局 Worker 租约、每租户批次租约及持久化游标防重复执行；摘要更新与源游标同事务，旧租约不能发布。
- 新批次完整后事务替换正式明细，并同时更新成功状态。失败、暂停不替换上一成功结果；源数据较晚发生变化时保留下一次处理标记。发布需复制全租户结果，不再声称只切指针的常数成本。
- Hook 原记录删除立即通过删除遮蔽表阻断旧明细。删除 revision 不匹配时字段汇总回退到剔除已删除记录的白名单投影，不读取原始聊天。

这是非实时滚动读取，不是所有外部文件在同一瞬间的全局快照。页面的“数据截至”表示业务日期范围，不代表该日所有外部历史都已完整到达。

## Skill 调用口径（9 月 12 日调整）

- 只纳入原生 `Skill` 工具调用，以及用户实际提交、且可验证对应真实 Skill 的 `/名称` 命令。不识别 Read/Bash 读文件，也不从普通文本提及中猜测使用。
- `/help` 等命令不能仅凭斜杠计为 Skill。验证依据为业务时点有效的 Skill 绑定，或同一请求下匹配的原生 Skill 工具/SDK Skill 展开记录；只有文本候选而无依据时不计。
- 同一请求、同一分支、同名 Skill 的斜杠与对应工具调用合并；不同 `toolUseId` 保留独立计数。调用次数表示调用发起，不等于执行成功次数。
- 排除 Hook、Agent Graph、Top Skill 来源，包括可信标记的内部后续工具。按来源排除，而非把同名 Skill 永久拉黑。Hook 子代理标记仅影响注入之后的对应分支，之前的用户调用保留。
- 白天的 `ai_usage_skill_context` 仅记录可信租户/用户/工作区、请求 UUID、工具 ID、Skill 名称、时间、来源和可确认的子代理 ID；不存提示词或参数，不逐 token 写入。MCP 恢复继承原请求，不另造一次斜杠使用。
- JSONL 保存请求上下文与文件字节断点；数据库回退保留安全请求边界，夜间关联工具；同时间戳按既有 provider 消息序号判断先后，不按 UUID 排序猜测。display-command 侧文件仅补原命令名，必须匹配真实消息时间，不使用文件修改时间。
- 夜间先按页保存变更会话的元数据引用，再按请求/独立工具组重算。页游标与临时引用同事务保存，单个请求组原子替换；不会把整个会话证据塞入任务进度 JSON。迟到工具会替换原斜杠事实，并重算旧、新日期；优先采用真实工具发起时间。
- 计算版本已升级，下一次启用的夜间任务会重新索引旧定义；暂停的旧定义批次重建未发布部分，保留上一份已发布看板。

覆盖仍为 `partial`：历史来源/原消息丢失、旧目录名与命令别名不一致，以及 SDK 合并输入后无法确定工具所属请求时，不声称可完整关联。未知来源的明确原生工具保留，但不伪造其请求归属。发布者归因仍沿用可核验绑定；跨用户导入且缺少发布者平台身份的调用仍未补齐，不算给调用者，也不宣称租户共创总数已全覆盖。

## 闲时配置

`.env.example` 已提供以下项目；默认关闭统计。确认运行环境、容量和业务策略后再配置实际部署环境并重启服务：

```dotenv
AI_USAGE_ENABLED=true
AI_USAGE_RUN_AT=02:00
AI_USAGE_WINDOW_END=06:00
AI_USAGE_TIMEZONE=Asia/Shanghai
AI_USAGE_MAX_CONCURRENCY=1
```

时间格式为 `HH:mm`，时区必须是有效 IANA 名称。当前 SQLite 实现只允许并发数 1；非法配置会记录错误并关闭调度，不默默改用另一时间。窗口结束暂停，保留检查点；服务启动在白天不会补跑，窗口内启动则尝试恢复。启动应用会按既有机制迁移新表；即使统计关闭，必要的业务事实留痕仍保留，`AI_USAGE_ENABLED` 控制的是夜间处理。

跨日示例：9 月 11 日 23:58 发起，9 月 12 日 00:03 完成。9 月 11 日分到 2 分钟、9 月 12 日分到 3 分钟。12 日凌晨任务发布前一天的 2 分钟；13 日凌晨发布后一天的 3 分钟。如果首次运行时终点尚未确认，不预估时长；终点之后补齐，会重算相关历史日期。查询两天合计仍为 5 分钟，不根据下一次提问补空闲时间。

多轮并发目前按独立轮次相加，不做区间并集；失败、取消、incomplete/unsupported 不贡献时长，pending 不用当前时间补终点。这些是首版保守处理，不表示已确定所有业务计入策略。切换业务时区或计算版本会在后续夜间重新索引，并在完成前保留旧批次及其时区。

## Hook 字段配置

### 按用户统计业务字段（9 月 14 日追加）

“记录性 Hook → 具体业务记录 · 字段统计”新增“字段统计分组：按 Hook／按用户”。按用户时增加用户名称与 ID 列，使用记录所属用户而非 Hook 配置者；同名用户按 ID 分开，仍保留 Hook、后置行为、类型、版本、字段与单位边界。空用户单独展示为未知。

`hook-field-statistics` 支持 `groupBy=hook|user`，按用户模式支持用户名称、用户 ID 和原有数值表头排序，全量排序后分页。直接复用夜间 `hook_daily` 中已有的用户粒度，不增加采集，也不扫描原始消息；平均值使用总和／有效样本数，不平均各日平均值。删除修正沿用安全记录投影回退。

用户分组行的“记录明细”携带 `recordUserId`，同时约束记录列表与字段汇总；`__unknown__` 仅匹配用户缺失的记录，不能退化为全员。租户与本人权限仍由报表 CTE 限制。下方已有的“分组分析 → 用户”保留，用于记录总数、记录用户数和涉及工作区数。

在 Hook 编辑器的 `write_record` 后置行为中，可为已配置的字段显式开启报表展示，并设置名称、类型、单位和统计方式。保存并发布新版本后生效；历史记录按其发布版本定义处理，不用当前草稿重解释历史。

- 每个行为最多 20 个字段，默认不选中。
- 仅支持已有平级标量字段：number/string/boolean，不允许任意 JSON 路径和原型键。
- 数值字段支持 sum/avg/min/max/none；字符串和布尔值只展示、不聚合。
- 缺值、类型不符不补零；汇总同时返回有效样本数。不同版本、单位或行为不混算；分页不改变全周期汇总。
- 历史 SQL 指标类型有固定数值适配；其他未配置类型显示字段不可用，不复制原始 `data_json` 或会话正文。

## API 与异步导出

`/api/ai-usage` 下提供 `capabilities`、`status`、`overview`、`trend`、`users`、`hooks`、`templates`、`analysis`，以及 Hook records/statistics、模板 applications/sessions 和 exports 子路由。`analysis` 接受 `dataset/groupBy/sortBy/sortDir/metric/minValue/maxValue/page/pageSize` 和既有范围条件，返回分页 `items`、匹配分组 `total` 及全量去重 `summary`；所有查询固定 `batchId`。导出字段／格式仍待确定，本轮未启用分组结果导出。

每次请求重新核验用户、租户和角色；报表批次必须属于当前租户。导出下载还检查任务所属用户、当前权限、批次及数据删除 revision。客户端切换租户/身份或收到 401/403 时清除旧结果及权限缓存。

导出持久队列、状态查询、租约、原子文件发布和安全下载基础设施已实现并测试。**字段、格式及保留期限尚未确定，生产路由未配置序列化器；创建导出返回 `exportNotConfigured`，UI 明确提示。** 不预先决定 CSV/Excel，也不采用同步全量导出。未来接入代码内审核的序列化器及队列执行入口；只基于固定已发布批次生成文件。

## Skill 发布者归属补充（2026-09-14）

用户统计中的发布数量与被调用次数均按发布者归属，调用者仅保留为调用人数等独立维度。比如 A 发布 Skill，B 调用 3 次：A 发布数量为 1、被调用次数为 3，B 不增加这两项贡献。会话与时长仍属于 B。日期范围内首次发布的 Skill 按 Skill ID 去重；此前发布的 Skill 在范围内被调用也计入，顶部累计发布卡片口径不变。

夜间归属除了可信历史绑定，还查询同租户、相同远端 Skill ID 的已确认发布记录，补齐其他用户导入后的发布者关联。仅有保存/导入记录、外部账号数字、同名 Skill、晚于调用时间的首次发布或互相冲突的发布者凭据均不用于猜测归属。

发布确认晚到、纠正或删除会把相关工作区的 Skill 元数据加入夜间修正队列，重算受影响历史日期；旧已发布快照不变。`skill_publishers_v6` 会在下一次闲时窗口升级历史归属，不在打开报表时扫消息。UI 使用简洁的“Skill 调用次数”，各 Skill 列表保留发布用户名，并明确该页用户筛选指发布者。
