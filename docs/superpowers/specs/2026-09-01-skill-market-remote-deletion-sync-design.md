# Skill 市场远端删除同步设计

日期：2026-09-01  
状态：已确认

## 背景

当前技能市场在远端列表未返回某个 Skill 时，会继续检查当前工作区的市场导入记录。如果对应本地 Skill 仍然存在、但远端详情已经不存在，服务会将它重新补入技能市场列表，并标记为“市场已下架”。因此技能市场并未严格反映远端目录。

产品要求将两个视图的数据边界彻底分开：技能市场与远端目录保持同步；“我的技能”与当前工作区本地文件保持同步。远端删除不应影响本地 Skill。

## 目标

1. 技能市场列表只展示远端仍然存在的 Skill。
2. 远端 Skill 被删除后，不再在技能市场中展示“市场已下架”占位项。
3. 保留工作区中的本地 Skill 目录、文件内容和市场导入元数据。
4. “我的技能”继续根据本地文件展示该 Skill，不受远端删除影响。
5. 保留现有分页、搜索和本地导入状态关联能力。

## 非目标

- 不在列表同步时删除或修改 `.claude/skills` 下的任何文件。
- 不因远端删除而清理 `market-imports.json` 中的绑定。
- 不改变用户主动“下架”自己发布的 Skill 时清理发布绑定的既有流程。
- 不改变“我的技能”的本地发现和展示规则。
- 不新增远端删除提示、恢复入口或后台定时同步任务。

## 方案比较

### 方案 A：服务端跳过远端已删除的本地导入摘要（采用）

继续使用远端技能列表作为市场主数据。对于因分页或搜索未出现在当前响应中的本地导入记录，仍查询远端详情：远端存在时可按原逻辑补全；远端不存在时直接跳过，不生成 `remoteDeleted` 市场摘要。

该方案使所有客户端获得一致的市场结果，同时不修改本地状态，改动范围最小。

### 方案 B：前端过滤 `remoteDeleted`

前端可以隐藏带有 `remoteDeleted` 的市场卡片，但服务端仍返回与远端不一致的数据，其他调用方仍会看到占位项。不采用。

### 方案 C：发现远端删除后清理本地市场绑定

这会改变本地 Skill 的来源和发布状态，使“我的技能”受到远端目录变化影响，违反两个视图互相独立的要求。不采用。

## 服务端数据流

`listSkillMarket` 继续先请求远端分页列表，并为远端返回项关联当前工作区的本地导入状态。

随后处理“本地有导入记录、但当前远端分页未返回”的记录：

1. 如果本地 Skill 文件已经不存在，跳过该记录。
2. 使用绑定中的远端 ID（兼容 `id`、`skillId` 和名称）查询远端详情。
3. 如果远端详情仍存在，按现有搜索条件补入结果，以保持分页场景下的导入状态可见性。
4. 如果远端详情不存在，跳过该记录，不生成市场摘要。
5. 整个列表过程只读本地导入元数据和文件状态，不写入任何本地数据。

因此，技能市场最终只包含远端仍存在的 Skill；本地 Skill 和绑定仍可供“我的技能”及本地文件操作使用。

## 前端行为

- 市场列表刷新后，远端已删除的 Skill 卡片消失。
- 不再通过市场列表展示“市场已下架”状态。
- “我的技能”仍展示对应本地 Skill，用户可以继续查看和编辑本地文件。
- 本次改动不删除现有详情接口对过期请求的防御性处理；它只负责处理已经发出的旧请求，不再用于构造市场列表。

## 错误处理

- 远端市场请求整体失败时，沿用现有错误反馈，不把失败误判为远端删除。
- 只有远端详情查询明确得到“未找到”时才跳过对应市场项。
- 本地文件或导入元数据不会因远端查询失败、未找到或列表刷新而发生变化。

## 测试策略

服务测试覆盖：

1. 远端列表缺失、远端详情也不存在、本地 Skill 仍存在时，市场结果不包含该 Skill。
2. 上述情况下本地 Skill 文件仍存在，市场导入元数据保持不变。
3. 远端 Skill 只是未出现在当前分页、但详情仍存在时，仍按现有规则补入，避免分页回归。
4. 搜索条件不匹配时不补入远端存在的本地导入 Skill。
5. 现有市场服务测试、类型检查和相关前端测试继续通过。

## 验收标准

- 远端删除一个 Skill 后，刷新技能市场，该 Skill 不再显示。
- 技能市场中不再为该 Skill 显示“市场已下架”占位项。
- “我的技能”仍显示对应本地 Skill。
- `.claude/skills` 下的目录和文件内容不变。
- `market-imports.json` 不因列表同步而被修改。
- 远端仍存在但不在当前分页中的导入 Skill 不被错误移除。
