# Skill 页签点击刷新设计

日期：2026-09-01  
状态：已确认

## 背景

技能工作台包含“技能市场”和“我的技能”两个页签。当前页签切换只更新视图状态，不会主动重新加载目标列表。已发布的本地 Skill 被移除后，“我的技能”会刷新，但技能市场可能仍保留移除前的导入或发布状态，用户必须点击独立刷新按钮或刷新整个页面才能看到最新结果。

## 目标

1. 每次点击“技能市场”时刷新技能市场列表。
2. 每次点击“我的技能”时刷新工作区技能列表及其市场状态。
3. 重复点击当前已经选中的页签也执行刷新。
4. 刷新列表时不丢失当前页签中已经打开的详情或未保存编辑内容。
5. 切换到另一个页签时继续使用现有的未保存内容确认和详情清理逻辑。
6. 避免同一页签在已有刷新进行中时重复发起相同请求。

## 方案比较

### 方案 A：按点击的目标页签刷新（采用）

点击市场只刷新市场数据，点击“我的技能”只刷新本地清单及市场状态补充信息。请求范围与用户当前意图一致，状态能够立即更新，也不会无条件请求两个数据源。

### 方案 B：每次点击同时刷新两个页签

可以同步全部缓存，但每次操作都会产生额外的工作区和远端市场请求，响应更慢，不采用。

### 方案 C：使用缓存过期时间自动刷新

能够降低请求频率，但移除后仍可能在缓存到期前显示旧状态，不能保证点击后立即同步，不采用。

## 交互与数据流

页签点击统一进入现有 `changeView` 流程：

1. 判断目标页签对应的数据是否正在加载；如果正在加载，不重复发起请求。
2. 如果点击当前页签：
   - 保留当前详情、选中文件、编辑状态和提示；
   - 只刷新当前页签的列表数据。
3. 如果切换到另一个页签：
   - 先执行现有未保存内容确认；用户取消时既不切换也不刷新目标页签；
   - 用户确认后切换页签并清理旧详情；
   - 刷新目标页签列表。
4. “技能市场”调用现有 `loadMarket(1, true)`，从第一页重新加载并替换旧列表。
5. “我的技能”调用现有 `mine.reload()`，重新加载工作区清单，并继续执行已有的市场状态补充流程。

## 错误与并发

- 市场刷新失败继续写入现有 `marketError`，工作区刷新失败继续由 `useWorkspaceSkills` 保存错误状态。
- 一个页签刷新失败不清空另一个页签的数据。
- 加载期间重复点击同一页签不产生第二个相同请求。
- 页签刷新不调用远端写接口，不改变 Skill 文件、绑定或发布状态。

## 测试策略

- 将页签点击后的刷新决策提取为纯函数或等价的可测试单元。
- 验证点击市场返回市场刷新动作，点击“我的技能”返回工作区刷新动作。
- 验证点击当前页签仍需要刷新。
- 验证对应页签已经加载时不重复刷新。
- 验证不同页签切换仍经过未保存内容保护。
- 运行相关单元测试、TypeScript 类型检查、ESLint 和客户端构建。

## 验收标准

- 移除已发布或已导入 Skill 后，点击“技能市场”立即显示最新状态，无需手动刷新页面。
- 点击“我的技能”立即重新加载当前工作区清单。
- 再次点击当前选中页签同样刷新。
- 刷新当前页签不会关闭详情或丢失未保存内容。
- 快速重复点击不会创建同一页签的并发重复请求。
