# Skill 文件树编辑与拖拽移动修复设计

日期：2026-09-01

## 背景

“我的技能”详情页使用 `SkillFileTree` 管理本地 Skill 的文件和文件夹。当前行内操作存在三类问题：新建文件或文件夹后按 Enter 没有可见响应，输入框会停留在原处；重命名只有按 Enter 才提交，点击空白区域会直接取消；文件和文件夹不能通过拖拽改变所在目录。

后端现有 `renameEntry(path, nextPath)` 已允许改变完整相对路径，因此重命名和移动可以共用现有接口，无需扩展 API。

## 目标

- 新建文件和文件夹时，按 Enter 稳定提交并立即显示提交状态。
- 重命名时，按 Enter 或点击输入框外部均提交；Esc 取消。
- 文件和文件夹可以拖入目录，或拖到文件树根部空白区域移回根目录。
- 操作失败时保留足够的上下文，让用户可以修正后重试。
- 保持现有权限、路径安全校验和未保存内容保护。

## 非目标

- 不支持批量拖拽或多选移动。
- 不支持跨 Skill 移动。
- 不新增后端移动接口。
- 不改变 `SKILL.md` 的不可重命名、不可移动、不可删除约束。
- 不引入新的拖拽依赖。

## 方案选择

采用原生 HTML5 拖拽，并复用现有 `renameEntry(path, nextPath)` 完成移动。

与引入拖拽库相比，该方案不增加依赖，改动集中在现有文件树组件；与新增移动弹窗相比，它直接满足拖拽需求。项目通用文件树已经使用相同的原生拖拽模型，可复用其数据类型标识、合法目标高亮和 `dropEffect` 处理方式。

## 行内创建与重命名

### 统一提交入口

行内输入使用表单提交语义。Enter 触发表单提交，创建和重命名共用同一个经过防重复保护的异步提交函数。提交开始时立即锁定输入并显示加载图标；成功后关闭草稿，失败后保留输入内容、显示错误并恢复焦点。

名称校验继续在请求前执行：名称不能为空，不能是 `.` 或 `..`，不能包含路径分隔符、空字符或控制字符。

### 新建行为

- Enter 提交。
- Esc 取消。
- 点击输入框外部取消，避免仅仅切换选择时意外创建文件。
- 创建成功后刷新详情、展开父目录并选中新节点；新文件同时显示在右侧编辑区。
- 请求失败后保留草稿，供用户修正或重试。

### 重命名行为

- Enter 提交。
- 点击输入框外部提交。
- Esc 取消，并阻止随后发生的失焦再次提交。
- 名称去除首尾空白后与原名称相同时，不发送请求，直接结束编辑。
- 请求失败后保留草稿和焦点。

失焦提交使用最新草稿值，并与 Enter 共用防重复标记，避免 Enter 导致失焦时重复发送请求。

## 拖拽移动

### 拖动源

- 除根 `SKILL.md` 外，文件和文件夹行均可拖动。
- `dragstart` 写入 Skill 文件树专用的数据类型和源路径，并将 `effectAllowed` 设为 `move`。
- 开始拖动时记录源节点；拖动结束时清理拖动状态和目标高亮。

### 放置目标

- 拖到文件夹行：目标父路径为该文件夹路径。
- 拖到文件树根部空白区域：目标父路径为空字符串，即 Skill 根目录。
- 合法目标在 `dragover` 时高亮，并将 `dropEffect` 设为 `move`。
- 文件行不是放置目标。

### 路径与合法性

新路径由目标父路径和源节点 basename 组成。以下情况不发送请求：

- 源节点是 `SKILL.md`。
- 新路径与旧路径相同。
- 文件夹试图移动到自身或自身后代。

目标位置已有同名节点时，沿用后端 `409` 冲突响应，并在页面消息区域显示错误。其他非法路径、权限或文件系统错误也沿用现有错误处理。

### 移动后的状态

- 移动成功后刷新 Skill 详情。
- 新父目录自动展开。
- 选中路径更新为移动后的路径。
- 如果当前右侧文件本身或其祖先目录被移动，右侧文件路径同步映射到新路径并继续显示。
- 移动前继续执行现有未保存内容保护；用户拒绝时不发送移动请求。

## 组件与数据流

`SkillFileTree` 新增拖动源、当前放置目标和根部放置状态，并负责计算目标路径和前端合法性。它通过新增的移动回调把源路径和目标路径交给详情页。

`SkillsWorkspacePanel` 继续负责权限、未保存内容保护、API 调用、刷新详情、选中路径映射和页面消息。移动回调复用 `renameEntry` 的请求路径，但使用独立的成功文案，以便用户区分重命名与移动。

路径计算和移动合法性放入 `utils/skillFileTree.ts` 的纯函数中，避免拖拽事件处理器同时承担路径规则与 UI 状态管理。

## 可访问性与视觉反馈

- 可拖动行设置 `draggable`，拖动时保持明确的移动光标。
- 合法目录目标和根部目标使用统一高亮样式。
- 非法目标不阻止默认放置，也不显示可移动反馈。
- 所有创建、重命名和移动操作仍可通过现有按钮与键盘完成；拖拽不是唯一操作路径。

## 测试方案

### 纯函数测试

- 根目录与嵌套目录下的移动目标路径计算。
- 同目录放置判定为无操作。
- 文件夹移动到自身或后代时判定为非法。
- 文件和文件夹移动到合法目录时生成正确的新路径。

### 组件交互测试

- 新建文件和文件夹按 Enter 只提交一次，并进入加载态。
- 创建失败保留草稿，成功关闭草稿。
- 重命名按 Enter 和失焦均提交一次。
- Esc 取消重命名且不会因失焦补发请求。
- 合法目录与根部空白区域在拖拽时高亮并触发移动。
- `SKILL.md` 不可拖动，非法后代目标不触发移动。

### 回归验证

- 运行相关单元测试、TypeScript 类型检查和客户端构建。
- 在“我的技能”详情页手工验证根目录与嵌套目录的新建、重命名及双向拖拽移动。
- 验证移动当前打开文件及其父目录后，右侧内容与选择状态保持一致。

## 验收标准

- 新建文件或文件夹输入合法名称后，按 Enter 会立即进入提交态，并在成功后出现新节点。
- 重命名输入合法名称后，按 Enter 或点击空白处都能完成重命名；Esc 取消。
- 文件或文件夹拖到目录行会移入目录，拖到根部空白区域会移回根目录。
- `SKILL.md`、自身/后代目标和同目录无效移动不会发送请求。
- 失败操作不会造成界面永久卡住，也不会丢失用户可修正的输入。
