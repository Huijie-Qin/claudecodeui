# 技能全量搜索设计

## 背景

技能工作台包含“技能市场”和“我的技能”两个独立视图。当前技能市场把搜索词直接传给远端分页接口，搜索范围受远端搜索行为和分页结果限制，导致尚未导入当前工作区的市场技能可能无法被找到。“我的技能”已经读取当前工作区的技能清单，但需要明确保证搜索始终在该完整清单上执行。

本次改动让两个视图分别在自己的权威数据源内进行全量搜索，同时保持二者的数据边界不变：技能市场搜索全部已发布市场技能，“我的技能”搜索当前工作区中的全部本地技能。

## 目标

1. 技能市场中的任意已发布技能，无论是否已导入、位于远端第几页，都可以被搜索到。
2. “我的技能”中的任意本地技能，无论来源是市场导入还是本地创建，都可以被搜索到。
3. 两个视图都只匹配技能名称、描述和创建者。
4. 匹配忽略大小写并支持子串。
5. 技能市场搜索结果继续支持正确分页和“加载更多”。

## 非目标

- 不搜索 `SKILL.md` 或其他技能文件的正文。
- 不引入全文搜索引擎或新的远端搜索服务。
- 不合并技能市场与“我的技能”的数据源。
- 不改变技能导入、更新、发布、下架或本地文件管理流程。
- 不改变无搜索词时技能市场现有的远端分页加载方式。

## 方案比较

### 方案一：服务端读取完整市场目录后过滤并分页

有搜索词时，CCUI 服务端不依赖远端接口的关键词过滤结果，而是分页读取全部已发布市场技能，在本地按约定字段过滤，再对过滤结果分页并补充当前工作区导入状态。

优点是前端接口保持不变，未导入技能和后续远端分页中的技能都能稳定命中，且分页语义由 CCUI 控制。代价是搜索请求需要读取完整市场目录。

### 方案二：前端加载全部市场技能后过滤

前端先加载市场全部分页，再在浏览器中搜索。

实现路径直观，但会把全量数据和工作区导入状态补充开销放到浏览器，首次搜索等待时间更长，也会让列表状态和分页管理更复杂。

### 方案三：改造远端技能市场搜索接口

由远端服务保证全量字段匹配和分页。

长期扩展性较好，但依赖当前仓库之外的服务改造，无法在 CCUI 内独立保证搜索结果，因此本次不采用。

## 选定设计

采用方案一。

### 技能市场数据流

无搜索词时保留现有流程：前端请求指定页，CCUI 服务端向远端技能市场请求同一页，并返回该页及分页信息。

有搜索词时改为：

1. CCUI 服务端分页读取远端技能市场的全部已发布技能，请求远端时不携带搜索词。
2. 对完整远端清单进行去重，防止远端分页数据重复造成重复卡片。
3. 使用统一匹配规则过滤技能名称、展示名称、描述和创建者。
4. 对过滤后的完整结果按前端请求的 `page` 和 `pageSize` 分页。
5. 只对当前结果页补充工作区导入状态、版本状态和本地目录名称，避免对全部匹配项执行不必要的文件系统检查。
6. 返回基于过滤结果计算的 `total`、`totalPages` 和 `hasNextPage`。

技能市场搜索的权威集合是远端全部已发布技能。工作区导入记录只负责补充状态，不能限制候选集合；因此尚未导入的技能与已导入技能具有相同的搜索资格。

远端完整目录使用有上限的分页循环，沿用现有市场目录读取策略：单页读取较大的固定数量，在远端报告无下一页或返回空页时结束。若远端请求失败，沿用现有错误响应，不返回不完整搜索结果冒充成功。

### “我的技能”数据流

“我的技能”继续以工作区技能列表接口返回的 `.claude/skills` 完整清单为权威数据源。来源筛选和关键词匹配都在完整清单上执行，不调用技能市场搜索，也不要求技能具有市场导入记录。

关键词匹配发生在来源筛选之后或之前都不改变交集结果；实现保持当前清晰的数据处理顺序，并通过单元测试锁定所有本地技能均可参与匹配。

### 匹配规则

搜索词和候选字段均转为小写后执行子串匹配，搜索词首尾空白被忽略。空搜索词匹配全部技能。

参与匹配的字段为：

- `name`：技能名称或本地目录名称。
- `displayName`：存在时作为技能展示名称参与匹配。
- `description`：技能描述。
- `createUserId`：创建者。

空字段被忽略。技能文件路径和文件内容不参与匹配。

## 组件边界

- `server/services/skill-market.js`：负责读取完整远端目录、市场搜索过滤、结果分页和工作区状态补充。
- `server/routes/skill-market.js`：继续透传搜索词与分页参数，不改变 HTTP 接口。
- `src/components/skills-market/SkillsWorkspacePanel.tsx`：继续发送市场搜索请求；“我的技能”继续对工作区完整清单做本地过滤。
- 搜索匹配逻辑应保持为可单独测试的小函数，市场与“我的技能”遵循相同字段和大小写规则。

## 错误与边界处理

- 远端返回空目录时，搜索结果为空且分页结束。
- 远端缺少总数时，依据每页数量和空页终止完整目录读取。
- 重复远端记录按稳定技能标识去重，优先使用 `id`、`skillId`，最后使用名称。
- 单个技能缺少描述或创建者时，仍可通过名称搜索。
- 搜索结果页超出范围时返回空列表，并返回真实的过滤结果总数与页数。
- 远端目录加载失败时返回现有错误，不使用部分数据生成误导性结果。

## 测试计划

服务端测试覆盖：

1. 目标技能位于远端第二页或更后页时仍能被第一页搜索结果命中。
2. 尚未导入当前工作区的市场技能能够被搜索到。
3. 名称、展示名称、描述和创建者分别可以命中，且匹配忽略大小写。
4. 搜索结果先过滤后分页，`total`、`totalPages` 和 `hasNextPage` 正确。
5. 空搜索词继续走现有单页远端请求，不产生全量读取回退。
6. 远端分页重复记录不会在搜索结果中重复出现。

前端或搜索工具测试覆盖：

1. “我的技能”的市场导入技能和本地创建技能都参与搜索。
2. 名称、展示名称、描述和创建者分别可以命中。
3. 技能文件内容不会造成命中。
4. 来源筛选与关键词搜索正确取交集。

## 验收标准

- 在技能市场搜索一个未导入、位于远端后续分页的技能名称时，该技能出现在结果中。
- 在技能市场按描述或创建者搜索时，所有符合条件的已发布市场技能均可通过分页查看。
- 在“我的技能”按名称、描述或创建者搜索时，当前工作区内所有符合条件的本地技能均可显示。
- 两个视图均不因技能文件正文包含关键词而命中。
- 清空搜索词后，技能市场恢复现有普通分页列表，“我的技能”恢复完整本地列表。
