# Skill 公共片段详细设计

日期：2026-09-08；2026-09-10 更新片段分类与模板使用边界

状态：核心产品规则已确认；以下交互和技术细节为建议方案，待评审。本次仅设计，不实施业务代码。

## 1. 结论与已确认规则

片段是由系统管理员维护、整个平台所有租户共享的 Markdown 文本库。用户在编辑 Skill 时选取片段，将正文复制到编辑器；复制完成后，它就是 Skill 自己的普通文本，不再与片段库保持关联。

| 事项 | 已确认规则 |
| --- | --- |
| 共享范围 | 整个平台所有租户、所有工作区共用一份片段库，不按租户隔离 |
| 管理权限 | 仅管理员创建和维护；本方案映射到现有系统管理员角色 |
| 普通用户入口 | 只在 Skill 编辑过程中看到片段选择入口；管理员另有维护入口 |
| 插入方式 | 复制正文，不建立引用，不生成只读胶囊 |
| 首期内容形式 | 仅固定 Markdown 正文，不提供插入时参数填写或变量替换 |
| 插入后的内容 | 可自由编辑、删除、撤销，与手工输入的 Markdown 相同 |
| 发布结果 | 正常 Markdown，不展示片段标识，不要求运行环境连接片段库 |
| 片段版本 | 没有版本、版本历史、版本选择、升级或回滚功能 |
| 片段后续变更 | 修改、删除片段均不改变已经插入过的 Skill，包括尚未发布的内容 |
| 使用追踪 | 不维护 Skill 与片段的关联，不统计 `usedBy`，不反向查找引用方 |
| SQL Check 联动 | 不因插入片段自动开启或触发校验，不改变现有 SQL Check 配置及启用状态 |

“无法跟踪”准确地说是：不保留来源关系后，无法可靠判断某段 Skill 正文是否来自某个片段、是否被修改，以及是否仍在使用。文本搜索或相似度只能猜测，不能作为引用追踪。本方案也不额外记录插入事件。

片段规则不取消文件冲突保护。后续已确认 Skill 本身也不区分版本、不提供历史版本查看；完整功能边界以最新技能市场主方案为准。

## 2. 范围与建议默认值

首期包含：公共片段查询、系统管理员增删改、编辑器选择与插入、权限控制及回归验证。

以下是技术设计建议，不视为用户已经确认的额外需求：

1. 数据保存在当前平台后端的公共数据库中，不改远端 Skill 市场服务。
2. 在已确认的固定正文范围内，首期也不增加嵌套片段或附件打包。
3. 首期入口仅用于 Skill 根目录 `SKILL.md` 的正文；其他 Markdown 文件暂不提供入口。
4. 不单设片段分类或类型，只提供标题/说明搜索，不做标签、收藏和推荐。
5. 管理员保存即对后续查询生效，不增加草稿、发布审核、启停状态或回收站。

2026-09-10 修订：移除原先建议的片段类型/分类，保留 Skill 分类即可。管理员可在模板编辑中选取片段并保存为固定正文；模板自定义字段属于生成输入，不为片段增加参数或引用。详见[模板与独立生成方案](2026-09-10-skill-template-generation-design.md)。

不包含：片段依赖解析、源文件/产物分离、发布时展开、引用快照、更新提示、批量同步、独立测评、使用排名，以及向已有 Skill 注入片段。

部署前提：这里的“平台”共享同一逻辑后端数据库。若实际要求多套独立部署、独立数据库也共用一个片段库，需要改为统一片段服务；不能靠每个实例建一张表实现跨部署共享。

## 3. 用户流程与内容生命周期

### 3.1 普通用户

1. 打开“我的技能”，进入有编辑权限的 Skill，选择根目录 `SKILL.md` 并进入编辑。
2. 将光标放在正文位置，或选中需要替换的正文，点击“插入片段”。
3. 在弹窗中按名称/说明搜索，查看 Markdown 源文及预览。
4. 无选区时点击“插入到光标处”；有选区时明确显示“替换选中文本”。
5. 内容通过一次编辑事务进入编辑器，弹窗关闭，光标位于插入内容末尾。
6. 用户继续编辑，沿用当前 Skill 的保存、预览和发布流程。

插入只改变编辑器缓冲区，不自动保存、不自动发布，也不向服务端提交 Skill 与片段的关系。取消弹窗不改变正文；插入后撤销一次即可恢复原文本及选区。

### 3.2 生命周期约定

| 时点 | 保留的内容与行为 |
| --- | --- |
| 公共库中 | 片段当前标题、说明和正文 |
| 选择弹窗中 | 临时持有所选片段及本次加载的正文，用于预览与插入 |
| 插入后、保存前 | 编辑器仅新增普通文本；后续管理员修改不改变缓冲区 |
| Skill 保存后 | 原文件直接保存完整正文；没有片段 ID、来源注释或附加元数据 |
| 发布、下载、安装、运行 | 使用正常 Skill 文件，不查询片段库 |
| 再次进入编辑 | 不识别历史片段、不恢复胶囊、不展示“来源于片段” |

示例：管理员片段“查询结果约束”的正文为：

```markdown
## 查询结果要求
- 默认最多返回 100 条记录。
- 说明筛选条件和排序方式。
```

插入后，`SKILL.md` 中就是上面的原文；片段标题不会被系统额外写入。管理员以后将片段改成“最多返回 50 条”，已经插入的 Skill 仍保留 100 条，除非 Skill 编辑者自行修改。

文本中的约束只是 Skill 指令，不等于数据库权限、执行沙箱或强制安全控制。片段中的相对路径也不会自动携带脚本和附件；这项设计消除了对片段库的依赖，但不承诺整个 Skill 无其他外部依赖。

正文中如出现 `{{项目名}}` 等字符，只作为普通文本复制；系统不识别为变量、不弹出填写表单，用户可在插入后自行编辑。

### 3.3 SQL Check 的边界

已确认不做“插入片段后自动开启实际校验”的联动。SQL 编写规范可以由管理员整理成普通固定正文，例如列出查询字段、限制结果数量、更新和删除时要求筛选条件；它与其他片段使用完全相同的插入流程，不是特殊可执行片段。

- 插入操作不启用 Hook、不调用检查工具、不安装 MCP，也不修改租户、工作区或用户的 SQL Check 规则配置。
- 是否开启检查继续由现有 SQL Check 功能管理；已经开启的检查照常工作，插入片段不会将其关闭或增加一条重复检查链路。
- 规则正文是提供给模型的指令，不承诺强制执行或保证 SQL 安全。
- 不自动导入、同步 SQL Check 规则，不将租户专属规则或配置自动提升为全平台公共内容。
- 不提供特殊的 SQL Check 执行型片段，也不因这类正文增加变量、依赖关系或发布处理。

## 4. 权限与全平台共享

| 操作 | 未登录用户 | 普通登录用户 | 租户管理员 | 系统管理员 |
| --- | --- | --- | --- | --- |
| 查询公共片段 | 不允许 | 允许 | 允许 | 允许 |
| 创建、修改、删除片段 | 不允许 | 不允许 | 不允许 | 允许 |
| 插入后保存 Skill | 不允许 | 按原工作区编辑权限 | 按原工作区编辑权限 | 按原工作区编辑权限 |

- “公共”表示平台内登录用户共享，不表示匿名互联网访问。
- 复用现有 `is_system_admin` 与后台 `requireSystemAdmin`，不新增租户级片段管理角色。
- 片段查询不依赖当前租户，不带 `tenantId` 或 `workspaceId`；切换租户不会切换片段库。
- 编辑和保存 Skill 仍沿用原工作区鉴权。能查询公共片段不代表能修改任意 Skill。
- 普通用户不增加独立“片段市场”页；市场详情、只读预览、发布详情均不增加片段展示。
- 管理员页面固定提示“全平台共享，请勿填写任何租户专属信息、密钥或私人数据”。

全平台共享仅涉及管理员编写的片段，绝不共享任何租户的 Skill 正文或插入情况。

## 5. 交互细节

### 5.1 片段选择弹窗

- 左侧列表显示标题和简短说明；右侧显示选中片段的源文/预览。
- 列表支持关键词搜索和分页；初始按标题、ID 稳定排序。
- 列表不加载全部正文，选中后再请求详情；快速切换选择时丢弃过期响应。
- 普通用户界面不显示创建、修改、删除按钮，也不显示版本、使用数量或引用方。
- 底部说明：“插入后成为普通文本，片段后续修改不会同步到当前 Skill。”
- 初次加载、空库、无搜索结果、加载失败分别显示；失败时可重试或关闭，不影响编辑中的内容。
- 插入按钮在正文加载完成且目标有效时才启用；提交期间防止双击重复插入。

### 5.2 插入与编辑器保护

1. 打开弹窗前保存编辑器实例、当前工作区/Skill/文件标识、文档状态和主选区，避免弹窗夺取焦点后丢失位置。
2. 首期只处理单选区；多选区时提示用户改为单一光标或选区，不自动批量插入。
3. 仅允许在 frontmatter 结束分隔行之后插入。选区覆盖 frontmatter 时禁止替换；若无法识别完整 frontmatter，提示先修复，不自动移动光标或改写元信息。
4. 原样插入正文，不自动补标题、缩进、空行或执行变量替换；换行符按当前编辑器文档约定处理。是否另起段落由用户控制，预览只是片段本身的预览。
5. 通过 CodeMirror 的一次 `dispatch` 事务替换选区；事务与前后输入分隔为独立撤销步骤，沿用现有 `onChange` 更新受控状态。
6. 不重建编辑器，不用整篇字符串替换绕过其撤销历史。插入后的 dirty 状态仍按现有文件内容比较计算。
7. 弹窗打开期间编辑区域不可编辑。若工作区、Skill、文件、编辑模式或文档发生变化，关闭弹窗或阻止提交，要求重新选择插入位置。
8. 不根据片段 ID 去重。同一个片段允许插入多次，重复操作由用户自行判断和撤销。

### 5.3 片段在弹窗打开期间发生变更

采用“插入本次已经预览的正文”规则：

- 详情尚未加载时被删除：详情请求返回不存在，禁用插入并刷新列表。
- 详情已经加载后被修改或删除：本次仍可插入已经获取的正文；它等价于用户已经复制到手中的文本。
- 点击插入时不重新拉取并暗中替换正文，不用管理员的新内容替代用户刚看到的内容。
- 用户主动刷新或重新打开弹窗时重新查询，看到当前库内容；不承诺实时推送。

这不是历史版本功能：弹窗只临时保存一次读取结果，关闭即释放，不提供旧正文检索。

### 5.4 管理员维护

管理后台新增“公共片段”入口，不显示租户选择器。若后台保留全局租户切换控件，页面明确说明“此设置对全平台生效，不受所选租户影响”。

- 列表：标题、说明、最近修改时间、编辑和删除操作。
- 新建/编辑：标题、说明、Markdown 正文，提供源文和安全预览。
- 保存：校验通过后直接替换当前记录；无版本号、发布按钮或历史面板。
- 删除：二次确认，文案为“删除后无法从片段库继续选择，已插入的 Skill 不受影响。此操作不提供撤销。”
- 删除不检查引用方，也不显示“影响了多少 Skill”；删除已打开的正文不能撤回。
- 表单切换、关闭时，对未保存修改进行确认；保存失败保留当前表单。
- 创建者记录仅供后台识别维护人员，不赋予个人所有权；任意系统管理员都可维护。

Markdown 按不可信内容处理：预览不得执行 HTML/脚本，链接使用安全协议白名单；不加载片段相对路径为工作区文件。仅复用符合这些要求的现有渲染配置。日志不输出正文和用户凭据。

## 6. 数据设计

在现有公共数据库中新建 `skill_snippets` 表。虽随现有多租户数据库初始化流程建表，但它本身是全平台表。

| 字段 | 类型/规则 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 片段库内部定位 ID，不写入 Skill |
| `title` | TEXT NOT NULL | 去除首尾空白，1～80 个 Unicode 码点 |
| `description` | TEXT NOT NULL DEFAULT '' | 去除首尾空白，最多 300 个 Unicode 码点 |
| `content` | TEXT NOT NULL | Markdown 正文；不允许全空白，最大 32 KiB UTF-8，保留有效正文空白 |
| `created_by_user_id` | INTEGER，可空 | 关联用户，删除用户时 SET NULL |
| `updated_by_user_id` | INTEGER，可空 | 关联用户，删除用户时 SET NULL |
| `created_at` | TEXT NOT NULL | 服务端生成 UTC 时间 |
| `updated_at` | TEXT NOT NULL | 服务端维护 UTC 时间 |

字段长度是首期建议值；前后端必须一致，正文大小以 UTF-8 字节数为准。数据库 CHECK 约束类型及基础有效性，服务层执行完整校验。

- 不设 `tenant_id`、`workspace_id`、`visibility`、`version`、`status`、`variables` 或 `used_by`。
- 不建片段历史表、Skill-片段关系表、引用快照表；不修改现有 Skill 市场绑定数据。
- 标题允许重复，由说明和 ID 区分；删除后新建即为新记录。
- 首期直接删除记录，不保留可检索的历史正文；不影响平台正常数据库备份机制。
- 初始化创建空库，不自动从任意租户的 Skill 提取或复制内容到公共库。
- 建立标题查询需要的普通索引；首期不引入全文检索服务。

普通用户响应不返回维护人员账号信息，后台详情可返回维护者 ID 和时间。

## 7. 接口设计

### 7.1 路由

| 方法 | 路径 | 权限/用途 |
| --- | --- | --- |
| GET | `/api/skill-snippets` | 登录用户查询公共库 |
| GET | `/api/skill-snippets/:id` | 登录用户获取当前正文 |
| GET | `/api/admin/skill-snippets` | 系统管理员列表 |
| GET | `/api/admin/skill-snippets/:id` | 系统管理员详情及并发校验信息 |
| POST | `/api/admin/skill-snippets` | 系统管理员创建 |
| PUT | `/api/admin/skill-snippets/:id` | 系统管理员整体修改当前记录 |
| DELETE | `/api/admin/skill-snippets/:id` | 系统管理员删除 |

公共查询路由挂载 `authenticateToken`，不挂载 `tenantContext`；保留平台已有的其他全局请求保护。管理接口放在现有系统管理员路由内，服务层复用同一套查询与校验逻辑。

### 7.2 请求与响应

- 列表参数：`q`、`page`、`pageSize`；页码默认 1，每页默认 20，上限 100。
- `q` 对标题和说明进行字面包含搜索，不搜索所有正文；正确处理 `%`、`_` 等 SQL 通配字符，所有查询参数化。
- 列表响应：`{ items, total, page, pageSize }`；普通列表项只含 `id/title/description/updatedAt`。
- 普通详情响应：上述字段加 `content`。记录不存在返回 404。
- POST/PUT 正文字段仅为 `{ title, description, content }`；创建者、时间等由服务端计算，拒绝额外业务字段。
- 创建成功返回 201 与详情；更新成功返回 200 与详情；删除成功返回 204。
- 接口不接受按租户或工作区分库参数；提供这类参数时返回 400，避免客户端误以为数据被隔离。

没有“插入片段”“绑定片段”接口：插入是前端编辑操作，保存继续调用现有 Skill 文件保存接口。

### 7.3 多管理员并发修改

建议采用当前内容摘要防止互相覆盖，不引入业务版本：

1. 管理员详情响应附带强 ETag，由当前记录 ID 和四个可编辑字段的规范序列化结果计算，不存历史。
2. 管理员 PUT/DELETE 带 `If-Match`；服务端在同一数据库写事务内读取、比较并执行操作。
3. 缺少条件返回 `428 SNIPPET_PRECONDITION_REQUIRED`；记录内容已变返回 `412 SNIPPET_EDIT_CONFLICT`；已删除返回 404。
4. 冲突时保留用户正在编辑的表单，提示重新加载当前内容、人工核对后再提交，不自动覆盖或合并。

ETag 只用于管理请求并发保护，不在用户界面展示，不作为可访问的版本，不写入 Skill。普通用户插入已加载正文不需要此校验。

其他错误统一保留可读 `error`，可附稳定 `code`：认证失败 401、无管理权限 403、参数错误 400、正文过大 413、服务端失败 500。删除按钮只对用户本次明确选择的 ID 发请求。

## 9. 验收与测试

### 9.1 产品验收

1. 系统管理员创建一个片段后，租户 A 和租户 B 的授权编辑者均可查询到同一条记录；切换工作区后仍是同一公共库。
2. 普通用户和只有租户管理权限的用户不能创建、修改、删除，直接请求接口也返回 403。
3. 插入入口只在约定的可编辑 `SKILL.md` 正文编辑场景出现；市场详情与只读预览不展示入口。
4. 有选区明确执行替换，无选区执行插入；一次撤销恢复插入前状态，并可重做。
5. frontmatter、多个选区和失效的目标位置得到保护；不会插入到另一个 Skill 或已切换的文件。
6. 管理员修改片段，只影响后续读取；已插入未保存、已保存未发布、已发布的 Skill 内容全部不变。
7. 删除片段后无法重新查询，但既有正文继续可用；已加载弹窗遵循“插入所见正文”的约定。
8. 保存、发布、下载后的文件只有正常正文，不包含本功能注入的片段 ID、来源注释或旁路文件。
9. 再次编辑已有 Skill 时不出现来源标记、升级通知、自动识别或反向引用统计。
10. 两位系统管理员同时编辑时，后提交的过期表单被阻止；无历史版本列表或业务版本号。
11. 空库、网络失败、保存失败、取消及多次打开弹窗均不丢失用户已有编辑内容。
12. 关闭片段查询服务后，已有 Skill 的原有文件保存和发布路径仍可正常使用。
13. 在 SQL Check 已开启和未开启两种情况下插入 SQL 规范正文，原规则配置、启用状态均不改变；插入操作不触发校验，也不新增重复检查链路。

### 9.2 自动化与人工验证分层

- 数据层：幂等建表、CRUD、字段边界、中文/emoji 长度、UTF-8 大小、字面搜索、分页、删除维护人员不删除公共片段。
- 路由层：跨租户读取一致、不要求当前租户、鉴权、伪造管理员/维护者字段、非法 ID、412/428 并发保护及删除竞态。
- 编辑器层：光标位置、选区替换、撤销/重做边界、换行、frontmatter 边界、多选区、只读态、目标切换、过期异步响应。
- 管理界面：表单未保存提醒、失败保留输入、并发冲突、删除确认及 Markdown 安全预览。
- 集成回归：插入到保存再发布的正文一致性，文件 revision 冲突、发布预览过期检查及既有 Skill 编辑/导入流程保持有效。
- 人工走查：两个租户的普通账号和一个系统管理员账号完成上述核心链路，检查发布预览及下载包，不仅检查页面截图。

检查“没有片段标记”针对系统是否注入额外内容，不禁止用户自己在 Markdown 中写出 `snippet`、ID 或 `{{变量}}` 等字面文本。

## 10. 实施计划与交付顺序

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 1. 设计评审 | 确认第 2 节默认值及部署前提，冻结接口、字段和交互边界 | 产品规则和首期范围无歧义 |
| 2. 数据与接口 | 公共表、数据服务、只读查询、系统管理员 CRUD、并发保护 | 数据/权限/跨租户测试通过 |
| 3. 管理员维护 | 后台入口、列表、表单、安全预览、删除与冲突处理 | 管理员可独立维护，普通用户不能写入 |
| 4. 编辑器接入 | 片段选择弹窗、位置保护、CodeMirror 事务、撤销与异常处理 | 插入后是普通正文，不新增引用数据 |
| 5. 端到端回归 | 保存、发布、下载、本地运行读取、多租户和不可用场景验证 | 第 9 节核心验收通过，既有流程无回归 |
| 6. 文档与上线 | 同步原需求片段章节、说明全平台数据边界；以空库上线，由管理员录入 | 无既有 Skill 迁移、扫描、回填或自动修改 |

首期无须回收或改造历史 Skill：已有文件原样保留。后续若暂停片段入口，已经插入的正文也无需回滚。

## 11. 与原 V2 文档的关系

本专项的已确认规则已整合到 [技能市场完整方案](/Users/theseus/Documents/Codex/2026-08-24/github-cli-gh-codex-pull-request/claudecodeui/docs/skill-market-v2.0-需求设计说明书.md) 第 7.4 节及相关权限、接口和数据模型中；原 V2 的片段引用、版本与租户可见性规则已撤回。尚未确认的技术默认值仍需按主方案待确认清单评审。

- “原子引用块/只读胶囊”改为“复制 Markdown 正文”。

- “个人或租户可见性”改为“系统管理员维护、全平台登录用户共享”。

- 片段不再作为独立引用单元参与发布、测评或调试；若未来建设 Skill 测评/调试，处理的是 Skill 中的完整正文。

后续整合已整体更新技能市场主方案，覆盖无版本、模板、测评、调试、贡献和发布。本文仍是片段专项设计，不代表功能已实现；旧章节编号仅作设计讨论记录，不覆盖最新主方案。
