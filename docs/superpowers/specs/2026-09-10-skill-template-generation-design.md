# 管理员模板与独立 Skill 生成方案

日期：2026-09-10

状态：产品设计及离线原型，未实施业务后端。替换主方案中“首期仅复制内置模板”的设计。

## 1. 本次补充与默认边界

- 公共片段继续由系统管理员新增、编辑和删除，整个平台所有租户共享，只有固定 Markdown 正文。
- 取消单独的片段类型、分类筛选和“两种分类”说明页；保留既有 Skill 分类。这是对“不需要两种分类”的本次解释，不引入其他分类体系。
- 模板中心支持管理员新建和编辑模板，设置名称、描述、生成要求、用户自定义字段及预置片段正文。
- 用户选择模板、填写业务信息后，在一个独立临时环境中调用 skill-creator，先取得候选文件，再预览并确认保存为本地 Skill。
- 生成不等于发布或测评通过。新 Skill 由创建者负责，按既定流程配置用例、正式测评并确认发布。
- 模板共享范围沿用原方案的租户内；租户管理员管理本租户模板，系统管理员须明确选择有管理权限的租户。原型仅用系统管理员演示一个租户，不模拟完整租户授权。
- 不引入 Skill、片段或模板的产品版本/历史查看。内部任务 ID、并发校验和候选摘要不作为版本展示。

## 2. 三类信息分开配置

| 信息 | 配置人 | 示例与用途 |
| --- | --- | --- |
| 模板名称、模板描述 | 管理员 | “经营分析”“按业务场景与数据口径生成分析技能”，用于模板发现 |
| 生成要求、预置正文 | 管理员 | 定义生成目标和业务约束；不能配置容器权限或任意执行入口 |
| 自定义字段定义 | 管理员 | “业务场景”多行必填、“交付形式”下拉选项；指定填写提示与默认值 |
| Skill 标识、名称、描述 | 创建用户 | 新 Skill 的身份和触发说明，不与模板名称混为一谈 |
| 自定义字段的值 | 创建用户 | “分析月度销售及退款”“Markdown 报告”，作为生成输入 |

首期自定义字段支持单行文本、多行文本、下拉单选。每项具有唯一 key、名称、类型、必填、填写说明、默认值；下拉项另有选项集合。表单顺序即定义顺序，不开放用户提供的 JavaScript、动态表达式、任意正则、远程选项接口或文件上传。

建议限制：每模板最多 12 个字段、12 段预置正文；字段值最多 4,000 字符；下拉选项 2–20 个，不允许重复或非法默认值。正式上限应结合平台模型输入预算确定，服务端与界面使用同一协议。

字段 key 采用受限标识，拒绝重复、内置字段名及原型链保留名。不依赖前端校验。缺少必填值、非法下拉值、额外未声明字段，均在创建任务前拒绝。

## 3. 模板如何预置片段

1. 管理员在模板编辑表单选择公共片段，点击加入。
2. 表单复制此时所见的标题和正文，支持预览、移除、上移和下移。
3. 保存模板只存有序的普通正文块，不存 snippetId 或实时引用，不维护使用者列表。
4. 公共片段之后修改、删除，已有模板、已提交的生成任务及已有 Skill 均不变。
5. 管理员希望模板使用新正文时，显式移除旧块、重新选择并保存；保存只影响此后新建的任务。
6. 用户提交后固定整份模板及其填写值。进行中的任务不重新读取模板库。

片段仍没有参数：正文中的 {{project}} 只是普通文本，不进行字符串替换；自定义字段是独立结构化输入，不是片段变量体系。生成服务把字段值交给 skill-creator 用于编写业务说明；已选固定正文由服务端按顺序加入候选 SKILL.md 正文并核验未丢失，不交由 AI 随意改写。模型仅按约定生成其负责的正文区域，不输出装配标记。若产生冲突、重复或矛盾，应在预览及检查中提示，不宣称仅因复制成功就满足业务要求。

最终 Skill 只有正常的 SKILL.md 和必要文件；没有模板引用、片段 ID、来源注释、只读胶囊或运行时装配。生成任务暂存固定输入用于完成任务，并不构成反向片段追踪；不得采集“哪个 Skill 用了哪个片段”的埋点。

## 4. 交互流程

### 管理员

模板中心 → 新建模板 → 填名称/描述/生成要求 → 添加字段 → 选择并排序片段正文 → 核对后保存。保存即在当前租户可选，不自动启动模型。已有模板可编辑，采用当前内容 ETag 防止旧表单覆盖新配置。

公共片段管理 → 新增片段 → 填标题、说明、固定正文 → 保存。取消不保存，不要求选片段分类。普通用户不增加独立片段库入口。

### 用户

模板中心 → 使用模板 → 填 Skill 基本信息及自定义字段 → 查看固定要求 → 发起生成 → 查看进度 → 预览候选文件 → 确认保存到我的技能。

进度分为“固定输入、准备独立环境、调用 skill-creator、产物检查、回收环境与待确认”。用户可取消；终态后不可追问或恢复为会话。失败、超时、取消均不创建半成品 Skill；重试需要用户显式确认新任务，不自动重复调用到成功。

结果区左侧展示文件列表/树，右侧默认只读 SKILL.md，可以切换参考文件。只有产物有效且清理状态已确认才允许保存；环境回收异常要显示异常并由任务回收器处理，不假装已回收。权限变化、同名目标等在确认时重新校验。

## 5. 独立执行环境与现有项目的差异

| 当前代码 | 可复用的基础 | 不能直接照搬的部分 |
| --- | --- | --- |
| [agent-graphs.js](../../../server/services/agent-graphs.js) | skill-creator 提示组装、SDK 调用和文本结果提取 | 当前 prepareClaudeRuntime 面向现有工作区；maxTurns=1 且无工具，只取 SKILL.md 文本；结束后标记 idle/failed，不等于删除临时环境 |
| [server/skills/skill-creator/SKILL.md](../../../server/skills/skill-creator/SKILL.md) | 项目已有生成技能 | 目前是 Agent Top Skill 专用，要求固定七节，只返回 Markdown；不应直接用此限制所有市场 Skill |
| [top-skill-jobs.js](../../../server/services/top-skill-jobs.js) | 按租户/用户/工作区定位任务、状态与过期机制 | 内存 Map、无取消控制、仅 generate/optimize 操作；不是模板持久任务服务 |
| [agent-session-runtime.js](../../../server/services/agent-session-runtime.js) | 运行环境准备与资源限制的部分构造逻辑 | 真实工作区、持久 HOME、常驻运行环境不能作为此功能隔离边界 |
| [workspace-skills.js](../../../server/services/workspace-skills.js) | Skill 创建、文件路径与导入相关校验 | 写入目标工作区须放在用户确认后，不能让生成器自行覆盖现有 Skill |

建议在 CCUI 新增 template-generation 任务服务和独立 runtime profile，复用可注入的 SDK 调用封装，不调用普通聊天路由，不修改 Agent Graph 的现有结构约定。

平台维护经过审查的 skill-creator 市场生成配置，按任务只读装载：要求合法 name/description 和足够完成任务的简明指令，不强制通用 Skill 使用 Top Skill 七节。与 Codex 的本地 skill-creator 同名不代表同一实现；不可依赖客户端本机安装的技能，也不可从用户工作区优先解析并执行同名覆盖。

首期可采用无工具的生成调用：skill-creator 输出 SKILL.md 文本，后台受控写入候选区；用户填写的业务要求必要时由后台生成 references/requirements.md，并要求正文引用它。无需为了生成指令运行目标 Skill 或开放 Shell。多文件的模型创作能力应另行扩展产物协议和校验，不声称现有 Top Skill 调用已经具备。

新任务创建新容器/同等沙箱、独立工作目录及临时 HOME。生成器只读取固定模板、填写值和平台维护的生成技能；只写本任务候选区。不得挂载真实工作区、宿主 HOME、Docker socket、生产凭据、其他租户资料或会话历史；不自动继承用户 Hook、MCP、其他 Skill、启动脚本和跨任务记忆。

仅开放批准的模型出口。模型认证由平台代理或短期任务凭据提供，不写入模板或产物，不因异常读取用户生产认证。首期无任意网络、依赖安装、工具执行和发布权限。模板和填写值均按不可信业务数据传递，不能改变平台安全策略。

现有 executeSkillCreator 在认证失败时会生成 auth-fallback 文本。模板生成路径必须明确报告生成失败；不能沿用该行为并提示“AI 已成功生成”。若未来提供非 AI 的复制创建模式，须另设明确入口，不在故障时隐式降级。

任务设超时、Token/输出大小/CPU/内存上限；取消、超时及 worker 失联要终止进程并回收。镜像和只读依赖可复用，可写状态不能复用。释放状态独立记录，有失败重试与孤儿回收。

## 6. 候选检查、确认与原有测评的衔接

候选不因模型返回“成功”就可采用，服务端检查实际产物：

1. 输出必须存在，只有一个目标 Skill 根目录；路径规范化后仍在候选区，无越界、绝对路径、符号链接及设备文件。
2. SKILL.md 可解析，name 与用户确认标识一致，description 合法，正文非空。
3. 文件总数、单文件及总大小受限；必要引用存在，没有未替换的系统装配占位符。
4. 固定正文按指定顺序纳入且内容一致，不包含片段引用元数据；不得把其中普通的双花括号文本当作装配占位符。
5. 执行基础秘密/危险内容检查。缺失解析能力或检查服务异常不能假定通过。

这是“生成产物检查”，不代替正式静态检测与动态测评。不自动执行生成出的脚本或 Skill 来验收，不把平台结构检查结果当成发布报告。

确认保存时重新检查任务发起人、当前租户/工作区创建权限、候选摘要及目标名称冲突。后台在工作区目标内采用原子创建；并发同名只有一个成功，不覆盖、合并或隐式改名。幂等采用请求重复时返回已创建的同一 Skill。

成功后：source=created，负责人为创建者，协助人为空，分类默认未分类，无市场导入时间、无发布状态、无已通过报告。用户可编辑，后续由负责人确认测试用例并执行现有完整测评；发布门禁保持不变。

## 7. 数据、接口与示例

建议新增 CCUI 内部数据，不修改远端 data-agent：

- skill_templates：tenantId、id、title、description、instructions、fieldsJson、bodyBlocksJson、编辑人及时间。无版本历史、无片段外键。
- skill_template_generation_jobs：任务归属、状态、固定输入/摘要、generator 配置摘要、执行租约、取消信息、私有候选清单、检查结果、cleanup 状态、createdSkillId。
- 固定输入和候选私有短期保存，便于刷新后继续查看或确认；保留期建议 30 分钟，部署时配置，过期不可确认。任务元数据只保留必要审计；不进聊天历史，也不作为 Skill 历史版本。

字段示例：

~~~json
{
  "key": "delivery",
  "label": "交付形式",
  "kind": "select",
  "required": true,
  "help": "选择此 Skill 的主要交付形式",
  "defaultValue": "分析报告",
  "options": ["分析报告", "文字结论", "结构化 JSON"]
}
~~~

建议接口（均要求服务端鉴权）：

| 接口 | 作用 |
| --- | --- |
| GET /api/skill-templates | 返回当前租户可用模板 |
| POST /api/skill-templates | 管理员新建 |
| PATCH /api/skill-templates/:id | 管理员编辑，要求 If-Match |
| POST /api/skill-template-generations | 工作区用户发起，提交 templateId、If-Match、Skill 信息与字段值、幂等键 |
| GET /api/skill-template-generations/:id | 仅相应租户/用户/工作区可查询 |
| POST /api/skill-template-generations/:id/cancel | 请求取消，回收完成后才结束 |
| POST /api/skill-template-generations/:id/adopt | 确认候选摘要后原子创建本地 Skill |

举例：管理员创建“经营分析”模板，预置输出约定和事实核查正文，声明“业务场景、数据口径、交付形式”字段。用户填写“分析月度净销售与退款、脱敏 CSV、分析报告”。生成器根据这些信息编写操作步骤；后台纳入固定正文并检查文件，用户核对后保存为 sales-insights。此 Skill 不要求输出 JSON，也不会自动开启 SQL Check。

## 8. 原型与验收

[原型 HTML](../../prototypes/skill-market/index.html) 已补齐管理员片段新增、模板新建/编辑、自定义字段、正文选取与排序、用户填写、模拟生成/异常/取消、候选文件预览和确认保存。

原型只使用一个租户的内存对象、预设步骤及文本组装，没有实际 skill-creator、容器、持久任务、真实权限、TTL 或原子文件系统写入。模拟产物包含 SKILL.md 和按需生成的参考要求文件；修改模板不会触发真实语义理解。只能验证产品交互与模型状态，不证明生产安全。

实施验收应覆盖：普通用户不可维护模板/片段；跨租户或跨工作区任务拒绝访问；字段校验及过期表单冲突；选取后片段变更不回改；提交后模板变更不回改；无认证显式失败；取消/超时清理；危险产物阻断；确认前无本地文件；同名冲突不覆盖；重复确认幂等；新 Skill 未测评且不能直接发布。

原型测试与浏览器验收范围记录于 [README](../../prototypes/skill-market/README.md)。
