# Skill 市场下架设计

日期：2026-09-01  
状态：已确认，设计完成后直接实施

## 背景

系统服务层已经预留下架入口，能够校验小写 `yes`、本地发布绑定和创建者身份，但因为此前不知道上游接口，只返回 `501 SKILL_MARKET_UNPUBLISH_UNAVAILABLE`。现已确认上游接口为：

```text
POST /data-agent/portal/skill/delete
{"data":{"id":"<远端 Skill ID>"}}
```

该接口与现有发布接口使用同一套 DataAgent 请求、鉴权、租户和账户上下文。镜像和现网的网关前缀继续由现有市场基地址决定，不在业务代码中增加环境分支。

## 目标

1. 允许创建者下架自己通过当前工作区发布的 Skill。
2. 下架只影响技能市场可见性，不删除或修改任何本地 Skill 文件。
3. 上游下架成功后清理当前工作区对应的市场绑定，使本地 Skill 恢复为未发布状态并可再次发布。
4. 用户必须在危险操作弹窗中输入精确的小写 `yes`。
5. 弹窗提醒用户确认所需内容已经导入并保存在本地，但不提供保存、导出或复制能力。

## 方案比较

### 方案 A：远端下架后清理绑定，保留本地文件（采用）

市场版本消失，本地 Skill 恢复为普通未发布技能。状态清晰，也符合“下架和本地文件无关”的要求。

### 方案 B：保留市场绑定

可以保留旧远端 ID，但“我的技能”可能继续显示已发布或远端已下架状态，不能准确表达用户主动下架后的未发布状态。不采用。

### 方案 C：同时删除本地文件

会扩大下架操作范围并造成数据丢失风险，明确不采用。

## 后端流程

1. 工作区路由继续要求编辑权限。
2. 服务在工作区 Skill 操作锁内读取最新绑定。
3. 校验 `confirmation === "yes"`。
4. 按本地目录键查找绑定，要求 `bindingType === "published"`。
5. 要求绑定中的 `createUserId` 与当前账户一致。
6. 从绑定取 `id`，缺失时兼容回退 `skillId`；没有远端 ID 时返回绑定数据错误，不发送请求。
7. 复用 `requestMarketJson` 调用 `/portal/skill/delete`，由现有路径规范化补成 `/data-agent/portal/skill/delete`，并携带现有 `tenantCode`、`accountId`、签名及 JSON 负载。
8. 只有上游返回成功后，才从当前工作区的市场绑定集合中删除该条记录。
9. 返回下架的本地 Skill 名称和远端 ID；本地 Skill 目录、托管源目录和文件内容完全不变。

如果上游失败，不修改绑定或本地文件。如果上游成功但绑定清理失败，返回明确的部分成功错误，说明市场已经下架而本地绑定刷新失败；不删除本地文件。

## 前端交互

- 只对 `origin=local`、`bindingType=published` 且当前账户具备发布权限的 Skill 展示“下架”按钮。
- 点击后展示危险确认弹窗，文案明确：
  - 下架后该 Skill 不再显示在技能市场；
  - 本页面不提供保存功能；
  - 请先确认需要保留的 Skill 已经导入并保存在本地；
  - 当前工作区的本地 Skill 文件不会被删除。
- 用户输入精确的小写 `yes` 后才可提交。
- 成功后刷新技能市场、“我的技能”和当前详情；当前 Skill 保持打开并显示为未发布，可再次点击“发布”。
- 失败时保留当前页面和输入结果，并展示后端错误。

## 接口契约

CCUI：

```http
POST /api/skill-market/skills/:name/unpublish
Content-Type: application/json

{"confirmation":"yes"}
```

DataAgent：

```http
POST /data-agent/portal/skill/delete
Content-Type: application/json

{"data":{"id":"<binding.id || binding.skillId>"}}
```

镜像与现网继续复用现有市场请求基地址。下架代码只传 `/portal/skill/delete` 给现有请求工具，不硬编码 `/dataagent-mirror` 或 `/dataagent`。

## 测试策略

- 正确创建者、已发布绑定和 `yes` 会发送准确的 endpoint、租户头、账户头及 JSON 负载。
- 上游成功后绑定被删除，本地 Skill 文件保持不变。
- 缺少 `yes`、非 published 绑定、非创建者、缺失远端 ID 均不会调用上游。
- 上游失败时绑定和本地文件均不变。
- 路由正确传递 `tenantCode`、`accountId` 和确认值并返回成功结果。
- 前端只在允许下架时显示按钮，确认弹窗要求 `yes`，成功后刷新为未发布状态。
- 相关服务测试、类型检查、静态检查和生产构建通过。

## 验收标准

- 自己发布的 Skill 可以通过确认弹窗下架。
- 实际请求路径和负载与现有发布接口风格一致。
- 下架成功后技能市场不再显示该 Skill，本地绑定被清理。
- 当前工作区的本地 Skill 文件原样保留，并恢复为可发布状态。
- 任何失败路径都不删除本地文件。
