# Skill 发布与发布更新一致性修复设计

日期：2026-09-01  
状态：已确认，按用户授权直接实施

## 背景

当前发布链路把工作区目录名同时当作市场压缩包根目录。市场导入为了避让本地目录占用，可能把技能安装到 `<目录>_2`；此后发布更新会把这个本地后缀重新上传到市场，意外改变远端包目录。首次发布遇到市场目录占用时，前端还会要求重命名工作区目录，但 `SKILL.md.name` 保持不变，这与本地上传后“目录使用 manifest name”的规则冲突。

发布更新还存在两个一致性风险：预览与确认发布之间没有校验本地文件是否变化；同一工作区的并发发布请求没有串行化，可能重复创建市场记录或重复增加版本。

## 目标

1. 工作区目录只用于定位本地技能，不再被市场目录冲突反向改名。
2. 首次发布以技能的本地逻辑目录为首选市场包目录；市场目录已占用时，仅为远端包根目录自动分配 `_2`、`_3` 等后缀。
3. 发布更新沿用远端技能当前包目录，不因本地安装目录带后缀而改变远端结构。
4. 发布确认必须对应用户看到的本地文件快照；预览后文件变化时阻止发布并要求重新预览。
5. 同一工作区的导入、首次发布和发布更新共用串行锁，避免本地绑定竞态。
6. 保持市场技能 ID、`SKILL.md.name`、本地绑定键、版本和权限语义不变。

## 方案比较

### 方案 A：冲突时继续重命名工作区目录

实现最少，但会让上传技能的目录与 `SKILL.md.name` 再次分离，也会改变用户已有路径。不采用。

### 方案 B：本地目录与市场包目录解耦（采用）

首次发布时扫描市场实际包目录并选择空闲的远端 ZIP 根目录；本地目录完全不动。更新时下载目标远端技能，解析并复用其当前包目录。无需数据库迁移，远端包本身就是目录事实来源。

### 方案 C：在本地绑定中新增 `marketDirectoryName`

可以减少更新时的一次远端解析，但需要数据库、旧数据回填和缓存一致性处理；远端包被其他客户端改动后，本地字段还可能过期。本次不采用。

## 后端设计

### 首次发布

1. 在工作区串行锁内重新读取本地状态，确认技能仍存在且尚未绑定有效远端记录。
2. 读取完整本地目录。
3. 获取租户市场目录清单；首选目录空闲时直接使用，已占用时从 `_2` 开始选择第一个空闲目录。
4. 使用选定的市场目录构建 ZIP，但不移动或改名 `.claude/skills/<本地目录>`。
5. 调用保存和发布接口；成功后仍以本地目录为绑定键，记录远端 ID、版本和内容基线。
6. 响应可返回实际市场包目录用于诊断，但页面成功后的技能定位仍使用本地目录。

### 发布更新

1. 通过绑定中的远端 ID 获取目标技能并验证创建者和版本。
2. 从远端下载包解析其真实根目录。
3. 检查该远端根目录是否被另一个远端技能占用；正常情况下排除当前技能自身。
4. 使用远端根目录重新打包本地完整文件并更新同一远端 ID。
5. 发布成功后更新本地版本与基线，绑定键和本地目录保持不变。

### 预览一致性

- 发布预览返回本地目录内容摘要 `localContentHash`。
- 前端确认发布时把该摘要随请求发送。
- 后端在调用市场更新接口前重新计算摘要；不一致时返回 `409 SKILL_PUBLISH_PREVIEW_STALE`，不上传任何内容。
- 为兼容内部直接调用，服务参数允许不传摘要；正式 HTTP 页面链路始终传递并校验。

### 并发

- 市场导入、首次发布和发布更新对同一工作区使用同一把进程内串行锁。
- 锁内重新读取绑定和文件状态，避免两个首次发布请求同时保存两条远端记录。
- 远端跨实例唯一性仍由上游市场负责；CCUI 的扫描是用户体验和本地一致性保护，不替代上游约束。

## 前端设计

- 删除 `SKILL_MARKET_DIRECTORY_CONFLICT` 对应的“重命名工作区目录后重试”流程和弹窗。
- 首次发布直接处理后端自动选择的市场包目录，成功后继续停留在原本地技能详情。
- 发布预览保存 `localContentHash`；确认时随发布请求提交。
- 预览已过期时关闭旧确认状态，提示用户重新点击“发布更新”获取最新差异。
- 其他市场错误沿用现有页面错误提示。

## 测试策略

- 首次发布遇到同名市场包目录时，上传 ZIP 使用 `_2` 或后续空闲后缀，本地目录不变。
- 本地安装目录为 `remote-root_2` 时，发布更新仍上传 `remote-root` 作为 ZIP 根目录。
- 发布预览能正确剥离远端根目录，并返回本地摘要。
- 预览后修改本地文件，确认发布返回 `SKILL_PUBLISH_PREVIEW_STALE`，且不调用市场更新接口。
- 并发首次发布最终只调用一次市场保存接口。
- 现有创建者权限、远端版本领先阻止、二进制差异、中文目录和认证签名测试继续通过。

## 验收标准

- 发布操作不会再重命名任何本地技能目录。
- 发布更新不会因为本地目录后缀改变市场包根目录。
- 用户确认的差异与实际上传内容一致。
- 同一工作区的重复提交不会创建重复市场技能。
- 服务测试、类型检查、前端静态检查和构建通过。
