# Skill 市场下架入口位置设计

日期：2026-09-01  
状态：已确认

## 背景

当前“下架”按钮与“发布/发布更新”共用 `SkillPublishAction`，显示在“我的技能”详情顶部。下架实际作用于远端技能市场，并不删除本地 Skill 文件，因此入口放在“我的技能”容易让用户误认为它是本地删除操作。产品要求将下架入口移动到技能市场详情页顶部，与导入、更新和移除等市场操作放在同一区域。

## 目标

1. “我的技能”详情只保留“发布”和“发布更新”，不再显示“下架”。
2. 技能市场详情顶部展示符合权限条件的“下架”按钮。
3. 只有当前创建者自己发布、且当前工作区绑定仍为本地发布绑定的 Skill 可以下架。
4. 保留现有精确小写 `yes` 确认、保存提醒、错误处理和后端校验。
5. 下架成功后刷新市场与本地清单，并关闭已经被删除的市场详情。

## 方案比较

### 方案 A：拆分独立下架组件（采用）

将按钮、确认弹窗和下架请求从发布组件中拆出为独立组件。发布组件只服务“我的技能”，下架组件只服务技能市场详情。两个组件职责单一，避免用显示开关维护一组互不相关的状态。

### 方案 B：为发布组件增加显示模式

使用 `showPublish`、`showUnpublish` 控制同一组件在两个页面的表现。代码移动较少，但组件仍同时维护发布预览、发布确认、下架确认和两类提交状态，边界不清晰，不采用。

### 方案 C：在市场详情复制下架逻辑

会重复 API 调用、错误处理和确认弹窗，后续文案或校验容易不一致，不采用。

## 组件结构

### `SkillPublishAction`

- 保留发布状态查询、首次发布、发布更新、差异预览和发布确认。
- 删除下架状态、按钮、回调和确认弹窗。
- 仍只在“我的技能”详情中渲染。

### `SkillUnpublishAction`

- 接收工作区 ID、Skill 名称、禁用状态、错误回调和成功回调。
- 只渲染“下架”按钮和危险确认弹窗。
- 输入精确小写 `yes` 后调用现有 `api.skillMarket.unpublishSkill`。
- 不执行保存，也不调用“发布前保存”逻辑。
- 弹窗继续提示：页面不提供保存能力，用户应确认所需内容已经保存在本地，当前工作区本地文件不会被删除。

### 市场详情可见性

市场详情返回的本地绑定状态用于前端展示：

- `canPublish === true`
- `origin === "local"`
- `bindingType === "published"`
- 当前工作区具有管理权限

以上条件同时满足时显示“下架”。后端继续校验工作区权限、创建者、绑定类型、确认值和远端 ID，前端状态不作为安全边界。

## 成功与失败流程

下架成功后：

1. 刷新技能市场第一页和“我的技能”清单。
2. 清除当前市场详情、文件选择和编辑状态，返回技能市场列表。
3. 显示成功提示，说明远端已经下架且本地 Skill 保持不变。
4. 用户切换到“我的技能”后仍能看到该本地 Skill，并可再次发布。

下架失败时：

- 保留当前市场详情和确认弹窗。
- 保留用户输入，允许确认错误原因后重试。
- 展示后端返回的错误。
- 不清理市场绑定，不删除本地文件。

## 测试策略

- 保留并扩展 `canUnpublishSkill` 测试，覆盖创建者发布绑定、普通市场导入、非创建者和无管理权限。
- 验证“我的技能”的发布组件不再包含下架状态和回调。
- 验证市场详情只有满足下架条件时才接入下架操作。
- 验证下架成功回调刷新两个列表并退出市场详情。
- 运行前端工具测试、Skill 市场服务测试、TypeScript、ESLint 和客户端构建。

## 验收标准

- “我的技能”详情不显示“下架”。
- 自己发布的 Skill 在技能市场详情顶部显示“下架”。
- 他人 Skill 和普通市场导入 Skill 不显示“下架”。
- 下架确认、远端 API、本地绑定清理和本地文件保留语义不变。
- 下架成功后市场列表立即刷新，市场详情关闭，本地 Skill 仍存在。
