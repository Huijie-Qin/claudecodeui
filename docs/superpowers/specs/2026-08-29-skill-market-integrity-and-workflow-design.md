# 技能市场完整性与工作流修复设计

日期：2026-08-29  
状态：已确认

## 背景

当前技能市场与“我的技能”存在一组相互关联的问题：市场列表缺少创建者信息；移除 Skill 不需要强确认；`SKILL.md.name` 与目录名被错误地绑定；页面仍支持直接新建 Skill；ZIP 上传结构不够严格；旧数据库没有执行新增市场绑定字段的真实启动迁移；市场导入会在文件已写入后因数据库错误形成半成功状态；本地发布的 Skill 被展示为“已导入”；系统尚未为未来的市场下架操作预留安全接口。

此外，市场中不同远端 Skill 可能使用相同的 ZIP 顶层目录。如果依赖目录名匹配远端身份，可能产生错误的已导入状态、错误预览或跨 Skill 覆盖。

## 目标

1. 技能市场主列表展示创建者，并继续支持按创建者搜索。
2. 在“我的技能”移除整个 Skill 时，必须精确输入小写 `yes`。
3. 所有“我的技能”均可编辑文件，但有效的 `SKILL.md.name` 一旦存在就不可修改。
4. 删除直接新建 Skill 的能力，只允许通过符合严格目录结构的 ZIP 上传。
5. 修复旧数据库缺少 `origin` 等字段导致的市场导入半成功问题。
6. 本地 Skill 发布后显示“已发布”，而不是“已导入”。
7. 预留仅创建者可调用的下架后端接口；本次前端不展示入口，也不调用该接口。
8. “我的技能”完整展示当前 `.claude/skills/*` 的全部一级目录，而非只展示市场安装和 ZIP 上传记录。
9. 阻止同一工作区导入两个使用相同本地目录的远端 Skill。
10. 本地 Skill 发布前检查整个租户市场的实际包目录；冲突时拒绝发布并建议可用目录名。

## 非目标

- 本次不实现真实市场下架，因为 data-agent 当前没有下架或取消发布接口。
- 本次不允许第二个同目录市场 Skill 通过自动改名继续导入。
- 本次不修改待导入市场 Skill 的目标目录名。
- 本次不修改 data-agent 的数据库唯一约束；CCUI 只能提供本地预检，跨实例的最终唯一性仍需上游市场加固。
- 本次不恢复直接创建空白 Skill 的入口或 API 能力。

## 核心模型

### 目录名与展示名分离

每个本地 Skill 使用两种名称：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `name` / `directoryName` | `.claude/skills/<目录名>` | 文件路径、工作区 API 路由、本地绑定键 |
| `displayName` | `SKILL.md` frontmatter 的 `name` | 页面展示、搜索、市场内容描述 |

目录只承载 Skill 文件，不再要求目录 basename 与 `SKILL.md.name` 一致。`SKILL.md.name` 允许中文。现有的 `SKILL_NAME_DIRECTORY_MISMATCH` 诊断、目录同步重命名要求和相关弹窗全部移除。

远端身份必须优先使用远端 `id` / `skillId`，不能再优先使用名称或本地目录。名称匹配仅用于没有远端 ID 的历史记录兼容。

### `SKILL.md.name` 不可修改

保存 `SKILL.md` 时，后端同时解析保存前后的内容：

- 保存前存在有效 `name` 时，新内容必须保留完全相同的值，否则返回 `409 SKILL_MANIFEST_NAME_IMMUTABLE`。
- 保存前缺少 `name` 或 manifest 无法解析时，允许用户首次修复并写入一个有效 `name`；保存成功后该值立即锁定。
- 名称锁定由后端执行，不能只依赖前端编辑器。
- 其他 frontmatter 和正文仍可正常修改。

## “我的技能”数据源

`.claude/skills` 是“我的技能”的权威来源。列表先扫描其全部一级实体目录，再用上传元数据和 `workspace_skill_market_imports` 补充来源、远端 ID、版本、创建者和发布状态。

页面展示以下全部 Skill：

- 手工放入 `.claude/skills` 的 Skill；
- ZIP 上传的 Skill；
- 从市场导入的 Skill；
- 本地发布的 Skill；
- `SKILL.md` 缺失或解析异常、但目录实际存在的 Skill。

系统内置 Skill 不混入“我的技能”。符号链接继续按现有安全策略处理，不扩大可编辑范围。

对于现有的上传托管副本，运行目录是页面展示和编辑的实际对象；修改后同步内部源副本，防止后续托管操作用旧内容覆盖运行目录。移除整个 Skill 时同时清理运行目录、托管副本和本地上传元数据，但按既有规则保留远端市场关系所需的信息。

## ZIP 上传

### 唯一入口

“我的技能”页面只保留“上传技能”。删除“新建技能”按钮、弹窗和可调用的创建空白 Skill API。

### 结构要求

ZIP 必须严格符合：

```text
skill.zip
└── 任意目录名/
    ├── SKILL.md
    ├── scripts/       # 可选
    ├── references/    # 可选
    ├── assets/        # 可选
    └── 其他文件       # 可选
```

校验规则：

- ZIP 第一层必须有且只有一个目录。
- ZIP 第一层不能同时包含文件或其他目录；`__MACOSX`、`.DS_Store` 等杂项同样拒绝。
- 唯一目录的根部必须直接存在且只存在一个入口 `SKILL.md`。
- `outer/inner/SKILL.md`、根目录直接放 `SKILL.md`、多个技能目录和多个 `SKILL.md` 均拒绝。
- 继续执行路径穿越、文件数量、单文件大小、解压总大小和目录深度安全校验。
- ZIP 顶层目录名作为安装目标目录；`SKILL.md.name` 仅作为展示名，两者可以不同。
- 目标目录与现有 `.claude/skills` 目录进行不区分大小写的冲突检查。冲突时直接拒绝上传，不覆盖、不自动改名。

这一结构与 Skill 的加载约定一致：解压后的 Skill 目录根部直接包含 `SKILL.md`，脚本和引用位于其子目录。

## 市场列表与导入

### 创建者展示

技能市场主列表每行展示 `createUserId`，详情页继续展示创建者。列表搜索文本包含名称、展示名、描述和创建者。

前端列表和详情选择使用远端 ID 作为稳定键。返回 DTO 保持远端身份与本地安装目录分离，避免用本地目录覆盖远端 `name`。

### 同目录市场 Skill

导入前先解析远端包实际顶层目录，并区分以下状态：

- 目录不存在：允许导入。
- 目录是同一远端 ID 的现有绑定：按已导入或更新流程处理。
- 目录被本地 Skill 或不同远端 ID 占用：返回 `409 SKILL_DIRECTORY_CONFLICT`。

示例：

```json
{
  "error": "目录 common-skill 已被另一个 Skill 使用",
  "code": "SKILL_DIRECTORY_CONFLICT",
  "details": {
    "directoryName": "common-skill"
  }
}
```

本次只提示冲突并阻止第二个 Skill 导入，不提供自动重命名。即使调用方传入 `overwrite=true`，远端 ID 不同时也不允许覆盖。

### 导入原子性

远端内容先写入工作区内的临时目录并完成内容校验和摘要计算。正式替换前保存旧目录与旧绑定快照。文件落盘、数据库绑定写入、权限调整或详情刷新任一步失败时，恢复旧目录和旧绑定，不留下“接口报错但刷新后出现”的半成功状态。

成功响应必须在文件和数据库状态都已完成后返回。前端收到成功响应后并行刷新技能市场和“我的技能”，随后加载本地详情；失败响应不伪造成功状态。

## 数据库迁移

`workspace_skill_market_imports` 已新增但旧环境可能缺少：

- `origin`
- `binding_type`
- `baseline_hash`

当前缺陷来自迁移入口分裂：建表 SQL 和独立多租户初始化包含新列，但真实服务启动执行的 `runMultitenancyMigrations` 没有补列。`CREATE TABLE IF NOT EXISTS` 不会改变旧表，因此导入在文件写入后执行数据库 INSERT 时才报 `SQLITE_ERROR`。

修复要求：

- 抽取一份共享、幂等的市场绑定列迁移，由真实服务启动路径和测试初始化共同调用。
- 每列只在 `PRAGMA table_info` 确认不存在时执行 `ALTER TABLE ADD COLUMN`。
- 新列允许 `NULL`，不重建表、不删除历史记录。
- 旧行继续使用现有来源兼容推断；后续导入、发布或更新时固化显式值。
- 启动失败必须明确记录迁移错误，不允许带着不完整 schema 继续提供服务。

## 发布状态

市场绑定状态继续拆分为：

- `origin=local, bindingType=published`：本地创建或上传后发布。
- `origin=market, bindingType=imported`：从市场安装。

页面标签规则：

- 本地未发布：`本地创建`。
- 本地已发布：`本地创建`、`已发布`。
- 市场安装：`市场安装`、`已导入`。
- 市场安装且本地修改：追加 `本地已修改`。

内部 `imported` 布尔值可以继续表示“存在远端绑定”，但不得再直接决定“已导入”页面文案。

## 发布前市场目录检查

本地 Skill 首次发布和发布更新都必须检查市场目录冲突。发布更新排除当前绑定的远端 ID。

由于远端列表没有可靠、独立的 `directoryName` 字段，不能用 `skillName` 或 `SKILL.md.name` 代替包目录。CCUI 需要通过远端预览或下载结果解析实际包根目录，并按 `{tenant, remoteId, version}` 缓存结果。版本不变时复用缓存；版本变化时重新解析。

检查流程：

1. 读取当前本地实际目录名。
2. 枚举租户全部已发布市场 Skill。
3. 解析或读取缓存中的每个实际包目录。
4. 对本地目录和市场目录进行不区分大小写的比较。
5. 排除当前 Skill 自己的远端 ID。
6. 市场检查失败或结果不完整时采用失败关闭，不继续发布。

发现冲突时，发布请求返回 `409 SKILL_MARKET_DIRECTORY_CONFLICT`，且不修改目录、不上传、不发布：

```json
{
  "error": "技能市场已存在使用目录 xxx 的 Skill",
  "code": "SKILL_MARKET_DIRECTORY_CONFLICT",
  "details": {
    "directoryName": "xxx",
    "suggestedDirectoryName": "xxx_2",
    "conflictingSkill": {
      "id": "remote-id",
      "name": "市场技能名称",
      "createUserId": "creator"
    }
  }
}
```

建议目录同时检查当前 `.claude/skills` 和市场已发布目录，从 `xxx_2`、`xxx_3`、`xxx_4` 依次寻找首个可用名称。

前端收到冲突后提示是否把当前本地目录改为建议名称。发布请求本身已经被拒绝，不会自动改名或继续。用户确认后调用受控目录重命名 API，同步运行目录、上传托管副本、本地元数据和现有绑定键，不修改 `SKILL.md.name`；完成后重新执行完整市场检查并重新发起发布。如果发生并发冲突，返回新的建议名称。

CCUI 预检不能消除多实例并发竞态。长期应由 data-agent 对“租户 + 实际包目录”增加唯一约束；本次将其记录为上游加固项。

## 移除确认

移除整个 Skill 的确认弹窗复用发布更新的强确认交互：显示目标路径并要求精确输入小写 `yes`，否则确认按钮不可用。

该规则覆盖“我的技能”中的本地 Skill、市场安装 Skill以及仍可访问的旧技能市场弹窗。移除普通文件或子目录继续使用普通确认，不要求反复输入 `yes`。后端删除整个 Skill 的接口同样校验 `confirmation: "yes"`，避免直接调用 API 绕过前端。

## 下架接口预留

新增一个前端不可见、不会被当前 UI 调用的后端接口。建议契约：

```http
POST /api/skill-market/skills/:name/unpublish
Content-Type: application/json

{"confirmation":"yes"}
```

后端依次校验：

1. 当前用户具有工作区编辑权限。
2. 绑定存在且 `bindingType=published`。
3. 当前账号等于绑定记录中的创建者。
4. `confirmation` 精确等于小写 `yes`。

全部通过后，由于上游没有真实下架接口，返回 `501 SKILL_MARKET_UNPUBLISH_UNAVAILABLE`。接口不得修改本地文件、绑定、版本或页面状态。未来只需在校验后接入真实上游调用，并为前端增加同样要求输入 `yes` 的下架弹窗。

## 错误语义

新增或标准化：

- `SKILL_MANIFEST_NAME_IMMUTABLE`：禁止修改已有 manifest name。
- `SKILL_UPLOAD_STRUCTURE_INVALID`：ZIP 顶层或入口结构无效，details 包含非法条目。
- `SKILL_DIRECTORY_CONFLICT`：本地导入目标被其他 Skill 占用。
- `SKILL_MARKET_DIRECTORY_CONFLICT`：发布目录与市场已有包目录冲突。
- `SKILL_NAME_CONFLICT`：本地目录不区分大小写重名。
- `SKILL_MARKET_UNPUBLISH_UNAVAILABLE`：下架校验通过，但上游能力不存在。

前端必须根据错误码展示交互，不能匹配错误文案。

## 测试策略

### 数据库与导入

- 从旧版 `workspace_skill_market_imports` 表启动时自动补齐三个字段。
- 重复执行迁移保持幂等且保留原记录。
- 缺列的真实 `initializeDatabase` 启动路径回归测试。
- 数据库写入失败、目录替换失败和权限调整失败均不残留新目录或错误绑定。
- 导入成功后响应状态与数据库、文件系统一致，前端立即刷新“我的技能”。

### ZIP 与名称

- 接受唯一顶层目录且其根部直接包含 `SKILL.md` 的 ZIP。
- 接受目录名与中文 `SKILL.md.name` 不一致。
- 拒绝根部文件、多个顶层目录、嵌套入口、多个入口和本地目录重名。
- 所有来源的有效 manifest name 修改均被拒绝。
- 缺少或损坏 manifest name 的 Skill 可以完成首次修复，之后锁定。

### 列表与状态

- `.claude/skills` 手工目录、上传目录、市场目录和解析异常目录均出现在“我的技能”。
- 市场主列表展示创建者并支持搜索。
- 本地发布显示“已发布”，市场安装显示“已导入”。
- 市场远端匹配优先使用 ID，前端远端列表键不使用目录名。

### 冲突与发布

- 两个远端 ID 使用相同目录时，第一个可导入，第二个返回 `SKILL_DIRECTORY_CONFLICT`。
- 不同远端 ID 即使传入 overwrite 也不能互相覆盖。
- 本地发布目录与市场冲突时返回完整结构化 details，不产生远端写入。
- 建议名称同时跳过本地和市场的 `_2`、`_3` 等占用项。
- 用户确认重命名后同步所有本地元数据，重新检查通过才发布。
- 市场目录解析失败时发布失败关闭。

### 确认与下架

- 整个 Skill 移除只有输入小写 `yes` 才能调用后端；文件和目录移除不受影响。
- 下架接口覆盖无权限、非创建者、非本地发布、缺少 `yes` 和能力未接入五类结果。
- 下架不可用结果不改变任何状态，且前端无下架按钮和网络调用。

最终验证执行服务端相关单测、前端单测、TypeScript 类型检查、ESLint 和生产构建。

## 风险与控制

- SQLite 增量补列是非破坏性的，但必须只保留一份共享迁移定义，避免不同启动入口再次漂移。
- 文件系统和 SQLite 不能共享原生事务，必须使用 staging、备份和补偿回滚覆盖每个失败点。
- 全量运行目录扫描可能暴露以前被元数据过滤的损坏 Skill；这是预期行为，页面需保留诊断和修复入口。
- 严格 ZIP 校验会拒绝 macOS 自动生成的根部杂项；错误信息必须列出原因，便于用户重新打包。
- 市场目录索引首次构建可能较慢；按远端 ID 和版本缓存，并避免在一次请求中重复下载同一版本。
- CCUI 的发布预检无法提供分布式唯一性保证；上游唯一约束是长期完整解法。
