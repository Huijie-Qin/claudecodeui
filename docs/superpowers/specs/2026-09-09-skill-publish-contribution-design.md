# Skill 发布、贡献与市场更新设计（无版本）

日期：2026-09-09

状态：当前详细设计草案。本次修订只更新文档与测评预览，不实施业务代码。本文替代此前的“Skill 版本、发布与贡献详细设计”；此前的正式版本序列、历史查看、历史导入和回滚发布方案全部撤回，不再作为实施任务。

## 1. 已确认规则

- Skill 不区分版本，不生成或展示版本号，不提供技能市场或“我的技能”的历史版本查看、版本对比、回滚。
- 市场导入 Skill 是否有更新，比较“当前远端 Skill 的更新时间”与“本地成功导入该内容时保存的远端更新时间”，不比较本地编辑修改时间，也不比较版本号。
- 只有当前负责人能够发布或合并发布；负责人可以直接发布，包括首次发布。协助人可以贡献与评审，其认可不是强制合并条件。
- 贡献页只有“收到的贡献”和“我提交的贡献”；协助人可见自己协助 Skill 的全部请求。贡献继续按租户隔离。
- CCUI 发布和合并发布必须通过当前负责人亲自发起的静态＋动态联合测评；用例由负责人配置确认。只能改 CCUI，仍允许其他渠道直接发布。成功发布关联该次负责人报告，市场只读展示当前内容的结果；无适用报告时显示“未测评”。
- 调试单次执行、不持久化执行记录；正式测评报告、贡献讨论与发布操作审计仍保留，不等同于 Skill 历史版本。
- 下架保留贡献、测评、操作记录与本地文件，但不再建设正式版本归档。片段仍为全平台管理员维护的固定正文，复制插入、无版本、无追踪。

## 2. 三个时间必须分开

| 字段 | 来源与含义 | 何时改变 |
| --- | --- | --- |
| `remoteUpdatedAt` | 当前市场对应 Skill 的远端更新时间 | 拉取远端详情时刷新 |
| `importedRemoteUpdatedAt` | 成功导入／同步到本地的那份内容对应的远端更新时间 | 远端内容成功写入本地且绑定元数据提交成功后更新 |
| `localEditedAt` | 本地 Skill 内容编辑修改时间 | 本地文件修改时更新，仅用于本地展示 |
| `importedAt` / `lastSyncedAt` | 本地执行导入／最近同步操作的时间 | 记录操作发生时间，不参与远端更新判定 |

建议正式字段名采用 `importedRemoteUpdatedAt`，避免现有 `updatedAt` 同时指代远端修改、本地保存和同步时间。`importedRemoteUpdatedAt` 不是一个新的版本号，也不是“用户点击导入按钮的时间”。

例如远端内容在 10:00 更新，用户 11:00 导入、12:00 本地修改：保存的对照时间仍为远端 10:00。远端之后更新到 11:30，即使本地编辑时间为 12:00，也应提示待更新。

### 2.1 更新判定（建议采用的完整边界）

先确认同一租户、同一市场来源及稳定远端 Skill ID，再比较两个合法时间：

```text
remoteUpdatedAt > importedRemoteUpdatedAt  → 待更新
remoteUpdatedAt = importedRemoteUpdatedAt  → 无远端更新
remoteUpdatedAt < importedRemoteUpdatedAt  → 远端时间异常，待核实
任一时间缺失／非法／无法读取               → 更新状态未知
远端明确不存在                           → 来源已下架／删除
纯本地 Skill、没有市场绑定                 → 不适用
```

“大于”表示远端有较新的更新时间；对时间倒退不直接解释为已同步，也不静默覆盖本地。若产品希望任意不相等都提示“来源有变化”，可以调整文案，但不能把更早时间称为更新版本。

时间按远端契约统一单位、时区与精度后比较，同时保留原始值用于诊断；不能用不同格式字符串的字典序比较，不能混用秒和毫秒，不用客户端当前时间补缺失值。只有 UI 展示时才转为用户时区。

### 2.2 与本地修改是两个独立状态

| 远端时间是否更新 | 本地是否修改 | 展示与操作 |
| --- | --- | --- |
| 否 | 否 | 无远端更新 |
| 否 | 是 | 有本地修改；不因此提示远端待更新 |
| 是 | 否 | 待更新；用户确认后同步远端内容 |
| 是 | 是 | 待更新＋有本地修改；先查看差异并确认处理，不自动覆盖 |

沿用当前 `baselineHash / locallyModified` 思路检测本地是否偏离最后导入内容；摘要只用于编辑保护、差异与测评绑定，**不参与“远端是否有更新”的判定**。远端时间变了，即使文件摘要相同，也按时间规则提示；远端时间不变的内容变更无法靠该规则识别，需要如实承认远端时间契约的限制。

## 3. 导入、更新与旧数据

### 3.1 成功导入的提交边界

1. 拉取目标 Skill 元数据及其远端更新时间 T0，按同一稳定 ID 获取当前包，不请求旧版本包。
2. 在临时目录校验完整包、路径、大小及 manifest，再读远端更新时间 T1；T1 与 T0 不同则本次下载可能已过时，重新获取或提示重试，不能将 T1 直接贴到 T0 的包上。
3. 提交前检查目标目录、本地内容摘要与用户确认时一致，防止下载期间的新编辑被覆盖。
4. 成功替换本地内容并持久保存对应绑定后，写入 `importedRemoteUpdatedAt = T0`、新的 `baselineHash` 与操作时间。
5. 文件写入、元数据提交任一失败，恢复原目录与原绑定；崩溃恢复依据操作日志收敛，不能出现旧文件配新时间或新文件配旧时间却显示成功。

远端未提供原子下载或条件读取时，前后核对只能缩小竞态窗口，不能证明所有中间更新都可观察。需验证远端更新时间可靠、覆盖可分发内容变化且精度足够；不宣称时间相等就是绝对的原子快照证明。

### 3.2 什么操作不能推进导入时间

本地编辑／保存、打开详情、检查更新、刷新市场列表、生成用例、测评、提交或评论 PR、取消／失败的导入，都不能修改 `importedRemoteUpdatedAt`。也不能仅因为负责人发布成功就给所有工作区推进导入时间。

同一工作区发布后，只有它的当前文件与已核实的远端内容完全一致，且本次同步确认成功，才可更新这个工作区的导入绑定；期间有编辑则保留原绑定和内容。贡献者或负责人发布成功不会自动升级其他人的本地副本。

### 3.3 已有导入记录迁移

- 新增可空 `imported_remote_updated_at`；旧 `version / importedVersion` 不用于推导时间。
- 旧本地 `updatedAt`、文件 mtime、导入操作时间也不能回填为远端更新时间。
- 无可信历史远端时间的记录显示“更新状态未知，需要重新同步”；本地技能仍可用。
- 只有用户确认且新一次同步真实成功后才建立时间对照；存在本地修改先保护内容，不为完成迁移自动重新导入。
- 老版本字段可在存储／远端适配兼容层暂留，不参与产品状态、更新判定或 Skill 历史。存储格式、SDK、规则 schema 自身的技术版本不属于 Skill 版本，不应误删。

## 4. 发布与测评不再依赖版本

仍需固定“本次待发布内容”，否则先测评 A、后来编辑成 B，再发布 B 会绕过门禁。建议保留内部 `candidateId + contentHash` 和任务期间只读内容副本；这些不是 Skill 版本，不提供浏览全量历史 Skill 或恢复旧 Skill 的入口。

负责人流程：保存并确认本次内容 → 固定候选 → 静态检查 → 隔离动态测评 → 负责人确认 → 持久发布任务 → 核实远端当前内容。首次发布与更新沿用此流程，只是前者创建远端 Skill，后者更新现有稳定 ID。

测评报告绑定候选内容、用例与策略摘要、测试依赖、检测器和执行环境。内容变更或正式用例改变，旧报告保留当次事实，但不再满足当前发布条件；不通过版本号判断有效性。

本地保存不自动发布；无内容变化可提示无需更新，实际发布请求仍保存必要审计。审计记录操作者、目标、时间、内容摘要、任务结果、关联测评和 PR，不创建版本序列、父版本链或 `latestVersion`。测评/评审所需证据按权限与保留策略保存，不转为 Skill 历史页面。

## 5. 贡献与并发变更

### 5.1 提交与评审

- 贡献者在自己的可编辑工作区准备内容，提交时固定本次提交内容及目标 Skill，进入 open 请求；之后的本地编辑不偷偷改变已提交内容。
- 用 `expectedRemoteUpdatedAt` 记录提交时已核对的目标远端时间。它是本次操作的并发条件，与本地导入时间字段用途不同，不能互相覆盖。
- 来自旧导入内容的工作副本不能仅“刷新目标时间”就覆盖市场新内容；先对照当前市场内容处理差异并重新确认提交。
- 贡献者更新请求时固定新内容，旧评审注明针对此前提交，旧测评不用于新内容；保留请求讨论与必要审计，不给 Skill 增加版本号或历史入口。
- 负责人、协助人都可评审；只有负责人在联合测评满足条件后合并并发布。两个贡献子 Tab 复用同一请求与报告。

### 5.2 当前市场发生变化

准备发布和真正发起远端写入前，后端重新读取当前远端时间；与 `expectedRemoteUpdatedAt` 不相等时提示“市场内容已变化，请重新核对”，阻止按旧条件继续操作。若能取得完整当前包，也核验内容摘要用于发布安全，但不把它加进导入待更新判据。

两个 PR 并行时，一个成功发布导致远端时间变化，另一个需重新核对目标内容、处理差异、重新提交和测评。首期不自动三方合并，不引入 baseVersion 或 Git 分支。

### 5.3 请求状态与完成条件

业务状态保留 `open / merged / closed`。进行中提示使用“待测评／测评未通过／待评审／需处理意见／市场内容已变化／待负责人合并／发布中／发布待核实”，移除“基础版本过期”。

远端当前发布内容核实匹配后，CCUI 在同一事务内完成发布任务并将 PR 标为 merged；不产生“合并到 vN”。发布尚未核实则不提前显示已合并。发布中／结果未知时锁定该请求，禁止替换内容、重复合并、撤回或关闭，先处理既有任务。

贡献者可撤回 open 请求，负责人可拒绝并写原因；协助人不能代为关闭或发布。已合并／关闭请求保留记录，不等于可以从中一键恢复历史 Skill。

## 6. CCUI 内的发布协调与外部渠道边界

- CCUI 每个 Skill 使用持久租约和唯一活跃发布任务；请求幂等键绑定租户、用户、Skill 与内容，防止本系统重复提交。
- 发布从固定候选打包，不能临时重读正在编辑的目录；发起远端写入前实时核验负责人、内容、测评和远端时间条件。
- 调用现有远端创建／更新／发布接口；发布后重新读取该稳定 ID 的当前已发布状态、更新时间和完整内容，核验是否匹配本次候选，再提交本地任务结果。
- 不再通过历史版本接口、`queryVersion`、远端 `version+1` 或本地正式版本序列确认成功。远端响应若仍含 version，仅作为协议兼容数据，不参与本方案业务规则。
- 若远端无条件写入、原子发布、幂等保障，CCUI 本地锁无法约束其他客户端。时间预检与写入之间仍有竞态，不能保证全渠道线性一致或观测所有中间变化。

| 结果 | CCUI 行为 |
| --- | --- |
| 本地校验失败，未调用远端 | 明确失败，不改本地导入时间 |
| 远端超时／连接中断 | 结果待核实，保留任务，不盲目重新创建或发布 |
| 响应成功且当前已发布完整内容核实匹配 | 完成任务；如有关联 PR，标为已合并；记录操作审计 |
| 当前内容不匹配或无法取得完整包 | 冲突／待核实，不把响应 200 当成内容验证成功 |
| 核实时已被外部发布覆盖 | 只能记录已知响应和当前观察，不能靠不存在的历史版本能力推断中间成功事实 |
| 之后再次观察到外部变更 | 更新当前市场状态；不把旧内容测评标识贴到新内容上，不更改本地导入时间 |

市场测评页只关联经过核实的当前发布内容与发布使用的负责人报告，展示总体结论、静态检查及动态用例结果，不能仅按 Skill ID 查询最近一次 passed。报告记录真实发起人及启动时负责人，必须与发布时当前负责人匹配；贡献者/协助人自检不替代。远端更新时间改变先撤下缓存的适用状态；无对应报告显示“未测评”。后续本地编辑和未发布测评不覆盖市场报告。内部摘要核验用于报告适用性，不改变第 2 节规定的导入更新判据；私有输入与原始日志不随结果公开。

若远端更新时间缺失、不能确认当前包或身份映射不明，发布保持待核实／受阻；不得用本地时钟、文件 mtime 或版本号作为隐式回退。

## 7. 下架与界面

下架仅取消市场分发，保留本地文件、贡献、测评和操作记录；恢复分发使用当前明确选择的内容，重新满足测评和负责人确认条件，不称为回滚。管理员强制下架权限仍待单独确认。

每次负责人发布核实成功时，实际参与该次测评的正式用例获得永久删除保护；曾随 Skill 发布即一直不可删除，下架、负责人转移或后续发布不解除。待确认草稿不随发布自动激活，也不因此获得发布保护；失败不误标，待核实期间禁止修改/删除相关集合。正式定义修改需负责人逐条确认并重新测评，原报告定义不回写；具体规则见[完整方案 §9.3.1](../../skill-market-v2.0-需求设计说明书.md#931-用例编辑确认与删除)。

- 技能市场：概览／测评／管理，三个标签。概览左侧为默认全展开的当前发布文件树，右侧默认只读展示根 SKILL.md，支持切换文件；测评只读展示发布前负责人运行并随当前内容发布的结果；管理只读展示负责人、协助人、分类。配置用例与运行在负责人工作区完成，不在市场详情内提供写操作。
- 我的技能：文件编辑／单次调试／测评／管理，四标签，不设“发布与来源”。管理与市场显示相同的负责人、协助人和分类，仅当前负责人可转移负责人、配置协助人、修改分类；其他身份只读，管理员不自动绕过。
- 市场导入来源信息：市场更新时间、上次同步对应的市场更新时间；“本地最后修改”可单独显示，不用于待更新判定。
- 测评报告：总览／静态检查／动态测评，三个视角；撤回版本对比。保留独立测评运行记录，不自动引入“报告对比”作为替代需求。
- 贡献详情仍支持“本次提交与当前目标内容”的评审差异，这是当前操作检查，不是历史版本对比。

管理编辑与文件保存、测评、发布分开。转移二次确认，默认不保留原负责人为协助人；新负责人从协助人中移除，角色及贡献收件范围即时重算。转移使旧所有权授权下的未来发布资格失效，新负责人须重跑；转回原负责人也不能复用旧授权报告。已发布报告保留发布时真实测评发起人，不跟随负责人姓名改写。仅治理字段变化不改文件或导入远端时间。治理 ETag、成员授权、测评/发布互斥及真实远端权限前置验证，统一遵循[完整方案 §7.2.1](../../skill-market-v2.0-需求设计说明书.md#721-管理编辑与负责人转移)。

## 8. 数据与接口增量

| 对象 | 主要内容 |
| --- | --- |
| `skill_governance_skills` | tenantId、稳定身份、当前负责人/协助人/分类、ownerGrantId、治理 ETag、当前 remoteId、分发状态；无 latestVersion |
| 工作区市场导入绑定 | 稳定远端身份、`importedRemoteUpdatedAt`、当前导入 baselineHash、操作时间；无业务 importedVersion |
| `skill_release_candidates` | 本次固定内容、contentHash、来源、操作者、expectedRemoteUpdatedAt；不含 baseVersion、rollbackSourceVersion |
| `skill_contributions` | 目标、作者、当前提交、讨论与状态、关联 publishJob；不含 mergedVersion |
| 测评对象 | 正式用例、用例草稿、报告、静态发现和逐用例结果；按内容摘要绑定，沿用测评专项方案 |
| `skill_publish_jobs` | 候选、测评、预期远端时间、幂等键、阶段、租约、响应与核实结果 |
| 操作审计 | 必要操作者、对象、时间、内容摘要、原因及结果；不是 Skill 正式版本表 |

不创建 `skill_governance_versions`、父版本链或旧版本恢复服务。候选副本、贡献附件、报告证据仅在对应流程与访问权限内读取，回收不能破坏进行中任务和必要审计，也不为了取消版本功能删除既有用户数据。

## 10. 实施与验收

实施顺序：确认远端更新时间／完整包读取契约 → 时间字段与安全迁移 → 更新判断和四态本地保护 → 去掉版本 UI/接口设计 → 候选与 PR → 静态＋动态任务 → 所有 CCUI 发布路径统一门禁。上线发布前门禁必须完整，不先开放无门禁发布。

必须覆盖：

1. 远端 10:00、导入操作 11:00、本地编辑 12:00、远端后来 11:30 时仍提示待更新。
2. 本地连续保存、运行测评、刷新市场都不推进 importedRemoteUpdatedAt；失败／取消同步也不推进。
3. 成功同步后同时提交文件、baselineHash 与对应远端时间；恢复测试防止半提交，下载期间本地新编辑不被覆盖。
4. 旧导入缺时间为未知，不用当前远端时间伪装已同步；秒／毫秒／时区归一化，非法值和倒退有独立状态。
5. 同名不同 remoteId／租户不比较；远端删除不删除本地内容；纯本地 Skill 不提示市场更新。
6. 有本地修改且远端有更新时必须确认差异处理；待更新判定不使用内容摘要代替时间。
7. 测评 A 后改成 B，不能发布 B；贡献变更或远端操作条件变化不能继续沿用旧确认。
8. 不出现版本号、历史版本 Tab、回滚与版本对比；贡献和测评记录仍可按权限查看。
9. 外部并发发布、超时和读回不匹配不伪造成功或测评覆盖；更新状态未知与发布结果未知分别处理。
