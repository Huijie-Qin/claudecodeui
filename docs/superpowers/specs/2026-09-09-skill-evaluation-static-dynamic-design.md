## 1. 设计结论与边界

采用“一份固定候选、静态和动态两阶段、一份分层报告”。静态回答“文件是否合规、是否发现风险”，动态回答“真实执行是否满足用例”，发布门禁综合两者，但不把它们加权成一个总分。

已确认：

- 静态检测与动态检测共同组成正式测评，结果需要可视化。
- 动态验收完整任务和实际交付物，不强制 Skill 返回 JSON；文字、工具、subagent、文件均可作为证据。负责人确认的 AI 语义标准可作为必需项参与发布门禁，无法确定不能通过。
- AI 生成用例草稿，负责人核对、修改并确认后生效，也允许手工编写。
- 首期自动测评为 CCUI 发布与贡献合并发布的强制条件；发布前必须由当前负责人发起该次完整测评，再由负责人最终确认发布。贡献者/协助人自检不能代替，服务端记录真实 initiatedBy、ownerIdAtStart 和 ownerGrantIdAtStart。负责人转移撤销旧所有权授权下的未来发布资格，转回原负责人也必须重跑；已发布报告保留原发起人事实，不能改名冒充新负责人测评。
- 仅改 CCUI；保留其他发布渠道。无对应测评记录的外部发布的当前内容显示“未测评”，本地门禁不能拦截远端外部发布。
- 动态测评在隔离环境执行，不默认开放生产凭据或真实业务写入。
- 调试一次任务结束，不持久化执行记录；正式测评是另一种任务，必须保存报告与受控证据。下架不删除历史报告。
- 片段插入后就是普通正文，不做片段版本、来源、引用完整性检查，也不自动开启 SQL Check。

建议默认值，尚非逐项确认：确定性静态错误阻断；疑似高风险待复核；普通建议不阻断；所有必跑动态用例通过、观测到的安全违规为零；必需 AI 语义项须有证据并明确满足，不以综合分数决定通过。建议同一证据两次独立 AI 评审且一致满足；评分模型、校准、资源预算与高风险复核角色见第 13 节。

## 3. 一次测评如何运行

1. 保存编辑内容后，后端固定完整候选快照；PR 则使用当前不可变提交，不能直接测仍在变化的目录。
2. 固定负责人确认的用例集、平台策略、检测规则、测试依赖和执行配置；创建持久 `evalRunId`。
3. 先做静态检查。存在阻断错误或待复核高风险时，不启动动态任务，并逐条展示未执行原因。
4. 静态允许继续后，按用例启动独立临时容器，采集主任务文字、工具事件、subagent 任务树与真实文件；整棵任务树和写入结束后才封存证据。
5. 独立规则器核验确定性事实，AI 判定器按负责人确认的 rubric 核验语义项并验证引用；被测 Agent 不掌握标准答案、判定器写权限或通过状态。
6. 汇总静态结果、逐用例结果、执行异常和资源消耗，保存终态报告，计算当前发布资格。
7. 发布确认时再次检查资格、权限、内容、发起人必须为当前负责人及预期远端更新时间；不是报告页面显示过绿色就永远有效。负责人变化后必须由新负责人重新运行。
8. 发布及回读核实成功后绑定该次 evalRunId，在市场详情“测评”Tab 只读展示总览、静态检查和动态用例结果；后续本地草稿报告不覆盖它。市场 API 返回脱敏结果投影，不公开私有输入、标准答案、数据集、凭据及原始轨迹。

编辑时可提供“仅静态自检”。高级入口可单独运行动态诊断，但前置安全检查仍必需；单阶段报告明确标为“局部检查”，不能直接满足正式门禁。首期正式门禁只接受同一次完整测评，不跨运行拼接最好成绩。

离开页面不取消正式测评；重连通过报告接口恢复状态。取消需显式操作并释放资源，保留已完成部分及取消原因，不能算通过。

## 4. 静态检测：规则、风险与覆盖范围

静态指“不执行被测 Skill”，不等于“只能正则匹配”。文件解析、AST 分析和不运行工具的语义审阅都属于静态分析。

| 检查组 | 首期检查示例 | 建议处理 |
| --- | --- | --- |
| 包与路径安全 | 根 SKILL.md、路径穿越、越界链接、重复路径、文件数/大小/深度 | 确定性不合规阻断；归档解包前即做资源限制 |
| Manifest | YAML 语法、必填字段、字段类型、当前 CCUI 命名规则 | 确定性错误阻断；不能用解析器回退值掩盖缺失 |
| 本地资源完整性 | 明确声明必需的本地文件、Markdown 文件链接、脚本入口是否存在 | 可确定的必需依赖缺失阻断；动态生成路径与示例文本不直接当缺失 |
| 脚本语法 | 支持语言的只解析检查、明显语法错误 | 适用的必需检查失败阻断；不 import 脚本，不安装它的依赖 |
| 安全风险 | 密钥模式、可疑外传、危险命令、越权路径、指令绕过、混淆载荷 | 已确认违规阻断；启发式疑似高风险待复核，保留置信度与证据 |
| 可维护性 | 说明模糊、过长、缺少触发边界、绝对路径/环境耦合 | 建议，不折算为运行正确率；依赖是否可用还须动态验证 |
| 标准兼容性 | Agent Skills 规范与当前 CCUI 的差异 | 独立兼容性提示；不能偷偷改变现有目录与 manifest 身份规则 |

规则结果用 `passed / finding / error / not_applicable / unsupported` 表达；报告同时记录覆盖清单。检测器崩溃、必需语言不支持、扫描超时不视为“没有问题”。必需检查无法完成时阻断，非必需检查显示未覆盖；只有不适用才可不计入适用检查数。

标准中的建议不能全变成硬错误，例如 SKILL.md 长度建议不应直接阻断；CCUI 已将目录名与 manifest 名称解耦，规范目录名匹配要求需单列兼容性策略，不自动重命名文件。[Agent Skills 规范](https://agentskills.io/specification)

### 4.1 检测器选型

- CCUI 内置确定性检查：复用、拆分当前校验，作为必须可用的基础能力。
- 本地安全扫描适配器：可验证 Cisco Skill Scanner 的离线静态／行为分析能力；其行为分析包含 AST/数据流分析，不应误称真实运行测评。首期固定版本、关闭云端上传与可选联网功能，验证许可证、资源消耗及输出映射后再决定接入。[官方检测器架构](https://raw.githubusercontent.com/cisco-ai-defense/skill-scanner/main/docs/architecture/analyzers/index.md)
- 可选 LLM 静态审阅：只提供结构化文本审阅，禁用工具，不执行目标指令；用作建议或待复核线索，不用模糊评分替代硬规则。仓库内容属于不可信输入。

扫描器自身放在有配额、无网络和受限文件访问的 worker 中，防止解析恶意文件耗尽服务。静态扫描不得自动请求文档中的 URL、运行包内配置插件或安装依赖；外链无法检查应如实标明。扫描无发现不意味着绝对安全。

### 4.2 问题结果与复核

每条问题至少包含 `findingId / ruleId / ruleVersion / detector / category / severity / confidence / path / line / evidence / suggestion / disposition`；定位必须对应被测快照，日志和秘密片段脱敏，无法定位时不用虚构行号。

将“严重程度”和“是否阻断”分开：一条提示是否阻断由固定策略和复核状态决定，不由前端颜色或模型分数决定。

疑似高风险的复核仅允许“确认违规”或“有证据的误报认定”，记录操作者、原因与证据；不提供泛化的“忽略并发布”。例外范围绑定精确内容摘要、规则/检测器版本，任一变化需重新审核。原始发现不改写，以追加审计事件记录复核。复核权限待定；未配置有权人员前保持待复核、阻断。管理员有复核权也不因此取得发布权。

因待复核而终止的报告保留动态未执行事实；误报认定后发起新的完整测评，应用精确范围的复核结论并真实运行动态用例，不能直接把旧的局部报告改成通过。

## 5. 用例与判定规范

### 5.1 用例生命周期

AI 根据固定 Skill 与用户明确提供的背景生成独立草稿，标注来源摘要、生成模型和待补充项；负责人逐条核对输入、期望、测试资源与断言，确认所选草稿后才更新生效集合。重新生成只追加草稿，不覆盖正式用例或其他草稿；贡献包删除测试文件不能删除平台用例。

用例页同时展示“待确认草稿”和“已生效用例”，提供 AI 生成、手工添加、逐条编辑/确认/删除。手工新增和修改也先保存草稿；修改草稿可放弃，不影响原生效定义。删除未发布生效用例需要负责人确认，生效集合变更使旧资格失效；删除草稿不改变资格。定义 ETag/内部变更戳用于并发与失效，不作为 Skill 版本。

**曾随 Skill 发布的用例永久不可删除（已确认）。**负责人首次确认并用于核实成功发布后，服务端记录稳定 caseId 的不可撤销保护；失败不误标，发布待核实锁定相关用例。AI 起草后确认发布的用例同样受保护，转移负责人、下架及重新导入均不解除。不能批量遗漏、重建 ID、取消必跑属性或停用绕过；允许修正定义但必须保留身份/创建者，重新确认并测评，不改写旧报告。保护字段不接受客户端修改，任何身份均无删除/解除保护入口。详细 UI、接口与边界统一遵循[完整方案 §9.3.1](../../skill-market-v2.0-需求设计说明书.md#931-用例编辑确认与删除)。

用例定义与执行结果分开存储：定义中不放 `passed/duration/actual`，这些属于某次执行记录。草稿的期望与被测 Agent 的输出都不是天然真值。没有可靠预期时允许草稿存在，但不能进入必跑正式用例。

### 5.2 首期用例格式（CCUI 自定义，不宣称行业统一标准）

统一采用 `ccui.skill-eval/1` 嵌套结构：caseId、title、required、mode、input（prompt/fixtures）、outputContract（实际交付约束）、expected（description/referenceRefs/assertions）、environment、budget。每条断言按 target/targets 选择一个或多个明确证据，type=llm_rubric 时增加负责人确认的满足/不满足/无法确定标准和证据要求。outputContract 不默认 JSON，可同时要求文字和文件；完整非 JSON 示例见详细方案 §10.4。用例的必跑属性与每条断言的必需属性分开；完整可解析示例、输出契约和预期比较见[详细方案 §6](2026-09-09-skill-evaluation-execution-grading-design.md#6-用例协议与完整示例)。不再沿用早期扁平 input/expected/assertions 示例作为另一套协议。

ID、tenantId、创建者、确认者、永久发布保护及定义变更戳由服务端管理。输入资源、环境和判定器引用均需授权；有效工具权限取平台上限与用例配置交集。expected、隐藏断言和判定器配置不投影给被测 Agent；输出格式可以明确告知。

首期优先正常任务、边界、异常与安全场景。触发路由作为单独的 `routing` 模式：由 Agent 自然选择 Skill，包含应该调用和不应调用的近似任务；强制加载候选后得到正确答案，不能证明召回正确。首期若暂不支持路由 harness，则展示“未覆盖”，不生成虚构触发得分。

Anthropic skill-creator 的用例包含 prompt、expected_output、files、expectations，判定结果逐条保存 passed 和 evidence；本方案借鉴这种“输入—期望—证据”结构，增加租户权限、内部修订与发布绑定，不原样复制为平台契约。[官方 schema](https://raw.githubusercontent.com/anthropics/skills/main/skills/skill-creator/references/schemas.md)

### 5.3 如何判定结果

| 判定方式 | 适用内容 | 首期地位 |
| --- | --- | --- |
| 确定性断言 | 文本包含/排除、JSON 结构和数值、产物内容、工具允许/禁止、预算 | 正式必跑用例的主要判据 |
| 受信校验器 | 表格计算、文件结构、业务规则等声明式难表达场景 | 平台维护白名单、固定版本、隔离执行；不运行贡献者提交的任意评分脚本 |
| LLM 判定 | 内容忠实、需求覆盖、论据充分、建议可操作、文字与文件一致 | 负责人确认的必需项参与硬门禁；建议两次独立评审都 met 才通过，分歧/uncertain 阻断；不能覆盖规则和安全失败 |

多断言按预先确认的规则聚合；一个必需断言失败即该用例失败。禁止让 Skill 自报通过，禁止按输出文本中的“成功”认定成功。模型判定也可能被输出注入，应使用隔离、无工具的判定上下文，校验返回结构并展示不确定性。

用例状态区分 `passed / failed / inconclusive / error / timed_out / cancelled / not_run`。有效语义结论不确定或双评审分歧为 inconclusive；证据采集/解析故障、无效引用或模型服务故障为 error。执行器或测试服务故障是 error，业务断言不符是 failed；两者均不能满足门禁，但建议的处理分别为修复环境／修复内容。

## 6. 动态执行与证据采集

每个用例使用全新临时工作目录、HOME 与容器，复用镜像但不复用前一用例的容器状态。候选、批准的测试输入只读挂载，产物写入独立输出目录；评分标准和平台数据库不进入执行容器。

- 单独封装 `skill-eval-runtime`，参考已有 SDK 单任务调用，显式 `persistSession: false`；不走普通聊天记录写入、resume、用户 Hook/MCP 自动继承路径。
- 不挂载真实工作区、完整 HOME、宿主 socket、生产凭据或其他租户资源；依赖镜像和测试端点由平台维护，不能用宿主本地执行作为隔离失败的备用方案。
- 默认网络拒绝，按模型与测试资源白名单开放；仅给临时、最小权限的测试凭据，不将凭据写进快照或报告。
- 独立采集器记录根/子任务身份、实际工具调用、文件清单和证据覆盖；根 result/idle 不等于全部子任务结束，需结束屏障后冻结实际文件。按锁定 SDK 验证事件能力，不把普通会话的兼容性回退当完整审计。
- 同用例的主任务/subagent 可共享本用例沙箱，均受同一权限上限和累计预算约束；不宣称 subagent 自动拥有独立操作系统沙箱。不默认强制委派、固定顺序或子任务数量。
- 由宿主受控采集器保存脱敏的输出、工具事件、预算统计、产物摘要与断言证据。禁止直接信任候选提供的路径读取宿主文件，产物需防越界、防符号链接并限制体积。
- 成功、失败、取消、超时都先固化已有证据和清理状态，再清理临时资源；worker 崩溃通过租约与孤儿回收处理。清理未完成必须显示运维异常，不能假装资源已释放。
- 沿用主方案的预算建议：每用例 120 秒、20 轮、20,000 输出 token；一次最多 20 用例；实例并发 2、租户并发 1。都是待实施验证的默认值。

同一输入可能因模型与服务变化出现波动。首期每用例执行一次，清晰标记样本数；建议的两次 AI 评审读取同一份证据，不是重复执行 Skill；后续支持预设重复次数、稳定性统计及无 Skill 基线，不通过无限重试筛选一次成功。重试生成新记录，不能抹去失败历史或任意挑选较早的通过结果发布。

## 7. 报告状态与发布资格

三个概念分离：

| 层次 | 示例 | 含义 |
| --- | --- | --- |
| 任务生命周期 | queued / running / completed / error / cancelled | 流程是否结束；completed 不等于通过 |
| 阶段／用例事实 | 静态 1 个阻断；动态 4 通过、1 失败、1 环境异常 | 当次实际检查和运行的结果 |
| 当前发布资格 | eligible / blocked / pending / obsolete / unevaluated | 这份报告现在能否用于该候选发布 |

资格判断顺序：无匹配完整报告为 unevaluated；绑定失配/过期为 obsolete；运行或风险复核未完成为 pending；完整报告存在失败、异常、必需检查未覆盖等为 blocked；其余满足全部规则才为 eligible。多原因一并返回，不能只暴露第一个失败项。

`eligible` 还必须满足：无静态确定性阻断或未解决高风险；所有必需静态检查完成；至少一条有效必跑动态用例且必跑全部通过；无观测到的安全违规；候选、当前提交、预期远端更新时间、用例集、测试依赖、平台策略、静态规则/检测器、运行镜像、执行器和模型配置与本次绑定一致；报告在有效期内，未被更新运行取代。

必需规则须全部通过，必需语义项须全部满足，不能有 inconclusive/error/未覆盖。rubric、判定模型/模板/参数、证据提取器和校准配置固定为内部摘要，并纳入资格失效核验。没有语义项的纯确定性用例不强制调用 AI；以开放式内容质量为核心的用例不能只用文件存在冒充任务质量已覆盖。

以上仅表示测评条件满足，发布服务仍检查负责人身份、远端状态与发布事务条件。静态提示不会被成功率抵消，必跑失败也不会被 LLM 高分抵消。

报告终态事实不可变；后来内容改变或策略更新，应显示“当时通过／当前已失效”，而不是把历史 passed 改成 failed。外部发布的当前内容“未测评”是无记录事实，不是失败；后补测评不能倒推发布前通过。

## 8. 可视化与交互设计

### 8.1 页面归属

在“我的技能 → Skill 详情 → 测评”中，分为“测评报告”和“测试用例”两个工作区；报告内部使用“总览／静态检查／动态测评”视角。运行、历史报告选择、候选信息放在报告头部；用例生成、编辑、负责人确认放在用例工作区，避免报告页混入大量表单。

贡献详情引用同一候选报告组件，发布前由负责人配置用例并发起正式测评。技能市场详情改为“概览／测评／管理”三个 Tab；其中测评只读展示发布时关联的负责人报告，包含总体结论、静态检查和逐用例结果，而非只有摘要徽章。完整私有用例、输入、轨迹、测试数据需额外权限，不能因 Skill 公开而公开租户测试数据。市场接口返回脱敏结果投影，不包含秘密、内部路径或未发布内容；市场页不提供配置用例和执行按钮。

### 8.2 总览：先回答能否发布、卡在哪里

- 顶部状态：满足测评条件／暂不满足／进行中／已失效／未测评；列出具体原因及对应问题入口。
- 固定上下文：候选摘要、目标远端更新时间、用例集修订、静态规则版本、环境标识、开始时间和发起人。
- 静态：适用规则的完成覆盖、阻断数、待复核数、建议数；有问题的规则数和发现条数分开统计。
- 动态：全部必跑用例作为分母，显示通过、失败、异常、未执行数量及堆叠状态条；小规模逐用例结果直接可点选。
- 不展示默认五维雷达或综合质量总分。首期分组指标比来源不清的 85 分更容易追溯和决策。

### 8.3 静态视角：问题 → 文件证据

按阻断、待复核、建议呈现问题列表，显示规则 ID、检测器、文件和行号。点击后展示被测快照中的只读片段、风险原因与修复建议，并展示“适用且完成／不适用／未覆盖”规则清单。

“定位编辑”必须检查当前文件是否仍与快照匹配；不匹配时先看快照，不把旧行号当成当前行号。报告不提供自动执行命令或一键覆盖文件操作。误报复核在授权入口单独完成。

### 8.4 动态视角：用例 → 断言 → 轨迹

左侧用例列表，右侧详情；小屏上下排列。详情包含“验收结果／执行过程／产物”：逐项显示规则或 AI 判定、必需属性、预期与实际、满足/不满足/无法确定及证据定位；AI 项可展开 rubric、两次结论及分歧。执行过程呈现根任务—subagent—工具树；产物预览显示真实内容和解析覆盖。执行与 AI 判定成本分开，市场接口不泄露私有 rubric/引用内容。

工具轨迹借鉴会话页样式，但不提供继续对话、批准生产权限、编辑真实文件或重新执行某个工具的按钮。可以后续增加“用此用例调试”：重新创建一次临时调试，不恢复原运行，不把调试输出自动存成正式报告。

### 8.5 当前内容与测评记录

撤回版本对比矩阵、已发布 vN 与草稿对比，以及历史版本重跑入口。报告只展示本次被测内容的结果；历史测评记录按执行时间区分，不展示 Skill 版本号，不提供恢复历史 Skill 操作。

当前内容摘要、用例或策略与报告绑定不一致时，显示“本次报告不适用于当前内容”；保留报告事实和受控证据，不将旧报告改成失败。仅市场更新时间变化用于导入待更新判断；报告适用性仍核验完整内容，不能将这两个判断混用。

本次不自动用“报告对比”替代已撤回的版本对比需求。后续如需要比较不同测评运行，再单独确认范围和相同执行条件要求。

### 8.6 指标口径

- 必跑通过率 = 通过的必跑数 / 全部必跑数；未执行、异常、超时不从分母剔除。零用例显示“无有效用例”，不是 100%。
- 执行完成率与通过率分开；optional 用例独立统计，不用可选成功稀释必跑失败。
- 资源消耗包含失败和异常的实际花费；均值注明样本范围；未知 token 或价格显示未知，不填 0。不比较不同口径的耗时。
- 没做触发路由就显示“未覆盖”，没有安全发现写“本次未发现”，不写“绝对安全”。
- 状态同时有文字与颜色；键盘可选择问题／用例，移动端堆叠；不依赖 hover 才能看到证据。

## 9. 数据与接口增量

沿用无版本主方案的 Skill、当前候选、贡献与任务对象；内部内容摘要和只读任务副本用于防止测评对象漂移，不构成 Skill 历史版本。

| 对象 | 本次增量 |
| --- | --- |
| `skill_eval_runs` | scope、阶段状态、租约、请求/幂等键、配置指纹、覆盖摘要、当前聚合；终态报告不可变 |
| `skill_static_findings` | 原始发现、规则与位置、脱敏证据；复核另存追加审计，不覆盖原发现 |
| `skill_eval_case_runs` | 每用例/尝试的状态、实际输出、断言 JSON、轨迹/产物引用、token/耗时、错误类别 |
| `skill_eval_agents/events/artifacts/assertions/judge_attempts`（逻辑分表） | 任务树、真实事件、安全文件清单、逐项结论、两次 AI 判定及引用；实际表名与约束见执行判定详细方案 §12 |
| `skill_test_suites` / `skill_test_cases` | 稳定 caseId、当前定义、ETag/变更戳、创建者/确认者、不可撤销发布保护；运行固定定义另存任务证据，不建 Skill 版本 |
| `skill_eval_case_drafts` | 独立 AI/手工/修改草稿、来源摘要、待补齐项、生成状态及原定义摘要；逐条确认，不批量覆盖生效集合 |

所有对象携带 tenantId 并按候选/当前 Skill/报告访问权过滤；不能仅凭 evalRunId 授权。大体积证据放受控存储，DB 保存引用、摘要与大小。不得使用聊天 session/message 表保存测评。

建议接口均位于 `/api/skill-governance`：

- `POST /evaluations`：传入授权 candidateId，冻结执行配置并创建任务；首期正式发布只接受 full，局部自检必须明确标注；服务端限制并发、权限和幂等。
- `GET /evaluations/:id`：报告与当前资格；`GET /evaluations/:id/findings`、`GET /evaluations/:id/cases/:caseRunId`：授权分页明细。
- `POST /evaluations/:id/cancel`：按任务管理权限显式取消，不能取消他人租户任务。
- `POST /skills/:id/test-case-drafts`：追加草稿；`PATCH /skills/:id/test-case-drafts/:draftId`：编辑；`POST /skills/:id/test-case-drafts/:draftId/confirm`：负责人逐条核对确认，带 If-Match。
- `DELETE /skills/:id/test-case-drafts/:draftId`：删除草稿；`DELETE /skills/:id/test-cases/:caseId`：确认删除未发布生效用例，受保护项永久拒绝；检查权限、并发和运行互斥。

生成草稿和启动测评均需限额；沿用已确认角色，正式用例维护和发布用联合测评仅由当前负责人操作。其他成员的单次调试/局部自检不能替代负责人测评，也不能删除或减少受保护用例。PR 评审不能暴露未授权的原始测试资源。

事件传输可复用 WebSocket 基础设施，但用独立授权的 `eval.*` 通道；数据库任务状态为准，事件只通知增量。断线、进程重启、重复投递不得重复发布或伪造完成。

报告保留策略：测评事实、发布操作与贡献审计必须可追溯；原始大日志和产物可配置保留期，清理后显示“证据已过保留期”，不能伪装完整报告。摘要、断言结论、内容与配置摘要、审计记录继续保留。到期策略和存储限额需部署确认。

## 10. 实施顺序

1. 能力验证：固定可用模型、临时容器/网络策略、测试依赖、完整快照和证据存储；验证所有旧发布入口能收口。缺少隔离能力时暂停开放门禁发布。
2. 统一任务与静态检查：SQLite 任务状态、规则结果格式、覆盖清单、安全扫描适配器验证；先交付可定位问题的静态报告。
3. 用例管理：AI 草稿、负责人确认、受控测试资源、声明式断言与正式用例修订。
4. 动态执行与联合判定：临时 worker、完整任务树/文件采集、规则器、AI rubric 与双评审校准、证据脱敏、限额、取消/超时/崩溃回收。
5. 报告与联合门禁：结果页、授权的只读轨迹与当前内容适用性提示；纳管 Skill 的所有 CCUI 发布路径统一校验，之后才开放发布。
6. 后续迭代：路由测评、重复运行稳定性、无 Skill 对照、多模态/视觉质量验收与人工确认的 Badcase 回归。AI 语义硬门禁已纳入首期，不再作为未来待决定功能。

skill-creator、Promptfoo 等作为格式、判定器或评测方法参考，不要求首期引入完整平台。可通过适配器扩展，不能把它们的命令行输出直接当多租户发布授权。[Promptfoo Skill 测评指南](https://www.promptfoo.dev/docs/guides/test-agent-skills/)

## 11. 必须覆盖的验收场景

- 静态错误阻断动态；规则崩溃、不支持语言、超时明确显示未完成；无用例不通过。
- 非 JSON、多交付物、可选 subagent 能正常验收；根任务提前结束不提前判分，子任务违规不得漏检。
- AI 必需项两次满足才通过；不满足、分歧、无法确定、无效引用和服务故障都不放行，且区分业务失败与系统问题。
- 4 通过、1 失败、1 环境错误时，显示 4/6，通过率不变成 4/5；环境异常不归因成业务答案错误。
- 必跑断言失败、取消、超时、最新重试失败均不能拿旧通过发布；候选/用例/策略变化使资格失效，但保留历史事实。
- 跨租户 ID、恶意产物路径、秘密回显、判定器提示注入、包内插件、任意外网请求不能越过权限与隔离。
- worker 崩溃不遗留可无限运行容器；清理失败有可见状态与重试，不能破坏报告或用户文件。
- 贡献者不能减少权威用例或回写结论；市场页面不泄露私有 prompt、fixture、日志；只读报告不触发聊天副作用。
- 不出现 Skill 版本号、历史版本入口或版本对比；当前市场内容缺少适用报告显示“未测评”，内容已变更不能沿用旧通过标识。
- 页面离开后测评继续，重连后能恢复；调试不会因复用展示组件而开始保存聊天或执行历史。
- 320/360/736/1024 宽度、浅色/深色、键盘操作可用；颜色不是唯一状态提示，长路径/JSON 不导致页面溢出。
