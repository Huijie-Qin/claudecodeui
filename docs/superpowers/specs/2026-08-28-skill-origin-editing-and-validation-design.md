# Skill 来源、编辑与校验设计

日期：2026-08-28
状态：已确认

## 背景

当前实现将“从技能市场导入”和“本地技能已发布”都记录在同一份市场导入元数据中，并通过“是否存在市场记录”反推技能来源。这会产生以下问题：

- 本地创建或上传的技能发布后被误判为“市场安装”，失去编辑权限。
- 上传技能同时保留托管源目录；发布后第一次移除只删除运行目录和市场记录，托管源又将技能恢复为本地技能，因此需要第二次移除。
- 上传流程会把 `SKILL.md.name` 转为小写，导致目录大小写与脚本引用不一致。
- 解析失败只显示笼统标签，无法诊断入口位置、frontmatter 或目录名称问题。
- 市场导入技能不可本地编辑，无法支持本地定制以及后续共创、提 PR 等演进方向。

## 目标

1. 将技能来源、远端绑定、本地安装和本地修改拆成独立状态。
2. 本地技能发布后继续保持“本地创建”，并追加“已导入”。
3. 所有“我的技能”均可在当前工作区本地编辑。
4. 一次移除彻底删除本地副本，但保留远端绑定与作者关系。
5. 目录名称与根目录 `SKILL.md.name` 严格保持大小写一致，并提供可恢复的自动重命名交互。
6. 解析失败能够同时展示多个明确诊断。
7. 防止不区分大小写的重复技能名称。

## 非目标

- 本次不实现技能共创、fork 或提 PR。
- 非创建者对市场技能的本地修改不会发布到原市场技能。
- 本地移除不会删除技能市场中的远端版本。
- 子目录中的 `SKILL.md` 不会被兼容为合法技能入口。

## 状态模型

不再使用单一 `imported` 状态表达所有关系，而是拆分为：

| 状态 | 值 | 含义 |
| --- | --- | --- |
| `origin` | `local` / `market` | 技能最初来自本地新建/上传，还是技能市场 |
| `bindingType` | `published` / `imported` | 远端绑定由本地发布产生，还是由市场导入产生 |
| `installed` | boolean | 当前工作区是否存在本地可用副本 |
| `baselineHash` | string / null | 最近一次导入、更新或发布时的内容摘要 |
| `locallyModified` | boolean | 当前文件摘要是否与 `baselineHash` 不同 |

`origin` 是稳定来源，不会因为发布、移除或重新导入而隐式改变。`installed` 由实际本地状态决定。远端绑定保留远端技能 ID、创建者、版本和绑定类型。

### 典型状态

| 场景 | origin | bindingType | installed | 页面标签 |
| --- | --- | --- | --- | --- |
| 本地新建或上传，未发布 | local | 无 | true | 本地创建 |
| 本地技能已发布 | local | published | true | 本地创建、已导入 |
| 已发布本地技能被移除 | local | published | false | 不出现在我的技能；市场中可导入 |
| 从市场导入 | market | imported | true | 市场安装 |
| 市场技能被本地编辑 | market | imported | true | 市场安装、本地已修改 |

## 数据持久化与兼容

现有 `workspace_skill_market_imports` 表继续作为工作区与远端技能的绑定表，增量增加绑定类型和基线摘要字段。启动迁移只增加字段，不重建表、不删除记录。

新建和上传流程需要记录明确的本地来源。对于既有数据：

- `metadata.json` 中 `sourceType=local-upload` 的技能识别为本地来源。
- 既有本地新建并发布、但没有显式来源的技能，结合本地目录、远端创建者和当前账号进行兼容识别。
- 在下一次编辑、发布或重新导入时补齐明确来源，避免长期依赖推断。
- 初次迁移将当前内容摘要作为基线，避免全部旧技能被误标为“本地已修改”。

## 发布、导入、更新与移除

### 本地发布

- 发布成功后写入或更新 `bindingType=published`。
- 保持 `origin=local` 和编辑权限。
- 保存远端技能 ID、创建者、版本和内容基线。
- 页面显示“本地创建”与“已导入”。

### 市场导入

- 新导入写入 `origin=market`、`bindingType=imported` 和内容基线。
- 如果工作区保留的是原创建者的 `published` 绑定，重新导入不得将绑定降级为 `imported`。
- 导入后原创建者仍可执行“发布更新”。

### 本地编辑

- 所有“我的技能”都允许文件内容编辑、新建、上传、重命名和移除文件。
- 市场技能的编辑仅保存到当前工作区，不自动写回市场。
- 文件树摘要与基线不一致时显示“本地已修改”。
- 非创建者不显示原市场技能的发布更新入口。

### 市场更新

- 未发生本地修改时可直接更新。
- 存在本地修改时，后端返回结构化覆盖确认状态，前端使用项目统一弹窗说明更新将覆盖本地内容。
- 只有明确确认后才覆盖；成功后刷新基线并清除“本地已修改”。

### 本地移除

- “我的技能”中的移除统一为一次完整本地移除。
- 删除运行目录、上传托管源目录及本地管理元数据。
- 保留远端绑定、作者和远端技能 ID。
- 不删除技能市场的远端版本。
- 移除后技能从“我的技能”消失，在市场中显示“可导入”。

## 名称和目录一致性

### 基本规则

- 合法入口固定为 `.claude/skills/<name>/SKILL.md`。
- 目录 basename 必须与根目录 `SKILL.md` frontmatter 的 `name` 完全一致，包括大小写。
- 上传流程不再执行 `toLowerCase()`，按 manifest name 原样创建目录。
- 重名校验不区分大小写，因此 `Foo` 与 `foo` 视为同名。
- 新建、上传、编辑和自动重命名由后端复用同一套重名规则。

### 页面修改 manifest name

当保存后的 manifest name 与当前目录不一致时：

1. 后端返回 `SKILL_DIRECTORY_RENAME_REQUIRED`，包含当前目录名和目标名称。
2. 前端使用统一确认弹窗询问是否同步重命名目录。
3. 选择自动重命名时，先执行不区分大小写的重名检查。
4. 使用临时目录完成纯大小写重命名，并同步更新运行目录、托管源、技能元数据和市场绑定中的本地名称。
5. 迁移应具备回滚能力，避免出现一半成功的状态。
6. 用户拒绝自动重命名时仍保存 manifest，技能随后显示解析失败。
7. 如果目标名称与现有技能重复，则始终禁止保存或重命名，不允许覆盖。

## 解析与诊断

解析结果从单个 `parseError` 扩展为可组合的诊断列表。页面只显示一个“解析失败”标签，鼠标悬浮后逐条展示全部原因。

诊断至少覆盖：

- 根目录缺少 `SKILL.md`。
- 在子目录检测到一个或多个 `SKILL.md`，并展示相对路径。
- manifest name 与技能目录名不一致。
- frontmatter 缺少 name 或 description。
- YAML/frontmatter 无法解析。

如果根目录缺少入口，子目录中的 `SKILL.md` 仅用于提供诊断路径和可能的名称问题，不会作为有效入口。文件树仍可查看和编辑，方便用户修复；修复前禁止发布、发布更新以及正常 Agent 调用。

## 页面行为

### 标签

- 本地未发布：`本地创建`
- 本地已发布：`本地创建`、`已导入`
- 市场导入：`市场安装`
- 市场技能本地修改：追加 `本地已修改`
- 有远端更新：追加 `待更新`
- 解析异常：追加单个 `解析失败`，悬浮展示诊断列表

### 发布按钮

- 本地未发布：绿色“发布”。
- 本地已发布且当前用户为创建者：“发布更新”。
- 市场导入且当前用户不是创建者：不显示发布按钮。
- 市场导入且当前用户是创建者：允许“发布更新”。
- 解析失败时禁用发布，并展示原因。

### 编辑权限

编辑权限与来源解耦。“我的技能”中的本地技能、已发布本地技能、市场导入技能和解析失败技能都可以进入文件树进行本地修复或定制。

## API 与错误语义

后端继续作为状态和冲突判断的权威来源。新增或标准化以下错误码：

- `SKILL_DIRECTORY_RENAME_REQUIRED`：需要用户决定是否同步重命名目录。
- `SKILL_NAME_CONFLICT`：存在不区分大小写的同名技能。
- `SKILL_LOCAL_CHANGES`：市场更新会覆盖本地修改，需要显式确认。
- `SKILL_MANIFEST_INVALID`：返回结构化诊断列表。

前端不根据错误文案做字符串匹配，而是根据错误码打开对应的项目样式弹窗。

## 测试策略

服务端覆盖：

- 本地新建和上传发布后保持本地来源。
- 两类本地技能发布后都只需一次移除。
- 移除后绑定保留、市场显示可导入，重新导入后创建者仍能发布更新。
- 上传保留 manifest name 大小写。
- 根入口缺失、嵌套入口、名称不一致和 frontmatter 错误可组合诊断。
- 新建、上传、编辑、重命名均执行不区分大小写的重名校验。
- 自动重命名确认、拒绝、纯大小写变更和失败回滚。
- 市场技能允许本地编辑；内容摘要变化后标记本地修改。
- 市场更新在存在本地修改时需要显式覆盖参数。

前端覆盖：

- “本地创建 + 已导入”“市场安装 + 本地已修改”等标签组合。
- 解析失败悬浮层展示多条诊断。
- 自动重命名和覆盖本地修改使用项目统一弹窗。
- 不同创建者和解析状态下发布按钮的显示、禁用与文案。
- 一次移除后的列表和详情刷新。

完整验证包含服务端测试、前端测试、类型检查、ESLint 和生产构建。

## 风险控制

- 目录重命名是跨运行目录、托管源和元数据的多步骤操作，必须使用临时路径和补偿回滚。
- 市场更新不得在缺少显式确认时覆盖本地修改。
- 大小写重名检查必须在 macOS、Linux 和数据库查询中保持一致。
- 历史来源推断只用于兼容；任何后续写操作都应固化显式来源。
