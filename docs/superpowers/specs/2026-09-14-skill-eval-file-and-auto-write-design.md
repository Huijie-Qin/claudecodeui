# 技能市场：文件化用例、串行测评与自动落盘优化

日期：2026-09-14。状态：目标设计与离线交互原型，非后端已实现能力。

本文落实本次六项调整及后续修订（用例路径统一 evals/evals.json、按钮同排左对齐、后台串行留在测评页），替代旧方案的「用例草稿确认」「候选待采用」「仅负责人可发布」规则。Skill 仍无版本与历史版本；本次运行中的文件快照只用于一致性检查与差异展示。

## 1. 页面与角色

### 1.1 模板和片段

- 模板中心、片段管理均在技能区域可见，片段管理位于模板中心右侧。
- 普通用户可查看模板说明、自定义字段、默认值、预置片段正文；可使用模板，但不能新增、编辑或删除模板。
- 普通用户可查看、搜索及快捷插入公共片段，不能维护片段库。全平台片段由系统管理员维护；模板维护沿用管理员授权与租户范围。
- 模板、片段的只读是「不能修改库定义」，不限制使用模板创建自己的 Skill 或修改已复制到自己 Skill 的正文。
- Skill 管理员不等于系统/租户管理员，也不会因此获得模板或片段维护权。

### 1.2 技能生成入口

我的技能“新建技能”提供直接创建/模板创建下拉。前者保持现有填写弹窗；后者先复用会话“技能生成”的模板选择弹框，选定后进入会话填写，取消保持原页面。模板弹框与模板中心支持名称/描述搜索，片段管理支持名称/说明/正文搜索，关键词互不串用，提供清空及空结果反馈。

会话输入框底部与命令、其他能力、发送按钮同一排放置「技能生成」。不再另起一行「添加能力」。

选择模板后，在同一输入区展示模板名称、Skill 显示名称、文件标识（对应 frontmatter name，用户必填）、模板自定义字段；普通消息输入框 placeholder 切换为「请输入额外补充信息…」。未选择模板时保持原会话 placeholder。

发送后：CCUI 固定模板、预置正文与输入 → 独立环境调用 skill-creator → 检查文件与 evals/evals.json → 写入 Workspace/.claude/skills/<name>/ → 我的技能立即可见。无需确认保存或验收生成结果。同名目录不覆盖；生成失败不写入半成品。生成后继续在普通会话微调或 /skill-name 调用，不新增试用模式或调试页。

模板预置正文继续有效；片段库可作为授权参考供 creator 按需匹配，不给普通用户额外的片段选择/确认负担。生成结果为自包含正文，不建立动态引用。取消模板不会发送任何生成任务。

## 2. evals/evals.json：唯一用例定义来源

### 2.1 来源与项目差异

核对依据：

- [上游 skill-creator 主说明](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)中的用例生成示例。
- [上游 schemas.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/references/schemas.md)中的 evals.json 定义及 grading.json 结果格式。
- 当前仓库 [server/skills/skill-creator/SKILL.md](../../../server/skills/skill-creator/SKILL.md) 是精简的顶层 Agent 技能生成器，目前没有 eval 文件生成规范，后续需补充契约，不宣称已经接入。

本项目与上游统一使用 **每个 Skill 目录下的 evals/evals.json**，沿用同一数据结构。files 中的相对路径仍以 Skill 根目录为基准，不以 evals 目录为基准。运行方式按本产品要求串行执行，不照搬上游并行调度。旧根目录 eval.json 不再作为写入或读取目标，生产迁移应在校验后移动旧定义，避免两套真源。

### 2.2 标准示例

文件：.claude/skills/sales-summary/evals/evals.json

```json
{
  "skill_name": "sales-summary",
  "evals": [
    {
      "id": 1,
      "prompt": "读取所附订单，按币种统计净销售额并生成 Markdown 报告。",
      "expected_output": "报告可读取；CNY 净销售额为 90，USD 为 20，不混合币种；说明退款计算口径。",
      "files": ["evals/files/orders.csv"],
      "expectations": [
        "输出报告包含 CNY 90 和 USD 20",
        "未把不同币种直接相加",
        "生成文件可读取，最终答复提供文件位置"
      ]
    },
    {
      "id": 2,
      "prompt": "没有提供订单数据，请生成本月销售分析。",
      "expected_output": "说明缺少数据，提出需要补充的信息；不能捏造订单或销售结论。",
      "files": [],
      "expectations": ["明确说明缺少输入", "没有捏造销售数据"]
    }
  ]
}
```

示例输入文件 orders.csv 内容为：

```csv
currency,sales,refund
CNY,100,10
USD,20,0
```

| 字段 | CCUI 校验与语义 |
| --- | --- |
| skill_name | 字符串，与 SKILL.md frontmatter name 一致 |
| evals | 有序数组；顺序就是串行执行顺序；可为空，但空集合不能给出通过或允许直接发布 |
| id | Skill 内唯一正整数，新增由服务端分配；不按行号重排或复用已发布身份 |
| prompt | 非空用户请求，作为执行 Agent 的任务输入 |
| expected_output | 非空、可理解的预期结果描述，可包含参考输出；不是要求逐字相等 |
| files | 可选字符串数组；相对 Skill 根目录，输入资料必须已存在、已授权且能安全复制 |
| expectations | 可选字符串数组；每条为可验证要点；没有时仍依据 expected_output 判定 |

UI 用 prompt 摘要作为用例名称，不擅自增加 title、status、confirmed、draft、actual_output、runId 等字段到 evals/evals.json。后台审计、来源、调用ID、防重复键、发布保护登记与结果在 CCUI 元数据/报告区保存，不另存第二套可编辑用例定义。已存在旧用例要做显式迁移，不能在读取时生成另一套事实来源。

目录的所有用例——模板生成、会话保存、手工添加、AI 生成、从市场导入——最终都写入该目录同一个 evals/evals.json。不同用户的本地副本仍是不同物理工作区副本，不会写到负责人目录或隐式合并个人数据库用例。

## 3. 添加、编辑、删除与会话保存

- 「添加验证场景」下拉只包含「AI准备场景」「添加场景」。
- 手工表单填写输入和预期，可选填写检查要点、输入文件；点击「保存用例」后格式校验并立即落盘，不再出现第二次确认。
- AI 读取当前 Skill、已有用例及授权业务材料，生成符合相同 schema 的新增用例；校验后追加并保存，不替换整套用例、不要求确认草稿。格式错误可有限重试，仍失败时展示原因，不写入无效 JSON。
- AI 无法推断关键业务标准时可以请求补充信息，不能悄悄编造标准或标为已验证。保存的 AI 预期是可修改的测试定义，不代表经人类认证的真值。
- 普通会话完整调用结束后，用户点击「保存为测评用例」，从服务端绑定的 executionId 获取 query、最终输出、工具/subagent/产物。生成 prompt、expected_output、expectations，必要附件复制到 evals/files/ 后与 evals/evals.json 一并提交。直接保存，不再确认验收标准。重复点击同一调用幂等。
- 原输出作为语义参考，不要求句式、布局、token 或工具轨迹完全相同。不把生产会话/凭据直接带入测评环境。
- 所有本地有编辑权限的人可维护自己的 evals/evals.json。曾发布用例永久不可删除的旧约束保留，适用于表格删除、源码保存、文件删除、发布和贡献合并；发布保护不靠可伪造的 JSON 字段。
- 允许修改预期但立即使旧结果失效，AI 优化任务禁止修改用例。曾发布 id 改号视为删除；不能通过整体替换文件绕过检查。源码格式错误拒绝保存并定位；外部编辑造成的格式错误展示修复提示，不导致页面崩溃。
- 写入使用权限检查、文件摘要/If-Match、锁、临时文件和原子替换。运行期间 UI 及 API 暂停同目录用例修改，外部修改则使任务失效。添加无需确认不等于省略格式、安全与并发校验。

## 4. 运行全部：一次完整串行测评

1. 校验当前用户本地编辑权限、用例格式与输入资源；冻结 Skill 文件、evals/evals.json、测试策略、模型、环境和输入摘要。
2. 静态检查包结构、name/description、路径与符号链接、资源存在性、敏感内容、安全边界。确定性阻断直接失败，无执行的用例标为未运行。
3. 按 evals 数组顺序执行：第 1 条执行 → 等主任务、工具和所有 subagent 终态 → 收集产物及证据 → 规则与独立 AI 判定完成 → 回收该用例环境 → 第 2 条。任意时刻同一任务只有一个用例处于执行/判定阶段，不并行发起全部用例。
4. 单条业务失败继续下一条；单条执行/评分异常记录 error 后可继续。任务级安全事件、取消、目录冲突、全局环境不可用终止任务，剩余用例为 not_run，不能当通过。
5. 保存所有用例与预期的对比，在当前测评页更新表格进度。运行全部不修改 Skill，也不发布。即便上一份报告通过，本次失败/中断也不能回退到旧报告宣称通过。
6. 无有效用例、无法确定、执行异常或未运行，都不能合成全通过。汇总采用总用例数作为分母，不隐藏失败用例。

这里的串行指不同用例；单个 Skill 内部正常的 subagent 协作可保留，但受该用例隔离、资源和结束判定约束。

## 5. 实际结果如何与预期比较

### 5.1 执行与评分职责分离

- 被测执行 Agent：只拿 prompt、授权测试输入、清洁 Skill 与工具策略，不拿 expected_output、expectations 或答案。虽然 evals/evals.json 在源目录内，Runner 必须构建执行投影并移除该文件及答案资料，不能把整个工作区原样挂载给被测 Agent。
- 证据收集器：等待完整任务树结束，封存最终文字、工具名称/入参/结果、子任务状态、产物清单与可读内容、异常/耗时。
- 规则评分器：检查可确定要求，例如文件存在、数值计算、必需列、schema、安全违规。规则来自平台策略或冻结的用例计划，不能由 Skill 输出任意可执行脚本。
- 独立 AI 评审：新建隔离评分上下文/一次无工具模型请求，读取固定预期和只读证据，逐项返回满足/不满足/无法确定及证据定位。不复用被测 Agent 自评；模型调用不必等于新建常驻容器。
- 优化 Agent：可看固定预期与实际证据来定位问题，不能修改用例、评分器、安全策略，也不能自行设置 passed。

文字按事实与业务语义；工具按授权、参数与结果；subagent 按完整任务交付与必要约束；文件按存在、内容、可读取性和明确格式验收。只有用例明确指定工具或格式才要求完全符合；不因实现路径不同而无故失败。二进制/超长文件解析不完整时标明证据覆盖范围，无法验证不能假装通过。

评分结果可沿用上游 grading.json 的 expectations（text/passed/evidence）与 summary 结构；CCUI 在**报告外层**增加状态、证据引用、执行/评分错误、内容指纹等信息。不要把 error/uncertain 压成 false 后丢失原因，也不要回写到用例文件。

### 5.2 可信度边界

自动生成预期和自动评审可能共享偏差。减少人工干预不意味着有限用例通过就证明 Skill 在所有任务上可靠。规则能判断的不用模型猜；关键业务数值依赖可信测试数据。AI 评审输出必须有有效证据引用，无法判断应显式显示。隔离评审、固定预期、不让优化器改答案，是首期最小防护；盲测、重复采样和独立业务样本可作为后续增强，不在本次两遍流程中暗加验收或采用步骤。

## 6. 自动优化：完整前测 → 自动保存 → 完整复测

点击「自动优化」即授权在当前 Skill 的允许文件范围内自动修改，无额外启动确认或采用确认。

1. 固定本次输入并执行第一遍**全部**用例，不复用上次报告跳过前测。
2. 将前测每条实际输出、失败证据、原预期与当前 Skill 交给优化模型。先定位未满足的要求，再形成受限修改。
3. 校验路径、安全、name 不变、evals/evals.json/输入资料/评分策略未被更改，核对本地文件摘要。通过后原子写入当前 Workspace 的 Skill 文件；此时改动已经落盘。
4. 写入后立即将旧报告标为不适用于当前内容；保留本次修改前后的文件快照供 Diff 查看。
5. 用第一遍冻结的**同一批用例、顺序、输入、策略和环境配置**，串行再跑一次全部用例。新的执行环境不能复用前一次遗留文件。
6. 保存 beforeRunId、afterRunId 与逐例对比，结束任务。不增加采用、确认改动、自动发布或无限重试循环。用户需要进一步优化时再次点击，开始新的完整两遍过程。

若模型判断无需修改，记录「无文件变更」，仍执行第二遍验证；Diff 显示无差异。优化器/格式校验失败则不写入，显示失败。后测失败或取消发生在写入后，保留实际已经保存的改动，明确显示「修改已保存，复测未通过/未完成」，不能悄悄回滚或假装仍在候选态。外部写入冲突则停止，不覆盖用户修改。

对路径改动、scripts 等可执行资源不能无限放权：首期自动修正限定本 Skill 的 Markdown/文档性资源，新增工具权限、执行脚本改造或任务目标更换需要单独授权。任何模型输出仍经过统一文件校验。该范围是安全实现默认值，不改变用户直接编辑 MD 的能力。

## 7. 结果可视化

测评保持一张表格，「运行全部」「自动优化」「添加验证场景」三个按钮同高、左对齐、固定间距，不分散到整行两端；窄屏空间不足时自然换行。运行中提供停止。文件已修改后仅增加「查看 Skill 修改对比」，没有采用按钮。

| 场景 | 表格和详情 |
| --- | --- |
| 尚未运行 | prompt 摘要、预期、未运行、编辑/删除 |
| 运行全部 | 用例、预期、运行结论；详情展示预期 + 实际 + 判断依据/工具/子任务/产物 |
| 自动优化运行中 | 当前阶段和串行进度；优化前、优化后两列，未执行项保留未运行 |
| 自动优化完成 | 每条同一预期下的前后输出、结论和失败原因；不只显示分数差 |
| 修改或用例变化 | 旧报告标记失效；旧详情显示当次固定预期，不能用新预期解释旧输出 |
| Skill 对比 | 本次操作修改前/后的多文件差异，只读；无历史版本入口 |
| 市场测评 | 当前发布包关联报告的只读公开部分；合并后或外部更新后无匹配报告显示未测评 |

从我的技能点击「运行全部」或「自动优化」后，留在当前测评页，后台串行执行，不创建或跳转会话，不清空现有会话输入。表格逐行更新等待/运行中/结论，每条用例末尾均提供「查看详情」，显示固定预期、实际输出及优化前后对比；可离开页面再返回查看进度。模板生成和普通 Skill 调用仍在既有会话中，不新增调试或试用模式。

### 7.1 完整会话式输出详情

- 运行全部：详情上方保留输入、当次固定预期和检查要点，下方单列展示该用例的完整可见消息序列，沿用真实会话的用户气泡、Claude 回复、Markdown、代码块、工具调用、子任务和文件展示形式，不用摘要替代模型输出。
- 自动优化：宽弹框内左列为优化前第一遍、右列为优化后第二遍。两列各自完整展示相同用例的消息序列和判定。默认顶部对齐，共用详情区域纵向滚动；窄屏保留左右列，局部横向滚动，不挤压成不可读的细列，也不改成上下对比。
- 工具显示名称、完整输入与返回；subagent 可展开查看其可见消息，产物显示路径与可访问内容。可折叠长工具记录，但不能截断或只存摘要。判定状态、原因和证据属于独立的「测评判定」区域，不能伪装为被测模型的回复。
- 运行器按序存储 messages/events（runId、caseId、phase、sequence、role/type、content、toolCallId、parentId、artifactRefs），聚合流式片段时保留顺序和内容；前后记录以各自 runId 和 phase 区分。详情复用项目 MessageComponent / Markdown / ToolRenderer 的只读展示能力，不创建新聊天会话。大内容可分页或按需读取，但必须能读到完整末尾，不使用长度裁剪。
- 「完整」限于运行器实际采集、当前用户有权查看且经必要脱敏的可见消息；不要求或伪造模型内部思维链。异常明确显示中断和已采集部分；未运行、原始输出未公开/未采集时显示明确空态，不拿评审摘要补成模型输出。市场继续遵守公开投影权限。
- 离线原型的 messages、工具及子任务内容均为预设演示；完整展示演示记录并不代表已经接入真实运行器。

## 8. 发布、贡献与共享边界

- 负责人和指定 Skill 管理员均可直接发布；该发布人须亲自发起当前内容完整测评并通过，发布时重新校验实时权限、输入摘要、适用报告和远端更新时间。
- 非发布角色的本地测评不自动获得发布资格；对自己的副本优化和新增用例不影响远端。
- 贡献提交、Approve 与合并仍无测评模块或门禁。至少一位有效非作者认可后，负责人或技能管理员可合并；负责人可直接合并。文件变化后旧认可失效，作者无论角色都不能自我认可。
- 合并就是立即更新发布内容，检查路径/格式/保护项及冲突，不强制跑动态测评。成功清空当前市场适用报告标记，显示「未测评」。
- evals/evals.json 是 Skill 文件的一部分，随发布/贡献包保存与导入。不能同时声称其预期是市场不可见的私有标准。用例输入和预期须适合共享，不能包含真实客户信息、生产凭据、私人会话全文；发布前检查敏感信息。
- 原始执行报告、完整轨迹、前后 Diff 留在受权 CCUI 报告区，不默认随包分发。市场报告只发布允许公开的投影。模板与全平台片段同样禁止敏感数据。
- 其他渠道仍可直接发布，远端无 CAS/幂等保证时 CCUI 只能冲突预检、发起发布、回读比对并标为成功/失败/待核实，不能承诺跨客户端原子一致性。

## 9. 实现切分与验收

后续实现：

1. EvalFileService：schema、附件、原子读写、保护登记、并发摘要；文件编辑与可视化表单都走它。
2. SkillGovernanceService：owner、administratorIds、授权变更审计；发布/合并重新鉴权，普通系统管理员不绕过。
3. EvaluationOrchestrator：串行持久队列、输入冻结、每例隔离、取消/恢复、结果封存。
4. EvidenceCollector + RuleGrader + AIJudge：结果证据、确定性断言、独立语义评审。
5. OptimizationCoordinator：前测、模型修改、校验落盘、后测、Diff；不再提供 adopt 接口。
6. CreatorAdapter：补充当前精简版 skill-creator 契约，兼容上游 schema，输出evals/evals.json；模板/会话入口复用同一生成任务。

必须验收：普通用户看到库但不能维护；管理员授权/撤销及禁止自我认可；所有新增路径均落到根文件且无确认；源码与表格一致；串行顺序；单例失败仍跑完；空用例/异常不通过；第一遍全跑后才写入，第二遍在写入后；用例不被优化器修改；前后输出与同一预期对应；失败/取消后真实文件状态提示；无采用按钮；文件冲突不覆盖；发布权限与报告绑定；已发布用例不可通过删文件或贡献绕过。
