# 技能市场导入名称冲突与目录避让设计

日期：2026-08-31  
状态：已确认

## 背景

技能市场当前会在列表和详情中展示“冲突”标签，并在检测到本地同名目录时禁用导入。目录占用与技能名称重复实际上是两类不同问题：目录占用可以安全地通过选择其他目录解决，但两个技能拥有相同的 `SKILL.md.name` 会给调用、展示和后续管理带来歧义，必须阻止导入。

## 目标

1. 技能市场不再展示“冲突”标签，也不因预计算的 `conflict` 状态禁用导入按钮。
2. 导入时以根目录 `SKILL.md` 的 `name` 作为技能名称的权威来源。
3. 工作区已存在同名技能时拒绝导入，并通过项目样式弹窗明确提示用户。
4. 技能名称不重复、但目标目录被占用时，自动选择带数字后缀的空闲目录。
5. 保留远端技能的原始 `SKILL.md.name`，包括中文名称和原始大小写。
6. 任何失败都不得覆盖或删除现有技能目录。

## 非目标

- 不修改已存在技能的名称或目录。
- 不自动为重复的技能名称添加后缀。
- 不修改市场远端内容。
- 不改变更新、移除、发布和本地修改检测的业务语义。

## 名称与目录规则

### 技能名称

- 权威名称来自待导入包根目录 `SKILL.md` frontmatter 的 `name` 字段。
- `name` 必须是非空字符串；去除首尾空白后用于校验，但写入本地的 `SKILL.md` 内容保持原样。
- 名称允许中文及其他 Unicode 字符，不执行 ASCII 化、拼音化或 `toLowerCase()` 写回。
- 重复比较使用 Unicode NFC 归一化、首尾空白清理和不区分大小写比较。中文名称会按原字符稳定比较；拉丁字母大小写差异视为同名。
- 路径分隔符、NUL、控制字符、`.`、`..` 等不安全名称继续由现有名称校验拒绝，不能进入目录分配流程。

### 重名判断

导入前扫描当前工作区的实际技能目录，并解析每个根目录 `SKILL.md.name`：

- 任一有效技能的归一化名称与待导入名称相同，返回 HTTP 409 和错误码 `SKILL_NAME_CONFLICT`。
- 错误详情至少包含待导入名称和已存在技能的实际目录名，供前端生成稳定提示，不依赖错误文案匹配。
- 无法解析名称的既有技能不参与名称重复判断，但其目录仍参与目录占用判断。
- 同一个远端绑定已安装时继续沿用既有“已导入/更新”语义，不创建第二份副本。

### 目录分配

- 首选目录使用下载包解析出的根目录名；若远端未提供有效根目录名，则使用经过现有路径安全校验的技能名称。
- 目录占用比较同样执行 Unicode NFC 归一化和不区分大小写比较，确保 macOS 与 Linux 行为一致。
- 首选目录被占用而名称不重复时，依次尝试 `<目录>_2`、`<目录>_3`，直到找到空闲目录。
- 只改变实际落盘目录和绑定元数据中的本地目录字段，不修改 `SKILL.md.name` 或其他下载文件。
- 分配结果必须再次经过路径安全校验，并保持在 `.claude/skills` 根目录内。

## 后端流程

1. 通过远端技能 ID 获取并校验下载包。
2. 从根 `SKILL.md` 解析并验证原始名称，生成仅用于比较的归一化键。
3. 枚举工作区技能，按 manifest 名称检查重复。
4. 如名称重复，返回 `SKILL_NAME_CONFLICT`，不创建暂存目录、不修改绑定元数据。
5. 如名称唯一，扫描实际目录并选择首选目录或第一个可用后缀目录。
6. 将下载内容写入同级暂存目录，计算基线摘要。
7. 写入目标目录前重新检查名称和目录，处理并发导入：名称在此期间变为重复则返回名称冲突；目录在此期间被占用则继续分配下一个后缀。
8. 原子移动暂存目录并写入市场绑定。绑定通过远端技能 ID 标识远端身份，通过实际目录名定位本地副本。
9. 任一步失败时清理本次暂存数据；不得删除或覆盖先前存在的目录。

## 前端交互

- `SkillsWorkspacePanel` 和保留的旧市场弹窗都删除“冲突”标签或警告图标的渲染。
- 市场详情中的“导入”按钮不再读取 `detail.conflict` 决定禁用状态；权限不足和请求进行中仍会禁用。
- 导入接口返回 `SKILL_NAME_CONFLICT` 时，打开项目样式信息弹窗，显示“工作区已存在名为「{name}」的技能，无法重复导入。”，提供单个“知道了”按钮。
- 其他错误继续走现有错误提示，不根据中文或英文错误文本做判断。
- 自动选择后缀目录成功后按普通导入成功流程刷新市场和“我的技能”；不额外打断用户。

## 兼容性

- 现有市场绑定已经记录实际本地目录时，更新、移除和详情读取继续使用该目录。
- 为兼容旧绑定，远端技能身份优先通过远端 ID 匹配，不能依赖展示名称或新分配的目录名。
- 包含中文名称和中文目录的技能必须可导入、展示、更新和移除。
- 大小写敏感文件系统上也必须阻止 `Foo` 与 `foo` 作为两个技能名称同时存在。

## 测试策略

服务端覆盖：

- 中文名称首次导入成功且内容不被修改。
- NFC/NFD 等价名称、拉丁字母大小写差异和首尾空白不会绕过重名判断。
- 不同目录中的相同 manifest 名称返回 `SKILL_NAME_CONFLICT`，且没有文件或元数据副作用。
- manifest 名称不同但目录占用时，自动落到 `_2`；连续占用时落到 `_3`。
- 无效既有 manifest 不参与名称比较，但会触发目录后缀分配。
- 非法路径名称被拒绝，不能逃逸 `.claude/skills`。
- 并发导入不会覆盖目录；最终要么分配不同目录，要么以名称冲突安全失败。
- 后缀目录中的市场技能仍可更新和移除。

前端覆盖：

- 市场列表和详情不渲染“冲突”标签。
- `conflict: true` 不再单独禁用导入按钮。
- `SKILL_NAME_CONFLICT` 打开单按钮提示弹窗，并正确展示中文名称。
- 权限和加载状态仍按现有规则禁用按钮。
- 非名称冲突错误继续使用原有错误提示。

## 验收标准

- 工作区不存在同名 manifest 时，目录冲突不会阻止市场导入，且现有目录内容保持不变。
- 工作区存在同名 manifest 时，导入被阻止并出现明确弹窗。
- 原始 `SKILL.md.name` 在任何成功导入路径中都不被改写。
- 中文名称、Unicode 等价形式和大小写边界均有自动化测试。
- 服务端测试、前端测试、类型检查和生产构建通过。
