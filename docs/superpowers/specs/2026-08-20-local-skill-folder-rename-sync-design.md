# 本地 Skill 文件夹重命名同步名称设计

## 问题

“我的技能”中的可见名称优先来自 `SKILL.md` front matter 的 `name`。用户在文件管理器中重命名 `.claude/skills/<skill>` 根目录后，目录标识已经变化，但 `SKILL.md` 仍保留旧名称，导致界面继续显示旧名称，目录和 Skill 定义不一致。

## 目标

- 重命名本地创建的 Skill 根目录时，同步更新该 Skill 的 `SKILL.md` front matter `name`。
- 除 `name` 外，不修改描述、版本、作者、自定义字段或 Markdown 正文。
- 保持目录重命名和清单更新的一致性，避免只完成其中一步。

## 触发范围

只有同时满足以下条件的文件管理器重命名才触发同步：

1. 被重命名项是目录。
2. 旧路径严格匹配 `.claude/skills/<skill-name>`，即 `.claude/skills` 下第一层 Skill 根目录。
3. 该 Skill 不存在技能市场导入记录，因此属于本地创建。
4. 目录内存在且可以解析根级 `SKILL.md`。

市场导入 Skill、Skill 内部文件夹、普通项目目录和文件继续使用原有重命名行为，不自动修改清单。

## 数据流与事务

文件重命名接口在执行前识别是否属于本地 Skill 根目录，并准备更新后的清单内容。更新使用 front matter 解析和序列化，只替换 `name`，保留其他 front matter 字段和正文。

执行顺序：

1. 校验旧路径、新名称和目标冲突。
2. 识别本地 Skill，并在内存中生成更新后的 `SKILL.md`。
3. 重命名 Skill 目录。
4. 在新目录内原子写入更新后的 `SKILL.md`。
5. 广播现有文件变更事件。

如果第 4 步失败，服务端将目录重命名回旧名称并返回错误。若回滚本身失败，则记录原始错误和回滚错误，返回明确的服务器错误，便于人工恢复。

## 错误处理

- 本地 Skill 根目录缺少或无法解析 `SKILL.md` 时，不执行目录重命名，返回可理解的 400 错误。
- 新目录已存在时沿用现有 409 错误。
- 名称非法、越界路径和权限问题沿用现有校验。
- 市场导入记录只用于判定来源，不在本次操作中修改。

## 测试

- 本地 Skill 根目录重命名后，文件夹名称和 front matter `name` 同步变化。
- `description`、版本、作者、自定义字段和正文保持不变。
- 市场导入 Skill 不触发 `SKILL.md` 名称同步。
- Skill 内部文件夹及其他项目目录重命名不触发同步。
- 清单写入失败时，目录名称回滚。
- 本地浏览器回归：在文件管理器重命名测试用本地 Skill，刷新“我的技能”后卡片和详情显示新名称。
