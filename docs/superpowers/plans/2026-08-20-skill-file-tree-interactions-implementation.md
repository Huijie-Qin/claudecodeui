# Skill 文件树交互优化实施计划

## 目标

统一技能市场导入文案和移除确认体验，并将本地 Skill 的文件夹展开、行内新建及行内重命名封装为独立文件树组件；保持现有后端 API 和路径安全边界不变。

## 实施顺序

1. 新增文件树纯函数模块，负责生成树节点、过滤可见节点、计算新建父目录和重命名路径、校验节点名称。
2. 为纯函数补充单元测试，覆盖隐式目录、展开收起、三种新建目标、basename 重命名和非法名称。
3. 新增 `SkillFileTree` 组件，接管目录展开状态、节点选择、行内新建和行内重命名状态；Enter 提交，Esc 或失焦取消。
4. 新增 `RemovalConfirmDialog`，复用旧技能市场弹窗的危险操作视觉样式，并支持市场 Skill、本地 Skill、文件和文件夹目标。
5. 重构 `SkillsWorkspacePanel` 的文件操作回调，使新建和重命名返回成功状态并在刷新后恢复选中项与右侧文件。
6. 用统一待移除状态替换 Skill 和文件操作中的浏览器 `confirm`，将本地“删除技能”和文件树“删除”按钮统一改为“移除”。
7. 将技能市场的“已安装 / 可安装”以及统计文案替换为“已导入 / 可导入”，保留“市场安装”来源标签。
8. 运行 ESLint、TypeScript、相关单元测试和客户端构建。
9. 重启本地前端并在隔离工作区验证文案、目录折叠、根目录/子目录新建、重命名和三类移除弹窗。

## 验证重点

- 技能页面本次范围内不再调用浏览器原生 `prompt` 或删除确认 `confirm`。
- 折叠目录会隐藏全部后代，重新展开后节点与选中状态正确。
- 新建位置遵循“文件夹内、文件同级、无选中根目录”规则。
- 重命名只能修改名称，不能通过分隔符移动节点。
- API 失败时行内草稿保留，成功后选中和右侧预览恢复。
- 所有 Skill/文件移除弹窗均显示完整相对路径并使用一致按钮文案。
