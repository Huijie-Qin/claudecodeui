# 技能市场离线交互原型

[打开 HTML](index.html) · [完整设计方案](../../skill-market-v2.0-需求设计说明书.md)

将 index.html 直接用现代浏览器打开即可，不需要安装依赖或启动 CCUI。所有样式和脚本都在同一个文件内，不使用网络接口、外部图片/字体、浏览器持久存储。刷新后恢复示例数据。

## 运营优先：建议先体验这条主流程

新增[自动评测与优化方案](../../superpowers/specs/2026-09-10-skill-auto-optimization-design.md)。原型保留现有 CCUI 样式和 Markdown 编辑，但默认让 AI 自动试用、修改待确认副本和复测，不要求运营逐个调度检查。

1. 我的技能 → 周报助手 → 测评，直接进入统一验证清单表格。销售汇总有远端更新，需要先核对差异再同步。
2. 点击“开始自动改进”，沿用业务目标和固定标准，无需重复核对每条用例。AI 自动补充探索场景，默认第一轮发现问题、第二轮修复通过，再独立验收完整回归、新样本及重复运行。
3. 查看每轮结果和修改摘要；点击“查看并采用结果”核对修改前后。未采用时不会覆盖本地 Markdown，取消或失败也不会覆盖。
4. “确认采用到本地”后才可以“预览并确认发布”，最终仍需负责人明确确认。新的优化任务不能借旧通过报告绕过检查。
5. 启动弹窗的“演示选项与执行上限”可选无改善、业务歧义、服务异常、1 轮上限、新样本验收失败或重复运行不稳定。运行时可停止。独立验收不通过时，即使固定用例均通过也不能采用。
6. 模板中心 → 使用模板：默认只填技能名称和必需业务问题；其他设置折叠。保存后进入自动改进，无正式场景时可以先探索，再提示补充固定验收标准；不会自动激活 AI 标准或发布。

AI 探索与固定验收在同一张表中分别标注，探索数量不加入正式通过数。缺标准时可将探索项“补充为验收标准”，先进入可编辑草稿，核对业务依据并确认后须重新运行。已有 AI 草稿不阻塞自动改进；生效用例的修改草稿不替换原定义。人工主要负责业务依据与最终采用/发布。

## 非负责人也可以本地测评

默认“林舟”身份 → 我的技能 → SQL 审阅（负责人是周可）→ 测评，可点击“开始自动改进”，或运行全部。结果标为“本地结果 · 不用于发布”；负责人共享标准只读。

添加验证场景 → 添加场景，可以手工创建自己的本地用例；也可由 AI 准备草稿。保存后本人核对并确认，表格标记为“我的本地用例”，可编辑或删除。与“负责人共享 · 只读”的用例一起参与本地测评，但不修改正式标准。个人用例与草稿按用户隔离；修改生效定义后旧本地报告失效。负责人已发布用例仍不可删除。

自动优化通过后，核对并采用只写入林舟的个人副本，主操作变为“提交贡献”。提交内容来自这个副本，正式报告为空；由周可重新正式验收，再确认发布。切换为周可时，看到的仍是周可原有工作文件与正式报告，林舟的本地运行不会覆盖它们。没有本地编辑权限时不能发起任务或采用。

原型以 tenant/workspace/skill/user 组合键隔离个人编辑、导入对照时间、报告和待采用任务。示例用例为允许共享的虚构材料；负责人草稿及标为 localVisible=false 的私人用例不开放给其他人。市场安装可见性、成员列表和安装移除仍是单工作区示意，不代表完整权限或多工作区服务已实现。真实目录隔离与 API 设计见[方案 §17](../../superpowers/specs/2026-09-10-skill-auto-optimization-design.md#17-本地测评与正式验收的权限分离本次确认)。

测评不再有二级页签：一张表展示“验证场景 / 期望表现 / 检查结果 / 问题与优化 / 操作”。基础检查、正式场景、待确认草稿均按行展示；操作栏平级展示“运行全部”和“添加验证场景”等入口，“查看详情”保留规则、AI 评审及文件/工具证据；编辑器“快捷插入”支持片段、其他 Skill、MCP 工具三个 Tab。这些都没有调用真实 AI、扫描器或容器。优化正文和报告是固定模拟示例，不能说明任意输入已被真实修复。

## 既有功能体验（按钮名称以当前页面为准）

原型已按现有 CCUI 工作区的“技能”页对齐：保留左侧工作区/会话外框、顶部工作区功能页签；技能市场、我的技能、贡献、模板中心位于内容区子页签。外框中的项目、会话和非技能功能仅作界面示意，不连接真实应用。演示身份在侧栏底部；手机上先点击左上角展开侧栏。

市场详情现有“概览 / 测评 / 管理”三个 Tab。概览左侧文件树默认全展开，右侧默认只读 SKILL.md，可切换文件；管理只读展示负责人、协助人、分类。销售汇总预置一份负责人已运行并发布的模拟报告，可在市场“测评”的统一表格查看基础检查和业务场景结论，点击详情查看允许公开的说明。其他没有对应报告的 Skill 显示“未测评”。

我的技能详情为“文件编辑 / 单次调试 / 测评 / 管理”。管理与市场展示相同的三个字段，但只有当前负责人能编辑；协助人、贡献者和非该 Skill 负责人的系统管理员均只读。

1. 默认“林舟”身份打开技能市场，点击“销售汇总”整行进入详情，再点击“更新本地技能”。它同时存在远端更新和本地修改；先取消检查保护，再确认替换建立新对照时间。市场文件可切换预览/源码，两种模式都只读。
2. 在“我的技能”打开销售汇总 → 文件编辑 → 快捷插入，选择片段、其他 Skill 或 MCP 工具；搜索选择后插入到正文，可撤销。片段复制固定正文，Skill/MCP 仅插入实际名称，不附加说明；仅片段保留右侧正文预览，搜索框上方无可见标题，不复制 Skill 文件，也不安装或运行工具。保存仅影响本地，预览只显示普通 Markdown。
3. 打开单次调试，模拟执行一次。任务结束不可追问；切换其他 Tab 再回来，输入和轨迹已清空。
4. 在测评 → 添加验证场景中选择“AI准备场景”或“添加场景”。草稿显示为表格中的待确认行；行内“管理”可编辑、删除，点击“核对并确认”查看输入/预期，再确认此用例生效，不影响其他草稿。
5. 在运行全部中选择全部通过、规则不满足、AI 不满足/分歧/无法确定/评分异常、执行环境异常或静态阻断。表格展示结果，行内“查看详情”查看预期、实际及折叠证据；失败和不确定均不能发布。
6. 当前负责人亲自发起完整测评，全部通过后预览并模拟发布。市场测评页展示此次发布关联报告的只读结果，本地修改时间不参与远端待更新判断；后续本地编辑与草稿报告不覆盖市场结果。
7. 切换“陈然”查看贡献 → 收到的贡献，可见协助 Skill 的全部请求；“我提交的贡献”只显示本人提交。可评审，但没有合并发布按钮。
8. 切回负责人，打开贡献请求并运行模拟测评，通过后可合并并发布，不需要协助人先认可。
9. 切换系统管理员，进入技能顶部导航、“模板中心”右侧的“片段管理”进行片段增删改。普通用户的导航没有片段库，管理员身份不自动获得其他 Skill 的发布权限。
10. 在模板中心创建本地 Skill，（先填写字段、模拟生成、预览确认），或在我的技能上传一个 Markdown 文件。新建 Skill 没有正式用例，可先探索；需要负责人确认可信标准后才能正式测评和发布。
11. 以负责人身份打开我的技能 → 销售汇总 → 管理，分别配置协助人和修改分类；取消不保存，确认后同步到市场只读管理页，不改变文件和导入对照时间。
12. 点击“转移负责人”，选择其他示例成员，按需勾选“将我保留为协助人”（默认不勾选），再确认。当前身份立即失去负责人权限；切换新负责人可继续管理，下次发布前必须由新负责人重新测评。市场已发布报告仍显示原测评发起人。
13. 删除一条待确认草稿，不影响生效用例；删除未发布生效用例需要确认，并须重新测评。销售汇总的七条初始用例已随示例发布，显示“发布用例 · 不可删除”，删除按钮不可用。新用例在模拟成功发布后也会永久受保护，下架或转移负责人不解除。

## 快捷插入（三类内容）

文件编辑 → 快捷插入 → 片段 / 其他 Skill / MCP 工具。每次插入一项，可搜索、取消或确认；搜索框不显示上方标题，片段保留预览，Skill/MCP 为单列表且无右侧区域；无匹配时不保留旧预览，并禁用插入。其他 Skill 只列当前工作区本地技能并排除自身；MCP 使用三条明确标注的示例工具，不读取真实凭据或连接服务。片段复制正文，其他两类只插入实际名称（如 sales-summary、mcp__demo-data__query），不增加换行、标题、用途或说明，不建立动态引用或自动启用能力。迁移后仍需确认目标环境存在相应 Skill/MCP。

原型在光标位于 frontmatter 时提示改为正文末尾插入；正文选区可被替换。插入只改编辑缓冲区，支持一次撤销；弹框打开后正文或目标变化则拒绝插入。快照不会随原片段修改而回改，既有评测和发布要求不变。

本轮新增 quick-insert.test.mjs 的 9 项测试，与既有 92 项合计 101 项通过；覆盖资源范围、MCP 不可用过滤、固定预览、三 Tab、文本转义、空搜索、选区替换、frontmatter/过期保护、不修改业务状态及目标绑定。浏览器实测三类切换、片段/Skill/MCP 插入和撤销、搜索空结果与预览、桌面及 390px 弹框；手机页面宽度 390px，弹框宽度 362px，无整页横向溢出，未捕获 error/warn。键盘事件与空结果禁用由展示测试覆盖，不声称进行了全部键盘或跨浏览器验收。可运行 `node --test docs/prototypes/skill-market/*.test.mjs` 回归。

名称插入精简修订：搜索框只保留输入框与无障碍名称，不显示上方“查找……”标题；Skill/MCP 无右侧预览，只原样插入实际名称，不附加任何说明或换行。测试更新为 10 项快捷插入检查，连同既有检查合计 102 项通过，新增名称行内插入及无预览区断言。浏览器本轮实际验证了桌面 Skill 单列表、标题移除及仅插入 sales-summary；MCP、空状态和片段保留预览由展示/事务测试覆盖，本轮不重复声明完整移动端或全部交互验收。

## 管理员模板与独立生成

[详细设计](../../superpowers/specs/2026-09-10-skill-template-generation-design.md)。片段管理不再有类型、分类或“两种分类”页面；只有标题、说明、固定正文，系统管理员可新增。

1. 切换系统管理员 → 技能顶部导航的片段管理（模板中心右侧）→ 新增片段，保存固定 Markdown。
2. 模板中心 → 新建模板，设置名称、描述和生成要求；添加单行/多行/下拉字段，配置必填、提示、默认值及选项。
3. 选择公共片段加入模板，预览正文，可上移、下移或移除；保存后当前租户可使用。片段后续修改不回改已保存正文。
4. 切回普通用户 → 使用模板，填写 Skill 基本信息和自定义字段，查看预置要求后模拟调用 skill-creator。
5. 查看生成进度和取消；完成后默认预览 SKILL.md，可切换 references/requirements.md。确认后才出现在我的技能，当前创建者为负责人，未测评、未发布。
6. 生成服务异常或产物结构不合法不能保存；重新填写后可显式重试。不会自动覆盖同名 Skill。

模板和字段编辑、生成耗时、环境回收、结构检查均为模拟。没有实际模型或容器；正文由固定规则组装，支持填值展示，不验证语义。模板范围暂沿用租户内；原型仅演示一个租户的系统管理员，不代表完整角色权限已经落地。

## 独立 AI 评审原型

在原有六条用例之外，新增 TC-07“销售分析报告与依据”，示范“自然语言＋Markdown 文件＋工具调用＋可选 subagent”的联合验收。已有页面结构与权限不变，不要求所有 Skill 输出 JSON。

建议按以下路径体验：

1. 我的技能 → 销售汇总 → 测评：在 TC-07 行展开“管理”并编辑，查看交付形式、测试参考依据、AI 验收项的要求、满足/不满足/无法确定条件、证据范围及必需属性。
2. 添加 AI 验收项可新建标准；保存只产生草稿。负责人在“核对并确认”中再次查看整条标准，然后确认生效。已有发布必需项不能移除或降级，允许修正标准后重新确认与测评。未发布的新增项可删除。
3. 运行全部：选择“AI 不满足”“AI 评审分歧”“AI 无法确定”或“AI 评分服务异常”，点击开始检查。表格上方进度区分 Skill 执行、任务结束/证据封存、独立评审与门禁汇总。
4. TC-07 → 查看详情：先看预期与实际，再展开“规则检查与 AI 评审”查看两次独立意见和完整标准。
5. 同一详情展开“输出文件、工具与完整证据”，查看主任务、可选统计 subagent、工具记录、参考资料及 Markdown 文件正文和证据定位。评分调用不混作被测 Skill 的子任务。
6. 分歧、无法确定、评分异常都不能发布。先同步市场内容，再选择“全部通过”完整测评，可预览并模拟发布；市场测评展示两次 AI 结论，但不展示私有 rubric、参考资料、原始轨迹或引用正文。

没有 AI 标准的用例不产生评审调用。双评审是同一次 Skill 执行证据上的两次独立调用，可以批量检查多条标准；展示的评审耗时按调用累计，不因多条标准重复计数。双评审配置仅是原型中的建议默认值，不是已验证的模型能力。

所有“发布”“下架”“删除”“执行”都只操作本次页面内存中的示例数据，不会修改实际市场、工作区或文件。测试中创建的内容可通过刷新重置。

## 与正式实现的差异

### 2026-09-10 Agent 自迭代修订验收

当前合计 110 项原型检查通过（基础模型 68、自动优化 20、统一表格 12、快捷插入 10），两个内联脚本编译通过，git diff --check 通过。新增覆盖：AI 新草稿探索不激活、无固定标准不得发布、修改草稿不替换标准、静态阻断不运行探索、最终验收预算、新样本/重复运行失败拦截、候选绑定、探索身份不变成发布保护用例，以及市场独立验收摘要脱敏。

本轮浏览器实际验证：桌面启动弹框、正常两轮改进→独立验收→改动对比与采用操作；新样本失败时没有采用按钮。390px 界面实测页面宽度与滚动宽度均 390px，表格容器 349px、内容 720px，可在表内横向滚动；查看了桌面与手机截图，未捕获 error/warn，已恢复桌面尺寸。发布摘要隔离、无标准、预算与其他异常由模型/展示检查覆盖，未逐一重复浏览器验收。

这些检查验证产品原型，不是 110 个真实 Skill 测试。独立新样本、重复运行、报告证据和 AI 补丁仍全部为预设模拟；没有实际生成隐藏集、执行容器、调用评分模型或修改市场服务。

### 原型边界

- 这是产品原型，不是已实现的 React 页面或后端系统。
- 调试、AI 草稿生成、静态扫描和动态测评均为预设模拟，不调用 Claude，不启动容器，不构成安全或质量结论。
- AI 按钮每次追加一条预设草稿，重复点击可能出现同内容的不同草稿，不代表真正按 Skill 分析或去重；不覆盖生效集合。删除只作用于页面内存，正式实现需软删除、审计、报告引用保护和服务端永久发布保护。
- 仅一个示例租户/工作区；身份切换演示 Skill 角色，全部示例身份具有当前工作区编辑权限，不是实际鉴权。
- 管理编辑及转移只修改内存治理数据，模拟角色撤销、旧表单冲突和任务互斥；现有业务服务仍检查远端 createUserId，真实负责人转移需先验证合法远端授权路径，不能只改本地 owner 字段。
- 固定内容在原型中用规范化字符串比较，生产要使用服务端内容摘要及不可变候选。
- 不模拟远端超时对账、持久任务、真正的并发锁、TTL、跨工作区同步或资源清理；完整方案包含这些要求。
- 上传仅演示 1 MiB 内单个 Markdown 的本地读取和表单填充，创建时重新组装 name/description/标题/正文。不是 ZIP 解包，也不是任意 frontmatter 的无损导入。
- 编辑器是 textarea；生产沿用已有 CodeMirror。片段插入落在元信息区域时，原型提示并移到正文末尾；生产应要求用户主动移到正文。
- 贡献只展示当前市场/提交正文两栏，不提供历史版本。完整逐文件 diff、更新提交与过期评审标记属于正式实现范围。
- 当前报告展示于页面内存；正式测评需持久化，调试则不能持久化。
- AI 评审理由、证据、文件与任务树都是预设数据；本原型没有真实模型、文件解析器、工具审计或沙箱。更改标准后选择“全部通过”也只是选择模拟结果，不证明改后的标准已经真实满足。
- 原型的 review/criteria 为表单状态简化结构，不代替正式 ccui.skill-eval/1 协议。规则检查沿用预设，尚未提供完整规则类型编辑器；实际生成文件只示范 Markdown，不代表 DOCX/PDF/XLSX 或图片验收已经接入。
- 片段不再单设类型/分类。管理员模板、自定义字段和独立生成任务已有原型，但真实后台、隔离环境、角色鉴权、持久任务与留存仍待实现。
