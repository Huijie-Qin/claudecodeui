# 技能市场离线交互原型

[打开 HTML](index.html) · [完整设计方案](../../skill-market-v2.0-需求设计说明书.md)

将 index.html 直接用现代浏览器打开即可，不需要安装依赖或启动 CCUI。所有样式和脚本都在同一个文件内，不使用网络接口、外部图片/字体、浏览器持久存储。刷新后恢复示例数据。

## 建议体验顺序

市场详情现有“概览 / 测评 / 管理”三个 Tab。概览左侧文件树默认全展开，右侧默认只读 SKILL.md，可切换文件；管理只读展示负责人、协助人、分类。销售汇总预置一份负责人已运行并发布的模拟报告，可直接在市场“测评”查看总览、静态问题和动态用例结论。其他没有对应报告的 Skill 显示“未测评”。

我的技能详情为“文件编辑 / 单次调试 / 测评 / 管理”。管理与市场展示相同的三个字段，但只有当前负责人能编辑；协助人、贡献者和非该 Skill 负责人的系统管理员均只读。

1. 默认“林舟”身份打开技能市场，在“销售汇总”点击更新。它同时存在远端更新和本地修改；先取消检查保护，再确认替换建立新对照时间。
2. 在“我的技能”打开销售汇总，编辑正文，插入公共片段并尝试撤销。保存仅影响本地，预览只显示普通 Markdown。
3. 打开单次调试，模拟执行一次。任务结束不可追问；切换其他 Tab 再回来，输入和轨迹已清空。
4. 在测评 → 测试用例中点击“AI 生成用例草稿”或“添加用例”。草稿与生效用例分区展示；编辑草稿后点击该条“核对并确认”，查看输入/预期，再确认此用例生效，不影响其他草稿。
5. 在测评报告选择全部通过、规则不满足、AI 不满足/分歧/无法确定/评分异常、执行环境异常或静态阻断。查看总览、静态证据、动态用例的预期与实际；失败和不确定均不能发布。
6. 当前负责人亲自发起完整测评，全部通过后预览并模拟发布。市场测评页展示此次发布关联报告的只读结果，本地修改时间不参与远端待更新判断；后续本地编辑与草稿报告不覆盖市场结果。
7. 切换“陈然”查看贡献 → 收到的贡献，可见协助 Skill 的全部请求；“我提交的贡献”只显示本人提交。可评审，但没有合并发布按钮。
8. 切回负责人，打开贡献请求并运行模拟测评，通过后可合并并发布，不需要协助人先认可。
9. 切换系统管理员，进入管理进行片段增删改。普通用户的导航没有片段库，管理员身份不自动获得其他 Skill 的发布权限。
10. 在模板中心创建本地 Skill，（先填写字段、模拟生成、预览确认），或在我的技能上传一个 Markdown 文件。新建 Skill 没有正式用例，需要负责人确认后才能测评和发布。
11. 以负责人身份打开我的技能 → 销售汇总 → 管理，分别配置协助人和修改分类；取消不保存，确认后同步到市场只读管理页，不改变文件和导入对照时间。
12. 点击“转移负责人”，选择其他示例成员，按需勾选“将我保留为协助人”（默认不勾选），再确认。当前身份立即失去负责人权限；切换新负责人可继续管理，下次发布前必须由新负责人重新测评。市场已发布报告仍显示原测评发起人。
13. 删除一条待确认草稿，不影响生效用例；删除未发布生效用例需要确认，并须重新测评。销售汇总的七条初始用例已随示例发布，显示“发布用例 · 不可删除”，删除按钮不可用。新用例在模拟成功发布后也会永久受保护，下架或转移负责人不解除。

## 管理员模板与独立生成

[详细设计](../../superpowers/specs/2026-09-10-skill-template-generation-design.md)。片段管理不再有类型、分类或“两种分类”页面；只有标题、说明、固定正文，系统管理员可新增。

1. 切换系统管理员 → 管理 → 新增片段，保存固定 Markdown。
2. 模板中心 → 新建模板，设置名称、描述和生成要求；添加单行/多行/下拉字段，配置必填、提示、默认值及选项。
3. 选择公共片段加入模板，预览正文，可上移、下移或移除；保存后当前租户可使用。片段后续修改不回改已保存正文。
4. 切回普通用户 → 使用模板，填写 Skill 基本信息和自定义字段，查看预置要求后模拟调用 skill-creator。
5. 查看生成进度和取消；完成后默认预览 SKILL.md，可切换 references/requirements.md。确认后才出现在我的技能，当前创建者为负责人，未测评、未发布。
6. 生成服务异常或产物结构不合法不能保存；重新填写后可显式重试。不会自动覆盖同名 Skill。

模板和字段编辑、生成耗时、环境回收、结构检查均为模拟。没有实际模型或容器；正文由固定规则组装，支持填值展示，不验证语义。模板范围暂沿用租户内；原型仅演示一个租户的系统管理员，不代表完整角色权限已经落地。

## 独立 AI 评审原型

在原有六条用例之外，新增 TC-07“销售分析报告与依据”，示范“自然语言＋Markdown 文件＋工具调用＋可选 subagent”的联合验收。已有页面结构与权限不变，不要求所有 Skill 输出 JSON。

建议按以下路径体验：

1. 我的技能 → 销售汇总 → 测评 → 测试用例：编辑 TC-07，查看交付形式、测试参考依据、AI 验收项的要求、满足/不满足/无法确定条件、证据范围及必需属性。
2. 添加 AI 验收项可新建标准；保存只产生草稿。负责人在“核对并确认”中再次查看整条标准，然后确认生效。已有发布必需项不能移除或降级，允许修正标准后重新确认与测评。未发布的新增项可删除。
3. 测评报告：选择“AI 不满足”“AI 评审分歧”“AI 无法确定”或“AI 评分服务异常”，点击模拟运行。进度区分 Skill 执行、任务结束/证据封存、独立评审与门禁汇总。
4. 动态测评 → TC-07 → 验收结果：展开 AI 项，查看两次独立意见。点击“sales-report.md”“主任务最终答复”“测试参考资料”等按钮打开带行号的只读证据。
5. 执行过程：查看主任务、可选统计 subagent 及工具记录；评分调用单独说明，不混作被测 Skill 的子任务。产物：查看最终答复和内置 Markdown 文件。
6. 分歧、无法确定、评分异常都不能发布。先同步市场内容，再选择“全部通过”完整测评，可预览并模拟发布；市场测评展示两次 AI 结论，但不展示私有 rubric、参考资料、原始轨迹或引用正文。

没有 AI 标准的用例不产生评审调用。双评审是同一次 Skill 执行证据上的两次独立调用，可以批量检查多条标准；展示的评审耗时按调用累计，不因多条标准重复计数。双评审配置仅是原型中的建议默认值，不是已验证的模型能力。

所有“发布”“下架”“删除”“执行”都只操作本次页面内存中的示例数据，不会修改实际市场、工作区或文件。测试中创建的内容可通过刷新重置。

## 与正式实现的差异

- 这是产品原型，不是已实现的 React 页面或后端系统。
- 调试、AI 草稿生成、静态扫描和动态测评均为预设模拟，不调用 Claude，不启动容器，不构成安全或质量结论。
- AI 按钮每次追加一条预设草稿，重复点击可能出现同内容的不同草稿，不代表真正按 Skill 分析或去重；不覆盖生效集合。删除只作用于页面内存，正式实现需软删除、审计、报告引用保护和服务端永久发布保护。
- 仅一个示例租户/工作区；身份切换演示 Skill 角色，全部示例身份具有当前工作区编辑权限，不是实际鉴权。
- 管理编辑及转移只修改内存治理数据，模拟角色撤销、旧表单冲突和任务互斥；现有业务服务仍检查远端 createUserId，真实负责人转移需先验证合法远端授权路径，不能只改本地 owner 字段。
- 固定内容在原型中用规范化字符串比较，生产要使用服务端内容摘要及不可变候选。
- 不模拟远端超时对账、持久任务、真正的并发锁、TTL、跨工作区同步或资源清理；完整方案包含这些要求。
- 上传仅演示 1 MiB 内单个 Markdown 的本地读取和表单填充，创建时重新组装 name/description/标题/正文。不是 ZIP 解包，也不是任意 frontmatter 的无损导入。
- 编辑器是 textarea；生产沿用已有 CodeMirror。片段插入落在元信息区域时，原型提示并移到正文末尾；生产应要求用户主动移到正文。
- 贡献只展示当前市场/提交正文两栏，不提供历史版本。完整逐文件 diff、更新提交与过期评审标记属于正式实现范围。
- 当前报告展示于页面内存；正式测评需持久化，调试则不能持久化。
- AI 评审理由、证据、文件与任务树都是预设数据；本原型没有真实模型、文件解析器、工具审计或沙箱。更改标准后选择“全部通过”也只是选择模拟结果，不证明改后的标准已经真实满足。
- 原型的 review/criteria 为表单状态简化结构，不代替正式 ccui.skill-eval/1 协议。规则检查沿用预设，尚未提供完整规则类型编辑器；实际生成文件只示范 Markdown，不代表 DOCX/PDF/XLSX 或图片验收已经接入。
- 片段不再单设类型/分类。管理员模板、自定义字段和独立生成任务已有原型，但真实后台、隔离环境、角色鉴权、持久任务与留存仍待实现。

### 2026-09-09 独立 AI 评审修订验收

56 项模型检查通过（保留原 43 项，新增 13 项），两个内联脚本语法检查通过。新增检查覆盖多形式产物、任务树与证据引用、独立双评审共识、失败/分歧/不确定/评分错误、静态阻断及取消不伪造执行、标准变更失效、已发布必需项保护、评分调用耗时不重复计数、市场公开字段白名单及规则失败不可由 AI 覆盖。

本轮浏览器实际交互验收覆盖：

- 负责人编辑 AI 标准、添加/移除新增标准时保留表单输入、保存草稿与逐条确认；AI 示例草稿包含待核对标准。
- 手机端手工添加用例；遗漏标准字段时，弹窗内错误可见，补齐后可以保存并确认生效。
- 同步市场后，分别运行 AI 不满足、评审分歧、无法确定、评分服务异常：报告正确区分状态，模拟发布按钮均不可用。
- 查看两次独立判定、带行号的证据弹窗、主任务/subagent 过程、工具记录及内置 Markdown 文件。
- 取消测评显示已取消；静态阻断时动态执行和 AI 评审均标为未执行。
- 全部通过后预览并模拟发布；市场对应报告显示 AI 验收项及两次结论，不提供原始证据、标准编辑或运行入口。
- 协助人不能运行测评或维护用例，管理页只读；浏览器未捕获页面 error/warn 日志。
- 浅色模式下检查 1440px 桌面双评审卡片、768px 平板市场报告、390px 手机表单/证据/产物、360px 手机评审详情，检查范围内页面无横向溢出。

验收后已刷新清除临时测试用例，恢复七条示例用例；演示页面停留在销售汇总的 AI 评审分歧结果。刷新会再次恢复初始数据。以上运行、发布和数据替换均只影响页面内存。

### 2026-09-10 管理员模板与独立生成修订验收

68 项模型检查通过（保留原 56 项，新增 12 项），两个内联脚本语法检查通过。新增检查包括片段无类型、管理员模板维护及旧表单冲突、字段协议校验、固定正文复制、输入/任务隔离、模板变更不回改任务、预览前不创建 Skill、采用权限/幂等/同名冲突，以及失败/取消不产生可保存文件。

本轮浏览器实际验收覆盖：管理员新增片段；新建模板并配置多行与下拉字段、默认值、预置正文及上移；普通用户无维护入口；基本信息和自定义必填字段的可见错误；运行进度、取消、服务异常、结构不合法及显式重试；成功结果的 SKILL.md/参考文件切换与固定正文；确认后创建者成为负责人、默认未分类、未测评不能发布。另检查管理员编辑时添加/移除字段、移除预置正文及取消不保存。

390px 手机下检查用户表单、管理员模板编辑和产物预览，检查范围无横向溢出；1440px 桌面查看生成结果。使用浅色模式，未覆盖所有主题与浏览器。验收后保留“销售洞察”的生成结果供预览，尚未采用；刷新清空模拟任务并恢复初始模板。

原先本地 file:// 标签页受浏览器自动化访问策略限制，本轮验收使用同一 HTML 的本机静态服务，不声称通过自动化验证了直接 file:// 打开。未执行真实 skill-creator、启动生成容器或修改业务工作区。

未宣称完成真实服务、安全、容器、跨租户、并发故障或所有浏览器兼容性验收。深色主题提供跟随系统样式，本次视觉验收以浅色为主。

交互验收通过本机静态预览完成。自动化浏览器的安全策略不允许直接访问 file://，因此未通过自动化验证双击打开方式；HTML 本身没有外部依赖或网络请求，可交由用户浏览器直接打开。

文件分工：index.html 为可交付原型；model.test.mjs 为纯状态测试；本 README 记录使用方式、范围与验证边界。项目业务代码和依赖未改动。
