# Agent 模板文件存储

Agent 模板高级配置上传的文件按模板 ID 保存在服务器文件系统，保留原始目录结构和文件名。每个模板只保存当前文件，不保留历史版本，也不按内容去重。新上传文件在请求中仍通过 Base64 传输，保存后不再保留 Base64 内容。

## 配置存储根路径

在 `.env` 中配置绝对路径，重启服务后生效：

```dotenv
CLOUDCLI_AGENT_TEMPLATE_ASSETS_ROOT=/data/db/agent-template-assets
```

未配置时，按以下优先级选择目录：

1. `${CLOUDCLI_DATA_ROOT}/agent-template-assets`
2. `${DATABASE_PATH 所在目录}/agent-template-assets`
3. `${应用根目录}/data/agent-template-assets`

配置目录需要允许服务进程读写；不能设置为文件系统根目录。Docker 部署应将它放在已持久化挂载的目录内，或为自定义目录增加宿主机与容器同路径的绑定挂载。

## 文件布局与使用

例如，模板 ID 为 `123`，上传了 `rules/review.md` 和 `commands/deploy.md`：

```text
<存储根路径>/
└── templates/
    └── 123/
        ├── manifest.json
        └── folders/
            ├── rules/
            │   └── review.md
            └── commands/
                └── deploy.md
```

`manifest.json` 记录模板 ID、当前名称及文件清单，便于人工查看。模板改名时更新清单，存储目录仍使用稳定的模板 ID。

保存模板时替换该模板当前的文件集合，删除的文件或目录也会从模板目录移除。文件按原始字节独立写入，不使用哈希去重或硬链接；空目录也会原样保留。SHA-256 仅用于检查文件是否损坏，不参与目录命名或去重。保存过程中暂存的目录只用于失败回滚，成功后会清理。

SQLite 中的模板保存目录结构、原文件路径、存储路径、字节大小和校验值。选择模板创建工作空间时，服务校验当前文件并按原目录结构复制到 `<工作空间>/.claude/<上传文件夹名称>/`。已有工作空间使用自己的文件副本，不受后续模板修改影响。

工作空间快照仅记录当时的目录结构、文件路径、大小和校验值作为审计信息，不依赖模板目录还原历史内容。实际文件保存在工作空间中。

## 旧数据迁移与备份

启动时会自动将模板中原有的 Base64 数据、旧 `objects/` 哈希引用及 `versions/` 路径迁移到对应模板的当前目录。迁移失败保留原始数据并记录错误，后续启动可重试；模板读取也支持迁移遗留记录。旧工作空间快照转换为审计清单，不会把历史内容写回当前模板或修改已有工作空间。

备份时需同时保存 SQLite 数据库及整个资源目录。改变根路径前，停止服务，将原资源目录完整复制到新目录，再修改配置并启动。配置变更不会自动搬移已经存在的资源。

迁移兼容逻辑仍可读取旧 `objects/` 数据，但新保存只写模板当前目录。
