# 技能市场完整方案（无版本）

更新：2026-09-14。目标设计与离线交互原型，仅改当前 CCUI，不代表已经实现。

本文件汇总本次会话最新决定；重点是运营通过普通会话生成、调用和优化技能。历史版本、草稿确认、人工采用均不在当前流程内。

## 1. 方案结论

本次目标：管理员维护模板与片段 → 运营在会话中「技能生成」 → skill-creator 独立生成并直接写入 Workspace → 普通会话继续调整/调用 → 直接保存为 evals/evals.json 用例 → 串行测评 → 模型优化自动落盘 → 再跑全部 → 查看输出和 Skill 差异 → 有权限的人发布。

最新细节以 [2026-09-14 文件化用例与自动落盘方案](superpowers/specs/2026-09-14-skill-eval-file-and-auto-write-design.md) 为准。旧的草稿确认、人工采用、负责人独占发布权不再适用。

| 主题 | 当前规则 |
| --- | --- |
| 内容与同步 | 无 Skill 版本/历史查看；比较远端更新时间与成功导入对应的远端时间，不比较本地编辑时间 |
| 模板/片段 | 普通用户可见且只读，可使用；仅获授权的管理员维护库定义 |
| 片段 | 固定正文，全平台共享，无版本、分类、参数、引用跟踪和回改；插入后是普通 MD |
| 模板生成 | 会话底部「技能生成」与其他能力一排；选择后 placeholder 为「请输入额外补充信息…」 |
| 角色 | 创建者初始为负责人；负责人可指定 Skill 管理员，两者可合并和发布 |
| 用例 | 每个 Skill 目录下的 evals/evals.json；兼容 skill-creator 数据结构；手工、AI、会话来源均直接保存，无再次确认 |
| 运行全部 | 冻结文件和全部用例；静态检查后按 evals 数组顺序串行执行及判定 |
| 自动优化 | 全量前测 → 模型对比预期/实际并改 Skill → 自动落盘 → 全量后测；无采用或确认改动 |
| 结果 | 单次运行看预期/实际；优化看同一用例前后两遍输出及文件 Diff |
| 发布 | 负责人或 Skill 管理员本人运行当前内容测评并通过后，可直接发布 |
| 贡献 | 不要求测评；非作者公开评审；至少一位他人 Approve 后由负责人/Skill 管理员合并，负责人可直接合并 |
| 保护 | 曾随 Skill 发布的用例永久不可删除；优化器不能修改用例或评分规则 |
| 市场报告 | 当前发布内容的只读结果；无适用报告、合并或外部更新后显示「未测评」 |
| 边界 | 只改 CCUI；保留其他发布渠道；不新建单次调试/试用模式，复用普通聊天与原生调用 |

测评可信度来自固定预期、确定性检查、独立 AI 评审与可追溯证据。AI 生成的预期可能有偏差；自动化减少人工操作，不等于证明任意任务都可靠。

## 3. 信息架构与用户旅程

最新入口补充：我的技能“新建技能”为下拉，含“直接创建”（沿用填写弹窗）与“模板创建”（复用会话的模板选择弹框，选择后跳会话填写）。模板选择弹框、模板中心支持名称/描述搜索，片段管理支持名称/说明/正文搜索，均有无结果和清空反馈；取消选择不跳转、不生成。

技能区域依次展示：技能市场、我的技能、贡献、模板中心、片段管理。普通用户也能打开最后两项，查看库内容与使用入口；不提供维护按钮。

- 市场详情：概览 / 测评 / 贡献 / 管理。概览默认全展开文件树，默认展示 SKILL.md，右侧只读；测评只读；贡献可评论/认可/授权合并；管理只读。
- 我的技能：文件编辑 / 测评 / 管理。编辑直接改 MD，也能看evals/evals.json；测评为单表格；管理展示负责人、技能管理员与分类。
- 贡献：收到的贡献（我负责或管理）/ 我提交的贡献；市场技能详情可看该 Skill 的全部授权请求。
- 会话：底部「技能生成」选择模板，填写 name、显示名称与自定义字段，再补充信息发送；生成后直接写 Workspace。用现有 /Skill 调用，无额外试用或调试状态。
- 从测评页启动运行/优化后留在原页，后台串行运行，表格逐行更新；每条用例末尾提供查看详情，不跳转会话。

会话复用原消息气泡、Agent 消息、工具折叠过程、滚动及输入栏；不另建 Skill 专属聊天外壳。编辑权限不能由界面是否展示按钮代替服务端鉴权。

## 4. 身份、范围与权限

创建者初始成为负责人。负责人指定/移除 Skill 管理员；Skill 管理员可发布与合并，不自动获得负责人转移、管理员指派、分类修改或系统后台权限。已有负责人转移保留；createdBy 只作初始创建审计，当前 owner 决定权限。

| 身份 | 授权能力 |
| --- | --- |
| 有查看权的普通用户 | 查看市场/模板/片段；评论及 Approve 他人贡献，禁止自我 Approve |
| 有本地编辑权的用户 | 编辑自己的文件和 evals/evals.json、测评、自动优化、提交贡献，不自动获得市场发布权 |
| 负责人 | 指定 Skill 管理员、转移负责人、改分类、直接发布、评审后合并或直接合并 |
| 指定 Skill 管理员 | 本人运行全部通过后直接发布；至少一位有效非作者认可后合并 |
| 模板管理员 | 在授权租户维护模板，不自动获得技能发布权 |
| 系统管理员 | 维护全平台片段；其他权限仍需独立授权，不自动等于每个 Skill 的管理员 |

指定/撤销必须校验真实身份、工作区与租户成员、授权戳和任务互斥，原子保存并审计。发布/合并执行前再检查权限。默认延续「只有负责人无认可可直接合并」的已确认例外，未将此例外扩给 Skill 管理员。

角色与远端认证的衔接需验证现有接口，不能仅改 owner/administratorIds 前端字段就宣称远端有权限。

## 5. 内容、来源与状态模型

Skill 身份、当前文件、治理信息、导入绑定和报告分别维护，不建版本表。

- Skill：稳定 id、name、title、description、category、createdBy、ownerId、administratorIds。
- 工作区文件：SKILL.md、evals/evals.json、references/scripts/assets 等。一个目录内只有一份用例定义真源；不同本地目录是独立副本。
- 来源绑定：remoteSkillId、remoteUpdatedAt、importedRemoteUpdatedAt；localEditedAt 独立。
- 用例元数据：case id、来源/调用幂等键、发布保护登记及操作审计；不存第二套可编辑用例正文。
- 测评：runId、输入摘要、固定用例与预期快照、环境/策略摘要、发起人/授权戳、逐例结果、证据引用、状态。
- 优化任务：beforeRunId、afterRunId、本次前后文件快照、修改是否已写入、Diff、终态。
- 发布：目标时间、固定包摘要、适用报告、回读结果、发布人；贡献：固定前后文件、评审、冲突与合并审计。

业务失败、执行异常、评分无法确定、取消、未运行和失效分别展示，不能合并为成功。自动优化写入后即使复测失败，当前 Skill 仍是已修改内容；快照只是本次任务证据，不提供历史版本操作。

## 6. 市场导入和更新：时间规则是唯一业务判据

### 6.1 字段定义

| 字段 | 含义 | 是否参与待更新判断 |
| --- | --- | --- |
| `remoteUpdatedAt` | 远端当前 Skill 更新时间 | 是 |
| `importedRemoteUpdatedAt` | 上次成功导入/同步的那份内容对应的远端更新时间 | 是 |
| `localEditedAt` | 本地文件最近编辑时间 | 否 |
| `importedAt` / `lastSyncedAt` | 本地执行导入/同步操作的时间 | 否 |
| `baselineHash` | 上次成功同步文件的内容基线 | 仅判断本地修改，不判断远端更新 |
| `expectedRemoteUpdatedAt` | 提交贡献/发布前已核对的远端时间 | 用于目标变化保护，不是版本 |

先确认 `tenantId + source + remoteSkillId` 是同一对象，再将远端时间规范化为 UTC 瞬时值；禁止跨对象、跨租户和按格式化显示字符串比较。

```text
未绑定市场                                  → 不适用
远端明确不存在/已下架                       → 来源已下架
任一时间缺失、无效或本次无法读取             → 更新状态未知
remoteUpdatedAt > importedRemoteUpdatedAt  → 待更新
remoteUpdatedAt = importedRemoteUpdatedAt  → 无远端更新
remoteUpdatedAt < importedRemoteUpdatedAt  → 远端时间异常
```

示例：导入内容对应远端时间 09:00，本地编辑 11:00，远端变为 10:00，仍然**待更新**。本地更晚的编辑不能把远端更新隐藏掉。

### 6.2 本地修改保护

| 远端状态 | 本地状态 | 操作 |
| --- | --- | --- |
| 无远端更新 | 无本地修改 | 正常使用 |
| 无远端更新 | 有本地修改 | 展示本地修改；允许按权限测评、贡献或发布 |
| 待更新 | 无本地修改 | 展示更新入口，用户执行后同步 |
| 待更新 | 有本地修改 | 同时展示两个状态；看差异，人工处理或明确确认覆盖 |
| 未知/时间异常 | 任意 | 不宣称已同步；不得通过改写时间掩盖未知状态 |
| 来源下架 | 本地存在 | 保留本地内容；停止普通来源更新，单独处理负责人重新发布 |

“更新”不是自动合并。保留本地内容并取消时，原对照时间不能前移。人工处理应基于当前远端内容重新形成候选，核对完整文件和远端时间后确认；不能只刷新时间戳就宣称已整合远端变化。

### 6.3 同步事务与并发

1. 读取远端元数据 T0，下载当前完整内容到暂存区。
2. 安全校验后重新读元数据 T1。若 T1≠T0，丢弃本次候选并有限次重试。
3. 校验工作区写权限、目标文件并发摘要以及未保存编辑提示；若本地在下载期间变动，要求重新确认。
4. 在工作区写锁下提交暂存文件，并同步写入来源绑定、基线和 `importedRemoteUpdatedAt=T1`。
5. 使用操作日志/暂存交换与崩溃恢复补偿，使文件系统与 SQLite 不能留下“文件旧但时间新”的完成态。成功后才反馈同步完成。

元数据两次读取只能降低竞态，不能构成远端原子读保证。同时间粒度内多次修改仍可能不可见；需验证远端时间字段单位、时区、精度和每次内容修改都会更新的契约。现代码兼容 `modifyTimestamp` / `mpdifyTimestamp`，需统一规范化。

导入失败、取消、查询更新、保存、调试、测评、评审和普通提交，均不得推进导入对照时间。负责人发布后，只有本地候选与已回读确认的远端内容一致，才可同步更新发起工作区绑定；其他工作区不自动变化。

### 6.4 旧数据迁移

- 新增字段允许空值。旧 `importedVersion` 只作过渡兼容，不能推导远端更新时间。
- 不从本地 updatedAt、文件 mtime、导入操作时间或“此刻的远端时间”伪造历史对照。
- 缺失可信对照的导入显示“更新状态未知”，由用户安全重新同步建立新基线。
- 同时清理 UI、类型、缓存键、预览参数与发布前检查中对 Skill version 的业务依赖。
- 不顺带删除用户目录、旧数据列或既有文件；兼容期后是否删除废弃列另做迁移审核。

## 7. 市场、我的技能、模板和片段

### 市场和本地管理

市场的概览与管理始终只读，展示负责人、指定的技能管理员与分类。我的技能管理页也展示这三项；仅负责人有「转移负责人」「配置管理员」「修改分类」。Skill 管理员能看到发布及合并操作，但不能自行添加管理员。

### 模板中心

普通用户能看模板名称、描述、默认值、字段及预置正文；可「查看模板」「在会话中使用」。管理员可新建/编辑模板、维护自定义字段、配置预置片段。字段类型首期支持单行、多行、选择；校验名称、字段键、必填、选项与默认值。选中模板后在会话输入区填写，不要求运营配置模板结构。

生成任务固定模板定义、输入及正文副本，独立调用 skill-creator。检查通过自动写入当前 Workspace；不再提供确认保存/采用生成结果。继续输入可微调已落盘 Skill。

### 公共片段与快捷插入

片段全平台共享，系统管理员新增/编辑/删除；普通用户可查看内容及使用，不维护库。固定 Markdown，无版本和双重分类。模板复制预置正文；creator 可按授权参考匹配适用片段；已生成的 Skill 不与片段建立活引用。

快捷插入弹框有片段、其他 Skill、MCP 工具三个 Tab，搜索框上不另放重复标题。片段显示正文预览并复制文本；Skill/MCP 只插入名称，无右侧正文区，不开启工具，不复制其他 Skill 全套文件。SQL Check 片段只是规范文字，不自动执行实际校验。

模板或片段更新不追踪/修改已有 Skill，发布后不显示片段结构；但普通用户仍可从片段管理入口查看当前公共库。

## 8. 会话创建、Skill 调用与用例沉淀

1. 会话底部「技能生成」或模板中心「在会话中使用」进入同一输入流程。
2. 用户填写显示名称、文件标识 name、自定义字段；额外输入框提示「请输入额外补充信息…」。
3. 独立环境生成普通 Skill 包，包含evals/evals.json（无初始用例则为空 evals）；检查后自动保存到 Workspace/.claude/skills/<name>/，同名不覆盖。
4. 用户继续发消息修改已保存 Skill；直接 /skill-name query 调用，没有专门试用按钮或调试页。
5. 完整根调用结束后，消息底部提供「保存为测评用例」。服务端绑定 executionId/query/完整结果，生成标准用例并直接写该 Skill 的 evals/evals.json，无第二次确认。
6. 输入资料需持久复制且脱敏；缺少附件不能伪称可重跑。调用重复保存用幂等键去重。
7. 测评/优化在后台串行运行，在测评页单表格查看进度与逐例详情，不跳转会话。普通会话按既有策略留存，测评证据单独保存。

原输出作语义参考而非逐字答案。保存测试用例不自动发表会话原文；发布前必须检查 evals/evals.json 和附件适合共享。

## 9. 静态 + 动态联合测评

### 9.1 统一文件契约

所有用例存evals/evals.json，数据结构为 skill_name + evals；每条含唯一整数 id、prompt、expected_output，可选 files、expectations。遵循上游 skill-creator 的 schema，并统一使用 evals/evals.json 路径。仓库精简版 creator 还没有此规范，需补充。

完整 JSON/附件示例、校验与 API 语义见 [最新专项 §2—3](superpowers/specs/2026-09-14-skill-eval-file-and-auto-write-design.md)。UI 是该文件的表单视图，不再存草稿/生效双集合。手工保存、AI 生成、会话沉淀均校验后直接落盘，不确认。

曾发布用例永久不可删除，表格、源码、文件 CRUD、贡献和发布都要检查保护登记。未发布用例可删除，运行期间暂停写入；外部变更使当前报告失效。优化器只读用例。

### 9.2 静态检查

| 类别 | 检查与处理 |
| --- | --- |
| 必需结构 | 根 SKILL.md、frontmatter、有效 name/description；缺失阻断 |
| 用例文件 | evals/evals.json 语法/schema、skill_name 一致、唯一 ID、非空输入/预期；错误阻断 |
| 包路径 | 路径穿越、绝对路径、符号链接、文件类型/数量/大小边界；危险路径阻断 |
| 输入资源 | files 路径可解析且授权可复制，不引用 evals/evals.json/答案；缺失阻断 |
| 安全 | 凭据、危险脚本与生产工具配置按策略检查；明确违规阻断，疑似风险需可解释处理 |
| 文档质量 | 描述/触发范围、引用有效性、结构完整度等给定位建议；不把样式警告等同业务失败 |

确定性规则由平台代码实现；可加 AI 质量建议，但不能让 AI 建议覆盖安全阻断。复用当前 workspace-skills 服务的校验，不把宽松展示解析等同严格检测。静态通过不代表功能正确。

### 9.3 串行动态执行与判断

固定内容、用例、资料与环境配置 → 静态检查 → 按 evals 顺序逐例执行 → 等待该例主任务/工具/subagent 完成 → 收集文字及产物 → 规则 + 独立 AI 判定 → 清理后再开始下一例。

单例业务失败继续跑后续；任务级安全事件/取消/并发冲突停止，未执行项标为未运行。判定对象包括文字、工具、子任务及文件，不要求输出 JSON。

执行 Agent 不可见 evals/evals.json/预期；Runner 必须移除答案文件构建受控运行投影。评分 Agent 则接收固定预期与只读证据；结果包含满足/不满足/无法确定、原因及引用。规则失败与安全违规不能由语义评分覆盖。评分和结果存 CCUI 报告区，不写回 evals/evals.json。

### 9.4 自动优化自动保存

点击自动优化后：第一遍全量串行测评 → 模型根据实际/预期差距修改 Skill → 安全/路径/摘要校验 → 自动原子落盘 → 第二遍以完全相同用例串行复测 → 保存逐例前后结果及本次 Diff。

不复用上次结果跳过前测，不修改预期、评分器或工具权限，不只重跑失败用例，不新增采用/确认改动步骤，不自动发布。即使无需修改也记录无差异并跑第二遍。写入后复测失败/中断仍保留修改，显示真实文件状态。后续再点击优化才启动新的两遍过程。

### 9.5 可视化

统一表格：场景、预期、运行结论、操作；优化时是优化前/优化后两列。顶部同排左对齐、同高、固定间距排列运行全部、自动优化、添加验证场景（AI准备场景/添加场景）。详情保留当次固定预期，运行全部以单列会话形式展示完整可见模型输出；优化前后以左右两列会话对比展示完整输出，不用摘要替代。沿用真实聊天页的消息、Markdown、工具、subagent 与文件呈现，判定依据单独放在底部。长内容可滚动读到末尾；窄屏保持两列并局部横向滚动。未采集/未公开输出显示空态，内部推理不展示。改动后只提供「查看 Skill 修改对比」。

市场只展示当前发布报告的公开投影，无运行或用例管理控件；本地失效结果要标记，详情保留当次预期，不能混用新标准解释旧输出。模板生成和用例已成为普通文件，不得把 evals/evals.json 中公开随包的预期冒充私有数据。

## 10. 贡献请求

保留多文件 Diff：左边列新增/修改/删除文件，右边按所选文件展示前后差异。贡献固定提交时文件包与市场基线，后续内容变化使旧认可失效。evals/evals.json 与输入附件也属于包文件，进入 Diff 和路径/保护校验。

所有有权访问技能的用户可评论、建议修改或 Approve；不能认可自己的贡献。至少一位当前有效非作者认可后，由负责人或指定 Skill 管理员合并；负责人可无认可直接合并并单独审计。普通用户不能因为 Approve 而取得合并权限。

提交和合并均不需要测评，不出现测评 Tab 或状态门禁。合并直接更新市场已发布内容；回读成功后请求为已合并，当前市场测评显示未测评。本地文件不被合并操作自动覆盖。远端变化需重新核对，不静默强推。

查看范围：市场详情贡献 Tab 为该技能全部可访问请求；个人贡献分「收到的贡献」（我负责/管理）和「我提交的贡献」。

## 11. 发布、下架与远端并发限制

负责人或指定 Skill 管理员本人运行当前文件全部测评且通过后，可以直接首次发布/更新发布。发布前检查当前角色、授权戳、固定文件与用例/环境摘要、当前适用报告、远端更新时间、包合法性及发布保护。非发布角色的报告不能冒充发布人的结果。

优化落盘不等于发布；前测结果不能绑定优化后的内容，必须有完整后测通过。发布确认仍保留，因为发布会改变共享市场；取消的是本地优化「确认改动/采用」，不是取消外部发布授权。

贡献合并单独走免测评路径。成功后报告清为未测评，不套用普通直接发布门禁。evals/evals.json/共享输入随包；完整结果/会话轨迹不默认发布，公开结果须经过授权过滤。

仅改 CCUI、保留外部渠道。现有远端无原子 CAS/幂等保证：做冲突预检、持久发布状态、回读摘要比对，超时或结果不明置待核实，不盲重试，也不能声称绝无竞态。外部内容变更后旧市场报告失效。

下架默认仍仅负责人，停止分发但保留本地文件、贡献、报告与审计，不提供历史版本。系统管理员强制下架等权限不在本次扩大。

## 12. CCUI 技术架构

| 模块 | 职责及存储 |
| --- | --- |
| 会话/技能页面 | 模板入口、原生调用保存用例、统一测评表、文件/输出 Diff、角色感知操作 |
| CreatorAdapter | 固定模板/输入，独立生成，输出 SKILL.md + evals/evals.json，检查后写 Workspace |
| EvalFileService | 所有来源统一读写evals/evals.json；schema、附件、原子写、锁、摘要、已发布身份保护 |
| SkillGovernanceService | owner/administratorIds、授权变更及审计；在发布/合并时再次鉴权 |
| EvaluationOrchestrator | 持久任务和串行游标；每例完成执行/评分/清理后进入下一例 |
| Runner / EvidenceCollector | 独立测试环境、去答案投影、权限最小化、完整任务树终态、产物封存 |
| RuleGrader / AIJudge | 固定规则、独立语义判断、证据覆盖和异常区分 |
| OptimizationCoordinator | 全量前测、受限文件修改并自动落盘、全量后测、操作级前后文件 Diff |
| Publish / Contribution | 固定包、认可与权限、远端冲突/回读、报告关联、免测评合并 |

用例正文只在文件中；数据库保存元信息、幂等键、发布保护登记、授权、任务与审计。运行快照及 outputs、grading、前后差异放 CCUI 私有报告存储，不写回 evals/evals.json，不建 Skill versions。

建议接口（目标方案，不代表已存在）：

- GET/PUT skills/:id/eval-file；POST/PATCH/DELETE skills/:id/evals；POST skills/:id/evals/generate；所有写入带 If-Match，新增无需 confirm。
- POST skills/:id/evals/from-invocation：服务端执行ID授权与幂等，直接保存。
- PATCH skills/:id/administrators：负责人指定当前有效成员；分类/转移继续单独校验。
- POST evaluations：固定全部用例，serial=true；GET 报告/事件；POST cancel。
- POST optimizations：before-all → write → after-all；GET 对比；POST cancel；不再提供 adopt。
- POST skills/:id/publish：当前 owner/admin、固定包和本人适用报告。
- POST contributions/:id/merge-publish：当前 owner/admin、固定提交/认可和冲突检查，无测评要求。

任务持久化应支持取消、断线恢复与租约。写入前后分别记状态，服务重启后根据写入摘要与已封存前测恢复后测或标记待核实，不重复写入补丁。预算与超时采用部署配置。

## 13. 安全、可用性和性能

- 不继承生产凭据、普通会话的持久 HOME、Hook/MCP 权限；测试环境与评分上下文独立。
- 执行 Agent 不挂载 evals/evals.json/答案；预期仅评分器与受限优化器可读，输出中的提示不能指挥评分器。
- 输入及产物解析按白名单和资源限制运行；不可读/证据不完整显示无法确定，不推测通过。
- 优化仅写授权 Skill 文件，不改评测预期、输入、策略、角色、脚本或工具权限；扩大修改范围需另行授权。
- UI 禁写不能替代后端锁/摘要；任务开始到自动写入均校验文件和权限。外部编辑不覆盖。
- evals/evals.json 是可分发内容，发布前做共享/敏感检查；私人报告与原始会话不自动公开。
- 串行降低并发压力但增加总耗时，展示每条进度；取消不会将已落盘改动恢复为假想候选。
- 格式/运行/评分异常分别展示；不以旧通过报告掩盖最近失败。

## 14. 实施计划与依赖

1. 统一evals/evals.json 契约及 CreatorAdapter；完成表单/文件/会话三入口读写与原子检查。
2. 增加 Skill 管理员与后台鉴权；验证现有远端认证可支持受权发布，不能前端越权代理。
3. 接入独立 Runner、串行队列和证据收集；再接入规则与独立 AI 判定。
4. 实现前测 → 自动落盘 → 后测任务状态与 Diff，恢复/取消和文件冲突保护。
5. 对齐市场报告、普通发布门禁、免测评贡献合并与包内用例保护。
6. 实际浏览器/集成测试验证多角色、多用例、文本/工具/子任务/文件、失败与断线。

HTML 当前只模拟这些流程。容器、真实 AI、文件实际落盘、远端鉴权和持久化均需后续生产实现。

## 15. 验收清单

- 普通用户可见模板中心/片段管理，能看内容和使用，无库维护入口；伪造 CRUD 仍被拒绝。
- 技能生成在会话底部能力同排；选模板后 placeholder 变化，name 必填；生成自动保存，普通调用可直接存用例。
- 负责人指定管理员；管理员可发布/合并但不能指派自己、转移或自我 Approve；撤销立即生效。
- 任意来源用例均写evals/evals.json 且无需再次确认；非法 schema/资源路径不能保存；UI/源码一致。
- 运行全部按数组顺序逐例执行和评分，业务失败仍完整跑完，异常不伪装通过。
- 自动优化必跑完整前测后才落盘，之后同一批完整后测；优化不能修改用例/预期。
- 写入前取消不修改文件；写入后取消/失败保留修改；不出现采用/确认改动；只读 Diff 可查看前后文件。
- 用例详情展示固定预期、实际或前后两份输出，文件变动后旧结果标失效。
- 发布保护覆盖用例删除、ID替换、删文件、整体覆盖和贡献合并。
- 两类发布角色亲自运行当前内容通过可发布；普通用户不能发布；免测评合并保持独立。
- 贡献多文件 Diff、非作者认可、owner/admin 正常合并及 owner 直接合并、回读核实和未测评均可验证。
- 窄屏表格/长文本在局部滚动或上下排列，不撑宽页面，按钮与输入可用。

## 17. 原 V2 其余能力的安排

完整方案保留其目的，但不把下列功能混入首期发布门禁或声称已经实现：

| 能力 | 后续设计方向 | 约束 |
| --- | --- | --- |
| SOP → Workflow 编译 | 以当前项目 Workflow 能力为候选目标；分析固定步骤、生成产物草稿、人工核对后单独测评 | 需先验证实际执行接入；含模型/外部工具的流程不能承诺完全确定性 |
| 编译产物检验 | 用明确业务用例验证产物行为，记录不支持步骤 | 有限用例通过不等于证明全域等价；产物仍走负责人或技能管理员发布与联合门禁 |
| description 优化 | AI 给出适用/不适用范围和措辞建议，由负责人编辑普通字符串描述 | 不直接把当前兼容的 description 改成不兼容对象；不自动发布 |
| 召回测评 | 单独 trigger 模式、正负样本、明确候选集合和选择证据 | 直接加载目标 Skill 的任务测评不能冒充召回准确率 |
| Badcase 闭环 | 仅在用户对某次完整 Skill 调用显式点击保存后生成生效用例；其他 AI 生成用例按 schema 校验后直接写入 evals/evals.json | 不暗中采集普通对话；不自动把未保存的会话内容作为共享数据 |
| 相关度搜索/向量召回 | 先优化当前 CCUI 可控的检索，验证规模与权限过滤 | 不能假定可改远端检索接口，跨租户隔离不变 |
| 无 Skill 基线、重复运行统计、A/B | 另行设计实验口径与成本预算 | 不借测评对比恢复 Skill 历史版本或默认新增报告比较页 |

## 18. 上线前仍需验证
