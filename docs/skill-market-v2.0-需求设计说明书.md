# 技能市场完整方案（无版本）

日期：2026-09-09；2026-09-10 补充管理员模板、快捷插入与 Agent 自迭代方案

状态：完整需求与技术设计稿，配套离线交互原型；不代表业务功能已实现。

范围：仅修改当前 CCUI，复用现有远端技能市场接口；不改造远端 data-agent。

> 本文是本轮讨论整合后的主方案。文件名中的 V2.0 是文档命名，不代表 Skill 具有版本。早期方案中的 Skill 版本、历史查看、回滚、片段动态引用与版本锁定均已撤回。专项设计作为细节参考；若存在旧措辞，以本文及用户后续确认优先。设计文档、测评运行编号和编辑并发令牌都不是 Skill 版本。

## 1. 方案结论

运营优先补充：主流程调整为“提供业务目标 → AI 自主探索、测评、定位、修正、回归 → 独立新样本与重复运行验收 → 负责人采用并确认发布”。固定业务标准首次确认或变化时才请人核对，已有标准不反复确认；未确认 AI 新场景可用于内部探索，但不能自动成为发布标准。只有业务歧义、缺依据/资源、无改善或权限扩展才要求人工介入。运营仍可直接编辑 Markdown；自动化不降低门槛、不修改固定标准、不自动覆盖或发布。详见[Agent 自迭代详细方案](superpowers/specs/2026-09-10-skill-auto-optimization-design.md)，包括用例分层、可信预期、证据反馈、独立验收及 CCUI 改造位置。

技能市场负责发现和分发当前已发布内容；我的技能负责工作区内的编辑、调试和测评；贡献负责接收和提交修改请求。Skill 的交付物始终是普通 `SKILL.md` 及其附带文件。

负责人可以直接发布自己的 Skill，也可以合并贡献后发布；两条路径均必须通过静态检查和真实动态测评。协助人可以评审，但不能发布，也不要求一定获得协助人认可。片段仅是编辑器中的固定文本插入工具，由系统管理员维护，全平台共享；不建立引用关系。

### 1.1 已确认的产品规则

| 主题 | 当前决定 |
| --- | --- |
| Skill 内容 | 不区分版本，不提供历史版本查看、回滚或版本对比 |
| 导入更新 | 比较远端更新时间与上次成功导入所对应的远端更新时间；不比较本地编辑时间 |
| 片段可见性 | 普通用户只在编辑时可见；发布后只看到普通 Markdown，不暴露片段结构 |
| 片段治理 | 系统管理员创建和维护；全平台所有租户共享；无版本、参数、引用追踪和自动回改 |
| 模板创建 | 管理员维护模板名称、描述、自定义字段和预置片段；用户填写后在独立环境调用 skill-creator 生成 Skill |
| SQL Check | 可以插入 SQL 编写规范文字；不自动开启或运行实际 SQL Check |
| 发布权限 | 仅 Skill 负责人可发布；允许直接首次发布和直接更新发布 |
| 协助人 | 可看协助 Skill 的全部贡献请求并评审；无发布权限；认可不是强制条件 |
| 贡献入口 | “收到的贡献”和“我提交的贡献”两个子 Tab |
| 测评 | 静态检查与动态测评共同构成首期强制发布门禁；发布前必须由当前负责人发起运行，结果随当前内容发布并在市场只读展示 |
| 本地测评与优化 | 有本地编辑权限的用户均可运行、采用自己的副本；本地结果仅供本人参考，不替代负责人正式验收；采用后可提交贡献 |
| 本地用例 | 用户可新增、编辑、确认、删除自己的本地用例；负责人共享验收用例只读，不自动将个人用例升级为发布标准 |
| 市场详情 | 概览 / 测评 / 管理三个 Tab；概览为默认全展开的文件树与只读文件内容；管理只读展示负责人、协助人和分类 |
| 我的技能管理 | 不设“发布与来源”Tab，改为“管理”；展示与市场相同的三项信息，仅当前负责人可转移负责人、配置协助人、修改分类 |
| 测试用例 | AI 新场景可自主探索；固定验收标准由负责人确认，也可手工创建；探索结果不计发布通过数 |
| 动态验收对象 | 完整任务及实际交付物：文字、工具调用、subagent、文件；不强制 Skill 输出 JSON |
| AI 语义判定 | 负责人确认的语义标准可作为发布必需项；必须给出证据，无法确定不能通过，不覆盖规则失败或安全违规 |
| 用例增删与保护 | 草稿逐条确认，不整套覆盖；负责人可添加、删除未发布用例；凡曾随 Skill 发布的用例永久不可删除 |
| 隔离 | 接受独立测试环境，默认不开放生产凭据或真实业务写入 |
| 调试 | 一次完整任务结束，不提供追问，不持久化执行记录 |
| 系统边界 | 只能改 CCUI；仍保留其他渠道直接发布 |
| 市场测评文案 | 当前内容没有适用测评报告时显示“未测评” |
| 下架 | 停止市场分发，保留本地文件、贡献、测评和操作记录；不建设历史版本 |

### 1.2 首期建议默认值，不冒充已确认结论

- 片段不再单设类型或分类；保留 Skill 分类，片段按标题/说明搜索。
- 平台确定性错误阻断，疑似高风险待复核，普通质量建议不阻断。
- 必需语义项建议对同一份证据做两次独立 AI 评审，都满足才通过；模型、校准与成本预算需部署验证。没有语义项的确定性用例不强制调用 AI。
- 至少一个有效必跑用例，全部必跑用例通过，观测到的安全违规为零。
- 测评资格建议最长 24 小时有效；内容、用例、策略或环境变化可以提前使其失效。
- 首期支持管理员创建/编辑模板、自定义字段和预置片段正文；用户填写后独立调用 skill-creator，预览确认后创建 Skill。模板范围暂沿用租户内。
- 下架默认由负责人执行；系统管理员强制下架、风险误报复核角色另行确认。

这些建议可独立调整，不影响无版本、更新时间同步、负责人发布和联合测评四条主线。

## 3. 信息架构与用户旅程

### 3.1 UI 基准：现有 CCUI 工作区“技能”页

页面沿用 CCUI 工作区的布局，不另建一套独立技能后台，也不采用 DataAgent 的技能页样式。左侧保留工作区/会话侧栏；顶部保留聊天、文件、CodeHub、技能、MCP 工具、SQL Check 等工作区功能入口。“技能市场 / 我的技能 / 贡献 / 模板中心”作为技能内容区内的子页签，不占用工作区侧栏。

- 视觉令牌以 `src/index.css` 为准：背景、边框、主色、文字、圆角、系统字体及深色主题。
- 外框与顶部页签以 `MainContentHeader`、`MainContentTabSwitcher`、`PillBar` 和 `Sidebar` 为准。
- 列表以 `SkillsWorkspacePanel` 为准：三栏统计、搜索/筛选、圆角边框内的整行点击列表，避免原型独有的大标题和多操作列。
- 详情以现有返回面包屑、操作栏及文件浏览布局为准。桌面文件树基准宽度 280px；默认展开，选中 SKILL.md；市场内容只读，支持 Markdown 预览/源码切换。导入、更新、移除放在详情操作区。
- 测评、管理、贡献、模板属于新增信息架构，但继续使用现有按钮、分段页签、表单、面板和弹窗样式，不改变已确认权限与业务语义。
- “片段管理”入口位于技能区域顶部导航、“模板中心”右侧，仅对系统管理员显示；移动入口不扩大管理权限，真实项目仍须校验管理员身份。
- 窄屏隐藏工作区侧栏并提供展开入口；技能页签保留可访问性，文件树与正文上下排列，表单和结果面板单列显示。

这是以仓库实际组件为基准的 UI 对齐，不代表已将新增业务接入 React 页面，也不声称与某个线上部署完成逐像素截图比对。

### 3.2 信息架构

```text
CCUI 工作区 → 技能（当前租户 / 当前工作区）
├─ 技能市场
│  └─ 当前 Skill：概览 / 测评 / 管理（全部只读）
│                  ├─ 概览：左侧文件树默认全展开，右侧默认 SKILL.md
│                  ├─ 测评：当前内容发布时关联的负责人测评结果
│                  └─ 管理：负责人 / 协助人 / 分类
├─ 我的技能
│  └─ 本地 Skill：文件编辑 / 单次调试 / 测评 / 管理
│                 ├─ 管理：负责人 / 协助人 / 分类（仅当前负责人可编辑）
│                 └─ 测评：统一验证清单表格（无二级页签）
│                         ├─ 主操作：自动改进 / 必要时补充业务依据 / 核对采用 / 确认发布
│                         ├─ 表格行：基础检查 / 正式场景 / 待确认草稿
│                         └─ 查看详情：预期与实际 / 规则与 AI / 文件与执行证据
├─ 贡献
│  ├─ 收到的贡献
│  └─ 我提交的贡献
│     └─ 请求详情：文件变更 / 讨论与评审 / 测评
├─ 模板中心
└─ 管理（按权限显示）
   ├─ 公共片段：系统管理员，全平台
   └─ 技能分类 / 预置技能：保留各自租户权限边界（模板维护位于模板中心）
```

不为普通用户增加“片段库”导航，不设置全局“历史版本”入口。首期测评在 Skill 和贡献详情内完成，不额外建设排行榜式质量大屏。

主要旅程：

- 使用者：搜索市场 → 只读查看 → 导入 → 当前工作区使用；出现待更新时核对差异后同步。
- 负责人：新建/模板/上传 → 编辑普通文件 → 单次调试 → 确认用例 → 联合测评 → 预览确认 → 发布。
- 贡献者：导入并核对当前市场 → 本地修改 → 提交固定内容 → 跟踪评审 → 按意见更新提交。
- 协助人：收到的贡献 → 查看本 Skill 全部请求 → 看差异、报告、给评审意见。
- 负责人处理贡献：核对本次提交 → 运行适用测评 → 最终确认 → 合并并发布。
- 系统管理员：维护全平台固定片段；不会因此取得别人 Skill 的发布权限。

## 4. 身份、范围与权限

权限由“租户/工作区授权 + Skill 角色 + 系统角色”共同决定，不以按钮隐藏替代后端校验。

| 操作 | 有权访问的使用者 | 当前 Skill 贡献者 | 协助人 | 负责人 | 仅系统管理员身份 |
| --- | --- | --- | --- | --- | --- |
| 看已发布市场内容 | 是 | 是 | 是 | 是 | 仍需相应租户访问权 |
| 导入、移除、编辑本地 | 需工作区写权限 | 同左 | 同左 | 同左 | 不自动获得工作区写权限 |
| 提交贡献 | 需来源可用、工作区写权限 | 是 | 是 | 可直接发布，无需自提 PR | 不自动获得该 Skill 权限 |
| 看贡献详情 | 不默认开放 | 本人请求 | 协助 Skill 全部请求 | 负责 Skill 全部请求 | 不自动跨租户读取 |
| 评论 | 无默认权限 | 本人请求 | 是 | 是 | 不自动获得 |
| 提交评审认可/建议修改 | 否 | 仅另有评审角色时 | 是 | 是 | 不自动获得 |
| 用例草稿建议 | 可随贡献提供 | 是 | 是 | 是 | 不自动获得 |
| 激活正式用例/调整必跑项 | 否 | 否 | 否 | 是，保留审计 | 不自动获得 |
| 运行发布用正式测评 | 否 | 否 | 否 | 是，发布前必须由其发起 | 不自动获得 |
| 我的技能管理：转移负责人、配置协助人、修改分类 | 否 | 否 | 否 | 是，仍需有效租户/工作区授权 | 否，除非同时为当前负责人 |
| 发布/合并并发布 | 否 | 否 | 否 | 是，且门禁通过 | 否，除非同时为负责人 |
| 撤回贡献 | 否 | 本人未结束请求 | 仅本人请求 | 可关闭请求并说明原因 | 不自动获得 |
| 公共片段读取 | 编辑器内 | 编辑器内 | 编辑器内 | 编辑器内 | 是 |
| 公共片段 CRUD | 否 | 否 | 否 | 否 | 是，全平台 |
| 模板新建/编辑 | 需本租户管理员授权 | 同左 | 同左 | Skill 负责人身份不自动获得 | 需明确目标租户管理授权 |
| 通过模板生成并保存本地 Skill | 需工作区创建权限 | 同左 | 同左 | 同左 | 不自动获得工作区创建权限 |

市场内容、贡献和测评依旧在租户访问域内。仅片段正文跨租户共享，且是平台已登录用户共享，不是公开互联网接口。禁止管理员在公共片段放入租户秘密或生产凭据。

Skill 首次纳管时对齐远端创建者/负责人身份；后续通过受控转移维护当前负责人，不能每次读取市场都用不可变的原始创建者覆盖已转移的治理 owner。新建尚未发布的 Skill 使用 CCUI 本地稳定治理 ID，首次成功发布后绑定远端稳定 ID。身份无法映射时禁止发布，不用显示名称或文件夹名称猜测。负责人转移规则见 §7.2.1；远端权限能否同步必须先核验，不以本地字段变化冒充远端权限已转移。

## 5. 内容、来源与状态模型

将状态分开存储，不用一个 status 混合发布、同步和测评状态。

| 维度 | 典型状态 |
| --- | --- |
| 分发 | 尚未发布 / 当前已发布 / 已下架 / 来源不可读 |
| 本地副本 | 存在 / 不存在；来源 market / created / uploaded |
| 编辑 | 已保存 / 有未保存编辑；相对导入基线无修改 / 有本地修改 |
| 更新 | 不适用 / 无远端更新 / 待更新 / 未知 / 远端时间异常 / 来源已下架 |
| 贡献 | open / merged / closed |
| 测评任务 | queued / running / passed / failed / inconclusive / error / timed_out / cancelled；无法确定与系统异常分开 |
| 当前发布资格 | 未测评 / 通过 / 不通过 / 已失效 / 待复核 |
| 发布操作 | preparing / publishing / verifying / succeeded / failed / uncertain |

### 5.1 文件与治理信息分离

Skill 目录保留普通 `SKILL.md`、references、scripts、assets 等文件。不写入片段来源 ID、治理数据库 ID、测评通过标记或发布令牌。

可迁移的是这些文件及普通正文；容器依赖、外部工具、网络资源和凭据并不会随 Markdown 自动迁移。静态兼容性提示和动态环境校验应说明这些依赖，不承诺所有 Skill 任意环境直接可用。

用于并发保存的文件摘要/编辑令牌、用于测评的完整内容摘要，属于技术一致性校验，不对用户展示为版本。

### 5.2 固定候选与保留边界

保存/提交后，服务端将**本次**需要测评和发布的完整文件集合固定为只读候选，计算规范化内容摘要。摘要需包含排序后的安全相对路径、文件字节、必要权限等发布相关信息；不能用 ZIP 压缩包字节直接代替内容摘要，因为压缩时间戳会改变包摘要。

候选仅用于当前编辑、贡献、运行任务、审核证据与发布核对，不建立 Skill 历史目录或恢复接口。更新提交后旧评审可以保留“针对先前提交，已失效”的讨论事实；不要由此提供旧 Skill 一键下载、回滚和历史浏览。

关闭贡献及任务终态后按留存策略处理候选内容；报告保留摘要和必要脱敏证据。下架不触发级联删除。正式留存时长需要运维确认。

## 6. 市场导入和更新：时间规则是唯一业务判据

### 6.1 字段定义

| 字段 | 含义 | 是否参与待更新判断 |
| --- | --- | --- |
| `remoteUpdatedAt` | 远端当前 Skill 更新时间 | 是 |
| `importedRemoteUpdatedAt` | 上次成功导入/同步的那份内容对应的远端更新时间 | 是 |
| `localEditedAt` | 本地文件最近编辑时间 | 否 |
| `importedAt` / `lastSyncedAt` | 本地执行导入/同步操作的时间 | 否 |
| `baselineHash` | 上次成功同步文件的内容基线 | 仅判断本地修改，不判断远端更新 |
| `expectedRemoteUpdatedAt` | 提交贡献/发布前已核对的远端时间 | 用于目标变化保护，不是版本 |

先确认 `tenantId + source + remoteSkillId` 是同一对象，再将远端时间规范化为 UTC 瞬时值；禁止跨对象、跨租户和按格式化显示字符串比较。

```text
未绑定市场                                  → 不适用
远端明确不存在/已下架                       → 来源已下架
任一时间缺失、无效或本次无法读取             → 更新状态未知
remoteUpdatedAt > importedRemoteUpdatedAt  → 待更新
remoteUpdatedAt = importedRemoteUpdatedAt  → 无远端更新
remoteUpdatedAt < importedRemoteUpdatedAt  → 远端时间异常
```

示例：导入内容对应远端时间 09:00，本地编辑 11:00，远端变为 10:00，仍然**待更新**。本地更晚的编辑不能把远端更新隐藏掉。

### 6.2 本地修改保护

| 远端状态 | 本地状态 | 操作 |
| --- | --- | --- |
| 无远端更新 | 无本地修改 | 正常使用 |
| 无远端更新 | 有本地修改 | 展示本地修改；允许按权限测评、贡献或发布 |
| 待更新 | 无本地修改 | 展示更新入口，用户执行后同步 |
| 待更新 | 有本地修改 | 同时展示两个状态；看差异，人工处理或明确确认覆盖 |
| 未知/时间异常 | 任意 | 不宣称已同步；不得通过改写时间掩盖未知状态 |
| 来源下架 | 本地存在 | 保留本地内容；停止普通来源更新，单独处理负责人重新发布 |

“更新”不是自动合并。保留本地内容并取消时，原对照时间不能前移。人工处理应基于当前远端内容重新形成候选，核对完整文件和远端时间后确认；不能只刷新时间戳就宣称已整合远端变化。

### 6.3 同步事务与并发

1. 读取远端元数据 T0，下载当前完整内容到暂存区。
2. 安全校验后重新读元数据 T1。若 T1≠T0，丢弃本次候选并有限次重试。
3. 校验工作区写权限、目标文件并发摘要以及未保存编辑提示；若本地在下载期间变动，要求重新确认。
4. 在工作区写锁下提交暂存文件，并同步写入来源绑定、基线和 `importedRemoteUpdatedAt=T1`。
5. 使用操作日志/暂存交换与崩溃恢复补偿，使文件系统与 SQLite 不能留下“文件旧但时间新”的完成态。成功后才反馈同步完成。

元数据两次读取只能降低竞态，不能构成远端原子读保证。同时间粒度内多次修改仍可能不可见；需验证远端时间字段单位、时区、精度和每次内容修改都会更新的契约。现代码兼容 `modifyTimestamp` / `mpdifyTimestamp`，需统一规范化。

导入失败、取消、查询更新、保存、调试、测评、评审和普通提交，均不得推进导入对照时间。负责人发布后，只有本地候选与已回读确认的远端内容一致，才可同步更新发起工作区绑定；其他工作区不自动变化。

### 6.4 旧数据迁移

- 新增字段允许空值。旧 `importedVersion` 只作过渡兼容，不能推导远端更新时间。
- 不从本地 updatedAt、文件 mtime、导入操作时间或“此刻的远端时间”伪造历史对照。
- 缺失可信对照的导入显示“更新状态未知”，由用户安全重新同步建立新基线。
- 同时清理 UI、类型、缓存键、预览参数与发布前检查中对 Skill version 的业务依赖。
- 不顺带删除用户目录、旧数据列或既有文件；兼容期后是否删除废弃列另做迁移审核。

## 7. 市场、我的技能、模板和片段

### 7.1 技能市场

默认列表，不自动打开第一个详情。只列当前已发布 Skill；已导入排前。名称、说明、分类和负责人可见；支持搜索叠加分类筛选。行内提供导入、更新、移除本地副本；不增加启用开关、置顶控件或质量分进度条。

详情固定为三个 Tab，所有身份（包括负责人）在市场详情中都只读查看：

| Tab | 布局与内容 | 默认状态与限制 |
| --- | --- | --- |
| 概览 | 左侧展示当前市场 Skill 的完整文件树，右侧展示选中文件内容 | 进入详情默认打开概览；文件夹默认全部展开，默认选择根 SKILL.md；单击文件切换右侧，只读，不出现保存、上传、片段插入或文件管理按钮 |
| 测评 | 展示负责人在发布前运行、与当前已发布内容关联的联合测评结果 | 包含总览、静态检查、动态用例结果、测评负责人及时间；只读，不提供用例配置和运行按钮 |
| 管理 | 展示当前 Skill 的负责人、协助人、分类 | 全部只读；无协助人显示“未设置协助人”，无分类显示“未分类”；不提供编辑、人员选择或分类修改控件 |

概览使用**远端当前发布文件**，不读取导入后的本地副本。Markdown 安全只读渲染，代码/文本以只读内容展示；二进制或不支持类型显示不可预览说明。切换文件不修改内容；重新进入另一个 Skill 时恢复全展开与根 SKILL.md 默认选中。根文件缺失时明确提示异常，不编造文档内容。移动端可上下堆叠文件树与内容，语义保持一致。

测评的形成路径为：负责人配置并确认用例 → 负责人发起完整静态与动态测评 → 通过后确认发布 → 远端当前内容回读核实 → 将该次报告关联至当前市场内容 → 市场“测评”只读展示。贡献合并发布也必须使用负责人亲自发起的该次提交测评，不能以贡献者/协助人的自检或代点确认代替。

市场结果不是按 Skill ID 任意取最近一份报告，也不是只显示一个通过徽章。展示发布时关联报告的可公开结果：总体结论、必跑用例通过数、静态问题与逐用例断言结论。私有输入、数据集、标准答案、凭据和原始日志仍按权限隔离，不因市场可见就全部公开。返回市场的 API 使用脱敏投影，不把完整私有报告交给前端后仅隐藏字段。

报告必须对应当前远端内容及发布核实记录，否则显示“未测评”。发布后的本地编辑、草稿测评、未成功发布的报告不能覆盖市场结果；外部渠道改变远端内容或时间后，应先撤下不适用的报告。没有合规报告时不生成虚假的通过结果。

移除只影响本工作区；下架是独立负责人操作，两者文案和确认框分开。市场列表遇到已下架来源不保留伪发布条目，本地仍可在“我的技能”查看来源异常。

### 7.2 我的技能与编辑器

沿用现有文件树、CodeMirror 和 Markdown 预览。四个详情 Tab：文件编辑、单次调试、测评、管理。不再单设“发布与来源”Tab。

- 空白创建和 ZIP 上传沿用现有流程；模板创建先独立生成并预览，用户确认后才写入当前工作区。空白/模板来源为 created，上传为 uploaded。
- 当前目录已存在的合法 Skill 仍可读取；治理字段缺失时逐步建档，不要求重新创建。
- 编辑只改本地，保存不发布；切换 Skill/工作区和离开页面时保护未保存内容。
- 并发修改返回冲突，让用户重新加载或人工比较，不静默覆盖。
- 文件操作继续执行后端路径、类型、大小和工作区权限校验。
- 本地重命名不以名称变化重新绑定远端 Skill；根 Manifest 身份变化须专门确认。
- 负责人显示“发布”，其他可贡献用户显示“提交贡献”；未绑定且非本人负责的 Skill 先解决治理身份。
- 管理页与市场管理页复用同一组字段：负责人、协助人、分类。仅当前负责人看到相应编辑操作，其余用户（包括仅具系统管理员身份者）只读。
- 来源状态、远端/导入对应/本地修改时间保留在详情摘要或编辑器同步提示中；发布、提交贡献保留独立操作入口。已发布 Skill 的负责人下架操作保留在详情操作区，不用旧 Tab 承载，也不在三项管理字段中混入文件保存功能。

### 7.2.1 管理编辑与负责人转移

| 管理项 | 负责人操作 | 约束 |
| --- | --- | --- |
| 负责人 | 点击“转移负责人”，选择同租户有效成员，阅读影响后单独确认 | 不能选自己、跨租户、失效或无资格账户；一次仅有一位负责人 |
| 协助人 | 多选同租户有效成员，保存或取消；可全部清空 | 不包含负责人、不重复；只授予评审和相关请求可见性，不授予发布与管理权 |
| 分类 | 选择当前租户可用分类或未分类，保存或取消 | 不在此创建分类体系；分类管理后台仍是另一权限范围 |

默认交互建议：负责人确认转移后生效，原负责人可显式勾选“将我保留为协助人”（默认不勾选）；新负责人若原为协助人，自动从协助人列表移除。原负责人不因曾经拥有 Skill 保留管理、正式测评或发布权限；没有被保留为协助人时，也不再因旧 owner 身份访问“收到的贡献”。本人提交的贡献仍按作者权限保留。

转移不要求清空文件、关闭贡献或重新创建 Skill。当前贡献的负责人、收到请求列表、市场管理信息及本地详情都读取同一治理记录，保存成功后失效相关缓存，立即按新权限计算；已有评论保留真实作者，不改写历史归属。管理修改不影响普通工作区文件编辑权限，贡献者仍可在有写权限的工作区修改自己的副本。

三项操作与文件“保存”、测评、发布独立。仅变更 CCUI 治理元数据时，不改 SKILL.md、候选字节、远端正文、本地编辑时间、导入基线及 importedRemoteUpdatedAt；其他工作区也不被自动覆盖。分类仅为展示标签时无需重新测评；若分类选择实际切换平台安全/测评策略，则按策略指纹使资格失效，不能把策略变更当普通标签修改绕过门禁。

负责人转移会撤销原所有权授权下的**未来发布资格**。新负责人必须重新核对用例并亲自运行完整测评；即使之后再次转回原负责人，也不能复用第一次拥有时的通过报告。服务端绑定当前所有权授权标识（如 ownerGrantId，或内部权限变更戳），不把它作为 Skill 版本展示。已经发布的市场报告保留当时发起人和结果事实；仅 CCUI owner 变化、内容未变时不把旧报告中的人改成新负责人。若实际同步远端元数据导致远端时间变化，按现有适用性核验流程处理，不伪造更新时间。

并发与失败处理：

- 打开编辑表单记录当前治理 ETag；保存/转移均在服务端重新校验当前 owner、有效成员、租户/工作区授权和 If-Match。旧表单返回冲突，不能覆盖较新的配置。
- 转移持有同一 Skill 治理/发布互斥锁。该 Skill 正式测评运行中、发布进行中或结果待核实时不允许转移，先结束/取消测评或完成发布对账。其他管理修改也不能与不确定发布并发改变授权条件。
- 确认、写入新负责人、调整协助人、失效未来发布资格及记录审计作为一笔治理事务；失败不出现“新旧两人都能发布”或“UI 已转移但服务仍按旧 owner”的成功态。
- 所有写接口实时检查权限，不能依赖打开页面时的角色缓存。审计记录原负责人、新负责人、协助人/分类前后值、操作人及结果；不暴露为 Skill 历史版本。

**当前项目实现限制：**现有 skill-market.js 的 ensurePublishAllowed 仍比较远端 createUserId 与 currentUsername，现有下架路径也检查创建者。因此不能仅修改本地 owner 字段或 HTML 就承诺新负责人已能在真实市场发布。落地时必须统一 CCUI 当前治理 owner 鉴权，并验证远端已有接口是否接受对应新账户或已授权服务身份。没有可用的合法远端授权路径时，实际转移接口不得报告“权限转移完成”，应保持原治理状态并说明能力不可用；不冒用旧负责人凭据、不授予管理员绕过，也不扩展为修改远端后端。原型只模拟上述产品目标，远端授权契约是开发前置验证项。

### 7.3 模板

生成成功后支持“预览 → 补充要求 → 继续修改 → 再预览”的多轮创建流程，满意后才确认保存到我的技能。每轮独立执行并完成基础产物检查，失败或取消保留上一份可用候选；运行中禁止保存或重复提交。此流程不是单次调试追问，不自动发布，不生成 Skill 历史版本；保存后仍须完整测评。详细状态、隔离与并发规则见模板生成方案 §4。

2026-09-10 补充：模板中心支持管理员新建与编辑模板，维护模板名称、模板描述、生成要求、用户填写的自定义字段，以及有序的预置片段正文。首期字段为单行、多行、下拉，支持必填、说明、默认值及下拉选项；不开放脚本或任意表达式。

管理员加入片段时复制当时正文，模板不存片段外键，不因片段更新而变化。用户选择模板后，填写新 Skill 标识/名称/描述和自定义字段值；后端固定输入，在全新独立环境中调用平台维护的 skill-creator。生成结果经过产物结构/路径检查及环境回收，用户只读预览并确认后才原子创建本地 Skill。创建者成为负责人，默认未分类、未测评、未发布。

自定义字段是结构化生成输入，不是片段变量；片段正文仍原样复制。生成失败、取消、超时不能创建半成品或伪装成功；同名不覆盖。生成检查不替代负责人配置用例和运行正式联合测评。模板不引入历史版本、自动发布、持续引用或自动工具启用。

模板沿用租户内共享，租户管理员维护本租户，系统管理员仍需明确目标租户授权。原型以一个租户及系统管理员演示。完整协议、现有 skill-creator 与独立环境的差异详见[管理员模板与独立 Skill 生成方案](superpowers/specs/2026-09-10-skill-template-generation-design.md)。

### 7.4 快捷插入与全平台公共片段

文件编辑下的入口统一为“快捷插入”，弹框提供“片段 / 其他 Skill / MCP 工具”三个 Tab，暂不增加更多类型或第二层分类。搜索框上方不显示“查找……”标题，保留无障碍名称。片段采用列表＋正文预览；Skill/MCP 只显示单列表，不保留右侧预览或空白栏。选择后点击“插入到正文”，也可取消；切换 Tab 清空搜索并选择该类首项，无结果时禁用插入。支持键盘切换页签，窄屏片段列表与预览上下排列。

| Tab | 可选范围 | 插入的内容 |
| --- | --- | --- |
| 片段 | 平台管理员维护的公共片段 | 用户预览的固定 Markdown 正文，保持原有片段语义 |
| 其他 Skill | 当前有权访问的工作区中已导入或创建的技能，排除正在编辑的技能 | 仅实际 Skill 名称（如 sales-summary），不插入展示标题、用途、使用说明或附件 |
| MCP 工具 | 当前工作区已安装且允许使用的具体工具，显示实际工具名称供核对 | 仅实际 MCP 工具名称（如 mcp__demo-data__query），不插入服务说明、参数或凭据 |

所有类型都只产生普通文本，按正文光标插入或替换选区；Skill/MCP 名称原样行内插入，不附加标题、说明、空格、换行或引用语法，不自动保存、发布、运行、安装或修改 allowedTools/Hook/MCP 配置。插入一次可撤销；如果正文或目标文件在弹框打开后变化，拒绝写入并要求重新打开。片段插入已预览的正文；Skill/MCP 插入列表中展示的实际名称，资源变化不静默替换用户已看到的内容。插入文字不会授予权限或保证依赖可用：Skill 和 MCP 的名称可能在迁移后需要调整，运行环境仍须配置对应能力。评测和发布要求保持不变。

正式接入复用当前工作区技能清单与 MCP 工具列表（现有 useWorkspaceMcpTools 的 installed、tools、allowedToolNames、连接状态），服务端仍做租户/工作区授权与工具可用性校验；不将仅“已安装”视为一定可执行，不将服务凭据、环境变量或私有 schema 默认值写入 Markdown。加载失败/无权限/无匹配分别提示，不自动读取其他租户目录。当前 HTML 用内存 Skill 清单及显式标注的 MCP 示例演示，不调用真实发现或连接接口。

**使用端：**只在 Skill 编辑/创建流程中显示片段相关能力。根 SKILL.md 正文编辑支持名称/说明搜索、预览、插入、取消；管理员在模板编辑时也可选择并复制正文。不单设片段类型、分类筛选或分类管理页。

**插入语义：**

1. 读取选中的片段正文，明确预览本次待插入内容。
2. 在有效正文光标位置插入，或替换选区；不插入 YAML frontmatter。
3. 作为一个编辑事务，可一次撤销；只改编辑缓冲区，不自动保存。
4. 插入结果没有片段 ID、注释、引用标记、只读胶囊或隐藏来源元数据。
5. 此后当普通文字编辑；管理员修改/删除片段不影响它，不做批量更新和反向追踪。
6. 若管理员在用户预览后修改，插入用户已看到的预览正文；不要静默改用另一份内容。
7. SQL 片段仅传达书写规范，不修改环境、Hook、MCP、工具白名单或 SQL Check 开关。

正式 CodeMirror 实现对 frontmatter 内光标/跨界选区禁用插入并提示移动到正文；HTML 原型为便于演示，在光标位于元信息时明确提示改为末尾插入。

**管理端：**系统管理员 CRUD，字段为 title、description、content、createdAt、updatedAt、createdBy、updatedBy。固定 Markdown 正文，无变量替换、附件、嵌套引用、版本和使用次数。更新使用当前记录 ETag 做并发保护，不提供历史版本。删除先确认，旧 Skill 不受影响。

片段管理审计仅记录管理员维护行为；不记录“哪个 Skill 插入哪个片段”的关系，也不上传正文到分析埋点。

全平台共享还需部署层保证：若所有租户使用同一 CCUI 治理数据库，可用全局片段表；若存在多个独立实例或数据库，必须由 CCUI 提供同一权威公共片段服务/共享存储，不能在各租户私库分别维护后宣称全平台共享。上线前核对部署拓扑，不要求改远端 data-agent。

### 7.5 分类和预置技能

技能分类属于租户，建议一级领域 + 二级分类；未分类有独立入口。不再为片段设置类型或分类，模板也不新建另一套分类体系。分类删除需处理仍引用该分类的当前条目，可迁到未分类，不能删除 Skill 正文。

预置技能继续沿用现有租户配置和下载流程。它分发整个 Skill，片段只辅助编辑，两者数据表、权限和生命周期分开。

## 8. 单次调试

### 8.1 产品语义

调试是“输入一个任务，真实执行一次完整任务并展示结果”，不是“只调用一次模型”。内部允许多轮模型/工具调用，但任务终态后不可继续追问、恢复会话或加入历史会话列表。

页面风格与会话一致：用户输入、助手 Markdown、工具事件、耗时/错误提示。交互结构不同：没有历史会话、追问框、会话切换和继续执行按钮。提供取消、清空并开始新任务。

### 8.2 容器与数据

建议新增每次任务独立的临时 Claude 运行容器，复用基础镜像，不复用用户普通会话容器。固定当前编辑内容（允许未保存，但明确标注“当前编辑内容”），独立 HOME、工作目录和输出目录。

- 只读挂载 Skill 与显式测试输入；不挂载真实业务工作区、Docker socket 或用户 HOME。
- 测试模型服务通过受控出口/短时代理凭据访问，凭据不对被测工具和产物暴露。
- 默认网络拒绝，只允许模型出口和登记的测试服务；生产工具默认不可用。
- SDK 不持久化 session；业务层也不得写入聊天表、调试记录表或内容日志。
- 浏览器输入与轨迹仅保存在内存；离开调试 Tab、切换身份/Skill、关闭页面即清空。
- 完成、取消、超时、异常均清理容器与临时目录；服务崩溃由带标签的过期资源清理器兜底。
- 可留不含输入、输出和轨迹的基础运维计数；“无记录”要求同时检查服务日志、容器日志驱动和反向代理日志。
- 不自动把调试结果转成测试用例或正式测评；需要沉淀时由负责人另行创建草稿。

隔离运行不可用时明确报错，不降级为宿主机执行。

## 9. 静态 + 动态联合测评

运营默认使用“检查并优化”，不必逐项调度静态检查、执行和评分。每轮按本节协议完整执行，优化器只改隔离候选中的允许内容；最终采用与发布仍需负责人确认。无场景时 AI 先起草，确认后才运行；业务歧义、无改善和预算上限会停止任务。完整任务状态、权限与并发设计见[自动评测与优化方案](superpowers/specs/2026-09-10-skill-auto-optimization-design.md)。原有手工维护与详细测评入口保留。

### 9.1 职责与主流程

| 环节 | 谁提供 | 谁执行/确认 |
| --- | --- | --- |
| 静态基础规则 | 平台开发/治理策略维护者 | CCUI 确定性检测器自动执行 |
| 静态语义建议 | 可选 AI 辅助分析 | 输出建议；疑似高风险走受控复核 |
| 动态用例草稿 | AI、负责人手工、贡献者建议、模板草稿 | 负责人核对标准后激活 |
| 被测运行 | 当前负责人发起，固定 Skill + 用例输入 | 独立隔离 Claude 运行器；服务端记录真实发起人 |
| 结果判定 | 固定规则、可信业务判定器、平台工具策略、负责人确认的语义 rubric | 独立规则与 AI 判定服务联合验收；必需语义项有证据且满足，不由被测 Agent 自报通过 |
| 发布 | 适用联合报告 | 负责人最终确认；不能绕过门禁 |

流程：保存/固定候选 → 固定用例与环境 → 静态检查 → 逐用例动态执行 → 独立判定 → 脱敏报告 → 计算当前发布资格。静态阻断或高风险待复核时，动态标为未执行。

编辑期间可提供“仅静态自检”，但必须标为局部检查，不满足正式发布门禁。正式资格只取同一次完整测评，不拼接多次运行中最好的部分。

### 9.2 静态检查明细与现有覆盖

静态检查不执行被测 Skill，也不自动安装其依赖、访问正文链接或运行包内工具。

| 检查组 | 内容 | 现状 | 首期处理建议 |
| --- | --- | --- | --- |
| 清单结构 | 根 SKILL.md、YAML 语法、name/description 必填及类型、命名约束 | 解析和创建/保存校验已有，入口标准不完全统一 | 必需结构错误阻断 |
| 包与路径 | 路径穿越、绝对路径、符号链接、重复路径、大小/数量/深度 | 部分已有；需前置解包限额并统一规则 | 确定性错误阻断 |
| 资源完整性 | 明确必需本地文件、脚本入口、可解析 Markdown 相对链接 | 缺统一检查 | 必需资源缺失阻断；动态路径/示例不直接误报 |
| 脚本语法 | 支持语言的纯解析检查 | 无统一 Skill 语法报告 | 必需脚本错误阻断；不 import/执行 |
| 安全风险 | 密钥模式、可疑外传、危险命令、越界访问、指令绕过 | 不构成现有完整能力 | 确认违规阻断；启发式高风险待复核 |
| 质量与可迁移性 | 说明模糊、绝对环境路径、缺少适用边界、过长内容 | 未形成统一规则 | 建议，不伪装为正确率 |
| 兼容性 | 当前 CCUI 约束与选定 Skill 格式规范的差异 | 零散 | 独立提示；不擅自改现有名称/目录关系 |

保留现有基础限制作为起点：上传归档约 10 MiB、解包文件数 500、深度 20、单文件约 10 MiB、总解包量约 50 MiB、编辑文本约 5 MiB；实施时以实际常量核对后统一配置。现有发布空文件保护应纳入发布合法性规则，不能仅测根 MD。

每条结果包含 ruleId、detector、严重程度、置信度、文件/行号、脱敏证据、建议、阻断原因及处理状态。检测器结果区分 passed/finding/error/not_applicable/unsupported；崩溃或不支持不能当检查通过。必需检测无法完成则阻断，非必需检测明确标为未覆盖。

扫描器自身也应受 CPU/内存/超时和文件权限限制。第三方扫描器仅作为可替换适配器，需验证离线能力、许可证和资源开销，不是首期不可替代前置。AI 静态审阅仅获得不可信内容与格式约束，无工具权限。

疑似高风险不能通过泛化“忽略并发布”绕过。误报复核须记录证据、操作者和范围，绑定精确内容及规则；复核通过后重新运行完整测评，不能把旧的未执行报告改绿。复核角色未配置时维持阻断。

### 9.3 动态用例格式

这是 CCUI 自定义用例协议，不宣称行业统一规范。schemaVersion 是协议标识，不是 Skill 版本。下面只是明确要求 JSON 的特定示例；普通 Skill 可以交付文字和文件，多来源完整示例见[详细方案 §10.4](superpowers/specs/2026-09-09-skill-evaluation-execution-grading-design.md#104-一个非-json可带-subagent-的完整任务)。outputContract 描述实际交付约束，每条验收项按 target/targets 指定证据，不强制一条任务只有一种结果。

```json
{
  "schemaVersion": "ccui.skill-eval/1",
  "caseId": "TC-REFUND-01",
  "title": "退款应扣减净销售额",
  "required": true,
  "mode": "task",
  "input": {
    "prompt": "读取测试订单，计算净销售额，返回含 net_sales 的 JSON，金额单位为元。",
    "fixtures": ["fixture-orders-refund"]
  },
  "outputContract": {"source": "final_output", "format": "json"},
  "expected": {
    "description": "销售 100，退款 10，净销售额 90。",
    "assertions": [
      {"id": "A1", "type": "json_valid", "target": "final_output", "required": true},
      {"id": "A2", "type": "json_path_equals", "target": "final_output", "path": "$.net_sales", "value": 90, "dependsOn": ["A1"], "required": true},
      {"id": "A3", "type": "tool_policy", "policyRef": "test-read-only-v1", "required": true}
    ]
  },
  "environment": {
    "profileId": "isolated-sales-test",
    "allowedTools": ["read_test_fixture"],
    "networkPolicy": "test-allowlist"
  },
  "budget": {
    "timeoutSeconds": 120,
    "maxTurns": 20,
    "maxOutputTokens": 20000
  }
}
```

格式要求：

- caseId 在本套用例内唯一；名称、明确输入和可验证预期必填。
- fixtures 通过服务端登记的资源 ID 解析，只挂载测试输入，禁止任意宿主路径或 URL。
- 定义不包含 passed、actual、duration 等运行结果。
- 支持 JSON 结构/字段、文本包含或禁止、实际输出文件/内容规则、工具策略、subagent 执行完整性、受信业务判定器及 AI 语义 rubric。
- 不允许用例上传任意 shell/JS/Python 判分代码在服务端执行；复杂评分用平台登记的 graderId。
- 正则、文件读取和 JSON 路径判定均有资源上限；产物先校验路径、类型、大小，不渲染活跃 HTML。
- 不能只用“回答看起来很好”作为必跑标准。语义项需负责人确认 requirement、满足/不满足/无法确定条件、参考依据和证据要求；不需要唯一措辞的标准答案。没有可靠业务依据或清楚验收边界的用例保留为草稿/观察项。
- 覆盖正常、边界、异常输入、安全拒绝等场景；数量按 Skill 风险确定，不规定每个 Skill 机械套用同样业务用例。
- 生成 AI 的猜测不是标准答案；负责人以业务样本、可信计算或明确契约核对。
- 草稿生成只追加待确认项，不覆盖已生效用例或其他草稿；负责人逐条核对确认，不提供未经核对的一键整套替换。正式用例变更记审计，并使原资格失效。

### 9.3.1 用例编辑、确认与删除

用例在 §9.5 的统一表格中管理，已生效、AI 探索与待确认草稿按行区分。“添加验证场景”下拉包含“AI准备场景”和“添加场景”。单独生成草稿不会自动运行、激活或产生通过结论；负责人启动“自动改进”后，新增 AI 草稿可被复制到内部探索集合自动执行，不参与正式发布判定。已有用例的修改草稿不能替换固定标准。原型所有生成/运行均为预设模拟。

| 用例状态 | 负责人可执行操作 | 对测评的影响 |
| --- | --- | --- |
| 新增草稿（AI / 手工） | 编辑、核对并确认、删除 | 不参与正式测评，生成/保存/删除不改变生效定义与资格 |
| AI 内部探索场景 | 查看；必要时整理为待确认正式草稿 | 自动执行以寻找问题，结果不计入发布验收，不自动激活 |
| 生效用例的修改草稿 | 编辑、核对并确认、放弃修改 | 确认前仍按原生效定义执行，放弃修改不删原用例 |
| 已生效、从未随 Skill 发布 | 编辑、确认删除 | 编辑先生成草稿；确认修改或删除后原测评资格失效 |
| 曾随 Skill 发布 | 编辑；删除按钮禁用并说明“发布用例 · 不可删除” | 永久保留用例身份，修改仍须负责人确认并重新测评 |

草稿确认弹窗展示输入、预期及必跑/观察属性，由负责人点击“确认此用例生效”。只确认所选项，其他草稿保持待确认。没有可信预期的草稿不能激活为必跑用例。删除需确认，取消不产生变更；有修改草稿的生效用例须先处理草稿再删除，避免悬空关联。协助人、贡献者及不负责该 Skill 的管理员均只读；市场详情仍只展示已发布结果，不增加用例编辑入口。

**永久保护规则（已确认）：**只要用例曾由负责人确认并用于一次核实成功的 Skill 发布，就写入不可撤销的发布保护标记。后续发布、下架、负责人转移、重新导入或删除本地测试文件均不解除保护。AI 生成后经负责人确认的用例，同样在首次随发布成功后受保护；只生成或只测评通过，不等于已发布。发布失败不新增已发布标记；结果待核实期间锁定相关用例，禁止删除，核实成功后写入保护。

保护绑定服务端稳定 caseId，不接受前端传入或取消。不能通过批量覆盖、换 ID、删除重建或贡献包移除文件绕过；受保护的必跑用例不能改为观察项或停用以达到等价删除。允许负责人修正输入/预期，但保留同一身份和原创建者，并重新确认及测评；旧报告继续引用执行时的固定定义，不被后来编辑改写。首期不提供“解除保护”入口；确需废弃受保护用例属于后续另行决策，不默认放开。

保存、确认、删除都重新检查当前负责人、租户授权、定义 ETag 及原生效定义是否变化；转移后旧表单失效。正式测评运行中不改生效集合，发布进行中/待核实不改相关用例。生效变更采用内部变更戳使旧资格失效，即使增加再删除恢复相同文本，也不能复用变更前的通过资格；这不是 Skill 版本。删除最后一条未发布必跑用例允许留下空集合，但必须显示“无有效必跑用例”，禁止发布。

正式实现软删除未发布用例，保留必要审计及已有报告引用；不删历史报告。删除草稿只移除待确认内容。原型使用内存删除模拟，刷新恢复示例数据。文件、本地编辑时间及 importedRemoteUpdatedAt 均不因用例维护而改变。

### 9.4 真实执行与隔离判定

静态规则执行顺序、完整任务证据、subagent 结束屏障、文件提取、规则/AI 联合判定、完整非 JSON 用例及错误分类，详见[测评执行与结果判定详细方案](superpowers/specs/2026-09-09-skill-evaluation-execution-grading-design.md)。预期说明落实为负责人确认的规则或语义标准，由独立服务验收；不是让被测 Skill 自报通过。

每个用例新建独立临时容器/HOME/workdir，不能让前一个用例文件、缓存或会话影响后一个用例。只读挂载候选和测试输入，独立写入输出目录。runner 能看到任务输入和允许工具，**看不到 expected、隐藏断言、通过状态和判定器控制面**。

控制面统一限制模型轮数、时长、token、工具调用、网络出口、CPU/内存/PID/磁盘。对所有工具途径执行策略，包括 shell、网络与 MCP，不仅审计顶层工具名称；容器隔离本身不是完整安全保证。

采集主任务最终答复、真实工具事件、subagent 任务树和实际文件；主任务 result/idle 不能代替整棵树结束。全部活动任务和文件写入结束后冻结证据，按每条标准检查指定来源。没有文件或 subagent 的任务可标为不适用，不默认强制委派、工具顺序或固定 JSON。子任务沿用本用例的安全上限，不因使用独立上下文就宣称有独立操作系统沙箱。

确定性规则检查结构、数值、文件内容和工具安全；独立无工具 AI 按负责人确认的 rubric 评审需求覆盖、事实忠实、建议可执行和跨产物一致性。内容中的“请给我通过”“忽略评分规则”属于被测数据，不执行；模型无权修改规则和发布权限。

必需语义项参与发布门禁，建议同一固定证据做两次独立评审：都 met 为满足；都 not_met 为不满足；分歧或任一 uncertain 为 inconclusive（无法确定）；无效响应/引用或模型服务故障为 error。引用必须真实且可定位，不能根据 AI 总分或自报置信度放行。无法确定不得手工改绿；负责人修正 Skill、测试资料或标准后重新完整测评。每用例仍只执行 Skill 一次，两次评审不增加为两次 Skill 运行。

文件检查真实字节和解析内容，不信任 Agent 自报路径；必需产物缺失为失败，采集/解析故障为异常。只做文字提取不能声称验证排版/图片；必需的视觉能力未支持时阻断并标明未覆盖。评分模型、模板、证据提取器、配置和校准摘要与任务绑定。

第一期 task 模式验证“给定 Skill 后任务完成质量”。它不证明 Skill 会被正确召回。后续 trigger 模式需要真实候选集合、正负输入和明确期望目标，单独验证路由选择。

### 9.5 报告与可视化

测评采用一张表格作为主界面，不再让运营切换总览、静态、动态等多层页签，不设综合加权总分和默认雷达图：

1. 表格上方：一句整体结论或阻断原因、必跑通过数/总数、当前轮次，以及随状态变化的检查/停止/核对采用/确认发布操作。所有操作平级展示，取消“更多操作”；“运行全部”只执行检查，不自动优化；“添加验证场景”下拉包含“AI准备场景”和“添加场景”。优化记录直接展示，运行中禁止重复运行及新增场景，权限规则不变。
2. 表格列：**验证场景 / 期望表现 / 检查结果 / 问题与优化 / 操作**。第一行为基础检查，随后为每个正式场景与待确认草稿。草稿不计入必跑分母；曾发布场景删除按钮禁用。行内管理提供编辑、删除。
3. “查看详情”按需展开：基础检查展示规则、严重程度、阻断状态、文件定位、证据、建议、未覆盖项；业务场景先展示输入、预期与实际，再折叠规则或 AI 验收、rubric、双评审分歧、根任务/subagent/工具记录、文件产物和解析覆盖。耗时/token 等技术明细放在详情中。
4. 市场与贡献详情复用表格。市场仅取当前发布关联报告的脱敏字段，无运行或用例管理；私有预期、rubric、原始证据不公开。无匹配报告显示“未测评”，不回退到本地结果。贡献检查针对本次提交，保留负责人最终确认发布。
5. 运行中、候选修改待复测、报告失效明确标注，不沿用旧通过状态。窄屏在表格内部横向滚动，保持所有列可访问，不让整页横向溢出。

passed/failed/inconclusive/error/timed_out/cancelled/not_run 都要可区分。环境错误不混作业务失败，也不从必跑分母排除；无用例或全跳过不能显示 100% 通过。重复次数和样本量应明确，单次成功不宣传为模型稳定准确率。

报告属于正式测评记录，要持久化；离开页面后任务继续，可重连查询。取消是显式操作，保留已完成结果和原因并清理资源。报告只读，不提供聊天式继续执行。

### 9.6 发布门禁与失效

服务端每次发布重新校验：

- 当前请求者仍是负责人；工作区和租户权限仍有效。
- 报告的 authenticated initiatedBy、启动时 ownerId 与当前负责人一致，且 ownerGrantId 与当前所有权授权标识一致；这些字段由服务端记录。转移后需新负责人重新运行，转回原负责人也不能恢复旧授权下的资格。
- 同一次完整测评终态通过，静态无阻断、无未处理高风险。
- 至少一个必跑用例，所有必跑通过；必需规则全部通过、必需语义项全部满足，无无法确定、异常或未完成项；所有已执行用例观测到的安全违规为零。
- 候选内容、当前生效用例/rubric、平台策略、检测器、运行镜像、执行与判定模型/模板/配置、文件提取器和测试依赖指纹匹配；必需证据仍可用。
- 未超过有效期；未被当前适用条件下更晚的失败/异常/取消结果替代。
- 提交核对的远端时间仍符合发布前条件。
- 前端不能上传 passed=true 代替真实任务，也不能挑旧报告绕过失败。

内容改动只使**当前资格**失效，不篡改旧报告事实。第三方渠道更新后即使名称不变，旧报告也不能自动套用到新内容。

## 10. 贡献请求

### 10.1 两个子 Tab

“收到的贡献”：用户作为负责人或协助人的 Skill 的所有请求，支持状态、Skill、贡献者筛选。“待我评审”可以是辅助标记，不作为协助人可见范围过滤条件。

“我提交的贡献”：本人提交的所有请求，包含进行中、已合并、已关闭。用户兼具负责人/协助人和贡献者身份时，同一请求可出现在两个 Tab，不复制数据。

### 10.2 提交、评审和修改

提交要求稳定目标 Skill、当前远端内容核对、标题、原因、完整变更文件。后端固定本次提交文件和 `expectedRemoteUpdatedAt`，返回 PR 编号；提交本身不发布。

详情显示当前市场与本次提交的逐文件新增/删除/修改 diff、说明、讨论、评审及适用报告。提交者更新内容后创建新的当前提交引用，旧评审标记针对之前提交，旧报告不满足当前资格。不要把它称为 Skill 历史版本。

贡献者建议的用例变更由负责人独立核对生效；不能通过在包里删测试或标记 optional 来修改平台权威用例。贡献者不能更改负责人、绕过工具策略或携带发布令牌。

远端更新后需重新核对并处理完整文件差异，不允许仅更新 expectedRemoteUpdatedAt 就消除冲突。

### 10.3 合并语义

首期“合并”就是“把负责人确认且测评通过的本次提交发布为市场当前内容”，不设计合并到隐藏分支再另行发布的复杂链路。

```text
open → 评审/测评/人工处理 → 负责人确认 → 发布中 → 回读核实成功 → merged
open → 贡献者撤回或负责人关闭（填写原因） → closed
发布超时/回读不确定 → 保持 open + 发布结果待核实 → 对账后确定结果
```

协助人认可不是必需，自动测评是必需。只有远端成功且回读核实匹配才标 merged。已合并或已关闭请求不能继续变更提交；重新修改另建请求。

发布中/结果不确定期间锁定该请求的再次发布、更新提交和关闭操作，避免把未确认操作当失败重发。合并不会覆盖其他工作区已有本地副本。

## 11. 发布、下架与远端并发限制

### 11.1 CCUI 发布事务

1. owner 预览确认，服务端固定候选及适用报告，建立持久发布任务和幂等请求键。
2. 获取 CCUI 中该租户 + Skill 的发布锁，重新校验权限、报告和远端当前更新时间。
3. 复用远端现有保存/更新/发布接口，发送当前负责人已测评的固定完整内容，不在发布时重新读取活动目录。
4. 回读当前完整内容及更新时间，规范化比对内容；成功后更新本地操作状态，并绑定此次发布使用的 owner-run evalRunId、内容摘要、发起负责人和远端更新时间，供市场测评页只读展示。
5. 根据发起路径完成直接发布或 PR merged；源工作区的绑定只在内容仍一致且可确认时更新。

所有 CCUI 写入发布入口都要接入同一服务，包括现有 submit、publish、upload-publish 以及任何内部调用。发布门禁不能只做新 UI 或单个路由。相关旧接口保持兼容时也不能绕过门禁。

CCUI 幂等键只防止本应用重复受理，不意味着远端支持幂等。远端返回超时、网络断开、部分成功或回读不匹配都要进入核实流程；不得立即盲重试，也不能无条件显示失败。

### 11.2 只能改 CCUI 的能力上限

用户已确认保留外部直接发布。远端现有接口没有已验证的原子 compare-and-swap、幂等发布或跨系统事务，因此：

- CCUI 只能约束自身发布路径，不能强制所有渠道测评。
- CCUI 进程内/数据库锁只能阻止 CCUI 内部冲突，不能锁住外部发布者。
- 发布前检查与发布后回读能发现部分竞争，但不能保证检查和写入之间无外部覆盖，也不能证明稍后远端不会变化。
- 当前完整内容回读接口、更新时间契约和权限映射必须先验证；不依赖历史读取/queryVersion 补强保证。
- 无法确认当前内容时显示“待核实”或“未测评”，不伪称远端最终内容一定是已测评内容。
- 不为解决这个限制擅自停用其他发布渠道，也不自动覆盖外部修改。

这是方案明确接受的系统边界，不通过“加一个 hash”掩盖缺少远端原子条件的问题。

### 11.3 下架与重新发布

下架只停止分发，保留治理身份、本地文件、贡献讨论、测评记录及操作审计；不建立 Skill 历史版本。

负责人重新发布同一 Skill 前重新核对远端身份/存在性，固定当前候选并满足门禁。不得让“来源已下架”永久堵死 owner 的重新发布通路，也不得把重新发布伪装成普通导入更新。如果远端删除会失去稳定 ID，使用原身份重建还是新身份需验证接口契约并显式处理。

## 12. CCUI 技术架构

```text
现有 React 技能界面
    ├─ 文件编辑、来源同步 → workspace-skills / skill-market
    ├─ 贡献、用例、报告、发布 → 新 skill-governance 路由
    ├─ 单次调试 → 独立短生命周期任务与事件流
    └─ 编辑器片段读取 / 系统管理员片段维护

治理服务（Express + SQLite）
    ├─ 身份/权限、候选内容、并发锁、来源时间
    ├─ 持久任务队列与 worker（测评 / 发布）
    ├─ 静态检测器 → 独立动态 runner → 任务树/工具/文件证据 → 规则与 AI 联合判定器
    ├─ 隔离文件区、脱敏报告、过期清理
    └─ 远端适配器 → 现有 data-agent 当前内容接口
```

沿用当前 React/TypeScript、Express、SQLite 与 Claude SDK，不为首期引入独立测评平台、Git 分支系统或重型图表系统。实现时提取服务模块，不把整个功能继续堆入单一 UI 面板或 skill-market.js。

建议新增服务：skill-governance、skill-candidates、skill-contributions、skill-test-suites、skill-evaluations、skill-isolated-runner、skill-publish-jobs、skill-snippets。持久队列需数据库领取租约、心跳、过期恢复和唯一执行约束；不能仅靠 setTimeout、内存 Map 或 HTTP 请求生命周期。

### 12.2 建议 API

保留现有工作区文件和市场读取 API，新治理能力统一 `/api/skill-governance`。下面路径为设计稿，不代表当前可调用。

| 方法与路径 | 用途 / 关键约束 |
| --- | --- |
| GET /skills/:id | 当前治理信息、权限、时间状态、适用摘要 |
| GET /skills/:id/management-members | 按租户/工作区授权返回可选负责人与协助人；不开放全平台账号枚举 |
| PATCH /skills/:id/management | 当前负责人修改协助人/分类；If-Match、成员授权和发布互斥检查，不接受 ownerId 字段 |

| GET /skills/:id/published-evaluation | 当前发布关联报告的只读脱敏投影；核验内容与远端时间，不能返回私有原始用例和日志 |

| GET /skills/:id/test-suite | 读取有权查看的用例 |

| DELETE /skills/:id/test-cases/:caseId | 负责人删除从未发布的生效用例；拒绝永久保护项，检查任务互斥/If-Match，软删除并使资格失效 |
| POST /evaluations | 当前负责人创建发布用持久联合测评；服务端记录发起人、启动时负责人及所有权授权标识，返回 runId |
| GET /evaluations/:runId | 进度、报告、适用性；重连恢复 |
| POST /evaluations/:runId/cancel | 显式取消、资源回收 |
| POST /debug-runs | 创建一次临时调试任务，无持久执行记录 |
| GET /debug-runs/:id/events | 仅当前任务的短时事件流，需鉴权 |
| DELETE /debug-runs/:id | 取消并清理；不提供历史查询 |
| POST /skills/:id/publish | 负责人直接发布，candidateId + 服务端适用报告 + 幂等键 |
| POST /contributions/:id/merge-publish | 负责人合并并发布当前提交 |
| GET /publish-jobs/:id | 发布/核实状态 |
| POST /skills/:id/unpublish | 下架，保留治理记录 |
| GET /snippets | 编辑器读取固定片段，平台登录态 |
| POST/PATCH/DELETE /admin/snippets[/:id] | 系统管理员维护，更新带 ETag |

时间、权限和通过状态由后端计算。稳定错误码建议覆盖：permission_denied、local_conflict、remote_changed、remote_time_unknown、eval_required、eval_stale、eval_failed、publish_uncertain、quota_exceeded。响应含可读说明和可执行下一步，不只返回“操作失败”。

## 13. 安全、可用性和性能

- 所有读写按租户/工作区/Skill/请求授权；枚举 runId、PR ID 和 artifact ID 不能跨域访问。
- 未知身份、检测器错误、运行器不可用、报告失效均不能 fail-open。
- 容器非特权、最小文件权限、资源限额；拒绝宿主目录、Docker socket、生产凭据。
- 测试工具采用注册表与固定测试配置，不能由 Skill 指令自行扩大权限。
- 阻止文件路径穿越、ZIP 重复条目、越界链接、解压资源耗尽；扫描和读取都需限制。
- 前端 Markdown 和产物展示进行 HTML/URL 安全处理，不执行 Skill 内脚本或活跃内容。
- 用例生成会将选定 Skill/测试背景送往配置的模型服务，应遵循现有数据授权；不默认抓取工作区全部文件。
- 日志、报告、trace、模型错误栈做敏感信息脱敏；原始秘密证据只保留必要最小范围，不在列表预览回显。
- 正式测评按用户/租户配额排队；建议首期单次最多 20 用例、全局并发 2、租户并发 1，具体按机器容量确认。
- 每用例建议 120 秒、20 轮、20k 输出 token，并设置整次任务预算；这些是起点，不是性能保证。
- 任务异常结束清理临时资源；重启恢复测评为 error/可重跑，而不是无证据地接着标成功。发布任务优先对账，不盲重放。
- 列表分页、筛选请求取消、内容按需加载；大型 diff/trace 分页/虚拟化，下载产物鉴权且限时。
- 保留现有主题、国际化和键盘操作习惯；状态不只靠颜色，按钮有文本，弹窗有焦点管理，移动端表格转摘要或局部滚动。

## 14. 实施计划与依赖

下面是一个首期闭环内部的实施顺序，不表示可以先开放无门禁发布。

| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| P0 契约与身份验证 | 核对远端更新时间、当前完整内容读取、owner 映射、转移后的合法发布授权和下架重建语义 | 无法确认的契约有明确降级/阻断，不伪造保证 |
| P1 数据与同步基础 | 治理身份与管理编辑、负责人转移、时间字段迁移、文件并发/暂存恢复、移除版本依赖 | 角色撤销、治理冲突、时间矩阵、并发更新和旧记录未知状态测试通过 |
| P2 编辑与片段 | 工作入口、本地详情页、固定正文插入、管理员片段维护 | 插入无引用/无自动工具启用，本地编辑保护完成 |
| P3 静态检测与独立运行器 | 统一静态规则、临时调试、真实动态执行、安全策略与清理 | 不写会话历史，隔离/取消/超时/崩溃验收通过 |
| P4 用例与报告 | 草稿确认、可信断言、持久测评队列、统一表格与按需详情 | 报告可追溯且当前适用性正确；零用例/异常不通过 |
| P5 贡献与发布闭环 | 两子 Tab、评审、固定提交、统一门禁、发布核实任务、下架保留 | 所有 CCUI 发布入口受控；外部发布竞争/不确定状态测试通过 |
| P6 上线与增强 | 管理员模板/字段与独立生成任务验收、迁移演练、权限/资源监控和分类完善 | 试点可用、回归完成、运维可恢复 |

首期上线门槛必须同时包含 P1—P5 的关键闭环，尤其不能把动态测评推到“发布已上线之后再补”。若运行器未具备安全环境，相关发布入口保持受控不可用，而不是提供临时绕过按钮。

## 15. 验收清单

### 15.1 内容与同步

- 市场详情只有概览、测评、管理三个一级 Tab；概览默认全展开文件树并选中 SKILL.md，切换只读文件不受本地编辑影响。
- 市场管理页负责人、协助人、分类对所有身份均只读；测评页无运行、用例编辑或发布控件。
- 我的技能只有文件编辑、单次调试、测评、管理四个详情 Tab；管理与市场展示同样字段，仅当前负责人有三个管理编辑入口。
- 协助人/分类保存与取消不改变 Skill 文件、本地修改时间、导入对照时间或已发布报告；市场与本地管理信息一致。
- UI/API 不再有 Skill 版本、历史查看、回滚、版本选择；协议兼容字段不暴露为产品概念。
- 本地编辑时间晚于远端更新时，仍根据两份远端时间正确显示待更新。
- 相等、不等、缺失、非法、时间倒退、来源下架均有独立处理。
- 保存、刷新、测评、调试和评审不改变 importedRemoteUpdatedAt。
- 更新遇本地修改/未保存编辑要确认；取消/失败后文件与对照时间不变。
- 下载期间远端变化、本地变化、进程崩溃均不能留下错误成功状态。
- 旧记录不伪造导入对照；一个工作区更新不修改另一个工作区。

### 15.2 片段、权限与贡献

- 普通用户仅编辑器看到片段；系统管理员可维护；租户管理员不能越权。
- 插入内容可编辑和撤销，不保存 ID/来源引用，不自动保存/发布。
- 管理员改删片段不改旧 Skill，不能查询其使用关系；SQL 规范不启用任何实际检查。
- 收到的贡献包含协助 Skill 全部请求；我提交的贡献按作者过滤；同记录可在两边出现。
- 协助人不能发布、合并、激活正式用例；管理员身份不自动取得发布权。
- 非负责人不能转移负责人、配置协助人或修改分类；伪造接口、跨租户成员和过期治理表单被拒绝。
- 转移须二次确认；新负责人从协助人中移除，原负责人仅在主动选择保留时成为协助人，相关贡献可见范围随角色即时重算。
- 转移撤销旧负责人未来发布资格；新负责人需重新测评，转移后再转回也不能沿用旧授权报告；已发布报告保留当时发起人。
- 正式测评中、发布中或发布待核实不允许转移；真实远端授权不具备时不能出现部分成功的权限转移。
- 负责人无需协助人认可即可在联合测评通过后发布。
- 提交更新、远端变更、权限变更使适用性重新校验；不确定发布期间不能重复操作。

### 15.3 调试、测评与发布

- 调试一次结束，不可续聊；离开清空，后台/容器/代理日志也不持久化内容轨迹。
- 正式测评可离开重连，报告持久且隔离授权，与聊天记录分开。
- AI 草稿不能自动成为标准；测试预期和隐藏判定不进入被测 Agent 上下文。
- 新增 AI 草稿可自动参与内部探索，不阻塞已有固定标准的优化任务；无固定必跑标准时可探索，但不能采用为合格结果或发布。
- 自迭代最终候选必须通过完整回归、独立新样本和关键场景重复执行。探索通过不能代替正式验收；验收失败、超预算和不稳定均不能采用。
- Skill 无需固定 JSON；文字/多文件和可选 subagent 均可验收，根任务 result 早于子任务结束时不得提前判分。
- 必需语义项参与门禁；双评审分歧/无法确定、伪造证据引用、评分服务错误都不通过，也不能人工改为通过。
- 文件存在但内容错误仍失败，提取器不支持/截断时必需范围不能冒充已覆盖。
- AI 生成只追加草稿，手工添加先存草稿；单条确认不激活其他项，删除草稿不变更生效用例或旧报告。
- 曾发布用例永久不可删除，转移/下架/重新导入不解除保护；成功发布保护实际使用集合，失败不误标，待核实禁止删除。
- 未发布生效用例可以确认删除，取消无变化；最后必跑项删除后无法发布；旧表单、非负责人和伪造保护字段均被拒绝。
- 贡献者/协助人运行通过不能代替负责人发布前的测评；切换身份或伪造发起人字段不能改变真实运行归属。
- 贡献者/协助人及其他有本地编辑权限的用户可运行自己的本地测评与自动优化。local 与 release 报告隔离，个人采用不覆盖负责人文件、正式标准或市场报告；贡献提交后由负责人重新正式测评。
- 个人测评不自动获取负责人私人样本、隐藏验收集或工具权限；仅运行已授权的共享材料与个人探索场景。详见[自动优化方案 §17](superpowers/specs/2026-09-10-skill-auto-optimization-design.md#17-本地测评与正式验收的权限分离本次确认)。
- 市场测评结果由已核实成功的发布关联，展示当前内容的静态与动态结果；本地编辑或新的草稿报告不覆盖已发布结果，私有测试数据不随结果公开。
- 静态阻断不跑动态；检测器失败/不支持/超时不默认为通过。
- 每个动态用例隔离，无前例残留；生产写入、越权文件、网络外传路径被控制。
- 零必跑、失败、错误、超时、取消、未执行都不能通过门禁。
- 内容/用例/策略/环境改变后不能拿旧通过报告发布；不能拼接最优结果。
- 首次发布、普通更新、贡献合并、上传发布、重新发布均统一校验。
- 远端超时先核实，回读不匹配不标成功；PR 仅确认成功后 merged。
- 外部发布仍可发生；无适用报告的当前内容显示“未测评”。
- 下架不删报告、贡献与本地内容；不提供历史 Skill 恢复功能。

## 16. 本次 HTML 原型

入口：[打开技能市场交互原型](prototypes/skill-market/index.html)

说明与验收：[原型 README](prototypes/skill-market/README.md)

定位：单文件、离线可打开的交互演示，不是 React 业务实现。全部数据在页面内存，刷新重置；不连接市场、Claude、数据库或云服务，不会产生真实发布或工具调用。

视觉基准为 §3.1 所列的当前 CCUI 组件。原型的工作区、会话、设置及其他顶部功能入口只示意现有应用外框，不提供真实功能；可交互范围仍限于技能相关流程。演示身份选择位于侧栏底部，手机上需先展开侧栏。

覆盖：市场列表/详情与导入更新、本地编辑/预览/片段插入、负责人管理编辑及转移、单次调试生命周期、联合测评场景与报告、测试用例草稿确认、独立 AI 评审标准配置/双评审结论/证据/任务树/文件产物、贡献双子 Tab 与处理、负责人模拟发布/下架、管理员模板/自定义字段/预置正文、独立生成模拟与候选采用、系统管理员片段新增及维护。

演示身份可切换负责人、协助人、贡献者和系统管理员。所有演示身份默认具有当前示例工作区编辑权限，不模拟完整租户授权或账号登录。

原型简化项：

- 单一工作区、固定示例数据；没有真实并发、持久队列、鉴权、容器或安全检测。
- 管理编辑与转移只模拟本地治理规则、旧表单冲突和角色撤销；没有改造现有远端创建者鉴权，不代表真实发布权限已可转移。
- 动态输出与测评场景均为预设模拟，不能作为 Skill 真实质量证据。
- 文件编辑用 textarea 演示；生产沿用 CodeMirror。上传仅演示单个 MD 本地读取，正式系统沿用 ZIP。
- 贡献 diff 演示当前正文两栏；生产要求完整逐文件差异及当前提交更新。
- 用例编辑展示名称/输入/预期/交付形式/参考依据/必跑项，以及 AI 验收项的三种判定条件和证据范围；规则类型编辑仍为预设简化，完整结构化协议以 §9 为准。
- TC-07 以 Markdown 报告演示非 JSON 任务；AI 不满足、双评审分歧、无法确定、评分服务异常分别呈现并阻断发布。市场仅返回两次评审的脱敏结论，不公开标准与引用原文。
- 片段不单设分类；模板维护、自定义字段、固定正文选取、独立生成/取消/失败/预览/采用均为内存模拟，不代表真实后端、skill-creator 或容器能力已接入。
- 超时对账、异常下载、跨工作区同步、资源隔离和留存恢复须由实际服务集成测试验收，HTML 不能证明。

## 17. 原 V2 其余能力的安排

完整方案保留其目的，但不把下列功能混入首期发布门禁或声称已经实现：

| 能力 | 后续设计方向 | 约束 |
| --- | --- | --- |
| SOP → Workflow 编译 | 以当前项目 Workflow 能力为候选目标；分析固定步骤、生成产物草稿、人工核对后单独测评 | 需先验证实际执行接入；含模型/外部工具的流程不能承诺完全确定性 |
| 编译产物检验 | 用明确业务用例验证产物行为，记录不支持步骤 | 有限用例通过不等于证明全域等价；产物仍走负责人发布与联合门禁 |
| description 优化 | AI 给出适用/不适用范围和措辞建议，由负责人编辑普通字符串描述 | 不直接把当前兼容的 description 改成不兼容对象；不自动发布 |
| 召回测评 | 单独 trigger 模式、正负样本、明确候选集合和选择证据 | 直接加载目标 Skill 的任务测评不能冒充召回准确率 |
| Badcase 闭环 | 经授权、脱敏、人工复核后生成用例草稿 | 不从无持久记录的调试中暗中采集；不自动把用户对话作为共享数据 |
| 相关度搜索/向量召回 | 先优化当前 CCUI 可控的检索，验证规模与权限过滤 | 不能假定可改远端检索接口，跨租户隔离不变 |
| 无 Skill 基线、重复运行统计、A/B | 另行设计实验口径与成本预算 | 不借测评对比恢复 Skill 历史版本或默认新增报告比较页 |

## 18. 待确认与上线前验证

不阻塞本次方案和原型交付，但会影响实际开发范围或上线安全：

1. **模板共享范围**：当前沿用租户内；本次“管理员新建模板”不默认扩大为全平台模板共享。
2. **高风险误报复核**：是否仅系统管理员可复核，还是设专门安全审核角色？未明确前不提供忽略入口。
3. **下架和身份**：是否允许系统管理员强制下架；已确认的负责人转移功能如何通过现有远端接口获得合法发布授权（不能仅改本地 owner）；远端删除后能否复用稳定 ID。
4. **环境预算**：可用隔离容器资源、测试工具/数据库替身、模型出口与模型配置、超时/token/并发配额。
5. **留存与适用期**：报告、贡献、产物、必要候选证据保留多久；24 小时资格 TTL 是否合适。
6. **远端契约**：更新时间精度/单位/修改范围、当前完整文件回读、发布失败语义与外部并发行为。若契约不成立，明确限制而非在 CCUI 内伪造原子保证。
7. **模板落地配置**：管理员模板及自定义字段已纳入方案；需确定生成器受控配置、任务保留期与独立资源预算。租户管理员的具体角色映射需接入现有权限。
