## 1. 阅读说明与范围

本文按最新确认结果重新组织待实现功能，不按对话发生顺序罗列。已有列表、搜索、文件上传、基础文件 CRUD、基础导入发布、普通聊天及命令调用不列为新需求，也不展开操作流程。代码路径仅用于定位改造点。本文中的“新增模块”“建议接口”“任务存储”都是目标设计，不代表当前仓库已经实现。

这里的“待实现”以生产代码为准：HTML 已演示某项交互，不代表该功能的前端、服务端和运行器已经接入。涉及已有模块时，只列本次增量，例如“发布前增加测评门禁”，不重述原有发布流程。

当前原型为浏览器内存中的交互演示：生成、文件写入、测评、AI 判定、优化和发布均为模拟，刷新重置，不能作为真实执行效果的证据。

### 1.1 本期目标

让运营通过普通会话创建和使用 Skill，逐步积累用例，由 Agent 完成测评、定位问题、修改并复测，减少人工操作；人保留业务输入、直接编辑 MD、共享发布及治理决策。

主流程：

```text
管理员维护模板/片段
  → 运营选择模板，在会话中补充信息
  → 独立环境调用 skill-creator，检查后自动保存到我的技能
  → 普通会话继续调整或直接调用 Skill
  → 将完整调用保存为用例 / 手工添加 / AI 添加
  → 运行全部，或自动优化（全量前测 → 自动写入 → 全量后测）
  → 查看完整会话输出与本次文件变化
  → 有权人员直接发布，或经贡献请求合并发布
```

### 1.2 已确认、不得恢复的旧交互

| 主题 | 当前约定 |
| --- | --- |
| Skill 内容 | 不区分业务版本，不提供历史版本查看/回滚入口 |
| 更新判断 | 比较远端当前更新时间与本地上次成功导入内容对应的远端更新时间；本地编辑时间不参与 |
| 片段 | 固定 Markdown、全平台共享、管理员维护，无版本、参数、动态引用与已插入内容回改 |
| 模板/片段浏览 | 普通用户均可见、只读并可使用；不等于普通用户能维护库 |
| 会话生成 | 底部能力行“技能生成”；选模板后提示“请输入额外补充信息…”；name 由用户填写 |
| 调试 | 不新建 Skill 调试页或试用模式，直接使用真实聊天和原有 Skill 调用 |
| 用例定义 | 每个 Skill 的 `evals/evals.json` 是唯一可编辑真源 |
| 添加用例 | 手工、AI、会话保存均校验后直接写入，无草稿确认/验收标准确认 |
| 运行 | 留在测评页后台串行执行，不跳转到会话 |
| 自动优化 | 全量前测 → 修改自动落盘 → 同一批用例全量后测；无采用/确认改动，无自动发布 |
| 输出详情 | 单次运行单列会话；优化前后左右两列完整会话输出，不只展示总结或分数 |
| 技能角色 | 创建者初始为负责人；负责人指定 Skill 管理员；两者均可发布、合并 |
| 直接发布 | 当前发布者本人完成当前内容测评并通过；发布确认仍保留 |
| 贡献 | 提交、合并免测评；不能 Approve 自己；正常合并需一位他人认可，负责人可直接合并 |
| 下架 | 取消市场分发，保留本地内容、贡献、报告及审计；不恢复历史版本概念 |

本期不增加复杂模板编排、片段双重分类、版本中心、自动发布、无限多轮自优化、默认召回测评、无 Skill 对照实验或固定八维评分。相关扩展不混入当前验收标准。

### 2.2 权限矩阵

以下权限均须先满足当前租户、工作区和资源访问范围。拥有市场治理权限不自动获得任意工作区的文件编辑权。

| 操作 | 普通查看者 | 工作区本地编辑者 | 当前负责人 | 指定 Skill 管理员 |
| --- | --- | --- | --- | --- |
| 查看市场、模板、片段 | 授权范围内可见 | 同左 | 同左 | 同左 |
| 使用模板创建 | 需工作区创建/编辑权 | 可以 | 需工作区权限 | 需工作区权限 |
| 改本地文件、维护用例、测评、优化 | 不可以 | 可以 | 需工作区编辑权 | 需工作区编辑权 |
| 评论/Approve 他人贡献 | 有 Skill 查看权即可 | 同左 | 同左 | 同左 |
| Approve 自己的贡献 | 不可以 | 不可以 | 不可以 | 不可以 |
| 已有有效他人 Approve 后合并 | 不可以 | 不可以 | 可以 | 可以 |
| 无 Approve 直接合并 | 不可以 | 不可以 | 可以，独立审计 | 不可以 |
| 直接发布 | 不可以 | 不因本地编辑权而获得 | 本人当前测评通过 | 本人当前测评通过 |
| 转移负责人、配置管理员、改分类 | 不可以 | 不可以 | 可以 | 不可以 |
| 下架 | 不可以 | 不可以 | 沿用负责人权限 | 不因本次授权自动获得 |

平台库管理员与 Skill 管理员分开：全平台片段复用系统管理员权限；模板维护沿用授权管理员及当前方案的租户范围。普通租户管理员不能因此获得全平台片段写权限。模板是否也全平台共享尚未明确扩展，本文不擅自扩大。

`createdBy` 记录最初创建人，`ownerId` 表示当前负责人。转移后原负责人不再拥有隐式权限，不自动加入管理员；新负责人从管理员列表中移除，其他管理员保留。负责人转移、成员有效性和权限撤销均在服务端检查。

### 2.3 三条数据边界

1. **工作区文件不等于个人数据库副本。** 不同物理目录彼此独立；同一共享工作区同一 Skill 目录只有一份文件，同目录编辑者看到同一份 `evals/evals.json`，必须共享写锁和失效通知。不能按 userId 额外制造互相矛盾的“个人用例正文”。
2. **业务无版本不等于取消一致性检查。** 内容 hash、文件 revision/ETag、任务 runId 和本次前后快照是并发与证据机制，不作为业务版本暴露，不提供历史恢复功能。
3. **本地自动保存不等于市场发布。** 生成和优化可直接保存已授权工作区；市场发布/贡献合并仍需要有权限的用户显式执行。

## 4. 功能逐项设计

### F01 市场详情与本地详情重组

**入口/角色：** 技能市场和我的技能；所有用户在授权范围内查看。

**流程与展示：**

1. 市场打开 Skill 默认进入概览，左侧完整文件树默认展开，右侧默认只读展示 `SKILL.md`；切换文件不改变内容。
2. 测评展示当前发布内容适用的公开报告，无运行/优化/添加按钮；未有适用报告时明确显示“未测评”。
3. 贡献展示该技能所有可访问请求；管理只读展示负责人、Skill 管理员、分类。
4. 我的技能默认文件编辑；测评和管理独立 Tab。仅负责人可编辑管理信息；本地文件是否可编辑仍按工作区权限。

**影响：** M01、M04、M05、M06、M09；新增详情组件与报告/治理接口。

**注意：** 不因为用户是负责人而开放市场文件直接编辑；不在“管理”偷偷恢复版本或发布来源 Tab。文件不可预览、缺失、加载失败各自提示；先授权再读取内容，不能只隐藏按钮。原本的导入/更新动作保留，不把新布局改造成新文件编辑器。

**验收：** 默认展开与默认文件正确，市场三个只读区无法写入，本地权限区分生效，报告与所选技能匹配，切换时无上一个技能数据残留。

### F02 公共片段库管理

**入口/角色：** 技能区域“片段管理”；普通用户浏览，系统管理员新增/编辑/删除。

**流程与数据：** 管理员填写片段名称、说明、固定 MD 正文，校验后保存；用户可搜索、查看完整正文并在编辑时使用。全平台只有公共库语义，不设置双重分类、版本、占位参数或动态引用。

**影响：** M01、M06、M09、M11；新增公共片段 CRUD、只读查询、系统管理员鉴权及维护审计。

**注意：** 全平台共享意味着正文不能含租户内部凭据、客户资料或私有环境配置。插入到 Skill 后成为普通文本，普通编辑者可修改这份副本；库删除/编辑不回改已有 Skill。模板内已经复制的预置正文也不静默更新。可以保留库操作审计，但不建立“哪些 Skill 引用此片段”的活引用关系。SQL Check 片段只是指令文字，不启用真实 SQL 校验。

**验收：** 普通用户可见内容但 CRUD 请求被拒绝；改库不改变已插入内容；发布包没有片段占位符或运行时加载依赖。

### F03 文件编辑中的快捷插入

**入口/角色：** 我的技能文件编辑器“快捷插入”；本地编辑者。

**流程与展示：**

- 弹框分“片段 / 其他 Skill / MCP 工具”三个 Tab；搜索框上方不增加重复标题行。
- 片段有列表与右侧正文预览；确认插入时复制完整正文。
- Skill 和 MCP 只显示列表，不展示右侧内容区；只插入所选名称，不加路径、配置、完整文件或额外解释。
- 插入到打开弹框时所对应文件的有效光标/选区，并支持编辑器撤销。

**影响：** M01、M02、M04、M06、M11；关联当前可用 Skill、MCP 工具目录和公共片段查询。

**注意：** 仅展示有权使用的资源，选择时再次检查是否存在/可用；插入名称不等于安装 Skill、启用 MCP 或授权工具。切换文件、光标失效、编辑器只读时不能插错位置。避免把片段插入 YAML frontmatter 导致文件失效；不把“快捷插入”设计成隐式依赖安装器。

**验收：** 三种插入内容准确，Skill/MCP 无预览区，搜索无结果时不可插入旧选择，文件切换无错写。

### F04 模板中心与模板维护

**入口/角色：** 模板中心；普通用户看和用，获授权管理员维护模板定义。

**流程与字段：**

1. 管理员配置模板名称、描述、自定义字段、默认值及预置片段正文。
2. 字段首期支持单行、多行、选项；字段有唯一 key、标签、类型、是否必填、默认值、选项及简短提示。
3. 普通用户可查看用途、需补充信息和预置内容，点击“在会话中使用”，不要求其创建模板或理解模板配置结构。
4. 模板选择完成后进入 F05；此时还没有创建 Skill。

**影响：** M01、M02、M06、M09、M11；新增 Skill 生成模板存储/鉴权/表单渲染，不直接覆盖已有 Agent 模板体系。

**注意：** `name` 等保留字段不能被自定义 key 覆盖；默认值与字段类型必须一致；模板是生成参考，不是能执行任意代码的脚本。生成开始时冻结定义，管理员中途改模板不会改变在途任务。管理员引用片段时复制正文，后续库改动不自动回填。被删除模板不能再发起生成，已固定的在途任务按其冻结数据完成或明确取消。

**验收：** 普通用户无法维护库但能进入生成；必填/默认值/重复 key 校验正确；模板变化不改变已生成 Skill。

### F05 在普通会话中生成 Skill

**入口增量：** 我的技能“新建技能”下拉提供直接创建/模板创建。直接创建保持原表单；模板创建复用会话“技能生成”的选择弹框，选定后才切到会话填写。连同模板中心，共三个模板入口。模板弹框/模板中心按名称和描述搜索，片段管理按名称/说明/正文搜索，保持权限、焦点和独立关键词，提供清空与无结果状态。

**入口/角色：** 聊天底部“技能生成”，或模板中心“在会话中使用”；需目标工作区创建/编辑权。

**完整流程：**

1. 我的技能的模板创建、会话底部技能生成、模板中心的使用入口共用模板与会话填写逻辑；模板中心已选定模板时直接进入填写。底部按钮与其他能力同行，不新建独立生成聊天 UI。
2. 用户填写 Skill 显示名称、文件标识 `name`、模板字段；`name` 对应 `SKILL.md` frontmatter，不能只作为内部随机目录名。其格式遵守项目严格校验规则。
3. 输入框 placeholder 为“请输入额外补充信息…”。取消模板恢复普通输入，不提交生成任务；不无提示清空用户已输入的信息。
4. 发送后服务端冻结模板、输入、预置正文及本次获授权的片段参考。creator 可匹配合适片段，但不要求运营手动逐条选择，不增加“是否注入片段库”开关。
5. 独立临时环境执行 CreatorAdapter，生成自包含 Skill 包；通过结构、路径、name、资源和用例格式检查后原子保存到工作区。
6. 保存位置为 `Workspace/.claude/skills/<name>/`；生成 `SKILL.md` 与 `evals/evals.json`，没有可成立用例时使用空 `evals`，不能伪造已测评。
7. 保存成功刷新我的技能和 Slash 命令目录。会话明确指出生成名称与目录；用户可继续普通消息微调，修改直接作用于授权 Skill。

**影响：** M01、M02、M04、M06、M07、M08、M09、M11。

**注意：** 当前仓库 creator 的“仅输出 SKILL.md”与目标包契约不一致，应新增专用适配/模式或有兼容测试的扩展，不全局替换并破坏已有顶层 Agent 生成。大片段库可采用完整目录索引加按需读取正文，避免超上下文；只纳入有权参考的内容。相同名称冲突返回错误且不覆盖。失败或取消不能留下半个 Skill；保存完成后取消也不能假装文件未创建。后续修改多技能目标不明确时才询问目标，不默认为上一次生成的目录。

**验收：** 三个模板入口一致、选择弹框取消不跳转、三处搜索与清空正常、name 必填、placeholder 正确、结果自动保存、同名不覆盖、生成失败无半成品、原有 creator 调用不回归。

### F06 普通调用保存为测评用例

**入口/角色：** 普通会话一次完整 Skill 根调用结束后，原消息底部“保存为测评用例”；需目标 Skill 本地编辑权。

**流程：** 直接使用原有 `/skill-name query` 等调用方式 → 主任务、工具与子任务结束 → 出现保存按钮 → 服务端用根 executionId/toolUseId 查找授权调用树 → 提取 query、输出及资源 → 转换成用例并直接写入 `evals/evals.json` → 按钮变为已保存，可查看用例。

**影响：** M02、M03、M04、M06、M08、M09、M10。

**注意：** 不从 UI 最后一段文字猜测调用边界；前端不能任意指定他人执行 ID 或上传伪造执行事实。同一会话多次调用需精确归属 Skill；无法定位时不显示误导按钮。不再确认验收标准，但原输出只能作语义参考，保存不等于证明它正确；用户后续可编辑预期。输入附件需复制到 `evals/files/` 并脱敏，临时地址不足以重跑。缺关键输入时提示缺失，不保存一个声称可重跑的空壳。相同调用重复点击幂等，明确错误/未完整调用不伪装为成功样本。

**验收：** 普通聊天仍可继续；不出现试用模式；一次点击直接新增；重复点击不重复；保存内容可在文件编辑器读到；其他用户调用不可越权读取。

### F07 文件化用例管理

**入口/角色：** 我的技能 → 测评 → 添加验证场景；所有本地编辑者均可维护，不限市场负责人。也可从文件编辑器打开同一个 JSON。

**流程：**

- 手工：填写输入、预期、可选检查要点/输入文件 → 保存 → 校验并立即写入。
- AI：读取当前 Skill、已有用例和授权参考材料 → 生成合法新用例 → 校验后追加；不要求确认草稿，不替换整份用例集。
- 编辑：修改同一 id 的定义，保存后旧报告失效。
- 删除：从未随 Skill 发布的用例可删除；曾发布用例永久保护。删除按钮禁用之外，服务端也检查。

**影响：** M01、M04、M06、M07、M09、M10；详细文件契约见第 5 节。

**注意：** 用例 id 由服务端分配，不按行序重排。已发布 id 改号、删除整个 evals 目录、上传覆盖、导入替换和贡献合并都不能绕过保护。已发布用例可人工编辑但必须使报告失效；“不能删除”不等于“预期永不可编辑”。AI 不能编造未知业务真值，信息不够可提示补充。任务运行期间暂停同目录写用例；外部直接编辑必须检测并使任务失效。格式不合法拒绝 UI 保存；外部非法 JSON 显示修复提示，不使页面崩溃。

**验收：** 三来源同文件、无确认、非法 schema 拒绝、已发布身份保护覆盖所有 CCUI 写入口、共享目录并发不会丢用例。

### F08 静态检查

**入口/角色：** 运行全部和自动优化的自动前置检查；结果在测评表的静态检查行展示。

| 检查组 | 主要内容 | 处理 |
| --- | --- | --- |
| Skill 必需结构 | 根 SKILL.md、合法 frontmatter、name/description、name 与目录规则 | 确定性错误阻断 |
| 用例契约 | JSON/schema、skill_name、唯一 id、非空 prompt/预期 | 错误阻断；空集不产生通过报告 |
| 包与路径 | 越界、绝对路径、符号链接、特殊文件、大小/数量/深度限制 | 危险项阻断 |
| 输入资源 | files 存在、相对路径可解析、允许复制、不指向答案/用例定义 | 缺失或违规阻断 |
| 安全策略 | 凭据暴露、明确危险资源/操作、生产工具配置 | 明确违规阻断，疑似项展示依据及策略处理 |
| 文档质量 | 触发范围、引用、说明完整性、歧义 | 提示建议，不把文风问题等同业务失败 |

**影响：** M04、M08、M10；复用现有严格校验并输出 ruleId、severity、path/line、证据、修复建议。

**注意：** 展示用宽松 manifest 解析不等于保存/发布校验。现有零散校验不等于完整安全扫描；包体限制不能只在解压后执行。确定性规则由平台代码维护，AI 可给质量建议但不能豁免阻断。静态通过只表示允许继续动态执行，不证明 Skill 有效；不能因插入片段自动启用 SQL Hook。

**验收：** 缺文件、坏 schema、路径越界均不启动 Runner；可定位错误；只有质量提示时按策略继续；无误报“业务已通过”。

### F09 运行全部：后台串行动态测评

**入口/角色：** 我的技能测评“运行全部”；本地编辑者。保持当前页面，不创建或跳转会话。

**完整流程：**

1. 校验权限、同目录互斥和用例资源，冻结本次 Skill、全部用例、输入及模型/环境/策略。
2. 静态检查通过后，按 `evals` 数组顺序，逐个执行以下闭环：构建干净环境 → 执行 → 等整个任务树结束 → 收集证据 → 规则/AI 判定 → 清理环境。
3. 当前例完成判定和清理后才启动下一例；表格逐行显示等待、运行中、判定中及结论。
4. 单例业务失败仍跑下一例；可隔离的单例运行/评分异常标记 error 后继续。任务级环境故障、安全事件、取消或文件冲突终止，剩余项标为未运行。
5. 保存报告及完整证据，不改 Skill、不发布。用户离开页面任务继续，回来读取服务端进度；浏览器刷新不能重启任务。

**影响：** M01、M06、M08、M09、M10。

**注意：** “串行”针对不同用例；一个用例内部正常 subagent 并行可以保留，但必须受资源/超时限制。关闭 SDK 会话持久化不等于容器隔离；测试不得挂载用户持久 HOME、生产凭据及完整真实工作区。冻结后检测目录外部变化，避免旧内容报告绑定新文件。被测 Agent 不可读 `evals/evals.json`、预期与评分规则；输入文件只按白名单复制。不能只删除一个答案文件却把答案副本或旧报告继续挂载进去。

**验收：** 任意时刻同一任务仅一个用例执行/评分；所有分支有终态；失败不删分母；刷新恢复；取消回收主任务、工具及全部子任务。

### F10 预期与实际的判定

**入口：** 每个动态用例执行完成后自动进行，不增加人工确认步骤。

| 对象 | 判定方式 | 不应强制的条件 |
| --- | --- | --- |
| 文本回复 | 事实、必要信息、业务语义、明确的格式要求 | 默认逐字匹配或固定句式 |
| 工具调用 | 权限、必要参数、结果是否真实、禁止操作是否发生 | 默认要求完全相同工具轨迹 |
| subagent | 所有必要子任务完成，交付可归并、无未结束分支 | 未在用例要求时强制固定子任务数量 |
| 生成文件 | 文件存在/可读取、内容/数值/结构满足预期 | 默认只能输出 JSON |

**执行分工：** EvidenceCollector 封存执行事实；RuleGrader 做确定性校验；独立 AIJudge 读取固定预期与只读证据逐项给结论和引用。AIJudge 是新的无工具/最小权限评审上下文，不复用被测 Agent 自评，也不必为每次评分新建一个常驻 Claude 容器。

**影响：** M08、M09、M10；报告保留执行结果与评审结果两个独立部分。

**注意：** 输出中的指令属于待评数据，不能修改评分规则。能计算的金额不交给模型猜。证据不存在、未采集、解析受限或 AI 无法判断时显示“无法确定/异常”，不是通过。AI 不能覆盖安全或必需规则失败。通过只说明当前有限用例满足预期，不证明普遍有效或召回准确。

**示例：** 输入 CNY 销售 100、退款 10，USD 销售 20，要求生成报告。规则检查报告存在且金额 CNY 90、USD 20；AI 判断是否解释退款口径、没有混币种或编造原因。写出了文件但算错金额仍失败；文字正确但文件根本不存在也失败；文件暂不可读取则不宣称通过。

**验收：** 明确通过、失败、无法确定、执行/评分异常及未运行；每个结论可定位证据；没有证据的“通过”被拒绝。

### F11 自动优化并立即保存

**入口/角色：** 我的技能测评“自动优化”；有本地编辑权，不要求用户一定是市场负责人。

**固定流程：**

```text
冻结同一批用例与当前内容
  → 全量串行前测（不能用旧报告替代）
  → 优化模型读取预期、实际、差距和 Skill
  → 产生受限文件修改
  → 权限/路径/内容并发/安全校验
  → 自动原子保存到本地 Skill
  → 使用原样用例全量串行后测
  → 展示两遍输出与本次文件 Diff
```

**影响：** M01、M04、M06、M08、M09、M10、M11。

**注意：** 不只重跑失败例；即便无需改动也记录无差异并完成后测。优化器不能改用例、预期、输入数据、评分器、角色、权限或自行标记通过。首期受限自动修改默认只允许本 Skill 的 Markdown/文档资源，可执行脚本及工具权限扩展需另行授权。修改后复测失败/取消仍保留已落盘内容，不能隐式回滚或显示“待采用”。若前测异常导致没有足够证据，应明确停止/失败，不凭空优化。其他进程已修改文件时不覆盖，其报告失效并提示重新运行。

**停止语义：** 写入前停止不改文件；写入后停止保留当前修改、未完成项不通过；写入过程采用事务日志/原子交换，重启先核实是否已经写入，不能盲目重复应用补丁。

**验收：** 完整前测先于一次自动保存，完整后测晚于保存；用例指纹前后一致；没有确认改动/采用按钮；没有自动发布；失败仍能查看已保存的文件差异。

### F12 用例详情与完整会话输出对比

**入口/角色：** 每条用例行末“查看详情”；本地按工作区访问权，市场按公开报告权限。

**展示规则：**

1. 顶部展示当次输入、固定预期和检查要点。文件后来修改时保留旧运行快照并标记旧结果，不混入新预期。
2. 运行全部结果是单列只读会话，展示用户输入与完整模型可见消息。
3. 自动优化左列第一遍、右列第二遍，顶部对齐，完整输出分别呈现。不是正文 Diff，也不是几句 AI 总结。
4. 复用现有聊天的 Claude 消息、Markdown/代码、工具输入/返回、subagent 展开、文件产物；测评判定和原因另放独立区域。
5. 工具/子任务可折叠，但展开后能够读完整记录。长文本可以纵向滚动到末尾；窄屏保持左右两列、局部横向滚动，不撑宽整个页面。
6. 未运行、运行中尚无输出、执行中断、原始记录未公开/未采集、证据因策略到期分别提示；不能以判定摘要伪装原始输出。

**影响：** M01、M03、M06、M09、M10；建议抽出只读消息组件和事件适配器，不直接嵌入带发送框、权限操作或写工具按钮的完整 ChatInterface。

**注意：** 完整指已采集且有权查看的可见消息，不指模型内部思维链。服务端顺序记录事件，UI 不能只取 final 字符串；Markdown/HTML 做安全渲染，文件下载逐项鉴权。超大记录可分页/虚拟化，但不能永久截断；加载中、已全部加载要区分。报告区只读，不应出现“重试执行工具”“确认授权”“发送消息”等副作用操作。市场只展示授权公开投影，不能因为复用组件泄露私人聊天。

**验收：** 多条助手消息、工具、子任务与产物均可读到末尾；左右 runId 不串；判定不是模型消息；恶意 HTML 不执行；窄屏可操作、无页面级横向溢出。

### F13 负责人、Skill 管理员与分类

**入口/角色：** 我的技能 → 管理；仅当前负责人维护。市场管理只读。

**流程：** 展示 createdBy/当前负责人、指定管理员和分类 → 负责人选择有效成员进行授权或转移/改分类 → 服务端再次校验当前 owner 与授权戳 → 原子保存并审计 → 各入口刷新权限。

**影响：** M01、M05、M06、M09、M11。

**注意：** 不能相信前端传入 owner 或管理员列表。撤销需对在途发布/合并执行前重验；已打开的旧表单不能把新权限覆盖回去。管理员不可以继续授权管理员；分类权限不跟着发布权自动扩大。把前端账号映射为远端已有发布身份是独立技术条件，CCUI 有权不保证远端接受请求；禁止默认借用负责人的私人凭据越权代理。

**验收：** 指定后可发布/正常合并但不可管理授权；撤销即时生效；原创建者转移后不再被当作当前 owner；并发更新不丢权限变更。

### F14 贡献请求与多文件评审

**入口/角色：** 本地“提交贡献”、顶层“贡献”和市场技能“贡献”；提交需本地编辑权及市场目标访问权。

**完整流程：**

1. 提交前基于当前远端内容构建固定基线与候选全文件包，填写标题/说明，保存贡献请求；无需测评，不展示贡献测评 Tab。
2. 左侧列新增/修改/删除的全部文件；右侧显示选中文件的前后 Diff。包含 `SKILL.md`、`evals/evals.json`、引用及输入附件。
3. 所有有访问权的非作者可评论、建议修改、Approve；作者不能认可自己，重复认可不增加人数。
4. 收到的贡献列出本人负责或管理的 Skill 全部请求；我提交的贡献按作者列出；市场详情提供单 Skill 全部可访问请求。
5. 当前提交至少有一位有效非作者 Approve 后，负责人或 Skill 管理员可合并；负责人可选择无认可直接合并并记录理由/审计。
6. 合并前重新检查成员/角色、当前候选、有效认可、远端基线、包安全和用例保护；调用市场更新发布，回读匹配后才标记已合并。
7. 合并等于更新发布，不要求测评；当前市场报告显示“未测评”。不自动覆盖各人的本地副本。

**影响：** M01、M04、M05、M06、M09、M11；新增贡献记录、固定文件包、评审与合并状态，复用市场发布传输而不是直接复用普通发布门禁。

**注意：** 内容更新后旧 Approve 失效；后续同一评审者要求修改后其旧认可不再有效。审批针对内容指纹而非只有 PR id。远端目标变化先重新核对，不能静默强推。二进制文件显示增删、大小/摘要及授权预览，不伪造文本 Diff。传输超时结果未知时不能直接标为失败后重发；保持待核实。无测评不等于无鉴权、路径校验、敏感检查和发布用例保护。

**验收：** 自我认可所有角色均失败；普通 Approve 用户不能合并；管理员需要有效他人认可；负责人可直接合并；多文件增删可核对；未知发布结果不会重复推送。

### F15 发布新增门禁、市场报告与记录保留联动

**入口/角色：** 详情操作区；负责人/Skill 管理员可直接发布，负责人沿用下架权限。

**增量范围：** 不重新实现现有发布/下架按钮及基础传输。新增角色鉴权、本人测评门禁、报告/用例保护关联、结果核实和贡献免测评分流；下架仅补充对新记录的保留规则。

**直接发布：** 当前发布者本人运行当前内容全部用例通过 → 服务端校验包/用例/环境/授权指纹与适用报告 → 预览并确认发布 → 固定包发送远端 → 回读核实 → 绑定公开报告并登记已发布用例。

**报告规则：** 只显示当前发布内容适用的公开结果。优化后只能绑定完整后测，不用旧前测。贡献合并、外部更新或不能证明内容匹配时为“未测评”；不能称“未经 CCUI 测评”。外部渠道未提供可验证报告时不编造通过。

**下架：** 停止市场分发，保留本地文件、贡献、报告与审计。重新发布另走有权限的当前发布路径；保留记录不代表提供历史版本查看。

**影响：** M01、M04、M05、M06、M09、M10、M11。

**注意：** 普通直接发布与贡献免测评合并必须是明确区分的服务端路径，不能靠前端 `skipEvaluation=true` 任意绕过。刚新增/改过用例、文件或策略时旧报告不可用；空用例、无法确定、错误、未运行不能满足门禁。发布已回读成功才更新发布绑定；回读内容不符/超时为冲突或待核实。只改 CCUI 且外部渠道保留，因此不能保证远端绝无竞态，也不能约束外部渠道永久保护用例，见第 8 节。

**验收：** 两类授权角色用自己的适用报告发布；内容变化后发布被阻断；合并仍免测评；市场不泄露原始私有轨迹；下架不删工作区或审计记录。

### F16 导入更新判据改造与失效处理

**入口：** 市场列表、我的技能状态及更新操作；沿用现有导入/更新主体流程，只替换业务判据。

| 数据/状态 | 规则 |
| --- | --- |
| remoteUpdatedAt | 当前远端内容对应更新时间 |
| importedRemoteUpdatedAt | 上次成功导入那份内容对应的远端时间，不是导入操作发生时间 |
| localEditedAt、importedAt | 可记录，但不参与市场待更新判断 |
| 远端时间大于导入对照 | 待更新；即使本地编辑时间更晚也一样 |
| 两时间相等 | 无远端更新；仍可独立显示有本地修改 |
| 时间缺失/读取失败 | 更新状态未知，不显示已同步 |
| 远端时间倒退 | 时间异常，提示核查 |
| 来源明确下架 | 来源已下架，保留本地内容 |

**同步：** 同一市场对象读取 T0 → 下载暂存并校验 → 再读 T1 → T0/T1 不一致则有限重试 → 校验本地并发摘要 → 写锁下交换文件并更新基线/导入对照 → 完成。存在本地修改先看差异，用户取消不推进时间。

**影响：** M01、M04、M05、M06、M09；当前代码仍有 `version/importedVersion` 路径，需一起调整类型、缓存、发布预检和迁移，不只改文案。

**注意：** 旧 importedVersion 无法推算历史远端时间；不得用当前远端时间或文件 mtime 补假值。未知绑定需安全重同步建立基线。统一时间单位/UTC，兼容已有远端字段拼写映射；同时间粒度修改可导致时间无法识别变更，是远端限制，不暗中改为“只按 hash 判断更新”。hash 用于内容核实与报告失效，不另造版本。文件系统和 SQLite 需要操作日志/补偿避免“文件旧、时间新”。

**验收：** 导入对照 09:00、本地编辑 11:00、远端更新 10:00 时仍待更新；失败/取消/测评不推进导入对照；旧数据不被伪造为已同步。

## 5. 文件与持久化契约

### 5.1 Skill 文件布局

```text
Workspace/.claude/skills/sales-summary/
├── SKILL.md
├── evals/
│   ├── evals.json              # 唯一可编辑用例定义
│   └── files/orders.csv       # 可分发、已脱敏的测试输入
├── references/
├── scripts/
└── assets/
```

各目录按实际需要创建；运行日志、判定报告和本次前后文件快照放 CCUI 私有报告存储，不混入 Skill 包，不写回 `evals/evals.json`。

### 5.2 用例格式示例

沿用已核对的 [文件化用例专项 §2](superpowers/specs/2026-09-14-skill-eval-file-and-auto-write-design.md)，当前仓库精简 creator 尚需适配。

```json
{
  "skill_name": "sales-summary",
  "evals": [
    {
      "id": 1,
      "prompt": "读取订单文件，按币种计算净销售额并生成 Markdown 报告。",
      "expected_output": "报告可读取；CNY 净销售额为 90、USD 为 20；解释退款口径，不混合币种。",
      "files": ["evals/files/orders.csv"],
      "expectations": [
        "报告包含 CNY 90 和 USD 20",
        "最终回复指出文件位置",
        "没有编造订单"
      ]
    }
  ]
}
```

`files` 相对于 **Skill 根目录**，不是 `evals/`。`id` 为 Skill 内唯一正整数；`prompt`、`expected_output` 必填；`files`、`expectations` 可选；`evals` 顺序就是运行顺序。禁止擅自加入 `status/draft/confirmed/actual_output/runId` 等平台状态字段。

### 5.3 建议存储职责

| 存储对象 | 建议字段/内容 | 注意 |
| --- | --- | --- |
| Skill 治理 | 稳定 skillId、createdBy、ownerId、administratorIds、category、授权戳 | name 非唯一全球身份，不只按名称鉴权 |
| 模板/片段 | 作用域、定义、维护人、修改审计 | 系统片段全平台；模板沿用授权范围 |
| 导入绑定 | workspaceId、source、remoteSkillId、importedRemoteUpdatedAt、baselineHash | 名称重命名不能错误绑定其他市场对象 |
| 用例元数据 | skillId/localInstanceId、caseId、来源、调用幂等键、已发布保护登记 | 只存元信息，不与 JSON 双写正文 |
| 任务 | jobId、type、workspace、发起人、指纹、状态、串行游标、租约、取消请求 | 后台持久化，不依赖浏览器定时器 |
| 用例运行 | runId、caseId、phase、冻结预期、状态、判定、证据引用 | 前后两遍分开；历史证据不等于 Skill 版本 |
| 消息/证据 | sequence、role/type、toolCallId、parentId、完整内容、产物引用 | 执行消息与 AI 评审消息分存，按权限读 |
| 优化任务 | beforeRunId、afterRunId、beforeHash、afterHash、written、文件 Diff | 重启核实真实落盘状态；不设 adopt 状态 |
| 贡献/评审 | 作者、目标、基线/候选指纹、文件包、评论、有效认可、合并任务 | 内容变更使旧认可失效 |
| 发布任务 | 操作类型、固定包摘要、报告引用、远端回读结果、操作者 | 区分 direct 与 contribution-merge，不盲目重试 |

所有本地操作都以服务端解析的工作区路径为准，不接受客户端任意绝对路径。建议锁键为租户/工作区/Skill 物理实例；全局任务配额与目录互斥是两层机制，不能按用户分锁后允许同目录互相覆盖。

## 6. 服务接口与任务状态建议

本节为逻辑接口清单，不声称以下 URI 已存在；实现时按现有路由前缀适配。公共模板/片段查询与工作区 Skill 操作分开鉴权。

| 业务接口 | 必须约束 |
| --- | --- |
| 片段/模板查询与 CRUD | 浏览与维护权限分开；租户/全平台作用域明确 |
| 创建生成任务、查询/取消 | name/字段校验、模板指纹、幂等、工作区创建权、同名不覆盖 |
| 获取/更新 eval-file；新增/修改/删除 case | 同一文件服务、If-Match/revision、唯一 ID、附件与发布保护 |
| AI 生成用例 | 只追加合法定义，生成期间文件改变时重新校验，不覆盖他人新增 |
| 从 invocation 保存用例 | 根执行归属、服务端取证、资源复制、幂等 |
| 创建 evaluation/optimization，查询报告/事件，取消 | 服务端固定全部用例并强制串行，目录互斥、持久进度 |
| 读取 messages/artifacts/file-diff | 身份/资源鉴权、完整分页、稳定事件游标、无执行副作用 |
| 管理 owner/administrators/category | 当前负责人、成员有效性、授权戳、审计 |
| 贡献提交/更新/评审/合并 | 固定包、禁止自我认可、旧认可失效、授权与冲突核查 |
| 直接发布/下架 | 区分发布路径；直接发布本人适用报告；回读核实 |

建议错误语义：403 权限不足；409 内容/授权并发冲突或目录忙；422 格式/资源/业务前置条件不满足。具体返回码应与项目现有约定统一，不在 UI 通过猜测错误文案控制权限。

### 6.1 任务状态与前端恢复

| 任务 | 正常阶段 | 异常/终态 |
| --- | --- | --- |
| 生成 | queued → generating → validating → saving → completed | failed、cancelled、conflict；保存已完成时需如实告知 |
| 运行全部 | queued → static-check → case-running → grading → cleanup → 下一例 → completed | failed/error、cancelled、stale；未执行项 not_run |
| 自动优化 | before-all → optimizing → validating → writing → after-all → completed | failed/error、cancelled、stale；独立记录 written |
| 发布/合并 | preparing → sending → verifying → succeeded | rejected、conflict、pending-verification；未知不能伪装成功 |

`completed` 仅表示流程结束，不等于所有用例通过；通过资格由完整用例数、逐例状态、静态结果和当前内容匹配单独计算。前端重连用 jobId 与事件游标补齐，不重复 POST 发起。重启恢复须有租约/单执行者，避免两个 Worker 同时继续同一游标。

## 7. 跨功能容易遗漏的细节

### 7.1 任何写入都要经过同一套边界

不仅表单保存：原文件编辑、文件/目录删除与重命名、上传安装、导入覆盖、生成、会话微调、优化、贡献合并、发布，都可能改到用例或覆盖目录。保护规则、路径检查、锁和失效逻辑要覆盖这些入口；不能靠测评页按钮禁用保证安全。

### 7.2 自动落盘与报告失效

改变 Skill 正文、脚本、用例、测试输入、策略/模型环境或相关授权后，旧结果不能再证明当前内容。详情仍可看当次证据，但明确标记失效。执行本身的写产物在隔离目录，不能意外回写被测 Skill；只有优化协调器通过校验后提交允许的修改。

### 7.3 执行环境与普通聊天分开

生成在独立环境进行，校验后由 CCUI 提交包。普通调用沿用真实聊天策略，不被偷偷当成自动隔离测试。测评独立环境必须去答案、去凭据、去不必要工具并控制外网/资源；仅设置 `persistSession: false` 解决不了挂载和权限问题。AIJudge 是独立只读评分上下文，优化器是受限编辑上下文，职责不混用。

### 7.4 公开包与私有证据分开

`evals/evals.json` 及测试附件随 Skill 包传播，不能包含不适合共享的数据；来源普通会话不能整段无筛选公开。原始消息、工具参数、子任务和产物可能敏感，默认在私有报告区，市场展示经授权过滤的投影。完整输出展示不构成绕过脱敏/权限的理由，删减或未公开部分需明确标记。

### 7.5 无人工确认不等于无安全失败

AI 用例生成格式不对、业务预期未知、生成目录冲突、前测证据不足、模型请求越界时可以失败或要求补充必要信息；不能为了减少交互伪造有效用例、覆盖文件或放开生产权限。取消的是额外草稿验收与采用环节，不是必要鉴权和安全检查。

## 8. 已知能力边界与上线前核实项

以下项目需联调或部署决策，不能因为原型可点击就当作已解决；除特别说明外不是重新询问已经确认的产品规则。

| 项目 | 当前设计/边界 | 上线前要核实 |
| --- | --- | --- |
| 远端发布授权 | CCUI 负责人授权 Skill 管理员，但远端认证未因此改变 | 已有远端接口能否接受合法代理身份；不行则明确阻断，不借私人凭据绕过 |
| 外部发布并发 | 保留其他渠道，CCUI 的锁无法约束外部客户端 | 时间精度/更新契约、回读内容可核实范围；无 CAS 时不承诺严格原子发布 |
| 已发布用例保护 | CCUI 所有写路径强制；无法拦截用户 OS 编辑或外部平台发布 | 外部删除如何检测、标记冲突、阻止 CCUI 继续传播；是否有额外治理手段 |
| 模板作用域 | 沿用授权管理员及租户范围；片段才是明确全平台共享 | 若模板也需跨租户共享，另行明确治理，不默默扩大 |
| 自动改动范围 | 默认 Markdown/文档资源，不允许改用例/输入/评分/权限 | 是否后续授权脚本修改及对应安全策略；首期不放开 |
| Creator 兼容 | 当前精简 creator 无 eval 包契约 | 独立模式、输出校验、对已有 top-skill 任务的兼容测试 |
| 任务预算 | 两遍全量运行有模型/容器成本 | 单例/任务超时、资源上限、配额、重试次数；未定具体数值不硬编码进文档 |
| 证据保留 | 私有持久记录，报告可判定证据是否过期 | 保留期、容量、脱敏、产物格式白名单、过期清理与访问审计 |
| AI 判定可信度 | 规则优先、独立评审、固定标准、无法判断显式显示 | 用真实业务样本校准误判，不能用“模型说通过”替代验收 |
| 旧数据迁移 | 不伪造历史时间，不制造第二套用例正文 | 旧 eval.json 校验后迁移至 evals/evals.json；双文件冲突人工处理，不静默覆盖 |

## 9. 实施拆分与验收建议

按依赖拆分，不要求第一步重做所有已有功能。

| 阶段 | 交付内容 | 关键依赖/验收 |
| --- | --- | --- |
| A 数据和权限底座 | Skill 身份/管理员、EvalFileService、原子写、目录锁、来源时间字段 | 所有写入保护统一；旧数据未知状态正确；不用业务版本 |
| B 会话生成与用例沉淀 | 模板/片段只读与维护、快捷插入、CreatorAdapter、调用保存用例 | 真实自动保存、name/同名保护、已有 creator 不回归、三来源同文件 |
| C 真实串行测评 | 静态检查、隔离 Runner、完整任务树、规则/AIJudge、后台任务 | 去答案与去凭据；串行；失败/取消/重启；真实文本/工具/subagent/文件 |
| D 自动优化与完整展示 | 前测/自动写入/后测、Diff、单列/左右会话详情 | 完整输出到末尾、写后失败保留内容、并发不覆盖、无采用 |
| E 发布与贡献治理 | 公开评审、多文件 Diff、授权合并、直接发布门禁、市场报告 | 本人测评与免测评两条路径严格区分、回读核实、未测评状态 |
| F 联调和灰度 | 多用户/共享工作区/外部更新/资源异常、真实浏览器与安全测试 | 不能以 HTML 模拟测试通过代替生产后端验收 |

### 9.1 最低验收用例清单

- 普通用户可浏览模板/片段但不能维护；系统管理员和 Skill 管理员权限不混用。
- 两个模板入口进入同一聊天流程；name 必填，生成直接保存，同名不覆盖，失败无半成品。
- 快捷插入的三类内容、布局和光标目标正确；插入不触发安装/授权/真实工具执行。
- 普通完整 Skill 调用能一键保存用例且幂等，无调试/试用入口和验收标准确认。
- 手工/AI/会话/导入全部映射同目录 `evals/evals.json`，文件表单一致，共享工作区并发无丢写。
- 已发布用例不可经删除、改号、删目录、整体覆盖、上传、导入或贡献绕过保护。
- 静态错误阻断；空用例不通过；每例执行/判定/清理后下一例才开始。
- 文本、工具、subagent、文件均有实际证据，数值错误/文件缺失/安全违规不能被 AI 放行。
- 任务断线继续、刷新恢复，取消回收子任务，重启不重复写补丁/重复发布。
- 自动优化完整前测后写入、再完整后测；不改标准；写后失败/取消保留真实修改，无采用按钮。
- 单次输出单列、优化前后左右两列，完整消息/文件可读到末尾；HTML 注入无效，市场无私有轨迹泄露。
- 负责人可指定/撤销管理员；管理员可发布和正常合并但不可再授权；撤销与转移即时重验。
- 所有角色禁止自我 Approve；正常合并需当前有效他人认可；负责人可直接合并；贡献均免测评。
- 直接发布必须发布者本人当前报告通过；贡献合并和外部更新后市场显示“未测评”。
- 待更新判断不受本地编辑时间影响；失败/取消不推进导入对照；来源下架不删除本地。
- 远端结果未知保持待核实；不盲重试、不宣称已经实现远端原子一致性。
