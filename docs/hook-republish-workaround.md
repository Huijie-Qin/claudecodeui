# Hook 修改后重新发布不生效

旧实现会在工作空间第一次启用 Hook 时保存其版本。重新发布只生成新的发布快照，没有同步普通工作空间的版本引用。因此管理页显示新配置，执行记录仍可能使用旧版，例如继续报 `Script output toolInput must be boolean`。

本次修复使普通手动启用的 Hook 随重新发布推进版本，保留用户启用状态、聊天显示、个人变量和安装状态。Agent 模板明确固定的版本保持不变。每个新执行回合仍会校验并准备对应发布快照的资源，运行中的回合继续使用启动时的配置。

## 暂时不部署的处理办法

1. 在管理页对修正后的 Hook 点“复制”，例如命名为“Python MCP 调用前参数确认 v2”。复制会新建 Hook ID，仅改名或重复发布原 Hook 无效。
2. 发布新 Hook，并设置相同的适用用户或租户。
3. 在目标工作空间先启用新 Hook，再关闭旧 Hook；需要个人变量时重新填写。
4. 等当前回合结束，再发起新回合；核对新 Hook 的执行记录。

关闭再开启同一个旧 Hook、刷新页面或只新建会话，都不会更新旧的工作空间版本引用。旧 Hook 保留即可，无需删除历史执行记录。

如果旧 Hook 来自禁止关闭的 Agent 模板，需要管理员更新模板中的 Hook 引用，并按已有模板安装流程创建新工作空间；仅改模板不会覆盖已安装工作空间。不要在强制旧 Hook 仍运行时以为新 Hook 已完成替换。

此方法解决的是**配置版本未更新**。MCP 强制确认弹窗仍依赖服务本身的确认处理能力；若运行版本尚未包含该处理，仅换一份 Hook 配置不能补齐它。

## 部署修复后

更新并重启后端，再发布一次原 Hook，可推进此前遗留的普通工作空间引用。设置 → 辅助功能显示工作空间实际使用的版本；模板固定版本有单独标识。历史失败记录保持原样，应查看新回合的执行结果。

## 回归验证

`server/services/hook-republish.test.js` 覆盖真实 Python 执行中旧版本的类型错误、重新发布后使用修正版本返回 `ask`、草稿隔离、不可变历史快照、模板固定版本，以及个人配置与安装状态保留。
