# 租户管理功能说明

更新日期：2026-09-22。

## 授权与入口

系统管理员进入 **Admin → 租户权限**，将指定成员的“租户角色”设置为“租户管理员”。授权界面不再显示“查看／编辑”权限选择；单人授权、批量授权和成员角色调整均按“编辑”提交。普通用户即使有编辑权限，也不能管理租户配置。已有的 `tenant_admin` 角色直接获得此功能，无须新建角色。

仅调整后续授权的默认值，不批量改写历史成员权限。成员角色调整保留原启用／停用状态；工作区共享仍独立保留“查看／编辑”权限。兼容接口中显式传入的旧权限值仍按原校验处理；未传权限时默认 `edit`。

仅租户管理员在当前租户的左下角看到“租户管理”，进入 `/tenant-management`。收起侧栏时显示同名图标。可以切换自己有管理权限的租户；切回普通用户所在租户时不显示管理入口。Admin 使用原有 Admin 入口，不显示“租户管理”（即使同时拥有租户管理员成员记录）；普通用户也不显示。入口显示与页面访问、后端管理授权分开控制。

AI 使用统计入口统一放在管理页面内：平台 Admin 从 **Admin → AI 使用统计** 查看，并在页面内选择租户；租户管理员从 **租户管理 → 租户 AI 使用报表** 查看当前租户报表。工作区侧栏（展开、收起和移动端）不再单独显示 AI 使用统计入口，普通用户不显示报表入口。保留旧报表地址兼容既有链接，后端报表权限与统计口径不变。

## 三项功能

| 功能 | 可执行操作 | 生效范围 |
| --- | --- | --- |
| Hook 配置 | 新建、编辑、保存草稿、发布、删除；复用现有事件、脚本、后置行为与返回配置编辑器 | 只管理本租户创建的 Hook；发布时自动限定当前租户，可设置用户默认启用，不覆盖用户已有选择 |
| 租户 AI 使用报表 | 查看现有 AI 使用、Skill 发布与调用、Hook 执行、Hook 业务、Agent 模板报表；沿用筛选、分组和导出 | 当前租户，沿用现有统计口径和已发布批次，不因配置编辑即时重算 |
| Agent 模板 | 配置说明、CLAUDE.md、文件夹、引导语以及本租户可用的 Skill／MCP／Hook 引用；保存、发布、下线、删除 | 仅分发到当前租户；删除前需先下线或停用 |

平台统一配置（历史数据的 `owner_tenant_id` 为空）仍在 Admin 维护，不自动归属任何租户。租户管理员不能编辑平台配置、跨租户分发或管理平台 MCP、事件、Skill 预设目录。已分发的可用资源仍可被模板引用。

### Admin 配置不可修改

Admin 创建的 Hook 和 Agent 模板，即使只分发到一个租户，也仍属于平台。租户管理员可以使用已分发的模板、引用已分发的 Hook，但不能修改原配置、重新发布、下线或删除。它们不会出现在租户管理的可编辑配置列表中；直接请求修改接口同样被拒绝。伪造配置 ID、创建人或 `ownerTenantId` 不能取得编辑权限。租户管理员自身创建的配置仍可正常管理。

## 权限与数据保护

- 新接口：`/api/tenant-management/:tenantId/*`，由登录认证保护，不放宽原 `/api/admin` 的系统管理员要求。
- 每次操作查询数据库中的账号状态、租户状态、成员状态和 `tenant_admin` 角色，不信任旧 JWT 角色或前端缓存；异步目录查询／发布后再次校验权限。
- Hook、Agent 模板新增 `owner_tenant_id`。创建时由后端写入当前租户，客户端不能修改归属；修改、删除、发布均先校验归属。
- 发布和工作区使用阶段都检查归属。没有明确租户上下文的旧 Hook 查询不返回租户私有配置，避免同一用户跨租户执行。
- 页面恢复焦点时刷新成员角色与管理权限；权限撤销后的下一次请求会被后端拒绝。
- 这是管理权限：受信任的租户管理员可以编写 Hook 脚本和配置项目模板；应仅授予需要承担此职责的成员。

## 预览与部署

原统计模拟预览 `http://127.0.0.1:4401/` 保持运行、不受影响。

新增管理模拟预览：`http://127.0.0.1:4402/`。入口页可切换系统管理员、租户管理员、普通成员；Admin 的租户权限操作只修改隔离的模拟成员。管理配置和报表使用独立测试数据，所以修改模拟 Hook 不会改变已有模拟报表。此预览不连接实际账号、业务数据库、模型或调度器。

完整 V1 页面预览：`http://127.0.0.1:4402/v1/`（端口可由 `TENANT_MANAGEMENT_PREVIEW_PORT` 指定）。此路径加载实际 App、V1 侧栏、租户上下文和租户管理页面；身份使用测试账号，项目列表等无关服务返回空数据。租户列表必须通过实际 `createTenantsRouter` 与 `createMultitenancyDb` 查询，不能手工补入角色掩盖接口缺陷。

### V1 租户管理员没有入口

V1 展开及收起侧栏都依据当前租户的 `role === 'tenant_admin'` 显示入口，同时排除平台 Admin。2026-09-22 修复了 `/api/tenants/me` 底层查询仅返回租户信息、遗漏成员 `role` 和 `permission` 的问题；原来的管理模拟页手写了这两个字段，未覆盖此问题。现查询从 `tenant_users` 返回当前用户在各租户的真实角色、权限；不变更历史成员数据。

部署修复后的后端，再刷新页面即可重新读取角色；无需重新授权，也无需切换到 V2。若后端构建缺少 `tenant-management` 模块，还需同步部署完整后端，单独更新前端不能解决。

安装项目依赖后，可在仓库根目录启动：

```sh
node --min-semi-space-size=128 --max-semi-space-size=128 scripts/preview-tenant-management.mjs
```

脚本仅监听本机地址。数据保存在内存及本次运行的独立临时目录，结束后不保留；不是生产部署方式。针对本机 Node 24 / SQLite 原生依赖的回收兼容问题，模拟脚本保留预编译语句直到退出，仅用于交互验收。

正式应用的源码已接入路由与数据库增量迁移，但本次没有部署或重启正式服务、没有变更真实成员权限。上线时按项目正常构建／发布流程执行；先备份数据库，再由新版本启动迁移添加归属字段，历史配置保持平台归属。
