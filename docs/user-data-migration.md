# 用户数据复制覆盖

## 不停服一键迁移（推荐）

先将本版本后端部署到**所有服务副本**（首次升级按原部署流程构建/重启一次）。以后迁移时无需停服。在部署宿主机的项目目录执行：

```bash
bash scripts/migrate-user.sh 源用户名 目标用户名
```

不填参数会依次询问两个账号，也支持 `id:12 id:34`。**直接复制覆盖目标业务数据，保留源账户、源文件和目标登录身份。** 不再要求手动预览或填写确认 ID。入口只暂停有关范围，不执行应用容器的 `stop` / `start`。

执行顺序：

1. 从 `.env` / 环境变量读取路径，检查账号和支持在线迁移的后端心跳，建立唯一迁移租约。
2. 暂停这两个账号，以及它们拥有或关联的工作区的新 HTTP、WebSocket 请求和定时任务。其他用户使用这些工作区时也暂时收到 `423 ACCOUNT_MIGRATING`；他们的其他工作区继续使用。
3. 等各个在线后端确认相关在途操作结束，包括会话、Hook/MCP、后台 Agent Graph、导出和终端。默认最多等待 300 秒；超时取消本次迁移并解除暂停，不强杀操作。可加 `--wait-seconds 900`。长期保持打开的终端或插件 WebSocket 需要先结束，否则会超时。
4. 冻结相关业务记录，并 `docker pause` 相关工作区/账号的运行中 runtime。此前已被暂停的容器保持原状。备份和复制文件期间不持有数据库写事务，其他用户可正常读写。
5. 用短事务校验冻结后的数据并覆盖目标，重映射 ID、路径和关联。SQLite 提交时仍会串行化写入，其他写请求可能短暂排队；不是完全零延迟。
6. 自动 `docker unpause` 本次暂停的 runtime，解除账号/工作区限制并恢复任务调度。源数据保持原样，原目标文件及容器保留供恢复核对；目标副本首次使用时创建独立容器。旧目标容器不再被新记录引用，确认迁移结果后可另行清理。

复制失败时回滚本次目标事务，清理新副本并恢复访问，**不会用整库备份覆盖在线数据库**。正常退出和 SIGTERM 会主动恢复；脚本被强制结束时，后端在最后一次续租约 30 秒后自动恢复。若 Docker 暂时不可用，后端会持续重试，并保持相关账号暂停，避免在 runtime 尚未恢复时开放写入。后端重启后也会读取持久化的恢复记录。恢复仅涉及本次记录的容器。

要求 Python 3.9+、Docker CLI、同一个 SQLite 实例，以及宿主机与后端使用一致的绝对存储路径。所有后端副本必须升级，且能访问同一 Docker daemon。旧后端没有协调/恢复协议，脚本会拒绝执行，不自动降级为停服迁移。多机共享 SQLite、绕过 CCUI 的外部文件写入进程不受支持；检测到文件在复制期间变化会中止。

副本位于 `WORKSPACES_ROOT/.account-copies`、`CLOUDCLI_RUNTIME_ROOT/.account-copies`，备份位于 `CLOUDCLI_DATA_ROOT/account-copy-backups`（未配置时使用数据库所在目录）。已有报告导出文件时设置 `CCUI_MIGRATION_EXPORTS_ROOT`；已有 Skill 评测记录时设置 `SKILL_EVAL_STORAGE_ROOT`，须为宿主机和后端共同可访问的持久目录。数据库路径不唯一时在 `.env` 中设置 `DATABASE_PATH`。后端需能读取这些副本目录和宿主机路径。

源、目标的启用任务在恢复后都会继续执行；到期任务可能立即运行。相关租户未完成的统计候选会失效并重新计算，避免迁移前的候选重新发布目标旧数据；其他用户的已发布统计保留。正在运行的操作须先完成，原生历史格式及共享目标工作区的限制仍适用，见下文。

## 离线高级入口

下面是需要手动控制路径和预览时使用的高级入口。

脚本：`scripts/migrate-user-data.py`。Python 3.9+，只用标准库，不需要安装 Python 包，也不会导入应用、启动调度器或读取 `.env`。

本脚本用于**同一个 CCUI 实例、同一个 SQLite 数据库**内，将 A 的服务端业务数据复制到 B，覆盖 B 原有的个人业务数据。A 的账户、数据库记录和文件保留；B 的登录身份保留。它不是跨服务器搬迁、账户合并或删除源用户的工具。

## 使用

先在部署机器或具有相同挂载路径的维护容器内运行预览，数据库路径应取该实例实际的 `DATABASE_PATH`：

```bash
python3 scripts/migrate-user-data.py \
  --database /data/db/auth.db \
  --source old_username \
  --target new_username
```

也可以用 `--source id:12 --target id:34`。纯数字字符串始终作为用户名处理，使用数据库 ID 时必须加 `id:`。

预览输出源、目标的数字 ID、各表的复制/替换条数、文件路径和保留范围。不输出密码、环境变量或凭据明文，不修改业务数据。预览会检查账户、表结构、外键、运行中任务、工作区共享关系及原生会话历史是否存在；文件中的 JSON、符号链接和特殊文件在正式执行的暂存阶段逐一检查。

确认预览后，停止**全部** CCUI 后端副本、调度/统计 worker，以及相关 runtime 容器，确保原生历史没有正在写入。`--offline` 是操作者的停机声明，脚本不能替你停止服务；数据库写锁也不能阻止其他进程直接写 JSONL 文件。

准备两个已有的持久目录，留足文件副本和完整数据库备份的空间：

```bash
mkdir -p /data/account-copies /data/account-copy-backups

python3 scripts/migrate-user-data.py \
  --database /data/db/auth.db \
  --source old_username \
  --target new_username \
  --data-root /data/account-copies \
  --backup-dir /data/account-copy-backups \
  --apply --offline --confirm-target 34
```

`34` 必须换成预览中 B 的真实数字 ID。不要把预览中的源 ID 填在这里。

`--data-root` 必须位于服务可访问、Docker 可绑定挂载的持久路径内；部署了工作区根目录限制或容器路径映射时，需要让这个路径符合相同规则。若希望 runtime 清理器也能管理这些副本，将副本目录放在部署的 `CLOUDCLI_RUNTIME_ROOT` 下，并同时确认工作区访问规则允许该路径。该根目录应归服务运行用户所有；以 root 执行时，新批次目录会继承根目录属主，复制文件会保留源属主。脚本保持数据库中的绝对路径语义，因此不能在挂载路径不同的另一台机器上直接执行。

源用户有 AI 报告导出文件时，预览和执行都要加上 `--exports-root /实例实际导出目录`。导出副本使用新文件名，仍放在原导出目录以兼容下载接口。已有 Skill 评测记录时增加 `--skill-evals-root /实例实际评测目录`；每个任务复制到该目录下的新 UUID 子目录。

执行成功后按输出检查 `manifest.json`、数据库备份路径和复制条数，再启动服务，用目标账户验证工作区、历史会话、任务、Hook/MCP 配置。定时任务的 `enabled`、cron/间隔、下次运行时间会保留；**恢复调度后，两个账户都会继续执行各自的任务**，过期的下次运行时间可能立即触发任务。

## 数据范围

| 数据 | 处理方式 |
| --- | --- |
| 源用户拥有的工作区 | 新 ID、独立文件副本，包括项目文件、`.claude` 下的项目配置/Skills/MCP 文件、`.ccui` Agent Graph 配置及隐藏文件；复制完整目录，不使用硬链接 |
| 源用户有权访问的他人工作区 | 复制该用户的成员关系、ACL、个人设置、任务和会话 runtime；继续引用同一共享工作区，不擅自复制/接管他人的工作区 |
| 会话索引、消息、名称、收藏、分叉元数据 | 创建新 ID 并重映射关联；避免会话名称的全局唯一键导致两个账户共用名称 |
| Claude runtime | 复制整个 home，重映射原生 JSON/JSONL、会话文件名及目录名；容器名独立、状态置为 idle，服务恢复后创建新容器；wrapper 由服务重新生成 |
| 定时任务及日志 | 全量复制并重映射任务、会话和工作区关联，包括缺失 user_id 但关联到任务的历史日志 |
| 用户配置 | Git 名称/邮箱/令牌、环境变量、可见性/加密标记、引导状态、通知偏好、用户凭据和 CodeHub 配置 |
| 权限与功能配置 | 租户成员关系、加入申请、工作区 ACL、MCP 工具偏好、SQL Check 规则、个人环境变量/禁止规则、Hook 绑定/作用域/偏好/加密变量 |
| 工作区安装信息 | MCP/Skill 安装、市场绑定、Agent 模板快照、Hook 版本分配、Skill 绑定历史 |
| Skill 创建与评测 | 复制创建任务、调用记录、评测任务及报告文件、个人评测最新索引和自有工作区测试用例元数据，重映射会话、任务和路径；进行中的创建/评测先等待结束，排队评测暂停后随副本恢复 |
| 业务记录 | Hook 执行及输出、MCP 循环任务及尝试记录、AI MR 提交及文件记录、AI 原始回合事实、Skill 上下文/发布记录、导出任务及文件 |
| 统计派生数据 | 复制原始事实，清理目标的旧个人派生行并标记租户待刷新；由现有统计 worker 重建。源账户的已发布统计行保留；目标统计不会立即完整出现 |
| 共享的租户/平台资源 | 保留租户、平台配置、Hook 定义及发布版本、模板、MCP/Skill 预设、公共 Skill 片段及审计、统计运行日志等，副本继续引用它们。创建者字段不表示资源属于个人，不能按创建者删除共享资源 |

以下内容属于身份或设备，不作为个人业务数据覆盖：

- B 的 `id`、用户名、密码、系统管理员标志、启用状态、注册/登录时间。
- B 的受管理 `USER_KEY`、登录 API Key、邀请/密码重置令牌、浏览器推送订阅。
- 浏览器 `localStorage` 中的 UI 偏好、草稿等。服务端没有这些数据，脚本无法读取；它们通常也是当前浏览器共享的设置。

其他用户对 A 工作区的 ACL 不会自动复制到新工作区，避免把 B 的副本额外分享出去。应用密钥和全局配置保持原实例不变，所以数据库内的加密业务配置可以直接复制，无需解密或输出明文。Git/第三方业务凭据仍是同一外部凭据的副本；脚本不创建新的第三方账号或撤销旧凭据。

## 通用完整性检查与离线执行条件

- 默认只读；只有 `--apply --offline --confirm-target <目标ID>` 和备份/数据目录齐全时才执行。
- 在 `BEGIN IMMEDIATE` 写锁内生成 SQLite 一致性备份，包含已提交的 WAL 内容。备份转换为独立的 DELETE-journal 数据库，权限为 `0600`，目录为 `0700`。
- 文件先复制到全新目录，成功后才覆盖数据库。普通异常会回滚 SQL 并清除本次新副本。源文件及目标原文件都不会删除。
- 提交前检查所有外键、数据库完整性以及每条源业务记录仍与迁移前相同。
- 未识别的表/用户字段、丢失的源目录/原生会话文件、无效 JSON、跨副本边界的符号链接、引用外部 Git 元数据的 worktree/alternates、socket/FIFO/device 等特殊文件都会中止，不静默跳过。
- 目标拥有的工作区存在其他账户的 ACL 或业务数据时会中止。先明确处理共享关系后再运行；脚本没有强制级联删除选项。
- 未完成的 Hook/MCP 循环/导出/AI 回合，以及仍有效的统计 worker 租约会阻止执行。请先完成或取消任务，不要仅为绕过检查而直接改状态。
- **当前原生会话文件复制支持 Claude 独立 runtime。** 对无 runtime 的旧式宿主机全局会话、Codex/Cursor/Gemini 会话，或 runtime 内含未支持的 SQLite 原生状态文件，脚本明确中止。这些历史存储不能仅靠修改 user_id 完整且独立地迁移，需要对应的原生文件适配器。

不要把备份或新副本根目录放进现有源/目标工作区或 runtime 内，防止递归复制。只有离线高级入口要求停止服务；上述一键入口使用在线协调协议。备份中含账户和加密业务凭据，按生产数据库备份管理。

## 恢复

在线迁移失败不会自动整库恢复。下面的整库恢复仅用于明确需要撤销整个实例变更的离线灾难恢复，不能在其他用户继续使用时执行。已提交迁移若要撤销，应根据清单进行目标账户范围的恢复，不能直接覆盖整库。

`manifest.json` 记录数据库路径、备份文件、新副本路径、原目标文件路径及 ID 映射，不记录凭据明文。原目标目录留在原位，因此数据库回滚后仍能使用原文件。

**完整数据库恢复会撤销该备份之后整个实例的所有数据库变更**，应在重新开放服务前完成。停止全部服务和容器后，可通过 SQLite backup API 恢复，避免直接复制文件时遗漏 WAL：

```bash
python3 - /data/account-copy-backups/user-copy-实际批次/before.sqlite /data/db/auth.db <<'PY'
import sqlite3, sys
from pathlib import Path
from contextlib import closing
source = Path(sys.argv[1]).resolve(strict=True)
target = Path(sys.argv[2]).resolve(strict=True)
assert source != target
with closing(sqlite3.connect(source.as_uri() + '?mode=ro', uri=True)) as backup:
    with closing(sqlite3.connect(target.as_uri() + '?mode=rw', uri=True)) as live:
        backup.backup(live)
        assert live.execute('PRAGMA integrity_check').fetchone()[0] == 'ok'
PY
```

恢复后再根据清单删除本次生成的副本；确认新副本不再被数据库引用后才删除。原目标目录不在脚本的自动删除范围内。

强制结束进程/掉电时，SQLite 事务负责数据库原子性，但可能留下本次暂存文件。每次成功提交都会同时写入 `app_config` 的 `migration:user-copy:<批次>` 标记：

- 标记存在：数据库已提交；即使缺少 `result.json`，也不要直接删新副本或重复执行。
- 标记不存在：事务未提交；在线模式先等待本批次自动恢复完成，离线模式保持服务停止，核对数据库和清单后可清理该批次暂存文件。

脚本不是按源/目标自动去重的作业。再次显式执行会再次覆盖目标并生成一个新批次。

## 测试

```bash
python3 -m unittest discover -s scripts -p 'test_migrate_user*.py' -v
node --test server/services/account-copy-guard.test.js
```

测试使用临时数据库和目录，并用 Node.js 22+ 的内置 SQLite 加载仓库当前真实 JS schema 和统计迁移/触发器。可通过 `NODE=/绝对路径/node` 指定测试运行时。执行迁移脚本本身不需要 Node。
